# Databasus 도입 비용 비교

고객사의 데이터베이스를 서버 밖에 안전하게 보관하면서 그 비용이 얼마인지 근거를 들어 설명하려고 이 문서를 만들었다. 결론부터 적는다. Databasus를 기존 운영 노드에 얹고 같은 서울 리전의 S3 Standard 버킷에 보관하면 새로 생기는 현금 비용은 S3 저장 요금 하나뿐이고, 측정된 백업 파일 크기 기준으로 14벌을 보관해도 월 2원 수준이다. 백업 파일이 1GB까지 커져도 월 473원이다. 전용 노드를 따로 세우는 경우에도 월 28,085원이고 기존 4대 견적을 더해 약 167,500원이므로 월 40만 원 예산 안에 남는다.

비용 비교에서 가장 중요한 결과는 절대 금액이 아니라 순위다. 복원 검증을 매일 돌린다는 조건을 걸면 전용 노드까지 세운 Databasus가 AWS Backup보다 싸다. AWS Backup은 복원 테스트 1건당 요금을 따로 받기 때문이다. 이 한 줄이 비용 문제로 반박당하지 않는 가장 강한 근거다.

## 이 문서의 성격

이 문서는 실행 전 설계다. Databasus를 학교 AWS에도 로컬 VM에도 아직 설치하지 않았고, 백업을 한 번도 받지 않았으며, S3 업로드와 복원 검증을 실행하지 않았다. 따라서 아래 금액은 공식 가격표에서 확인한 단가와 산식으로 만든 견적이지 청구서로 확인한 실적이 아니다.

문서 안에서 세 가지를 구분해 적었다. 공식 가격표나 증거본에서 직접 확인한 값은 확인으로 적고 출처를 붙였다. 계산을 위해 내가 정한 값은 가정으로 표시했다. 확인하지 못한 값은 [확인하지 못한 값](#확인하지-못한-값) 절에 모았고 본문에서도 그때그때 밝혔다. 권고안은 내가 제안하는 선택지이며 사용자가 확정한 요구가 아니다.

## 계산의 공통 가정

아래 가정은 전부 내가 정한 것이며 측정으로 확인한 조건이 아니다.

| 항목 | 값 | 성격 |
|---|---|---|
| 리전 | 아시아 태평양(서울) ap-northeast-2 | 현재 구성과 동일 |
| 가동 시간 | 월 730시간 | 가정 |
| 백업 주기 | 일 1회 전체 백업 | 가정 |
| 보존 기간 | 14일 | 가정 |
| 환율 | 1,350원/USD | 가정 |
| 세금 | 부가세와 각종 세금 제외 | 가정 |
| 용량 단위 | 1GB = 10의 9승 바이트 | 가정 |

환율은 가정이다. 2026년 9월 시장 환율은 약 1,340원에서 1,344원 사이로 조사됐으므로 1,350원은 조금 보수적으로 잡은 값이다. 실제 청구는 AWS의 청구 시점 환율과 부가세를 따르며 이 문서는 그것을 반영하지 않았다.

용량 단위도 가정이다. AWS가 저장 요금의 GB를 10의 9승으로 세는지 2의 30승으로 세는지 이번에 공식 문서로 확인하지 못했다. 둘 중 금액이 더 크게 나오는 10의 9승 기준으로 계산했다. 2의 30승 기준이면 이 문서의 저장 금액은 약 7퍼센트 낮아진다. 이 차이는 현재 규모에서 1원 미만이라 결론을 바꾸지 않는다.

원화 표기는 달러 값에 환율을 곱해 반올림했다. 단가 자체는 달러가 기준이므로 판단은 달러 값으로 한다.

## 측정으로 확인한 값과 그 한계

비용 계산의 출발점은 백업 파일이 실제로 얼마나 큰가이다. 이 값은 추정하지 않아도 된다. 증거본에 실측이 남아 있다.

2026-09-19 16:16:07 UTC에 DB 호스트에서 실행한 psql 출력에서 `pg_database_size('exchange')`가 58,726,067바이트였다. 같은 출력에서 디스크는 `/dev/nvme0n1p1 50G 2.3G 48G 5% /`, 메모리는 `Mem: 1909 277 719`였다. 출처는 `C:\Users\kopo26\Desktop\failstop\증거본\2026-09-20_백업_복구_보고\001_DB_백업전_상태.txt`다.

8분 뒤인 16:24:52 UTC에 받은 백업의 판정 파일에는 더 중요한 값이 있다. 백업 ID `20260919T162452010003Z`에서 `source_bytes`가 64,263,859바이트이고 `archive_bytes`가 4,559,507바이트다. 즉 61.3MiB짜리 데이터베이스를 `pg_dump` 커스텀 포맷으로 받으니 4.35MiB가 됐다. 압축비는 약 14.1대 1이고 덤프는 원본의 7.1퍼센트다. 출처는 같은 폴더의 `007_DB_백업_격리복원_통과.txt`이며 덤프 형식은 `C:\Users\kopo26\Desktop\failstop\deploy\backup\backup.py` 91행의 `pg_dump --format=custom`이다.

이 압축비를 Databasus에 그대로 적용해도 큰 무리는 없다. Databasus의 논리 백업도 `pg_dump` 커스텀 포맷을 쓴 뒤 zstd로 한 번 더 압축하고 암호화하는 구조이기 때문이다. 커스텀 포맷이 이미 압축돼 있어 zstd가 추가로 줄일 여지는 크지 않으므로 4.35MiB 근처가 나올 것으로 본다. 다만 이것은 추정이고 Databasus가 실제로 만드는 파일 크기는 측정하지 않았다.

측정값의 한계도 분명히 적는다. 이 값은 2026-09-19 시점이고 그 뒤 거래가 더 쌓였으므로 지금 크기는 더 크다. 하루 증가량은 측정하지 않았다. 위 두 측정값의 차이인 5,537,792바이트를 525초로 나눠 하루로 늘리면 약 911MB가 되지만, 이 계산을 증가량으로 쓰면 안 된다. 8분 45초 떨어진 두 점을 직선으로 이은 값일 뿐이고, 봇이 활발히 거래하던 구간이며, `pg_database_size`는 vacuum이 회수하는 팽창분까지 포함하기 때문이다. 저장소도 하루 1에서 2GB라는 추정을 측정값으로 쓰지 말라고 이미 적어 두었다. 하루 증가량은 24시간 이상 실제로 재야 한다.

그래서 이 문서는 절대 금액을 단정하지 않고 GB당 단가와 산식을 결론으로 삼는다. 금액은 측정된 4.35MiB, 보수적으로 잡은 56MiB, 그리고 규모가 커졌을 때를 보는 1GB와 5GB의 네 가지 경우로 나눠 제시한다.

## Databasus 도입 비용

Databasus 도입으로 새로 생기는 비용은 소프트웨어, 저장, 요청, 전송, 컴퓨트의 다섯 갈래다. 이 중 실제로 돈이 나가는 것은 저장과 컴퓨트 둘뿐이다.

### 소프트웨어 비용은 0원이다

Databasus는 Apache 2.0 라이선스이고 유료 티어나 기능 제한판이 없다. 출처는 `https://github.com/databasus/databasus`의 README.md 13행 라이선스 배지와 302행에서 304행의 License 절, 그리고 `https://databasus.com/`이다. 좌석당 요금도 데이터 용량당 요금도 없으므로 고객사가 늘어도 소프트웨어 비용은 늘지 않는다. 상용 제품과 비교할 때 가장 큰 구조적 차이가 이것이다.

### 저장 비용

일 1회 전체 백업을 N일 보존하면 정상 상태에서 항상 N벌이 버킷에 있다. 월 저장 비용의 산식은 다음과 같다.

```
월 저장비($) = 덤프 크기(GB) x max(보존일수, 계층 최소보존일수) x 계층 단가($/GB월)
```

S3 Standard는 최소 보존 기간이 없으므로 `max(14, 0) = 14`가 되어 덤프 크기에 14와 0.025를 곱하면 된다. 서울 S3 Standard 단가는 첫 50TB 구간에서 GB월당 $0.025이며, 출처는 `https://pricing.us-east-1.amazonaws.com/offers/v1.0/aws/AmazonS3/current/ap-northeast-2/index.json`의 2026-09-18T17:47:47Z 판이다.

| 덤프 1벌 크기 | 근거 | 14벌 합계 | 월 저장비 | 원화 |
|---|---|---|---|---|
| 4,559,507바이트 | 2026-09-19 실측 | 0.0638GB | $0.0016 | 약 2원 |
| 58,726,067바이트 | DB 크기를 덤프로 잡은 보수 가정 | 0.8222GB | $0.0206 | 약 28원 |
| 1GB | 규모 확대 가정 | 14GB | $0.3500 | 약 473원 |
| 5GB | 규모 확대 가정 | 70GB | $1.7500 | 약 2,362원 |

두 번째 줄은 덤프가 전혀 압축되지 않는다고 가정한 상한선이다. 실측 압축비를 적용한 첫 줄이 실제에 가깝다. 어느 쪽이든 금액은 무시할 수준이고, 판단에 쓸 것은 마지막 두 줄이 보여 주는 기울기다. 덤프 크기가 10배가 되면 비용도 정확히 10배가 되는 선형 구조이며 숨은 계단이 없다.

### 요청 비용

서울 S3 Standard의 PUT, COPY, POST, LIST는 1,000건당 $0.0045이고 GET을 비롯한 나머지 요청은 10,000건당 $0.0035다. 출처는 위와 같은 가격표다.

실측 크기인 4.35MiB는 멀티파트 임계값 아래이므로 백업 1회에 PUT 1건이면 된다. 월 30건이면 $0.000135다. 덤프가 1GB로 커져 16MiB 단위 멀티파트로 올린다고 해도 파트 60개에 시작과 완료 요청을 더해 회당 66건 수준이고, 월 1,980건이면 $0.00891이다. 복원 검증이 매일 파일을 다시 읽는 GET도 같은 규모라 합쳐도 월 1센트에 못 미친다. 요청 비용은 계산에는 넣되 의사결정에서는 무시해도 된다.

### 전송 비용은 0원으로 설계할 수 있다

이 항목은 설계로 없앨 수 있으므로 따로 적는다. 인터넷에서 S3로 들어오는 전송은 과금하지 않고, S3 가격 페이지는 대역폭 과금 예외로 버킷과 같은 리전 안의 AWS 서비스로 나가는 전송을 명시한다. 출처는 `https://aws.amazon.com/s3/pricing/`다. 따라서 서울 리전 EC2에서 서울 리전 버킷으로 올리는 업로드와 복원 시 내려받는 전송 모두 $0이다.

여기에 한 가지 조건이 붙는다. EC2에서 S3로 가는 트래픽이 NAT 게이트웨이를 거치면 리전 내 전송은 공짜여도 NAT의 데이터 처리 요금이 붙는다. S3 게이트웨이 VPC 엔드포인트를 만들면 이 경로를 피할 수 있고 엔드포인트 자체는 무료다. VPC 가격 페이지에 게이트웨이 형식 VPC 엔드포인트에는 데이터 처리 요금도 시간 요금도 없다고 적혀 있다. 출처는 `https://aws.amazon.com/vpc/pricing/`이며 2026-09-22에 다시 확인했다. 즉 같은 리전 버킷과 게이트웨이 엔드포인트 두 가지를 설계에 넣으면 전송 비용은 0원이 된다.

### 컴퓨트 비용은 배치 방식이 좌우한다

Databasus를 어디에 올리느냐가 이 도입의 유일한 큰 비용 변수다.

기존 노드에 얹으면 추가 컴퓨트 비용은 $0이다. ADR 0034 초안이 1순위 후보로 든 bot-1은 Prometheus와 Grafana가 이미 있고 DB Primary의 5432 인증이 그 노드의 사설 주소로 열려 있어 새 경로를 만들지 않아도 된다. 다만 이 $0이 성립하려면 그 노드에 메모리와 디스크 여유가 실제로 있어야 하는데 bot-1의 여유는 확인하지 못했다. 위에 인용한 `Mem: 1909 277 719`는 DB 호스트의 값이지 bot-1의 값이 아니다.

전용 노드를 세우는 경우의 단가는 공식 가격표에서 다시 확인했다. t3.small Linux 온디맨드는 시간당 $0.026, gp3는 GB월당 $0.0912다. 출처는 `https://pricing.us-east-1.amazonaws.com/offers/v1.0/aws/AmazonEC2/current/ap-northeast-2/index.csv`의 2026-09-01 발효판이다. 공인 IPv4는 주소당 시간당 $0.005이며 출처는 VPC 가격 페이지다.

```
전용 노드(공인 IPv4 없음) = 0.026 x 730 + 20 x 0.0912
                          = 18.98 + 1.824 = $20.80
전용 노드(공인 IPv4 포함) = 20.80 + 0.005 x 730 = $24.45
```

| 배치 | 월 비용 | 원화 |
|---|---|---|
| 기존 노드에 얹음 | $0 | 0원 |
| 전용 t3.small + 20GiB gp3, 사설 전용 | $20.80 | 약 28,085원 |
| 전용 t3.small + 20GiB gp3, 공인 IPv4 포함 | $24.45 | 약 33,013원 |

사설 전용 $20.80을 그대로 쓰기 전에 확인할 것이 하나 있다. 이 노드는 Docker 이미지를 받아야 하고 이후 갱신도 받아야 하는데, 공인 IPv4가 없으면 인터넷으로 나갈 경로가 따로 있어야 한다. 현재 학교 구성은 기본 VPC이고 기존 인스턴스들이 공인 IPv4를 갖고 있으므로 NAT 게이트웨이가 있다고 볼 근거가 없다. NAT 게이트웨이를 새로 만들면 그 요금이 노드 자체보다 클 가능성이 크다. 서울 리전 NAT 게이트웨이 단가는 VPC 가격 페이지에서 확인하지 못했고 같은 페이지의 미국 동부(오하이오) 값은 시간당 $0.045에 처리 GB당 $0.045였다. 다른 리전 값이므로 서울 금액으로 쓰면 안 되지만, 시간 요금만 730시간으로 환산해도 $32.85라는 규모는 보여 준다.

그래서 실무적으로는 두 가지 중 하나를 택한다. 설치와 갱신 때만 공인 IPv4를 붙였다가 떼거나, 처음부터 $24.45를 예산에 넣는다. 이 문서의 전체 비교표는 보수적으로 $20.80을 쓰되 이 조건을 함께 적는다.

## 저장 계층을 내리면 오히려 비싸진다

비용을 줄이라는 말을 들으면 Glacier로 내리자는 제안이 먼저 나온다. 보존 14일 설계에서는 그 제안이 틀렸고, 이것을 숫자로 보여 줄 수 있어야 한다.

저비용 계층에는 최소 보존 기간이 붙는다. Standard-IA와 One Zone-IA는 30일, Glacier Instant Retrieval과 Glacier Flexible Retrieval은 90일, Deep Archive는 180일이고 IA 계열에는 최소 과금 객체 크기 128KB도 적용된다. 출처는 `https://docs.aws.amazon.com/AmazonS3/latest/userguide/storage-class-intro.html`의 계층 비교표다. 14일 만에 지워도 최소 기간만큼은 요금을 낸다.

여기에 조회 요금이 더해진다. 이 프로젝트는 복원 검증을 예약 실행하는 것을 도입의 핵심 근거로 삼는데, 복원 검증은 백업 파일을 매번 다시 읽는다. Standard는 조회 요금이 없지만 Standard-IA는 GB당 $0.01, Glacier Instant Retrieval은 GB당 $0.03을 받는다. 출처는 서울 S3 가격표다.

덤프 1GB, 보존 14일, 복원 검증 매일 실행을 가정한 월 비용은 다음과 같다.

| 계층 | 과금 일수 | 저장비 | 검증 조회비 | 합계 | Standard 대비 |
|---|---|---|---|---|---|
| Standard | 14일 | $0.3500 | $0 | $0.3500 | 기준 |
| One Zone-IA | 30일 | $0.3300 | $0.30 | $0.6300 | 1.80배 |
| Standard-IA | 30일 | $0.4140 | $0.30 | $0.7140 | 2.04배 |
| Glacier Flexible Retrieval | 90일 | $0.4050 | 미확인 | $0.4050 초과 | 1.16배 초과 |
| Glacier Instant Retrieval | 90일 | $0.4500 | $0.90 | $1.3500 | 3.86배 |

Glacier Flexible Retrieval의 서울 조회 단가는 이번에 확인하지 못해 조회비를 비워 두었다. 다만 이 계층은 꺼내는 데 수 분에서 수 시간이 걸리므로 예약 복원 검증에는 애초에 쓸 수 없다. 금액을 채우지 않아도 탈락한다.

One Zone-IA는 저장비만 보면 $0.33으로 Standard보다 싸다. 손익분기가 13.2일이라 14일 보존이 그 선을 넘기 때문이다. 그러나 이름 그대로 가용 영역 한 곳에만 저장한다. 서버 밖에 백업을 두려는 이유가 한 곳이 사라지는 사고에 대비하는 것인데 보관지를 다시 한 곳으로 만들면 목적이 무너진다. 월 0.02달러를 아끼려고 그렇게 하지 않는다. One Zone-IA의 조회 단가는 서울 목록에서 따로 확인하지 못했고 위 표에서는 Standard-IA와 같다고 가정했다.

조회 요금을 빼고 저장비만으로 손익분기 보존 기간을 계산하면 다음과 같다. Standard는 보존일수에 단가를 곱하고 최소 보존이 있는 계층은 최소 보존일수에 단가를 곱하므로, 두 값이 같아지는 지점을 구하면 된다.

```
손익분기 보존일수 = 계층 최소보존일수 x 계층 단가 / Standard 단가
```

| 계층 | 계산 | 손익분기 |
|---|---|---|
| One Zone-IA | 30 x 0.011 / 0.025 | 13.2일 |
| Glacier Flexible Retrieval | 90 x 0.0045 / 0.025 | 16.2일 |
| Standard-IA | 30 x 0.0138 / 0.025 | 16.6일 |
| Glacier Instant Retrieval | 90 x 0.005 / 0.025 | 18.0일 |

따라서 보존 14일을 유지하는 동안에는 계층을 내리지 않는다. 계층 전환은 보존을 30일 이상으로 늘릴 때, 또는 월 단위와 연 단위 장기 보관본을 따로 둘 때만 검토한다. 그때도 그 보관본을 복원 검증 대상에서 빼야 조회 요금이 붙지 않는다.

## 대안과의 비교

### AWS Backup과 EBS 스냅샷

저장 단가부터 불리하다. 서울 EBS 스냅샷 저장은 GB월당 $0.05로 S3 Standard의 두 배다. 출처는 위 EC2 가격표의 해당 항목이며 2026-09-01 발효판이다. 스냅샷 아카이브는 GB월당 $0.0125로 싸지만 최소 90일이고 복구할 때 GB당 $0.03이 붙는다.

스냅샷은 증분이라 실제 저장량이 사용 블록 수로 결정되는데 이 값을 측정하지 않았다. DB 호스트의 파일시스템 사용량 2.3GB를 기준으로 2대 기본 4.6GB만 잡으면 월 $0.23이고, 하루 변경 0.5GB를 가정해 14일치를 더한 17.6GB면 월 $0.88이다. 둘 다 가정이다.

결정적인 차이는 복원 검증 요금이다. AWS Backup의 서울 복원 테스트는 복구 지점 1건당 $1.65다. 출처는 `https://pricing.us-east-1.amazonaws.com/offers/v1.0/aws/AWSBackup/current/ap-northeast-2/index.json`의 APN2-RT-RecoveryPoint-FixedFee 항목이며 2026-09-11 판이다.

```
매일 검증 = 30건 x $1.65 = $49.50, 저장 $0.88을 더해 $50.38
주 1회 검증 = 4건 x $1.65 = $6.60, 저장 $0.88을 더해 $7.48
```

| 검증 주기 | AWS Backup | Databasus 전용 노드 | 차이 |
|---|---|---|---|
| 매일 | $50.38 (약 68,013원) | $21.15 (약 28,558원) | Databasus가 $29.23 저렴 |
| 주 1회 | $7.48 (약 10,098원) | $21.15 (약 28,558원) | AWS Backup이 $13.67 저렴 |

Databasus는 자기 컴퓨트에서 복원 검증을 돌리므로 회당 추가 요금이 없다. 검증 횟수를 늘려도 금액이 변하지 않는 구조다. 반대로 AWS Backup은 검증 횟수에 비례해 요금이 오른다. 그래서 검증을 자주 할수록 Databasus가 유리해지고, 매일 검증을 조건으로 걸면 전용 노드를 세워도 Databasus가 더 싸다. 검증을 드물게 하면 AWS Backup이 싸다는 점도 함께 적는다. 어느 쪽이 싼지는 검증 주기에 달려 있고, 이 프로젝트는 매일 검증을 전제로 한다.

AWS Backup에 최소 요금이나 셋업 요금은 없고 EBS 복원 자체도 무료다. 출처는 `https://aws.amazon.com/backup/pricing/`다. 금액 밖의 차이는 따로 있다. EBS 스냅샷은 볼륨 단위 블록 복사라 테이블 단위 복원이나 논리 정합성 검사를 제공하지 않는다. 현재 구성은 PGDATA가 50GiB 루트 볼륨에 있어 스냅샷마다 OS까지 함께 담긴다. 잘못된 DELETE 한 건을 되돌리려고 볼륨 전체를 되감아야 한다는 뜻이다.

### RDS 자동 백업

RDS 백업은 할당 스토리지의 100퍼센트까지 무료이고 초과분만 서울 PostgreSQL 기준 GB월당 $0.095다. 출처는 `https://pricing.us-east-1.amazonaws.com/offers/v1.0/aws/AmazonRDS/current/ap-northeast-2/index.json`의 2026-09-17 판이다. 백업이 공짜로 보이지만 그 대가는 인스턴스 요금에 들어 있다.

서울 단가는 db.t3.small PostgreSQL이 Single-AZ 시간당 $0.056, Multi-AZ 시간당 $0.112이고 gp3 스토리지가 Single-AZ GB월당 $0.131, Multi-AZ GB월당 $0.262다. 출처는 같은 가격표다.

```
현재 EC2 2대  = 2 x 0.026 x 730 + 100 x 0.0912 = 37.96 + 9.12 = $47.08
RDS Multi-AZ  = 0.112 x 730 + 50 x 0.262       = 81.76 + 13.10 = $94.86
RDS Single-AZ = 0.056 x 730 + 50 x 0.131       = 40.88 + 6.55  = $47.43
```

| 구성 | 월 비용 | 원화 | 이중화 |
|---|---|---|---|
| 현재 EC2 2대 (t3.small 2대 + 50GiB gp3 2개) | $47.08 | 약 63,558원 | Standby 있음, 수동 승격 |
| RDS Multi-AZ db.t3.small + 50GiB | $94.86 | 약 128,061원 | 있음 |
| RDS Single-AZ db.t3.small + 50GiB | $47.43 | 약 64,031원 | 없음 |

같은 수준의 이중화를 맞추면 월 $47.78, 약 64,503원을 더 낸다. 무료 백업의 대가로 월 6만 원 이상을 더 내는 셈이다. Single-AZ로 맞추면 금액은 현재와 거의 같지만 Standby가 사라져 비교 대상이 아니다.

비용 밖의 이유도 있다. RDS 전환은 AGENTS.md가 최우선 역량으로 정한 Linux 서버 운영 범위를 줄이고, ADR 0004가 장애 실험을 위해 자체 운영 PostgreSQL을 선택한 결정과도 어긋난다. 이번 프로젝트에서는 금액 이전에 목적이 맞지 않는다.

### 직접 만든 스크립트

이 대안은 이미 저장소에 있다. `C:\Users\kopo26\Desktop\failstop\deploy\backup\backup.py`가 `pg_dump` 커스텀 포맷 백업과 격리 복원 검증을 수행하고 `failstop-backup.timer`가 매일 03:30 Asia/Seoul에 실행한다. 소프트웨어 비용은 Databasus와 똑같이 $0이다. 이 서비스가 이미 `Requires=docker.service`로 Docker를 쓰고 있어 Docker 회피라는 이점도 없다.

없는 것은 기능이다. 외부 보관 업로드, 보존 회전, 알림, 화면, 역할 기반 접근 통제, 감사 로그, 여러 DB 관리, WAL 기반 PITR이 전부 없다. 이 기능을 직접 만드는 개발 공수가 실제 비용인데 이번에 시간 단가를 확정하지 않았으므로 금액으로 환산하지 않았다. 추정치를 지어내지 않고 미확인으로 남긴다. 이 스크립트는 지우지 않고 대체 경로로 유지한다.

### Cloudflare R2

R2 Standard는 GB월당 $0.015로 S3 서울 $0.025보다 싸고 송신이 무료다. 출처는 `https://developers.cloudflare.com/r2/pricing/`다. 그런데 이번 구성에서는 절감이 되지 않는다. 원본이 AWS EC2 안에 있어 R2로 올리는 트래픽이 AWS 인터넷 송신이 되기 때문이다. 서울 송신은 첫 10TB 구간에서 GB당 $0.126이고, AWS는 전 리전 합산 월 100GB를 무료로 준다. 출처는 `https://pricing.us-east-1.amazonaws.com/offers/v1.0/aws/AWSDataTransfer/current/index.csv`의 2026-06-01 발효판과 `https://aws.amazon.com/ec2/pricing/on-demand/`다.

일 덤프 크기를 D(GB)라 하면 두 선택지의 월 비용은 다음과 같다.

```
S3 = 14 x D x 0.025
R2 = 14 x D x 0.015 + max(0, 30 x D - 100) x 0.126
```

두 값이 같아지는 D는 3.46GB다. 그보다 작으면 R2가 싸고 크면 S3가 싸다. 일 5GB면 S3가 $1.75, R2가 $7.35로 R2가 월 $5.60 더 비싸다. 무료 송신 100GB 구간 안에 머무는 현재 규모에서는 R2가 월 몇 센트 싸지만, 그 차이를 위해 AWS 밖 공급자와 자격증명을 하나 더 늘릴 이유가 없다. R2는 AWS 밖에 사본을 한 벌 더 두는 두 번째 보관지로만 의미가 있다.

## 고객사에 설명할 때 쓰는 산식

MSP 담당자로서 고객사마다 다른 규모에 같은 답을 주려면 금액이 아니라 산식을 들고 가야 한다. 보존 14일, S3 Standard 서울 기준의 월 보관비는 다음 한 줄로 끝난다.

```
월 보관비($) = 일 덤프 크기(GB) x 14 x 0.025
```

| 일 덤프 크기 | 월 보관비 | 원화 |
|---|---|---|
| 5MB | $0.002 | 약 2원 |
| 100MB | $0.035 | 약 47원 |
| 1GB | $0.350 | 약 473원 |
| 10GB | $3.500 | 약 4,725원 |
| 100GB | $35.00 | 약 47,250원 |

일 덤프 100GB짜리 고객사도 보관비는 월 5만 원을 넘지 않는다. 여기에 전송비가 붙지 않고 라이선스비도 없으며 복원 검증 횟수를 늘려도 금액이 변하지 않는다. 비용이 문제가 되지 않는다고 말할 수 있는 근거가 이 표다. 비용이 늘어나는 지점은 보존 기간을 늘릴 때와 백업 주기를 촘촘히 할 때이므로, 고객과 합의할 것은 가격이 아니라 복구 목표 시점과 보존 기간이다.

## 확인하지 못한 값

아래 항목은 이번에 확인하지 못했다. 발표와 보고에서 이 값을 아는 것처럼 말하지 않는다.

측정해야 할 값이 셋 있다. 현재 거래 DB의 실제 크기와 하루 증가량을 다시 재지 않았다. Databasus가 실제로 만드는 백업 파일의 크기와 압축비도 측정하지 않았고, README가 적은 4배에서 8배 절감과 약 20퍼센트 오버헤드는 제조사 주장이다. WAL 스트리밍으로 PITR을 켰을 때 하루에 생기는 WAL 용량과 객체 수도 모른다. 이 값이 없으면 PITR 구간의 저장과 요청 비용을 계산할 수 없다.

배치 판단에 필요한 값도 남아 있다. Databasus의 최소 RAM, CPU, 디스크 요구사항을 공식 문서에서 찾지 못했다. `https://databasus.com/docs`와 `/docs/getting-started/installation`은 404였다. 01-도구조사 문서가 설치 페이지에서 CPU 1코어, RAM 500MB, 디스크 5GB라는 최소치를 찾았으나 그것은 최소 표기이지 우리 규모의 실측이 아니다. bot-1의 현재 메모리 여유도 확인하지 못했으므로 기존 노드에 얹는 안의 추가 컴퓨트 $0이 성립하는지는 아직 단정할 수 없다. 사설 전용 노드의 인터넷 경로와 서울 리전 NAT 게이트웨이 단가도 확인하지 못했다.

가격표에서 찾지 못한 항목도 있다. Glacier Deep Archive의 서울 본 저장 단가가 목록에 없었고 Staging $0.023과 복구 요금만 있었다. 보존 14일 설계에서 쓰지 않을 계층이라 더 조사하지 않았다. Glacier Flexible Retrieval과 One Zone-IA의 서울 조회 단가도 확인하지 못했다. AWS Backup 서울 가격표에는 EBS 웜 저장의 일반 항목이 없고 논리적 에어갭 볼트용 $0.0575만 있었다. 미국 동부 페이지의 $0.05와 서울 EBS 스냅샷 $0.05가 일치하므로 같다고 보았으나 서울 목록에서 직접 확인한 값은 아니다. EBS 스냅샷의 실제 증분 용량도 측정하지 않았다. 스냅샷은 파일시스템 사용량이 아니라 기록된 블록 수로 과금되므로 df 출력의 2.3GB보다 클 수 있다.

비교 범위의 한계도 적는다. SimpleBackups 외의 상용 제품은 정가를 공개하지 않아 넣지 못했고, SimpleBackups 요금제의 보존 기간 상한과 SLA 조항도 확인하지 못했다. 직접 만든 스크립트를 Databasus 수준으로 올리는 운영 공수를 금액으로 환산하지 않았다. 시간 단가를 사용자가 확정하지 않았으므로 추정치를 쓰지 않았다. 환율과 세금도 위에 적은 대로 가정이다.

## 금액으로 환산되지 않는 차이

비용 비교를 금액만으로 끝내면 발표에서 반박당한다. 장애가 났을 때 누가 책임지는가는 표에 넣을 수 없는 항목이다.

Databasus와 직접 만든 스크립트는 오픈소스와 자체 코드라 공급사 보증이 없고 복구 실패의 책임이 운영자에게 있다. AWS Backup과 RDS는 AWS 서비스 수준 약정의 대상이지만 백업 정책 설계와 복원 성공 여부는 여전히 이용자 책임이다. 상용 SaaS는 지원 계약이 붙지만 SimpleBackups의 SLA 조항을 이번에 확인하지 않았다.

그래서 오픈소스를 고르는 쪽은 책임을 도구에 넘기지 않는 대신 복원이 실제로 된다는 증거를 스스로 만들어야 한다. 복원 검증을 매일 돌리는 설계가 그 증거이고, 그 검증에 회당 요금이 붙지 않는다는 점이 Databasus를 고르는 비용상의 이유와 신뢰상의 이유를 같은 방향으로 맞춘다.

Databasus는 Docker로만 설치한다는 점도 함께 적는다. README가 제시하는 설치 방법은 자동 스크립트, `docker run`, Docker Compose, Kubernetes Helm 네 가지이고 기본 포트는 4005이며 네이티브 패키지나 단일 바이너리 배포가 없다. AGENTS.md는 Docker를 필요한 항목만 이유와 범위를 기록해 쓰게 했으므로 도입 시 사유와 범위를 남겨야 한다. 금액 비용은 아니지만 규칙상 기록 의무가 있는 항목이다.

## 권고

아래는 내가 제안하는 선택지이며 사용자가 확정한 요구가 아니다.

Databasus를 도입하되 전용 노드를 먼저 만들지 않고 기존 노드에 얹어 시작한다. 보관은 같은 서울 리전의 S3 Standard 버킷에 S3 게이트웨이 VPC 엔드포인트를 통해 올린다. 이 조합에서 새로 생기는 현금 비용은 S3 저장 요금뿐이고 측정된 덤프 크기 기준으로 14벌을 보관해도 월 2원이다. 소프트웨어는 Apache 2.0이라 라이선스비가 없고 업로드와 같은 리전 복원 전송은 공식 가격표상 과금 대상이 아니다.

기존 노드의 메모리 여유를 실제로 재보고 부족하면 그때 전용 t3.small에 20GiB gp3를 붙인다. 그 경우에도 월 $20.80이며 기존 4대 견적을 더해 약 167,500원으로 예산 안에 남는다. 공인 IPv4를 붙이지 않는 설계를 쓰려면 Docker 이미지를 받을 경로를 먼저 정한다. 정하지 못하면 $24.45를 예산에 넣는다.

보존 14일을 유지하는 동안에는 저장 계층을 내리지 않는다. 최소 보존 기간과 조회 요금 때문에 오히려 1.8배에서 3.9배 비싸진다. 계층 전환은 보존을 30일 이상으로 늘리거나 장기 보관본을 따로 둘 때만 검토한다. Cloudflare R2도 이번 구성에서는 권하지 않는다. 원본이 AWS 안에 있어 업로드가 인터넷 송신으로 과금되고, 일 3.46GB를 넘으면 S3가 더 싸다.

대안은 비용 근거로 물리친다. 상용 SaaS는 가장 싼 요금제가 예산의 16.5퍼센트를 가져가고 S3 요금은 따로 낸다. RDS는 같은 이중화를 맞추면 월 6만 원 이상을 더 내면서 Linux 운영 범위를 줄인다. AWS Backup은 저장 단가가 두 배이고 복원 검증에 건당 $1.65가 붙어 매일 검증하면 월 $50.38이 된다. 전용 노드를 세운 Databasus가 $21.15로 그보다 싸다는 점이 이번 비교의 핵심이다. 복원 검증을 매일 돌리면서도 더 싼 구성이라는 사실이 비용 문제도 말 안 나오게 하겠다는 답변의 가장 강한 근거다.

발표에서는 금액을 단정하기 전에 세 가지를 먼저 측정해야 한다고 밝힌다. 현재 DB 크기와 하루 증가량, Databasus가 실제로 만드는 백업 파일 크기, PITR을 켰을 때의 하루 WAL 용량이다. 이 문서는 전부 실행 전 설계이며 공식 가격표에서 확인한 단가와 산식만 근거로 제시한다.
