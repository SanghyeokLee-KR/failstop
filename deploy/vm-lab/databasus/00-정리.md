# 산출물 정리와 남은 결정

Databasus 도입 산출물 일곱 종을 만들면서 작성자들이 서로 다르게 판단한 곳이 있었다. 여기서 정리한다.

2026-09-22에 로컬 VM 실습망에서 도입 절차의 앞 구간을 실제로 실행했다. 도구 설치와 기동, 화면 노출 제한, 방화벽, 읽기 전용 DB 계정, 접속 제어, 외부 보관소 접속까지가 실행된 구간이고 증거는 `캡처/예행-2026-09-22/`에 있다. 첫 백업, 외부 보관, 복원 검증은 아직 하지 않았고 학교 AWS에는 아무것도 설치하지 않았다. 남은 순서는 `08-이어서할일.md`에 있다.

그러므로 이 폴더의 문서를 읽을 때는 실행한 구간과 설계로 남은 구간을 구분한다. 실행 결과는 `05-보고서.md` 7장과 예행 폴더의 README 에 모았다.

## 정리한 것

**중복 ADR을 없앴다.** `0034-databasus-offsite-scheduled-backup.md`와 `04-ADR초안.md`가 같은 제목으로 둘 다 있었다. 내용이 더 갖춰진 `04-ADR초안.md`를 정본으로 두고 다른 하나를 지웠다. 저장소에 넣을 때는 ADR 폴더에 `0034-databasus-offsite-scheduled-backup.md` 라는 이름으로 둔다. 아직 넣지 않았으므로 그 경로를 있는 문서처럼 인용하지 않는다.

**복원 검증 에이전트의 실행 위치.** `01-도구조사.md`는 Databasus 서버에서 검증 에이전트를 실행할 수 없다고 적었으나 `02-배치설계.md`가 공식 문서에서 그 근거를 찾지 못했다. 같은 호스트를 기본으로 두고 실제 설치 때 확인한다. 확인 전에는 어느 쪽도 사실로 적지 않는다.

## 아직 정하지 못한 것: 학교 AWS의 배치

`04-ADR초안.md`는 학교 환경 1순위를 기존 `bot-1`로 적었고 `02-배치설계.md`는 `bot-1`을 기각하고 다섯 번째 노드 `ops-1` 신설을 권한다. 판단이 갈리는 이유는 이렇다.

`bot-1`에 두면 추가 비용이 없다. DB Primary의 5432 인증이 이미 봇의 사설 주소 하나로 열려 있어 새 네트워크 경로도 필요 없다. 그러나 그 노드는 이미 시장 봇과 Prometheus와 Grafana와 Alertmanager와 AI 보고를 겸하고 있다. 로드맵에 기록된 봇과 Grafana 동시 운영 표본에서 가용 메모리가 약 600MiB였다. 여기에 Databasus 본체와 자체 메타데이터용 PostgreSQL, 그리고 복원 검증이 띄우는 임시 DB 컨테이너까지 올리면 메모리가 모자랄 가능성이 크다. 사용자는 이미 "메모리가 부족하면 봇과 관측을 분리하라"고 지시한 적이 있다.

`ops-1`을 새로 만들면 역할이 분리되고 백업 관리자가 DB 호스트 밖에 선다. 대신 월 약 $24가 늘어 학교 합계가 약 $102에서 약 $126이 된다.

**권하는 것은 이렇다.** 지금은 로컬 VM의 `OPS01`에만 올린다. 메모리를 4GB에서 6GB로 올리면 되고 돈이 들지 않는다. 발표에서 보여 줄 화면과 숙제로 낼 증거는 여기서 만든다. 학교 AWS 적용은 보류하고, 대신 `03-비용비교.md`의 산식을 근거로 "고객사 규모에서 얼마가 드는지"를 설명한다. 인프라 담당자가 내놓을 답은 도구를 어디에나 깔았다는 사실이 아니라 어디에 왜 두는지와 그 비용이다.

학교 AWS에도 올리기로 정하면 `ops-1` 신설을 따른다. `bot-1` 집중은 메모리 여유를 실측한 뒤에만 판단한다.

## 발표에서 조심할 것

`06-발표구성.md`가 잘 짚었다. 비용이 싸다는 말만 하면 "그럼 장애 났을 때 누가 책임지느냐"는 반문이 들어온다. 관리형이 대신해 주던 운영 부담을 우리가 진다는 것을 같은 문단에서 말해야 답변이 끝난다.

벤더 자체 주장 수치(Docker 내려받기 횟수, GitHub 별 개수)는 넣지 않는다. 넣으려면 벤더 주장이라는 각주를 붙인다.
