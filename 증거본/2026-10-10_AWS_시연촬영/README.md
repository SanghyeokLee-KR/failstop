`deploy/reporting/reporter.py`를 고쳤다. AI 분석이 카드 형식에 맞지 않으면 분석만 빼고 수집한 사실로 카드를 만들어 보내고, 생성 오류는 두 번 더 다시 만든 뒤 dead로 둔다. 오류 기록에는 예외 종류만 남긴다(`report_generation_failed_<종류>`). 보고 서비스 시험 167개 통과. 서버 파일은 저장소 HEAD와 해시가 같은 것을 확인한 뒤 바꿨고, 원본은 `/opt/failstop/deploy/reporting/reporter.py.bak-20261010`이다. 배포 해시 `09d86d4a…`.

## 확인하지 못한 것과 한계

- 이번 시험에서 확정된 주문의 유실 여부는 대조하지 않았다. 영상 자막에 '유실 0건'을 쓰지 않는다.
- 주 DB 강제 종료부터 승격까지의 정확한 초는 Patroni 로그로 따로 재지 않았다. 서비스 흐름 화면의 변화 시각만 있다.
- 계획된 전환(`patronictl switchover`)은 REST API 인증이 필요해 401로 거절됐고 인증 정보는 다루지 않았다. 그래서 2차 시험은 그때의 주 DB(db-2)를 껐다.
- AI 상담 답은 이미 재개된 거래를 '중단된 상태'라고 했고(해제 전 사건 기록을 읽음), 예전 날짜의 증설도 섞였으며 중간에 잘렸다.
- 관리 콘솔 세션은 발급 뒤 30분으로 고정이라 촬영 중 두 번 다시 받았다.
- 04:42에도 사건 보고 4건이 만들어져 전송됐다. 어떤 경보에서 나왔는지는 확인하지 않았다.
- 06:12에 주 DB를 db-1로 되돌렸다. `patronictl switchover`는 REST 인증이 필요해 쓰지 않고, 주 DB였던 db-2의 Patroni를 정상 종료해 동기 예비 db-1을 승격시켰다. 그래서 db-2가 다시 붙을 때까지 십수 초 쓰기가 보류됐다. 이 구간의 정확한 초는 재지 않았다.
