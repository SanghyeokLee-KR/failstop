# 세 종목 시장 봇·용량 보호·관제 접속

학교 AWS의 bot-1에서 2026년 9월 20일 한국 시간으로 실행했다. 터미널의 UTC 시각은 전날 15시부터다. 명령 원문은 [Linux 실행 기록](Linux_명령실행.log)에 있으며 같은 번호의 PNG와 TXT가 실제 화면과 접근성 출력이다. 비밀 파일 원문은 조회하지 않았다. 브라우저 터미널은 종료 코드를 별도 수집하지 않으므로 명령 뒤에 종료 코드 출력문을 붙이지 않았다.

| 번호 | 확인한 내용 |
| --- | --- |
| 001~002 | 확대 전 메모리·수집 상태와 네 서버의 용량 표본 |
| 003~004 | BTC·ETH·XRP 설정, 자동 시작·제한된 오류 재시작, 플릿 기동과 메모리 |
| 005 | 세 마켓 체결, 원장 합계와 잔액 검사, 비동기 복제 표본 |
| 006~007 | ETH·XRP 실제 거래 페이지의 호가·체결·1분 차트 |
| 008 | 용량 보호 타이머 정상 종료, 현재 판정과 시간별 CSV |
| 009~011 | Grafana 외부 접속 준비를 위한 기존 설정·메모리·SG 조회 |
| 012~020 | EC2 Role의 SG 변경 거부, 학교 사용자 콘솔의 제한 규칙 적용, Grafana HTTPS 및 사용자 로그인 |
| 021~026 | 암호화된 내부 인증서 전달, 앱 SG 전용 8443, 운영자 조회·봇 제어 역할 등록 |
| 027~032 | 로그인 웹 업로드, 봇 관리 API 기동, 사용자 직접 비밀번호 설정, Nginx 적용과 비인증 검사 |
| 033~036 | 사용자 로그인, 실제 15대 플릿 조회·대수 적용, DB 감사의 fleet_present=true |
| 037~039 | 봇·Grafana 동시 운영 메모리·용량 보호, 1 OPS 단위 웹 보완본 업로드·해시·접근 검사 |
| 040~042 | 최종 로그인·슬라이더 범위 확인, 실제 속도 3→2→3 OPS 제어·복귀 |

세 마켓의 합계 목표는 주문·취소 3 OPS다. 실제 속도는 무작위 대기와 토큰 버킷에 따라 달라진다. 00:14:56 KST의 체결 수는 BTC 342건·ETH 7건·XRP 4건이고 원장 검사 불일치는 0건이었다. 이 짧은 표본은 하루 데이터 증가량이나 한 달 운영 가능성의 증거가 아니다.

용량 보호의 정상 실행만 AWS에서 확인했다. 임계 용량·inode 부족과 수집 오류에 대한 판정 테스트는 로컬 Python으로 4개를 실행해 통과했으며 실제 화면 캡처를 대신하는 증거로 취급하지 않는다. AWS 디스크를 채우는 실험은 하지 않았다.

비밀번호 등록과 웹 로그인 입력은 사용자가 직접 수행했다. 입력 구간은 파일로 캡처하지 않았고 생성 완료·로그인 이후 화면만 증거에 남겼다. 서버 인증서·키와 세션 토큰의 원문은 출력하지 않았다. 웹의 442개 테스트와 빌드·토큰 검사는 로컬 실행이며 AWS 화면 검사와 구분한다.

화면은 허용된 브라우저 도구로 실제 AWS 페이지와 로그인 후 봇 화면을 확인했다. 별도 Playwright 프로세스를 실행하는 `npm run check:browser` 전체 검사는 실행하지 않았다. 로컬 검사 출력은 `tmp/admin-final-tests.log`·`tmp/admin-final-build.log`에 있으며 화면 캡처 결과와 구분한다.
