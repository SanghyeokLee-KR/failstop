# 학교 AWS 백업·복구·운영 보고 검증

2026-09-20 KST에 학교 계정의 기존 앱·DB 두 대·봇 관측 노드를 대상으로 실행했다. 화면 속 Linux 시간은 UTC다. 로컬 Docker 결과와 구분한다. 최신 운영 상태와 다음 작업은 [로드맵](../../docs/ROADMAP.md), 재현 순서와 주의점은 [AWS 작업 안내](../../docs/reports/AWS_작업.md)를 따른다.

운영 데이터는 유지했다. 같은 스냅샷으로 pg_dump한 백업을 TCP 접속 없는 별도 시험 클러스터에 복원했고 네 테이블 건수 일치·정합성 필수 항목 실패 0건을 확인했다. 백업은 전환 전 Primary 서버의 로컬 디스크에 남아 있다. 서버 외부 보관·예약 백업 성공을 뜻하지 않는다.

Teams 카드·PDF·HTML 연결은 사용자가 열람을 확인했다. 실제 Standby 정지, 앱 정지, 별도 128MiB 시험 파일시스템의 공간 부족을 감지하고 발생·해제 보고의 전송 상태를 확인했다. 보고서는 운영 수치와 확인하지 못한 항목을 구분한다. 원본 로그·거래 데이터·비밀 값을 AI나 Teams로 보내지 않는다.

DB 전환은 옛 Primary 중지·mask와 앱에서 접속 거부를 확인한 뒤 진행했다. 현재 Primary는 AZ-c 172.31.33.195, Standby는 AZ-a 172.31.1.229다. 전환 전후 명령 17,610·이벤트 28,851·체결 9,337·원장 94,918건이 일치했고 새 Primary에서 체결 증가와 정합성 필수 항목 실패 0건을 확인했다. 기존 PGDATA를 보존하고 베이스백업 검증 뒤 재편입해 streaming과 WAL 위치 일치를 확인했다. 격리부터 거래 증가 확인까지 2분 52초이며 수동 명령·관측 간격이 포함된다. 계획된 쓰기 중단 시험이므로 비동기 복제의 무손실 보장은 아니다.

관측 역할 변경 뒤 과거 시계열이 남아 용량 보호기가 봇을 멈추는 현상도 확인했다. 90초 이내 표본만 선택하도록 보완했고 누락·중복·용량 부족 차단 조건은 유지했다. 첫 보완 쿼리는 HTTP 422로 실패해 다시 수정했다. 네 호스트의 정상 용량과 실패 누적 0을 확인한 뒤 봇을 수동 재개했다. 이 중단은 앞의 DB 전환 관측 시간에 포함되지 않는다.

## 파일 읽는 순서

PNG는 실제 브라우저 화면이고 같은 이름의 TXT는 접근성 원문이다. [명령 기록](Linux_명령실행.log)은 실행 명령과 증거 이름을 연결한다. 긴 설정 파일은 base64 전송 명령으로 남아 있으며 사람이 읽을 원본은 deploy/linux에 있다. 비밀 값은 캡처하지 않았다. 일부 중간 진단·수정 시도는 개별 화면 저장이 빠졌으며, 아래 캡처를 그 누락 구간의 증거로 재구성하지 않는다. 후속 확인 화면과 AWS 작업 문서에 실제 실패 원인·보완 결과를 남겼다.
