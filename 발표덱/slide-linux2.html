관제 화면이 멈춘 원인을 좁혀 가며 해결

학교 AWS, 관제 서버

시연에서 본 것과 같은 Grafana 화면이 학교 AWS 관제 서버에서 멈췄던 일, 기록으로 좁혀 감

Grafana 멈춤 진단 원본 캡처증거본 2026-09-19_학교AWS 325·334·343, 계정 ID·공인 주소가 있는 머리와 바닥, 사용자 이름이 든 로그 줄은 잘라 냄
  1. 1
    증상 관제 화면이 느려지다 응답 없음
    curl: (28) Operation timed out after 3002 milliseconds
  2. 2
    판단 정정 원격 접속 문제가 아니라 메모리 한도에 걸린 강제 종료
    처음엔 접속 경로(SSM)를 의심 → 서버 안에서도 시간 초과 → 서비스 기록의 원인:
    grafana-server.service: Failed with result 'oom-kill'
  3. 3
    1차 수정 → 재발 메모리 한도를 512/640MiB로 조정, 잠시 정상 뒤 다시 멈춤
    조이는 선에 걸린 횟수 13,898번, 메모리를 기다리며 멈춘 시간 91%
  4. 4
    2차 수정 조이기 전에 Grafana가 스스로 메모리를 비우게(목표 512MiB)
    쓰는 메모리(약 615MiB)가 조이는 선(512MiB)보다 커서 계속 조여짐
    → 선을 768MiB(조이기)·896MiB(강제 종료)로 올림
  5. 5
    확인 화면을 바꿔 가며 10초마다 6번: 모두 정상
    Grafana HTTP 200 NRestarts=0 oom_kill 0메모리 약 490MiB, 짧은 확인
같은 방식으로 찾아 고친 것

원인Java는 종료 신호를 받으면 코드 143으로 끝남

수정SuccessExitStatus=143 앱·봇에 적용

지킨 것메모리 부족 같은 다른 오류는 그대로 실패

옛 주 DB를 예비로 다시 붙이다 막힘

수정postgres만 읽는 0600 비밀번호 파일, 슬롯 지정 삭제

확인복제(streaming) 다시 연결
