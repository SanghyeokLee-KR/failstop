리눅스 Linux

직접 무엇을 해 봤나요?
학교 EC2에서 계정 · 서비스 · 로그 · 네트워크 · 디스크 다섯 분야를 상황을 만들어 확인했습니다. VM 6대는 Rocky Linux를 kickstart로 설치했습니다.
디스크가 고장 나면요?
RAID1이라 남은 디스크로 DB가 계속 씁니다. 새 디스크를 넣어 다시 맞추면(mdadm) 경보가 풀립니다.
용량이 차면요?
85%를 넘으면 RAID1 묶음을 붙이고 lvextend -r로 마운트한 채 늘립니다.

사례 Grafana가 메모리 한도로 죽음 → cgroup으로 실사용 약 615MiB 확인 → 한도 768/896MiB로.

네트워크 Network

망은 어떻게 나눴나요?
역할마다 VLAN(DMZ · 관리 · 거래 · 조회 · DB · 백업 · AI)을 나누고 ACL로 필요한 통신만 엽니다. 예: 거래 서버 → 주 DB는 5432만, SSH는 점프 서버를 거쳐야만.
실제 장비로 했나요?
구성도와 ACL은 Packet Tracer로 설계하고 ping으로 확인했습니다(8080 · 5432는 ACL 설정으로). 실제 차단은 VM의 pfSense · nftables와 AWS 보안 그룹에서 했습니다.
서버 방화벽은 어떻게 관리하나요?
nftables 6대를 원본 하나로 점검 → 계획 → 적용하고 어긋나면 되돌립니다. 적용 뒤 확인이 실패하면 VM이 90초 뒤 스스로 되돌립니다.

덧붙임 선 이중화(bonding)는 VirtualBox라 active-backup. 개인 AWS와 온프레미스 AI 서버는 WireGuard로 잇습니다.

서버 인프라 Infrastructure

어떤 순서로 구축했나요?
Docker로 검증 → VM 6대로 역할 분리 → 학교 EC2에서 Linux 운영 → 개인 AWS에 다시 배포(CloudFront → ALB → 앱 2대 · DB 2대 · 봇 · 관측).
DB가 멈추면요?
Patroni 엄격 동기로 자동 승격. 개인 AWS 전원 차단 시험(2026-10-10)에서 승격 23.0초, 주문 재개 70.1초(시험 도구가 옛 주 DB 를 28초에 켰을 때), 차단 4~64초 전 커밋 주문 196건 유실 0건, 차단 0.3초 전 마지막 주문도 새 주 DB 에 있음.
요청이 몰리면요? AI는요?
CPU 60%를 넘으면 AI가 app-3 켜기를 제안하고 운영자가 승인하면 붙습니다(CPU 65~71% → 52~59%). 평가 111번 중 잘못 실행 0번.

사례 10/7 백업 타이머가 켜지지 않아 하루 빠진 걸 경보로 찾아 고쳤습니다(매일 03:40, 검증 뒤 S3).

pfSense CE 투명 방화벽

왜 투명(브리지) 방식인가요?
서버 6대의 주소 · 경로 · DNS를 한 줄도 안 바꾸고 라우터와 서버 사이에 끼울 수 있어서입니다. 경계형(NAT)일 때는 6대 설정을 모두 바꿔야 했습니다.
HTTPS는 어떻게 검사하나요?
HAProxy가 웹 서버 인증서로 TLS를 풀어 검사한 뒤 다시 암호화합니다. SQL 주입 · 경로 탐색 403, TRACE 405.
방화벽이 죽으면요?
한 대라 단일 장애 지점입니다. 재부팅 때 약 82초 끊겼습니다. 운영이면 두 대 구성이나 작업 시간 공지입니다.

한계 Suricata는 경보(탐지)만. 차단 모드와 오탐 조정은 안 했습니다.

Databasus DB 백업

복원해 봤나요?
복원 검증 에이전트로 임시 DB에 되살려 표 109개가 원본과 같은 것을 확인했습니다(표 개수와 주요 표 행 수).
최대 얼마나 잃을 수 있나요?
하루 한 번 논리 백업이라 최대 하루치입니다. 시점 복구(PITR)는 켜지 않았고, 줄이려면 WAL 아카이브를 더합니다.
백업은 어디에, 왜 Databasus?
암호화해 DB 서버 밖(SFTP 전용 계정)에 7일. 오픈소스이고 웹 화면에서 예약 · 보관 · 복원 검증이 돼 작은 현장에서 다루기 쉽습니다.

한계 백업 대상이 DB01 주소로 고정이라 전환 뒤엔 바꿔야 합니다. 고친다면 HAProxy 쓰기 포트를 대상으로.

Kopia OS 백업

서버를 빼앗기면 백업도 지워지지 않나요?
DB01 계정은 저장소에 쓰기만 됩니다. 실습망에서 DB01 root로 삭제 · 보존 줄이기 · 정비 3가지를 시도해 모두 거부됐습니다.
OS를 통째로 잃으면요?
디스크 2개를 지우고 재설치(483초), 패키지 목록 · /etc · DB 데이터 복원(167초). 지운 때부터 15분 22초, 기준값 6가지 일치.
Databasus와 왜 따로 두나요?
Databasus는 DB 데이터만, Kopia는 설정 · 서비스 유닛까지 받아 새로 깐 OS를 그대로 되살립니다.

한계 랜섬웨어는 가정. 백업 중 DB 약 16초 정지, 저장소는 OPS01 한 곳뿐입니다.

공통자주 나올 질문
실제 운영과 다른 점은?
VM 실습망은 PC 한 대 위의 가상망이라 절차 훈련입니다. 학교 · 개인 AWS는 실제 클라우드이고, 거래는 실제 돈이 없는 모의 거래입니다.
다시 한다면 무엇을 더하나요?
방화벽 두 대 구성, Suricata 차단 모드와 오탐 조정, 시점 복구(PITR), 복원 시험 정기 자동화입니다.
비용은 어떻게 관리했나요?
월 40만 원 예산 기준으로 설계했습니다. 조회 서버는 평소 0대로 두고 몰릴 때만 켜서 돈이 드는 시간을 줄였습니다.
