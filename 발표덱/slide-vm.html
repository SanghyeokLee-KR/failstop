서버 주소는 그대로, 층마다 거르는 투명 방화벽

VM 실습망

VM 여섯 대를 구역으로 나누며, NAT 경계형 대신 선 사이에 끼우는 브리지로 L2부터 L7까지 거르기

변경처음 방식에서는 여섯 대 모두 경로·DNS·시간을 바꿈
그대로주소·경로·DNS는 그대로, 네 구역 모두 192.168.10.0/24
3nft같은 구역 안은 서버마다 nftables가 한 번 더 거름
무엇을 바꿨나
처음 방식: 경계형(NAT)

운영 중인 고객 서버 앞에 NAT 라우터를 유일한 길로 두자, 서버 여섯 대의 경로·DNS·시간까지 바꿔야 했음

현업 조언 반영: 투명형(브리지)

라우터와 서버 사이 선에 끼워, 서버의 주소·경로·DNS는 한 줄도 바꾸지 않음. 경로 추적에도 보이지 않음

층마다 거른 결과
L2모르는 장비 차단, MAC 고정라우터 쪽으로 샌 프레임 3 → 0
L3·L4구역 사이 필요한 포트만웹 → 앱 8080 허용, 웹 → DB 차단
L7입구에서 TLS 풀어 검사, HAProxy정상 요청 200, SQL 주입 403
IDS통과한 공격도 탐지, Suricata웹 → 앱 구간에서 탐지해 관제로 경보

거르는 곳은 세 겹

1기존 라우터, 작업 PC 쪽과 밖으로 나가는 길

2투명 방화벽, 구역 경계에서 L2~L7

3서버마다 nftables, 같은 구역 안

한계방화벽이 한 대라 재부팅 약 82초 동안 웹 접속과 앱 → DB가 끊김, 이중화와 차단 모드(IPS)는 다음 과제
