## 축과 관찰

[EP1-20260925-073828.verdict.json](EP1-20260925-073828.verdict.json)은 이 회차 뒤 고친 판정 도구로 같은 원시 파일을 다시 계산한 것이다.

- PASS: 승격 시간, 승격 뒤 조회 복구, 재개 지연, 체결 재개 지연, 앱 epoch 정확히 +1(api-1 → api-2), 승격한 리더의 승격 뒤 30초 안 fencing 거부 0·강등 0, 획득 사후 확인 실패 0, 중단 동안 상태 API 가 참, 옛 Primary 가 pg_rewind 로 재합류한 뒤 두 노드의 주요 표 건수·합 같음(E-P6a 기록), 사후 권위 run 위반 0, C16 0, 구 epoch 쓰기 증분 0, 주문 500 0, DB 수준 ACK 유실 0(acked 23,853, 주입 전 30초 5,396, 재개 뒤 30초 5,387).
- 판정 불가: 승격 뒤 멤버 사본 없이 확인된 쓰기(`confirmed_writes_before_member`). 이 회차의 기록기에는 복제 표본이 없었다.
- 설계 문구대로 센 'T_promote~T_sync 사이 확인된 쓰기'는 692 건이었다. 모두 옛 노드를 되살린 뒤(T_back + 3.3초부터) 끝났다. 네 스레드가 660.8초에 보내 커밋을 기다리던 시도가 678.9초에 한꺼번에 확인됐다. 새 Primary 는 동기 대상이 `'*'` 라 되감기를 마친 옛 노드(멤버)가 붙는 순간 커밋을 확인했고, /cluster 가 그 노드를 sync_standby 로 적은 것은 682.8초였다. 그래서 이 수는 멤버 사본이 있는 정상 확인을 센다. 판정 도구는 이 축의 끝을 /cluster 가 아니라 새 Primary 의 `pg_stat_replication` 에서 멤버 walsender 가 붙은 시각(`backend_start`)으로 바꾸었고, 기록기에 0.5초 간격 복제 표본을 더했다. 설계 8-1 (7) 문구를 바꿀지는 문서 단계에서 정한다.
- acked 가 아닌 시도 32 건: 소켓 제한 28(옛 노드가 없는 10분 동안 커밋 대기 90초를 넘긴 시도, 그 가운데 28 건이 나중에 표에 나타났다), 연결 끊김 4(강제 종료 순간).

DB 가 없는 동안의 거절이고 원인(수용 제한인지 계정 한도인지)은 이 표본으로 가르지 않았다.
