# ADR 0022 6단계 대역 모드 장애 주행 E2·E4·E5·E6·E7 (2026-09-14)

## 결론

- 다섯 실험 모두 실험 판정 PASS, 분리 판정 PASS 다. 이미지는 6단계 `exchange-chaos-app:adr0022-stage6-0cb57a3`(`0cb57a3`)이고 절차는 `harness/scripts/adr0022-stage5-chaos.ps1 -LatchBeforeTraffic` 이다. 실험마다 스택을 `down -v` 뒤 새로 띄우고 실험 스크립트 직전에 래치를 걸었다. 분리 판정 규약은 `docs/reference/contracts/하네스_검증설계.md` §2-4 끝의 대역 모드 장애 주행 분리 판정이다.
- 다섯 모두 래치 행이 있고 대역 행이 0 보다 크며, 하네스 C28 과 사후 권위 run C28 이 0 이다.
- RTO 는 4.360~10.450초로 목표 30초 안이다. 사후 창 C22 시간 축 팔과 마켓 안 팔은 모두 0 이고 마켓 안 `created_at` 역행도 0 이다. 연결 고갈은 없었다.
- 5단계에서 빠졌던 E5·E7 주입 사건이 이번에는 도커 사건 기록에 있다. 사건 수집을 실험 스크립트보다 먼저 시작했다.
- 판정과 따로 적는다. E7 의 `rpo_records` 가 1 이다. 원인은 아래 절이다.
- 실험별 판정 파일은 `harness/evidence/chaos-runs/` 의 `E2-20260914-171715.json`, `E4-20260914-171934.json`, `E5-20260914-172120.json`, `E6-20260914-172402.json`, `E7-20260914-172612.json` 이다. `code.commit` 은 E2 가 `0cb57a3`, E4~E7 이 `bd6e365` 이고 두 커밋 사이 변경은 문서뿐이다. `code.uncommittedPaths` 는 모두 0 이다.

## E7 rpo_records 1 의 원인

E7 은 `rpo_records` 를 사후 권위 run 의 C05 + C06 + C13A 합으로 센다(`harness/scripts/e7-gray-pause.ps1`:133-134). 17:27:42.338 사후 run 의 C13A 1 은 저널에는 있으나 아직 `orders` 에 물질화되지 않은 주문 생성 명령 하나다. 그 뒤 채집한 하네스 SQL(`E7/invariants_psql.txt`, `commands.log` 기준 실험 종료 17:27:43 와 다음 단계 17:27:47 사이)은 C13a 를 포함한 모든 검사가 0행이고, 같은 사후 run 의 C05, C06 은 0 이다. C13A 는 저널에 이미 있는 명령을 세므로 정의상 ACK 뒤 저널 유실이 아니다. 5단계 E5 의 `rpo_records` 1 과 같은 드레인 없는 합산이고, 이 측정 설계 결함의 수정은 후속이다. 같은 실험의 사전 권위 run(17:26:53.687)도 C13A 1 이었다.

## 사전 권위 run

사전 권위 run 은 E2·E4 가 PASS, E5·E6·E7 이 FAIL 이다(각 실험 `console.log`). 5단계 회차(`harness/evidence/adr0022-stage5-20260914/`)는 다섯 모두 사전 FAIL 이었다. 두 회차 모두 실험 판정은 PASS 다.

## 한계

- 로컬 카오스 스택에서 실험마다 한 번이다. 클라우드 스택은 NOT RUN 이다.
- 래치는 폐기용 도커 DB 에서만 걸었다. 래치 전 레거시 행이 12~13행뿐이라 긴 레거시 구간 뒤의 커트오버는 재지 않았다.
- E2 는 Toxiproxy 프록시 계층, E5 는 도커 네트워크 분리, E7 은 도커 pause 다. 커널 계층 주입(E10 tc netem)이 아니다.
- 5단계와 RTO 를 나란히 놓지 않는다. 실험마다 한 번이라 차이를 대역 채번 효과로 읽지 않는다.
