## E5·E7 주입 사건이 도커 기록에 없는 이유

도커 사건 수집이 주입보다 늦게 시작했다. E5 는 수집 첫 사건이 14:53:57 인데 주입은 약 14:53:28 이다(첫 체결 재개 시각에서 RTO 를 뺀 추정). E7 은 수집 첫 사건 14:58:20 이 주입 추정 시각과 같은 초라 pause 사건을 놓쳤다. 주행 뒤 `docker events --since` 로 다시 물었으나 도커 데몬 사건 버퍼에 이미 남아 있지 않았다.

주입은 다음으로 확인한다. 콘솔에 주입 단계가 실행됐고, 복귀 명령이 사건을 남겼다(E5 network connect 14:54:27, E7 unpause 14:59:05). 이미 연결된 컨테이너의 connect 와 실행 중인 컨테이너의 unpause 는 실패하고 사건을 남기지 않으며, 두 실험 모두 종료 훅의 두 번째 호출이 실제로 종료코드 1 을 냈다. 리스 보유자도 바뀌고 epoch 가 1 에서 2 로 올랐다. 수집 시작을 주입 전으로 옮기는 수정은 후속이다.

## E5 rpo_records 1 의 원인

E5 는 `rpo_records` 를 사후 권위 run 의 C05 + C06 + C13A 합으로 센다(`harness/scripts/e5-net-partition.ps1`). 이 스크립트는 사후 run 전에 봇을 멈추거나 드레인 0 을 기다리지 않는다. 14:54:39.6 사후 run 의 C13A 1 은 저널에는 있으나 아직 `orders` 에 물질화되지 않은 주문 생성 명령 하나다. 1.4초 뒤(14:54:41) 채집한 하네스 SQL(`E5/invariants_psql.txt`)의 C13a 는 0행이고, 같은 사후 run 의 C16(ACK 원장이 저널에 있음), C05, C06 은 0 이다. 곧 ACK 된 기록의 유실이 아니라 물질화를 기다리던 명령이다. E5 판정 식은 C13A 를 비동기 물질화 창 때문에 게이팅에서 면제하지만(`harness/scripts/lib.ps1` 면제 목록) rpo 합에는 드레인 없이 넣는다. 이 측정 설계 결함의 수정은 후속이다. 2026-09-13 E5 두 회차의 `rpo_records` 는 0 이었다.
