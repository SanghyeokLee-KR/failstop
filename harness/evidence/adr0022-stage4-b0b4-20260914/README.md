# ADR 0022 4단계 판정 주행 B0·B4 (2026-09-14)

## 결론

- **판정은 명제 성립이다.** 접수 비 B4/B0 가 1.354 로 T1 1.15 를 넘지만 상한 A 1.531 이하이고, 카운터 행 대기 표본이 10회 중 7회에서 0 보다 컸다(합 25, 최대 5). 판정 규약은 `docs/contracts/하네스_검증설계.md` §2-4 끝의 ADR 0022 4단계 B0·B4 판정 규약이다.
- 양성 축을 모두 채웠다. B0 접수 락 보유 점유 0.967, B4 마켓별 보유 점유 합 4.446, B4 표본 채집 성공 10회(15초 간격), 두 칸 모두 분류기 양성 대조 PASS, 12마켓 각 접수 0 초과, `k6_rc` 0, fsync 키 존재, append 풀 대기 0 이다.
- 연결 고갈은 없었다. 최대 연결은 B0 65, B4 56 이고 한도는 197(`max_connections` 200, 예약 3)이다.

## 절차 종료코드 1 의 원인

판정기는 종료코드 0(명제 성립)을 냈다(`commands.log` 의 judge rc=0, `judge.log`). 그 뒤 절차 스크립트가 `verdict.json` 을 다시 읽다가 B0 의 태그 없는 계열 키(빈 문자열)를 PowerShell `ConvertFrom-Json` 이 받지 못해 예외로 끝났다. 커밋 `9b1a2cd` 가 `-AsHashtable` 로 고쳤고, 고친 식으로 이 폴더의 `verdict.json` 을 읽어 '명제 성립' 과 일치함을 확인했다. 측정값과 판정은 이 예외 전에 저장됐다.

## 한계

- 로컬 카오스 스택 한 번이다. 클라우드 스택은 NOT RUN 이다.
- 이날 fsync 건당이 3.2ms 대로 2026-09-13(0.46ms 대)보다 느렸다. 절대값은 날짜를 넘어 비교하지 않는다. 같은 날 B0·B4 비만 판정에 쓴다.
- 요청 600/s 에 대한 제시 부하(접수와 수용거절 합)는 B0 564/s, B4 551/s 다.
