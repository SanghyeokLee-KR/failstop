# 로드밸런서 유무와 설정이 조회 분산에 미치는 영향 (2026-09-05)

같은 부하를 세 경로로 넣어 노드 분담과 CPU를 갈랐다. 27회차가 분산형 로드밸런서 한 팔만
쟀으므로 직결 대조군과 카오스 스택 자체 LB를 더한다.

조건은 세 팔이 같다. 조회 200/s와 주문 2/s를 한 주행에 함께 넣고 2분, 봇 정지, 게이트 기본값
(ON), 카오스 스택 2노드. 부하기는 k6 `order_flow.js` smoke 프로파일이다.

## 결과

| 경로 | node1 | node2 | 분담 | api-1 CPU 최대 | api-2 CPU 최대 | pg CPU 최대 |
|---|---:|---:|---|---:|---:|---:|
| 직결(LB 없음) | 30,499 | 196 | 99.4 / 0.6 | 66.5% | 6.5% | 253.9% |
| 카오스 LB | 30,501 | 196 | 99.4 / 0.6 | 93.2% | 3.3% | 252.7% |
| 분산 LB | 18,866 | 11,831 | 61.5 / 38.5 | 48.9% | 66.8% | 189.9% |

세 팔 전부 k6 체크 30,300건 이상에 성공률 100%, 실패 0이다. 주행이 실제로 돌았고 판정 대상이
있었다.

## 조회는 갈리고 주문은 갈리지 않는다

분산 LB에서 node2 분담이 0.6%에서 38.5%로 오르고 CPU가 3.3%에서 66.8%로 뛴다. 두 번째 노드가
실제로 일을 나눠 가진다.

주문은 그렇지 않다. `POST /api/v1/orders` 누적을 노드별로 직접 조회하면 node2가 세 팔 통틀어
0건이다. `limit_except GET` 이 쓰기를 리더 단독으로 보낸 결과다.

38.5%가 절반이 아닌 이유가 여기서 나온다. 이 주행은 주문 접수가 약 4,800건이라 그만큼이 통째로
node1에 얹힌다. 조회만 세면 반반에 가깝다. 27회차가 52 대 48로 나온 것은 주문이 181건뿐이었기
때문이다.

## 카오스 스택의 LB는 분산하지 않는다

직결과 카오스 LB의 분담이 소수점까지 같다. 설정을 보면 이유가 있다.

```
upstream exchange_api {
    server chaos-api-1:8080 resolve max_fails=1 fail_timeout=2s;
    server chaos-api-2:8080 resolve backup max_fails=0;
}
```

`backup` 은 1차가 실패할 때만 트래픽을 받는다. 평시 분산이 구조적으로 0이다. 이 nginx는
페일오버 승계용이지 부하 분산용이 아니다.

`제출_20260901/기획안_원본.md` §6.4 조회 라우팅이 같은 내용을 이미 적었다. 이 회차가 그 서술을 실측으로
확인한다. 27회차가 분산을 볼 때 카오스 LB를 쓰지 않고 `lb_verify_nginx.conf` 를 따로 세운
이유도 이것이다.

곧 로드밸런서를 두었다는 사실만으로는 분산이 성립하지 않는다. 같은 nginx 한 대인데 `backup` 과
`least_conn` 이 분담을 0.6%와 38.5%로 가른다.

## 미확인

직결 66.5%와 카오스 LB 93.2%가 같은 분담인데 api-1 CPU가 다르다. 프록시 홉은 nginx의 일이지
api-1의 일이 아니므로 주행 간 변동으로 보이나, 팔마다 표본이 하나씩이라 확정하지 못했다.

## 재현

분산 LB는 `lb_dist_nginx.conf` 를 nginx 컨테이너에 마운트해 세웠다. 27회차 검증본
(`../gateoff-20260903-2vcpu/lb_verify_nginx.conf`)의 upstream 대상만 카오스 스택 컨테이너명으로
바꾼 것이다.

```
docker run -d --name lb-dist --network chaos-net -p 18888:80 \
  -v <이 디렉터리>/lb_dist_nginx.conf:/etc/nginx/nginx.conf:ro nginx:1.29
```

부하는 팔마다 `BASE_URL` 만 바꿔 넣는다. 직결 `http://chaos-api-1:8080`, 카오스 LB
`http://chaos-lb:8080`, 분산 LB `http://lb-dist:80`.
