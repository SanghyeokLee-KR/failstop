# 스테일 쓰기 판정 교정 후 E5·E7 재주행 (2026-09-12)

`lib.ps1` 의 스테일 쓰기 판정이 두 축에서 fail-open 이었다. 판정 경로를 바꿨으므로 33절에
따라 종전 PASS 를 최신 증거로 쓸 수 없다. 같은 날 둘을 다시 돌렸다.

교정 내용은 커밋 `15eb1c9` 와 ADR 0022 §6-5 해소 항에 있다. 요지는 둘이다. 명령 축 존재
검사가 `Invoke-Psql` 을 직접 써서 psql 무응답이 "축 없음" 으로 읽혔고, 이벤트 축이 V36 대역
파생 때문에 낮은 대역 마켓의 구 epoch 쓰기를 못 봤다. 위치 워터마크를 버리고 epoch 기준
증분으로 바꿨다.

산출물. `e5-run.log`, `e7-run.log`. 주행 표준출력 전문이다.

## 교정이 판정에 실제로 참여했다

두 회차 모두 `cmd_fencing_col=True` 다. 명령 축이 켜졌다. 종전에는 psql 이 한 번 흔들리면
이 값이 조용히 거짓이 되고 판정이 축 하나를 통째로 건너뛰었다.

두 회차 모두 기준선이 네 자리다. 새로 건 양성 증거 축을 통과했다. 기준선이 0 이면 술어가
틀렸거나 그 회차에 부하가 실리지 않은 것이고 주행을 세운다. 종전 위치 워터마크 방식에는
"판정 대상이 존재했는가" 를 묻는 단계가 없었다.

## E7 의 C13A 2건

게이팅 면제 대상이라 verdict 는 PASS 다. 면제 근거는 `lib.ps1:627-629` 에 있다. C13A 는 저널
append 와 정산 커밋 사이의 비동기 물질화 창이라 큐 드레인을 전제하고, 실측으로 400 ops 에서
10~11건이 뜨며 드레인하면 0 이다. pause 해제 시점의 in-flight 2건이다.

`rpo_records=2` 가 같은 값이다. C13A 행 수를 그대로 적재한다.

**이 회차를 RPO 0 의 증거로 쓰지 않는다.** 정본 PASS 식은 `CRITICAL 전량 0행 ∧ rpo_records=0`
이고(CICD §6 R7, 검증설계 §5-3) 이 회차는 그 식을 만족하지 않는다. E7 스크립트의 자체 게이트는
스테일 쓰기, epoch, holder 교체, 무결성, RTO 다섯이고 RPO 는 그 안에 없다. 두 기준이 다르다.

## E5 의 DB 레코드가 없다

`harness.failover_runs` 에 E7 한 행만 있다. 실험 사이에 `down -v` 로 볼륨을 파기했기 때문이다.
파기가 필요한 이유는 종신 강등이 프로세스 내 플래그이고 서버에 자기 종료 경로가 없어서,
한 번 태운 노드가 컨테이너를 다시 세우기 전까지 승격 후보로 돌아오지 않기 때문이다. 생략하면
다음 실험이 승격 후보 0 으로 확정 FAIL 한다.

그래서 E5 의 증거는 이 디렉터리의 주행 로그뿐이다. ROADMAP 이 적은 구조적 문제가 이 회차에서
다시 나타났다. verdict 를 저장소 경로로 떨어뜨리는 배선은 여전히 M4 잔여 범위다.

## 이 회차가 증명하지 않는 것

**판정기가 진짜 위반을 잡는다는 것은 아직 미증명이다.** 이번에 보인 것은 둘이다. 판정기가
정상 상태를 통과시킨다는 것, 그리고 판정 대상이 존재했다는 것이다.

변이 주입이 남는다. 구 리더가 실제로 구 epoch 로 쓰게 만들어 델타가 양수로 뜨는지 봐야
하는데, 그러려면 fencing 을 우회하는 장치가 필요하다. `assert_current_leader` 를 지나지 않는
직접 INSERT 로 만들 수 있으나 그것은 저널 계약 밖의 행을 남기므로 그 회차의 다른 불변식을
깬다. 별도 스택에서 판정 함수만 대상으로 하는 편이 맞다.
