# ADR 0022 7단계 스냅샷 경계 재생 검증 (2026-09-15)

## 결론

- **판정은 스냅샷 경계 재생 성립이다.** 두 모드 모두 콜드 재기동 칸이 성립했다. 장애 칸 성립은 전역 3칸(E2, E4, E7), 대역 2칸(E4, E7)이고 FAIL 과 증거 불완전 칸은 없다. 규약은 `docs/reference/contracts/하네스_검증설계.md` §2-4 끝의 ADR 0022 7단계 스냅샷 경계 재생 판정 규약(2026-09-15 보강)이고, 판정기 종료코드는 0 이다.
- 재생 생략 5칸(전역 E5·E6, 대역 E2·E5·E6)은 스냅샷 판정에서 뺐다. 승격 때 새 리더(chaos-api-2)가 이미 모든 마켓 head 에 닿아 재생 없이 설치만 한 칸이다. 그 칸의 실험 판정과 분리 판정은 모두 PASS 다.
- 12칸 모두 실험 판정 PASS, 분리 판정 PASS 다. RTO 는 4.910~10.506초로 목표 30초 안이다.
- 성립 칸의 뜻은 판정기가 확인한 다음 조건이다.
  - 승격이나 부팅 복구가 활성 마켓마다 스냅샷을 채택했다.
  - 마켓별 적용 건수가 채택 seq 초과부터 종료 커서 이하까지의 저널 행 수와 같다.
  - 폴백 계수와 폴백 로그가 0 이다.
  - C17 이 matched 다.
- 대역 모드에서 판정기의 활성 마켓은 주입 전 채집 기준이라 칸마다 1~2개였다(E4·E6·E7·COLD 는 [1], E2·E5 는 [1, 2]). 사후 활성 마켓은 12칸 모두 [1, 2, 4] 다. 대역 E4·E7 과 COLD 두 노드가 세 마켓 모두 스냅샷을 채택한 것은 2026-09-15 reviewer 가 원자료로 대조했다.

## 한계

- 로컬 카오스 스택에서 칸마다 한 번이다. 클라우드 스택은 NOT RUN 이다.
- 스냅샷 경로를 거친 증거는 성립 7칸(콜드 2, 장애 5)이다. 재생 생략 5칸은 그 경로를 거치지 않았다.
- 대역 모드 스냅샷은 샤드마다 첫 명령 직후에 캡처됐다. `SnapshotCapture` 의 `lastCapturedSeq` 초기값 0 과 대역 seq(market_id x 10^12 + 지역 번호)의 차가 첫 명령에서 이미 명령 간격 100,000 을 넘기 때문이다(`server/app/src/main/java/kr/exchange/snapshot/SnapshotCapture.java`:86-94). 정확성 문제는 아니다. 그러나 대역 E4·E7 의 스냅샷 경계가 마켓마다 첫 명령 직후라 꼬리가 사실상 전 이력(867건, 857건)이었고, 이력 중간 경계를 거친 대역 증거는 COLD 칸 chaos-api-2 한 노드(꼬리 114·100·42건)뿐이다(2026-09-15 reviewer 원자료 대조). 캡처 기준 수정과 재측정은 후속이다.
- 꼬리 길이에 따른 복구 시간 이득은 재지 않았다. RTO 는 기록만 하고 5·6단계와 비교하지 않는다.
