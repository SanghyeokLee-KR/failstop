# 명령 저널의 미물질화 구멍 실측 (2026-09-12)

팔로워 상태 일치 검증의 상한을 무엇으로 둘지 가른다. 상한이 `max(source_cmd_seq)` 이면
그 아래에 아직 이벤트가 없는 명령(구멍)이 남을 수 있고, 그때 재생 대조가 짝을 잘못 잡아
거짓 불일치를 낸다. 구멍이 실재하는지 먼저 재고 판단한다.

## 왜 생길 수 있는가

명령 저널은 접수 시점에 커밋된다(`EngineBridge.submit` 이 `appender.append` 를 `sink.offer`
보다 앞에 둔다). 이벤트는 마켓별 라이터가 각자 정산 트랜잭션에서 적재한다. 곧 마켓 A 의
seq N 이 아직 정산 전인데 마켓 B 의 seq N+1 이 먼저 커밋될 수 있다.

## 실측

정지 상태에서는 0 이다. 명령 83,296 건에 물질화 83,296 건, 구멍 0 이다. 부하 중에만 창이
열리므로 그 구간을 봐야 한다.

`docker exec` 왕복이 표본당 100밀리초를 넘어 짧은 창을 놓친다. 서버 안에서 `pg_sleep(0.01)`
루프로 촘촘히 표본했다. 봇 기저 120 OPS, 12마켓이다.

| 항목 | 값 |
|---|---:|
| 표본 | 600 |
| 표본 간격 | 10밀리초 |
| 구멍 최대 | 1 |
| 구멍이 있던 표본 | 2 |
| 명령 head 와 물질화 최대의 최대 격차 | 2 |

술어는 이것이다.

```sql
SELECT count(*) FROM command_journal c
 WHERE c.seq < (SELECT coalesce(max(source_cmd_seq),0) FROM event_journal)
   AND NOT EXISTS (SELECT 1 FROM event_journal e WHERE e.source_cmd_seq = c.seq)
```

## 판정

**구멍이 실재한다.** 빈도는 이 부하에서 표본의 0.33퍼센트이고 깊이는 1 이다. 드물지만 0 이
아니다.

빈도가 낮은 것이 안전을 뜻하지 않는다. 팔로워는 주기마다 대조하므로 언젠가 그 창을 밟고,
밟으면 재생 이벤트와 저널 행의 `source_cmd_seq` 가 어긋나 `ReplayMismatchException` 이 난다.
팔로워는 `STATE_DIVERGED` 로 굳고 복귀 경로가 없다. 한 번이면 충분한 종류의 결함이다.

따라서 커서 축만 바로잡는 최소 교정은 쓸 수 없다. 상한을 연속 물질화 경계로 함께 재정의해야
한다. 경계는 첫 미물질화 명령 바로 앞이다.

## 한계

봇 120 OPS 한 조건에서만 쟀다. 부하가 높을수록 창이 넓어질 것으로 보이나 재지 않았다.
빈도와 깊이의 부하 의존성은 미측정이다. 판정에 필요한 것은 존재 여부이고 그것은 확인됐다.
