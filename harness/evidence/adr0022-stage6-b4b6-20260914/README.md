# ADR 0022 6단계 판정 주행 B4·B6 (2026-09-14)

## 결론

- **판정은 채번 분할 효과다.** B6 의 전역 카운터 행 대기 합이 0 이라 래치 무효가 아니고, 접수 비 B6/B4 가 1.359 로 1.15 를 넘는다. B4 는 전역 카운터 행 대기 표본이 9회 중 7회에서 0 보다 커(합 20, 최대 5) 재직렬화 기준선이 있다. 판정 규약은 `docs/reference/contracts/하네스_검증설계.md` §2-4 끝의 ADR 0022 6단계 B4·B6 판정 규약이다.
- **분기는 B(동시 커밋 확장)다.** B6 커밋 동시성이 1.233 으로 1.2 를 넘는다. 제시 부하 619.9/s x 커밋 1회 5.756ms 의 산술 상한이 3.568 이라 N/A 가 아니다. 분기는 기록만 하고 판정을 바꾸지 않는다.
- 칸 식별을 모두 채웠다. 두 칸 세 컨테이너의 서빙 이미지 id 가 하나(`sha256:1f16a036b451...`)이고 같은 날, 같은 스택과 부하 설정이다. B4 는 래치 행이 없고 대역 행이 0 이다. B6 는 래치 행이 있고 12마켓 대역 행이 2189~2493, C28 이 0 이다.
- 양성 축을 모두 채웠다. 두 칸 모두 12마켓 각 접수 0 초과, `k6_rc` 0, append 풀 대기 0, fsync 키 존재, 카운터 행 표본 채집 성공 9회(15초 간격), 분류기 양성 대조 PASS(전역, 마켓)다.
- 연결 고갈은 없었다. 최대 연결은 B4 51, B6 57 이고 한도는 197(`max_connections` 200, 예약 3)이다.

- 머리말 1회가 24.4ms 에서 3.0ms 로 줄었다. 4단계가 남긴 전역 카운터 행 재직렬화가 래치 뒤 사라졌다.
- 대기 표본과 독립인 확인이 둘 있다. 표별 쓰기에서 전역 `journal_counters` 갱신이 명령당 0.996 에서 0 이 됐고 `market_journal_counters` 갱신이 명령당 1 늘었다. 갭 회수 왕복(`exchange_writer_catchup_calls_total`)은 접수 대비 0.998 에서 0 이 됐다. 전역 seq 를 12마켓이 나눠 쓸 때 마켓 스트림에 생기던 갭이 대역 채번에서 없어진 것이다(ADR 0022 0단계 (c)). B6 의 마켓별 증가는 0 또는 1 이다.
- B6 는 머리말 활성 표본이 9회 중 1회라 대기 0 만으로는 검정력이 낮다. 래치 무효가 아니라는 판단은 위 두 계측을 함께 근거로 둔다.
- 채번 직렬이 풀리자 커밋이 겹쳤다. 커밋 1회가 5.0ms 에서 5.8ms 로, 커밋 동시성이 0.79 에서 1.23 으로 올랐고 DB CPU 도 올랐다.
- p95 는 485ms 에서 593ms 로 올랐다. 원인은 가르지 않았다.

## 한계

- 로컬 카오스 스택 한 번이다. 클라우드 스택은 NOT RUN 이고, 클라우드 DB 래치는 배포 때 ADR 0022 래치 전 확인 7 로 판단한다.
- B6 는 저널 0행에서 래치해 레거시 행이 없다. C28 0 은 섞임이 없다는 음성 확인이고, 이 주행은 C28 술어의 양성 검출을 보이지 않는다. 양성 검출은 `server/app/src/test/java/kr/exchange/harness/InvariantBandAxisIntegrationTest.java` 가 본다.
- 4단계 B4(`docs/measurements/20260914.md` 5.7.17, 152.25/s)와 이번 B4(157.53/s)는 같은 날이지만 이미지와 회차가 달라 판정에 쓰지 않는다. 차이는 3.5% 다.
- 요청 600/s 에 대한 제시 부하(접수와 수용거절 합)는 B4 615.5/s, B6 619.9/s 다.
- 이날 fsync 건당은 3.0ms 대다. 절대값은 날짜를 넘어 비교하지 않는다.
