# 문서 색인

`docs/`에는 현재 유효한 문서만 둔다. 현재 문서는 전부 이 색인에 등록한다.
`archive/`는 폐기 보관소이고 구현 근거로 인용하지 않는다. 2026-09-09 에 보관소를 정리해 직전 정본 한 편만 남겼다. 나머지 열 편은 과거 감사와 백로그와 현황 보고서로 결과가 이미 본문에 반영됐거나 새 정본이 대체했다. 과거는 git 이력이 갖는다.

폴더가 아니라 이 표가 분류의 정본이다. 폴더는 표를 따라 붙인 이름이라 어긋나면 표가 이긴다.
경로는 `docs/` 기준 상대경로다.

상태는 넷이다.

| 상태 | 뜻 |
|---|---|
| ACTIVE | 현재 구현의 근거 |
| REFERENCE | 참고 자료. 계약 아님 |
| ARCHIVED | 폐기. 구현 근거 사용 금지 |
| GENERATED | 원본에서 생성되는 결과물 |

생성물이라도 정본으로 지정된 것은 ACTIVE로 적고 원본을 비고에 밝힌다.

## 독자

문서를 누가 읽는지로 먼저 가른다. 독자가 문체 규약과 상세 수준을 정한다.

| 독자 | 위치 | 문체 규약 | 성격 |
|---|---|---|---|
| 기계 | `CLAUDE.md`, `docs/` 전체, `.claude/agents/` | 25절. 개조식 평서문 | 계약과 결정 이력. 구현이 지켜야 하는 것 |
| 사람 (심사자) | `제출_20260901/` | 27절. 존댓말, 용어 첫 등장 설명 | 무엇을 왜 만들었는지 |
| 사람 (운영) | `README.md`, `실행_가이드.md`, `docs/ROADMAP.md` | 25절 | 어떻게 돌리는지 |
| 둘 다 | `harness/evidence/` | 25절 | 기계가 만들고 사람이 읽는 판정 산출물 |

27절이 25절보다 우선하는 범위는 `제출_20260901/` 아래뿐이다. 그 밖에서 존댓말을 쓰지
않는다. 반대로 그 안에서 개조식으로 쓰지 않는다.

`docs/ROADMAP.md` 는 운영자용이지만 기계도 읽는다. 마일스톤과 잔여 범위를 갖고,
토폴로지 같은 다른 절의 관할 사실을 복사하지 않는다. 복사한 값은 반드시 드리프트한다.

`ROADMAP.md`는 `CLAUDE.md`가 정본 목록에 경로째 올려 둔 파일이라 하위 폴더로 옮기지 않는다.
DB 설계와 API 설계는 문서 헤더 버전을 기준으로 한다.

실측값과 그 유효성 판정은 `docs/` 밖의 `제출_20260901/테스트_정본.md`가 소유한다.
기획안 원본이 무엇을 증명하는가를 말하고, 그 문서가 어떻게 쟀고 그 값을 믿어도 되는가를
말한다. 회차마다의 원자료는 `harness/evidence/` 아래에 남는다.

클라우드 배포 계약은 `docs/` 밖의 `제출_20260901/기획안_원본.md` §6이 소유한다.
`deploy/` 산출물과 `.github/workflows/image.yml`이 그 절을 인용한다.

같은 독자를 향하는 심사 진입 문서는 `docs/` 밖에 있다.
`제출_20260901/산출물_1인대체_대응표.md`가 4인 팀 산출물과 대체물의 대응을 놓고,
`제출_20260901/WBS.csv`(작업 71행과 범례 1행)와 `제출_20260901/WBS_마일스톤.csv`(M1~M4)가
작업 분해와 실수행 구간을 담는다.

## 생성물

HTML이 원본이고 PDF가 인쇄 결과다. 원본이 인쇄용 `@page` CSS를 물고 있어 PDF는 원본에서
다시 뽑는다. PDF를 직접 고치지 않는다.

| 경로 | 상태 | 원본 관계 |
|---|---|---|
| `contracts/웹_화면명세서.html` | ACTIVE | 화면 명세 원본 |
| `contracts/웹_화면명세서.pdf` | ACTIVE | 인쇄 결과지만 `CLAUDE.md` 10절이 §6.2를 백엔드 수용 기준 정본으로 지정했다. 원본은 같은 폴더의 `contracts/웹_화면명세서.html` |
| `product/화면설계서.html` | ACTIVE | 화면설계서 원본 |

`제출_20260901/웹_화면명세서.pdf`는 `contracts/웹_화면명세서.pdf`와 바이트 동일한 사본이다
(SHA256 `525b5340...1156`). `제출_20260901/화면설계서.pdf`는 `product/화면설계서.html`의 인쇄
결과이고 GENERATED다. 같은 PDF를 `docs/`에도 두면 어느 쪽이 원본인지 흐려지므로 한 벌만 둔다.

## 폐기 (`archive/`)

직전 정본 한 편만 둔다. 전부 ARCHIVED다. 구현 근거로 인용하지 않는다.

| 파일 | 무엇이었나 | 왜 남기나 |
|---|---|---|
| `docs/archive/기획안_원본_20260908.md` | 2026-09-08 까지의 정본 | 새 정본이 무엇을 고쳤는지 대조할 근거다. 어긋남 129 건의 원본이다 |

2026-09-09 에 나머지 열 편을 지웠다. 과거 감사 넷과 백로그와 작업 목록과 현황 보고서와
이름 결정서와 초기 인수인계와 08-25 시점 스펙이다. 지적이 전부 본문에 반영됐거나 새
정본이 대체했다. 과거는 git 이력이 갖는다.

종전에는 자가 감사를 반복했다는 사실 자체가 증거라는 이유로 남겼다. 그 사실은 커밋
이력이 더 정확하게 증언한다. 반대로 폐기 문서가 남아 있으면 에이전트가 그것을 근거로
읽는 사고가 실제로 났다. `AI_인수인계서` 가 커밋 제목을 명령형으로 적어 스타일 게이트와
어긋났고, 그 함정은 `실행_가이드.md` 로 옮겨 두었다.
