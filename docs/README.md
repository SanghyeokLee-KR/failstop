# 문서 색인

`docs/`에는 현재 유효한 문서만 둔다. 현재 문서는 전부 이 색인에 등록한다.
`archive/`는 폐기 보관소이고 구현 근거로 인용하지 않는다.

폴더가 아니라 이 표가 분류의 정본이다. 폴더는 표를 따라 붙인 이름이라 어긋나면 표가 이긴다.
경로는 `docs/` 기준 상대경로다.

상태는 넷이다.

| 상태 | 뜻 |
|---|---|
| ACTIVE | 현재 구현의 근거 |
| REFERENCE | 참고 자료. 계약 아님 |
| ARCHIVED | 폐기. 구현 근거 사용 금지 |
| GENERATED | 원본에서 생성되는 결과물 |

생성물이라도 정본으로 지정된 것은 ACTIVE로 적고 원본을 비고에 밝힌다.

## 기록

`CLAUDE.md` 6절이 1인 대체 산출물로 지정한 둘이다. 4인 팀 산출물의 역할 분담표와
PR 리뷰 승인 이력을 각각 대신한다. 누적 대장이라 archive로 내리지 않는다.

| 경로 | 상태 | 담는 것 |
|---|---|---|
| `records/역할체계_운영기록.md` | ACTIVE | 역할 하네스 4개의 담당 범위와 도구 권한, 위임 규칙, 트리별 산출 실측. §7이 재측정 명령 |
| `records/검토_판정기록.md` | ACTIVE | reviewer 판정이 잡은 결함 18건과 교정 커밋. 검증 장치 자체의 결함은 §5, 문서 재배치 이력은 §7 |
| `records/인수인계_20260903.md` | ACTIVE | 2026-09-03 실측 회차의 결과와 다른 기계에서 이어가는 절차. 발표에 쓸 수치, 겪은 함정 다섯, 미배선 목록 |

설계는 이름 기준, 기록은 날짜 기준이다. 날짜가 중요한 기록을 새로 둘 때는 `YYYYMMDD_` 접두를 쓴다.

같은 독자를 향하는 심사 진입 문서는 `docs/` 밖에 있다.
`제출_20260901/산출물_1인대체_대응표.md`가 4인 팀 산출물과 대체물의 대응을 놓고,
`제출_20260901/WBS.csv`(작업 71행과 범례 1행)와 `제출_20260901/WBS_마일스톤.csv`(M1~M4)가
작업 분해와 실수행 구간을 담는다.

## 생성물

HTML이 원본이고 PDF가 인쇄 결과다. 원본이 인쇄용 `@page` CSS를 물고 있어 PDF는 원본에서
다시 뽑는다. PDF를 직접 고치지 않는다.

| 경로 | 상태 | 원본 관계 |
|---|---|---|
| `contracts/웹_화면명세서.html` | ACTIVE | 화면 명세 원본 |
| `contracts/웹_화면명세서.pdf` | ACTIVE | 인쇄 결과지만 `CLAUDE.md` 10절이 §6.2를 백엔드 수용 기준 정본으로 지정했다. 원본은 같은 폴더의 `contracts/웹_화면명세서.html` |
| `product/화면설계서.html` | ACTIVE | 화면설계서 원본 |

`제출_20260901/웹_화면명세서.pdf`는 `contracts/웹_화면명세서.pdf`와 바이트 동일한 사본이다
(SHA256 `525b5340...1156`). `제출_20260901/화면설계서.pdf`는 `product/화면설계서.html`의 인쇄
결과이고 GENERATED다. 같은 PDF를 `docs/`에도 두면 어느 쪽이 원본인지 흐려지므로 한 벌만 둔다.

## 폐기 (`archive/`)

수명이 끝난 감사와 이력이다. 전부 ARCHIVED다. 구현 근거로 인용하지 않는다.
각 파일 첫 줄에 폐기 표시가 있다.

시점 기록으로 남기는 이유는 자가 감사를 반복했다는 사실 자체가 증거이기 때문이다.
지적이 전부 해소됐다는 것은 그 문서를 읽지 않아도 된다는 뜻이지 없었던 일이라는 뜻이 아니다.

`개선_백로그` `정밀감사_2차` `수정_작업목록` `최종_통합감사` `실서비스_준비도_감사`
`문서감사_리포트` `프로젝트_현황보고서` `NAMING` `AI_인수인계서_20260722`

`AI_인수인계서`는 커밋 제목 규칙을 명령형으로 적어 `CLAUDE.md`의 명사형 종결과 충돌한다.
그 문서를 먼저 읽은 에이전트는 스타일 게이트에 걸릴 커밋을 쓴다. 유효한 빌드 함정은
`실행_가이드.md`의 알려진 함정 절로 옮겼다.
