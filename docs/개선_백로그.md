# 개선 백로그

## 개요

전문가 감사에서 도출한 결함·개선·디테일 항목을 우선순위 백로그로 정리한다. 병합 전 조치 대상과 후속 이월 대상을 심각도·공수 기준으로 구분한다.

- 감사 범위: 서버(server/), 웹(web/), 정본 문서(docs/), 하네스·CI/CD·관측(harness/, .github/)
- 감사 방법: 38개 전문 렌즈(B1~B20 백엔드, F1~F12 프론트, D1~D6 문서·하네스)로 읽기 전용 정찰. critical·high 후보는 적대적 재검증(코드·정본 교차 대조, 심각도 재판정)을 거쳐 확정.
- 제약: 읽기 전용. 빌드·테스트·스타일 게이트 미실행. 근거는 file:line으로 명시.
- 공수 표기: S(수 시간~반나절), M(1~수일), L(수일 이상).

동일 결함이 복수 렌즈에서 중복 관측된 경우 대표 1건으로 합쳤다(대표 사례: OrderPanel 멱등키, BEST 매수 NPE, TickCell matchMedia, InflightReserves 락, feeStats N+1).
