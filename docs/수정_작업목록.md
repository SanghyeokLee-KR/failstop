# 수정 작업목록

## 개요

1차 감사(개선_백로그.md, 204건)와 2차 정밀감사(정밀감사_2차.md)를 통합해 팬아웃 수정용 작업목록으로 재구성한다. 트랙(server·web·docs)·파일 단위로 묶어 한 파일이 한 팬아웃 단위가 되게 한다.

표기 규약.

- 심각도: high·med·low.
- 종류: 결함·개선·디테일.
- 공수: S(수 시간~반나절)·M(1~수일)·L(수일 이상).
- 출처: (1차)·(2차)·(1·2차)로 병기. 심각도 재판정은 방향 병기.
- 각 항목 형식: `[심각도·종류·공수] LN: 문제. 수정: 지시.`

통합 방법.

- 중복 제거: 같은 file:line·같은 결함은 1건으로 합치고 출처를 병기. 심각도가 다르면 높은 쪽을 채택하고 재판정 방향을 남긴다.
- 완료분 제외: 이번 세션에서 이미 수정·커밋된 건은 본 목록에서 빼고 아래 완료 요약에만 남긴다.
- 정보성·범위밖·설계 트레이드오프·추측성 항목은 본 목록에서 빼고 부록에 사유와 함께 나열한다(강제 변경 대상 아님).
- 남은 실제 결함·가치 있는 개선·디테일만 트랙별·파일별로 싣는다.

트랙 배정.

- server: server/ 자바 코드, Flyway 마이그레이션(V0~V10), application.yml, 서버 테스트, 하네스·CI·관측 인프라(harness/, scripts/, .github/). 코드 변경 단위.
- web: web/ 전체.
- docs: docs/ 정본·색인·로드맵 문서.
