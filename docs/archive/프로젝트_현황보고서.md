## 1. 요약

- 정의: 봇 플릿이 실시간 매매하는 완전 시뮬레이션 거래소. 실거래·실자산 없음. 1년 주기, 웹(정적 export 데스크톱 트레이딩 화면)이 메인 산출물, 앱은 후순위. 백엔드 Spring Boot.
- 최상위 목표(반증 가능한 두 명제):
  - 증명 ① 체결 무결: 트래픽 폭주·장애에도 자산별 원장 합 0, 주문 중복·유실 0.
  - 증명 ② 자동 복구: 서버를 죽여도 사람 개입 없이 복구, 체결 재개. RTO 30초 이내.
- 판정은 사람 눈이 아니라 SQL 위반 행 0, 메트릭 임계, exit code로만 한다.
- 현재 도달점: M1(코어 거래 + 고가용성 증명 1차) 구현 도달. M2(회원)·M3(커뮤니티·관리자)는 코드와 통합테스트가 반영됐으나 완료 기준(부하 동시 상시 게이트 통과)은 미검증. M4는 카오스 E1~E9 전량 배선 완료, 라이브 PASS 3건.
- 규모: 커밋 211건(2026-07-22 ~ 2026-08-19), Java 245파일, TS·TSX 146파일, 백엔드 테스트 59클래스, 웹 테스트 278건.

### 리더 kill 자동 복구 실측 (현 E4)

docker kill 주입 후 무개입 관찰. 판정 프로토콜은 사전 권위 run(불변식 green) → 주입 → 무개입 관찰 → 사후 권위 run.

| 지표 | 실측 | 목표 |
|---|---|---|
| RTO(체결 재개, T5-T0) | 약 11.4초 | 30초 이내 |
| epoch | 정확히 +1 | +1 |
| 자산합 위반(C01) | 0 | 0 |
| 중복 접수(C07 계열) | 0 | 0 |
| 중복 체결(C08) | 0 | 0 |
| 저널 gap(C05·C06) | 0 | 0 |
| 주문 유실(C13a 물질화) | 0 | 0 |

- RTO는 페일오버 후 최초 신규 TRADE의 engine_ts(T5)에서 kill 시각(T0)을 뺀 값. 게이지 다운타임(감지·승격 구간)보다 넓은 권위 창.
- T5 술어는 명령 축 fencing 기준(command_journal.fencing_token > 구 epoch)으로 확정됐다. 이벤트 축 술어와 승격 워터마크 술어는 승격 재생 산출물을 재개로 오인해 RTO를 과소 보고하므로 폐기됐다(E6 동일 조건 실측에서 0.086초 대 10.698초).

### 하드닝으로 교정한 서버 결함

라이브 실험이 설계 단계에서 보이지 않던 결함을 드러냈고, 그 교정이 실질 성과에 해당한다.

- 좀비 리더 자발적 강등: 리더가 요청을 하나도 처리하지 못하는데 리스만 계속 갱신해 스탠바이가 승격하지 못하는 상태를 실측. 쓰기 수요 대비 쓰기 커밋 완료율이 임계 미만으로 지속되면 갱신을 포기하고 자발적으로 강등하도록 교정(판정 신호를 세 차례 재설계한 끝에 확정).
- 무한 수용에 의한 노드 자멸: 수용 제한 부재로 리더가 스스로 죽는 경로를 확인. 쓰기·조회 2버킷 수용 제한과 재조회 전용 소형 버킷(409 requery_deferred)을 도입.
- 승격 재생 실패로 인한 2노드 전멸: 승격 재생 실패를 종신 강등으로 분류해 클러스터가 리더 없이 영구 정지하던 결함을 회복 가능 등급으로 교정.
- 판정 경로 결함 4건: 실험 FAIL이 코드 결함이 아니라 판정기 결함이었던 사례. 반환값이 파이프라인에 섞여 verdict 비교가 항상 참이 되던 문제 등.

### 그 밖의 증명 축

- 복식부기 총자산 보존: 정산이 SettlementService 단일 트랜잭션(event append + 정산 + trades + orders + outbox 원자 커밋). C01 자산별 원장 합 0을 기동 직후부터 유지(GENESIS 입금도 회계 경로 경유).
- 재생 결정론: 매칭 코어가 벽시계·난수·I/O·락을 쓰지 않고 비결정 입력을 명령 payload에 박제. 저널 재생 결과가 원본과 비트 동일.
- 스냅샷 채택 게이트: format_version·engine_version·config_hash 일치와 마켓별 state_checksum 대조를 통과한 세트만 채택하고, 어긋나면 세트 전체를 폐기해 seq 0 전량 재생으로 폴백한다. 세트는 단일 트랜잭션 INSERT라 부분 세트가 관측되지 않는다. SnapshotRecoveryIntegrationTest가 채택 후 tail 재생과 버전 불일치 폐기를 각각 고정한다.
- 멱등: 주문 생성 client_order_id 필수(미제공 400, 서버 생성 fallback 없음). 재시도는 동일 키 재사용, 멱등 replay로 수렴.
- 검증기 반증: verifierCatchesInjectedViolations가 위반을 고의 주입해 검증기가 잡아내는지 확인. 항상 통과하는 검증기 가능성을 배제한다.
- 라이브 봇 거래·웹 연동: 봇 플릿이 외부 클라이언트 규약(서명·자체 HTTP)만으로 접속, 내부 직호출 없음. 카오스 스택에서는 엔진을 끈 별도 노드로 분리해 승격 주체 오염을 막는다. 웹이 REST·WS로 실제 백엔드에 바인딩.

- 역할 하네스(.claude/agents/, .codex/agents/): backend-engineer(server 구현), frontend-engineer(web 구현), harness-engineer(부하·카오스·불변식·CI/CD·관측), reviewer(병합 전 적대적 검토, 수정 권한 없음 판정만).
- 흐름: 구현 역할 변경 → reviewer 판정(통과·조건부 통과) → 병합. 역할 간 이견은 정본 문서가 판정, 문서가 틀리면 문서를 먼저 고친다.
- 스타일 게이트(AI 흔적 금지): em dash·en dash·이모지·AI 상투 어투·도구 서명 금지를 CI(.github/workflows/style.yml)와 scripts/check-style.ps1이 강제. 위반은 리뷰 반려 사유.
- 정본 우선: 코드가 정본 문서와 어긋나면 문서를 먼저 고치고 코드를 맞춘다.
- 패치 노트 관행: 라이브 실측으로 설계가 틀렸음이 드러나면 하네스_검증설계.md 상단에 날짜별 패치 노트로 남긴다. 현재 24건 누적. 실패한 가설과 그 교정 근거가 문서에 남는다.

## 6. 기술 스택·아키텍처 요약

- 스택: Spring Boot 3.5.16 + Java 21, 매칭 코어 순수 Java, REST(MVC + Virtual Threads), 실시간 WebSocket + STOMP, PostgreSQL 17, Flyway, Resilience4j, 웹 Next.js 15 + React 19 정적 export(고정형 데스크톱 1280px), 부하·카오스 k6·Toxiproxy·Chaos Monkey, 관측 Prometheus·Grafana.
- 3계층 SoT: ① 복구 원천(command_journal·event_journal·snapshots, append-only 재생 가능), ② 회계 원천(ledger_entries, 복식부기 자산별 합 0), ③ 파생 프로젝션(balances·orders·trades, 언제든 재계산). 증명 ②는 ①의 명령 재생, 증명 ①은 ②의 자산 보존 불변식.
- 고가용성: 단일 라이터를 DB leader_lease 행으로 보장(resource=matching-engine 단일). 승격마다 epoch +1. 자산 변경 트랜잭션은 커밋 전 assert_current_leader(holder·epoch·리스 만료)로 stale 쓰기를 롤백. command_journal은 fencing_token, event_journal·trades·snapshots는 fencing_epoch에 승격 epoch 저장으로 split-brain을 데이터로 감사.
- 수용 제한: 쓰기·조회 2버킷 + 재조회 전용 소형 버킷. 초과는 거절이 아니라 판정 보류(409 requery_deferred + Retry-After)로 내보내 부하 도구의 안전 상태 집합 안에 머문다.
- 봇 플릿: 12개 마켓에 마켓메이커 14 + 테이커 12, 봇마다 가상 스레드 1개. 전역 OPS 버킷이 처리량 상한을 쥐므로 봇 수 증가가 백프레셔를 뚫지 못한다. 방향 bias는 하드캡 ±0.7이고 기준가 대비 ±40% 이탈 시 0으로 강제된다. 모든 난수는 시드 SplittableRandom을 고정 순서로 소비해 재현성을 유지하고, bias·레짐 배수는 확률·틱 오프셋 스칼라 전용이라 가격·수량 NUMERIC 산술에 유입되지 않는다.
- 배포 단위 분리: A 거래 평면(다중 인스턴스), B 봇 플릿(외부 클라이언트 규약만), C 관리 평면(분리 포트·네트워크·mTLS), 코어 exchange-core(Spring·락·I/O·벽시계·난수 금지). 분리는 카오스 실험(거래소만 죽이고 봇은 살림)의 전제.

### 미구현 기능

- REST 일부: orders/batch(일괄 발주), 일괄 취소, orders/chance(주문 가능 정보), my/trades, my/ledger, keys rotate. candles는 trades 실시간 집계로 구현됨(별도 candles 테이블 미적재).
- 다중 노드 선행 조건: NonceStore가 단일 노드 인메모리(정본은 Redis SET), WS가 단일 노드 SimpleBroker(크로스노드 팬아웃 미구성), 잔고 사전 가드 다중 노드 미성립.
- 리더 인지 LB 라우팅 미구현. nginx는 능동 health_check가 없는 오픈소스 판이라 api-1 1차·api-2 backup 정적 승계이고, 트래픽 이동은 접수 경로가 내는 503이 max_fails에 계상되는 수동 판정이다. POST 재시도를 위해 non_idempotent를 명시했다(2026-08-18 실측: 이 옵션 없이 구 리더 재합류 구간에서 POST /api/v1/orders 전량 503, 추가 후 20초에 체결 599건 재개). 강등 노드가 업스트림에서 빠지지 않으므로 약 1.25%의 POST 실패 바닥이 남는다.

### 검증 배선 잔여

- C16 외부 ACK 파이프라인(봇·k6 ACK 로그를 harness.loadtest_acks로 COPY) 미배선. 실험 한정 체크라 라이브 게이팅에서 면제되며, RPO=0은 저널 무결(C05·C06·C13a) 프록시로 판정한다.
- E3~E5·E7~E9 라이브 PASS 미기록. 스크립트는 배선 완료 상태다.
- V3 T1~T6 전건, soak 2시간, 성능 캘리브레이션, 빈 환경 콜드 스타트는 M4 대상.

### 환경·운영 리스크

- 한글 경로 테스트 이슈(해소): 프로젝트가 한글 경로에 있으면 gradlew test가 ClassNotFoundException으로 실패(Windows 매니페스트 jar 클래스패스 손상). 프로젝트를 실제 ASCII 경로 `D:\dev\exchange`로 옮겨 해소했고 정션 우회는 폐지했다. PowerShell·Git Bash 모두 통과. CI 러너는 ASCII 경로라 무관.
- 통합테스트는 Docker(Testcontainers)가 필요하다. 33개 테스트 클래스가 각자 PostgreSQL 컨테이너를 띄우며 재사용 설정은 쓰지 않는다. Docker가 없으면 해당 39건이 실패한다.
- RPO=0은 단일 PostgreSQL 인스턴스 범위에서만 성립. failover 포함 무손실은 동기 standby·synchronous_commit·클러스터 STONITH 운영 요건 전제.
