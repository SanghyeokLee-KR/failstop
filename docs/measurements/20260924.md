# 측정 20260924

2026-09-24 새벽(04:41~05:31 KST)에 ADR 0034 마켓 분할 리더의 S1·S2 관문 주행을, 오전(08:39~11:41 KST)에 S3 관문 주행을, 오후(13:51~15:36 KST)에 S3 관문 재주행을, 이어서(15:55~16:34 KST) S2 관문의 A/B 재측정을 로컬 Docker의 폐기용 스택에서 했다. S3의 두 주행은 각 절에 적은 이미지로 돌렸다. 작업 브랜치 `claude/per-market-leader`의 `b04acd5`(S1 잔여와 S2 코드)로 이미지를 구웠고, 비교 기준은 main `ec8ef8e`다. compose 프로젝트는 `exchange-pml`이고 볼륨·망이 보존 스택 `exchange-chaos`와 갈린다. 보존 볼륨 `exchange-chaos_chaos-pgdata`와 백업 볼륨 `failstop-keep-chaos-pgdata-20260924`는 마운트하지 않았고 주행 전후 그대로다. 환경은 Windows 11의 Docker Desktop 단일 호스트이고 앱 노드는 1 vCPU·1 GiB다. 이 기록은 AWS의 장애나 처리량을 대신하지 않는다.

## S2 관문 폐기용 스택 주행

원자료는 [pml-s2-gate-20260924-0440](../../harness/evidence/pml-s2-gate-20260924-0440/README.md)이다. [S2 설계](../reference/architecture/마켓분할_리더_S2_설계.md) 6-4의 세 주행을 설계 순서대로 했다.

**S2 관문은 통과하지 않았다.** 종단 주행과 되돌림 주행은 PASS, A/B 비교는 사전 규칙의 "5xx 증가 없음"을 채우지 못해 FAIL이다.

- 앱 역할 로그인 종단 주행(PASS). S2 이미지를 배포와 같은 런타임 로그인(`app_role` 소속, 수퍼유저 아님, Flyway 끔)으로 띄웠다. 리더가 서고 새 epoch로 주문·체결·스냅샷을 썼으며, api 연결은 모두 앱 로그인이었고 권한 거부는 0줄이다. 하네스 SQL의 C01~C29 31행이 모두 PASS다. V49를 적용하지 않은 권한 상태다.
- 되돌림 주행(PASS). A/B의 B 칸이 남긴 V48 DB에서 main 이미지의 배포용 마이그레이션 진입점과 Spring Flyway가 모두 "DB 버전 48이 이미지의 최신 47보다 새롭다" 경고 뒤 적용 없이 끝났다. 그 이미지를 앱 역할 로그인으로 띄우자 리더가 되어 주문·체결·스냅샷을 썼고 C01~C29가 모두 PASS다.
- A/B 비교(FAIL). `roundtrip_probe.py` 600/s를 칸마다 새 스택에서 A1(main), A2(main), B(S2) 순으로 돌렸다.

| A1 | 146.7 | 11.096 | 51.76 | 3,309 | 0 | 0 |
| A2 | 163.0 | 10.247 | 50.10 | 2,726 | 0 | 0 |

append 평균 증가 +0.310ms와 p95 증가 +1.565ms는 A-A 차이(0.849ms, 1.664ms)보다 작다. 5xx 증가 +1,119.5는 A-A 차이 583을 넘는다. 5xx는 모두 팔로워의 설계상 503과 nginx의 502(주 업스트림 연결 시간 초과 뒤 백업 거절)이고 리더가 낸 5xx는 0이다. 판정은 설계가 범위를 정하지 않은 5xx를 가장 넓게 셌다.

원인 좁히기로 B2·A3을 더 돌렸다(판정에 쓰지 않음). B2 접수 138.0/s·5xx 3,673, A3 160.0/s·2,493으로 같은 모습이 되풀이됐다. S2 이미지의 접수 처리율이 과부하(제공 부하가 능력의 약 4배)에서 약 12% 낮다. 접수 락 안의 DB 구간(머리말·저널 삽입·커밋)과 락 보유 시간은 이 차이를 설명하지 못했고, 원인은 특정하지 못했다.

**재지 않은 것.** 6-1·6-3 서버 시험의 재실행, V49 이미지 관문, 포화 전 부하의 A/B, 프로파일링이다. A/B는 칸마다 1회라 12% 차이의 신뢰구간이 없다. 이 A/B 판정은 아래 재측정이 새 규칙으로 대신한다.

## S2 관문 A/B 재측정 (15:55~16:34 KST)

원자료는 [pml-s2-gate-rerun-20260924-1553](../../harness/evidence/pml-s2-gate-rerun-20260924-1553/README.md)이다. 2026-09-24 11시 사용자가 "5xx는 리더가 낸 것만 세고, 반복 측정 뒤 넘어간다"고 정해, S2 설계 6-4의 조건을 "리더 노드가 낸 5xx 증가 없음(팔로워의 설계상 503과 과부하 때 nginx 502 제외)"으로 고친 뒤 A(main `ec8ef8e`, `exchange-chaos-app:mainref`)와 B(`b04acd5`, 임시 작업 트리에서 새로 구운 `exchange-chaos-app:s2ref`)를 A-B-A-B-A-B 순서로 돌렸다. 러너와 부하는 첫 주행과 같은 `roundtrip_probe.py` 600/s이고, 칸마다 스택을 새로 세웠다. 셈법(증가는 B 평균 − A 평균, A-A 차이는 A 세 칸의 최댓값 − 최솟값)은 주행 전에 적었다.

**새 규칙으로 A/B 비교는 PASS이고, 첫 주행의 종단·되돌림 주행 PASS와 합쳐 S2 관문의 폐기용 스택 항목은 모두 통과했다.**

## S3 관문 재주행 (13:51~15:36 KST)
