# Claude와 Codex로 개발하기

두 도구에 프로젝트를 매번 처음부터 설명할 필요가 없도록 작업 기준을 저장소에 모았다. 목표는 긴 프롬프트 하나를 계속 붙여 넣는 것이 아니라, 이번 작업에 필요한 자료를 찾고 실제 결과를 검증하게 하는 것이다.

사람이 프로젝트를 파악할 때는 [프로젝트 이해하기](프로젝트_이해하기.md)를 먼저 읽는다. AI에게 일을 맡길 때는 원하는 동작과 수정 범위, 완료 조건을 알려주면 된다. 세부 개발 기준은 루트 [AGENTS.md](../../AGENTS.md)에서 찾아가도록 연결했다.

## 두 도구가 같은 기준을 읽는 방법

Codex는 `AGENTS.md`를 프로젝트 지침으로 읽는다. Claude Code는 [CLAUDE.md](../../CLAUDE.md)의 `@AGENTS.md`를 통해 같은 내용을 읽는다. 그 뒤 주문·웹·배포·문서 등 작업에 맞는 규칙과 설계만 추가로 연다. 폴더별 문서의 본문이 모두 자동으로 들어가는 구조는 아니다.

이 구성은 공식 [Codex 프로젝트 지침](https://learn.chatgpt.com/docs/agent-configuration/agents-md)과 [Claude의 AGENTS.md 가져오기](https://code.claude.com/docs/en/memory#agentsmd) 방식을 따른다. 긴 내용을 여러 파일로 나누고 전부 가져오면 매번 읽는 양은 줄지 않으므로, 공통 진입점과 작업별 상세 기준을 구분했다.

| 기준 | 관리하는 내용 |
|---|---|
| [작업 절차](../ai/workflow.md) | 요청 해석, 역할 분담, 설계 충돌 처리, 검토와 보고 |
| [개발·검증 기준](../ai/engineering.md) | 거래 불변조건, 보안, 배포, 장애 시험과 완료 조건 |
| [코드·주석 기준](../ai/code-style.md) | 기존 코드에 맞춘 구현과 주석 작성 |
| [문서 작성 기준](../ai/writing.md) | 사람용 설명, 상세 설계, 근거와 문체 |

기존 CLAUDE 규칙의 개발·보안·검증 조건은 위 문서로 옮겼다. 기존 절 번호도 대부분 유지해 과거 코드 주석에서 찾을 수 있게 했다. 삭제한 기록을 다시 만들라는 지시, 낡은 현황, 도구별로 충돌하는 지시는 현재 작업 방식에 맞게 고쳤다.

## 새 세션이나 학교 PC에서 시작할 때

프로젝트 루트를 열고 [시작 요청문](../ai/prompts.md)의 '새 세션에서 이어서 시작할 때'를 사용한다. AI가 읽을 순서는 AGENTS → 0099 → 로드맵이다. AWS·Linux 운영 작업은 ADR 0027과 배포 안내까지 확인한 뒤, 로드맵의 '다음 작업의 시작점'에서 이어간다. 특정 작업을 요청했다면 그 작업에 필요한 계약과 코드도 읽는다.

저장소에 접근하는 Codex·Claude Code와 파일 접근이 없는 일반 채팅은 구분해야 한다. 일반 채팅에 로컬 경로를 적거나 `CLAUDE.md` 하나만 첨부해도 링크된 문서 전체가 전달되는 것은 아니다. 이 경우 `AGENTS.md`, `0099-current-architecture.md`, `ROADMAP.md`, `0027-msp-operations-and-autoscaling.md`, `deploy/README.md`의 내용을 먼저 제공한다. 구현을 맡길 때는 작업 대상 코드와 연결된 규칙·설계도 추가로 제공하거나 저장소에 접근하는 도구를 사용한다. AI가 실제로 읽은 파일과 읽지 못한 파일을 먼저 밝히게 한다.

다른 PC를 쓴다면 소스와 문서뿐 아니라 루트의 `AGENTS.md`·`CLAUDE.md`, `.agents/skills`, `.claude/agents`·`.claude/skills`, `.codex/agents`도 함께 옮긴다. Git으로 전달할 때는 `git status --short`에서 새 파일과 수정·삭제가 커밋에 포함됐는지 확인하고 원격 반영 뒤 학교 PC에서 받는다. 미커밋 변경과 untracked 파일은 clone·pull만으로 전달되지 않는다. 폴더 복사를 선택하면 정션이나 바로가기만 복사하지 않고 실제 작업 파일과 폴더 구조를 보존한다.

AWS 인증, 실제 `.env` 값, Teams 웹훅 등 비밀 값은 Git이나 채팅에 넣지 않는다. 새 PC에서 따로 준비하고 값 자체를 보고하지 않는다. 로컬 실행은 [실행 가이드](../../실행_가이드.md)를 따라 실제 경로로 `EXCHANGE_HOME`을 설정하고 PowerShell 7, JDK 21, Node.js 20 이상, Docker의 설치·기동 여부를 확인한다. 문서 확인만 한다면 서비스를 모두 띄울 필요는 없다.

## 실제로 요청할 때

예를 들어 다음처럼 요청할 수 있다.

```text
주문이 처리 중일 때 새 주문으로 다시 접수되지 않도록 웹 재시도 동작을 확인하고 수정해 줘.
수정 범위는 웹 통신과 주문 상태 처리야. 서버 계약은 바꾸지 마.
같은 주문 식별자를 유지하고, 응답이 늦을 때 화면이 어떻게 보이는지도 확인해 줘.
공통 규칙에 따라 관련 테스트를 실행하고 미확인 사항을 알려 줘.
```

반복해서 쓸 요청문은 [작업 프롬프트](../ai/prompts.md)에 있다. 새 세션 시작, 구현, 문서 정리, 변경 검토에 사용할 수 있고 운영 보고 AI의 초안도 분리해 두었다. 작업을 구체적으로 적을수록 불필요하게 다른 기능까지 바꾸는 일을 줄일 수 있다.

문서 정리에는 `exchange-docs` 스킬도 연결했다. Claude Code에서는 `/exchange-docs`, Codex에서는 `$exchange-docs`로 지정할 수 있다. 두 파일은 같은 공통 문서 작성 기준을 읽으며, 검사에서 내용이 서로 달라졌는지도 확인한다. 설치 경로는 공식 [Claude 스킬](https://code.claude.com/docs/en/skills)과 [Codex 로컬 스킬](https://learn.chatgpt.com/docs/build-skills) 기준을 따른다.

## 구현과 검토를 나눌 때

백엔드, 프런트엔드, 하네스, 리뷰의 네 역할을 준비했다. 역할의 실제 지침은 [공통 역할 폴더](../ai/roles/)에 한 번만 둔다. Claude의 `.claude/agents`와 Codex의 `.codex/agents`는 이 지침을 읽는 연결 설정이다. Codex 설정은 공식 [커스텀 에이전트 형식](https://learn.chatgpt.com/docs/agent-configuration/subagents)을 따른다.

작은 수정은 한 도구로 끝내도 된다. 역할을 나눌 때는 '백엔드와 프런트가 각각 어떤 파일을 수정하는지'를 먼저 정한다. 같은 파일을 Claude와 Codex가 동시에 수정하게 하지 않는다. 별도 세션에서 병렬 구현하려면 작업 트리를 분리하고 한쪽에서 결과를 통합한다.

리뷰 역할은 코드와 근거를 읽고 문제를 보고한다. Claude 리뷰 설정에는 읽기·검색 도구만 주었고, Codex 리뷰 설정은 읽기 전용 샌드박스를 요청한다. 실행 권한이 필요한 검증은 구현 담당자가 수행하고 결과를 전달한다. 모든 판단이 도구 설정만으로 보장되는 것은 아니므로 실제 검토 범위도 보고한다.

모델과 추론 수준은 사용자의 설정을 그대로 따른다. 저장소 설정에 특정 모델을 고정하거나 권한을 넓히는 옵션을 넣지 않았다.

## 결과를 확인하는 방법

문서 작업은 네 가지 검사로 확인한다. `check-docs.ps1`은 Markdown 링크, 공통 진입점, 두 스킬의 일치를 검사한다. `check-doclinks.ps1`은 소스 주석을 포함한 문서 경로 인용을 검사한다. `check-adr-current.ps1`은 ADR 누락·중복과 0099의 원자료 해시를 검사한다. `check-style.ps1`은 저장소의 금지 문자와 일부 상투적인 표현을 검사한다. 문서 구조와 0099 검사는 기존 CI에도 연결했다.

```powershell
pwsh -NoProfile -File scripts/check-docs.ps1
pwsh -NoProfile -File scripts/check-doclinks.ps1
pwsh -NoProfile -File scripts/check-adr-current.ps1
pwsh -NoProfile -File scripts/check-style.ps1
```

검사 통과와 읽기 좋은 문서는 같은 말이 아니다. 문장 품질은 실제로 이어 읽어 보고, 기술 설명은 코드와 원자료를 대조해야 한다. 문서 작성 스킬도 이 검토를 완료 조건으로 삼는다. 거래나 인증 코드가 바뀌면 문서 검사에 더해 해당 빌드와 테스트가 필요하다.

새 설정은 저장소 루트에서 시작한 새 세션에서 확인한다. Claude에서는 `/memory`와 스킬 목록으로, Codex에서는 로드한 지침과 스킬 목록으로 이 프로젝트의 파일이 잡히는지 확인할 수 있다. 파일 형식과 연결을 검사한 사실과 실제 새 세션에서 모델이 지침을 따르는지는 구분한다. 개인 설정이나 더 높은 우선순위의 지침이 있다면 그 영향도 함께 확인한다.
