# 체결 시각효과 · 관리자 제어 설계 (v1.0, 확정)

> 트레이딩 화면의 체결 시각효과("튀어나오는" 팝·플래시)와 관리자 콘솔의 봇·효과 제어 UI를 확정한다.
> 정본 소비: 프론트_디자인시스템.md(토큰·모션), 데스크톱_레이아웃설계.md(그리드·패널), 관리자_설계.md(§2-1 봇·§4 화면), 백엔드_API_설계.md(§6-A sim), V5__admin.sql(system_config).
> 본 문서는 설계 확정 산출물이다. 코드 구현은 관리자 화면 완료 후 별도 진행한다.
> 신규 API·토큰·타입은 정본을 먼저 개정해야 코드에 반영된다. 개정 대상은 §6에 열거한다.

## 1. 목표·범위

- 목표: 체결의 방향·속도·크기를 시각으로 전달해 시장 생동감을 만든다. 동시에 시각 소음·산만함을 통제한다.
- 원칙: 생동감은 강도의 문제이지 색·규칙의 예외가 아니다. 방향색·부호·화살표·대비·reduced-motion 규약은 강도와 무관하게 항상 성립한다.
- 범위 내: 트레이딩 화면(`/exchange/[market]`)의 프라이스 셀 팝, 체결 테이프 플래시, 대형 체결 강조. 관리자 콘솔의 봇 대수·방향 바이어스·자동 균형·효과 강도 제어.
- 범위 밖: 차트 렌더 애니메이션(라이브러리 소관), 시스템 헬스 플래시(별도 도메인, `--color-health-flash-*`), 호가 depth 막대 트랜지션(기존 유지).
- 불변 규칙(전 효과 강제):
  - 상승·매수 Red(`--color-up*`), 하락·매도 Blue(`--color-down*`). 가격 방향에 green 금지.
  - 색 단독 표현 금지. 효과에 부호(+/−)·화살표(▲▼)·수치를 병기한다.
  - 하드코딩 hex 금지. 효과 색·글로우도 토큰만 소비한다(§5·§6).
  - reduced-motion은 모션 제거가 아니라 정적 강조로 대체한다(§2-4).
  - 실시간 갱신은 레이아웃 시프트 0. 금액·수량은 문자열 포맷(format.ts), float 금지.
  - 데스크톱 고정형(최소 1280px). 정적 export 유지, 런타임 외부 의존 0.

## 2. 체결 시각효과 설계

### 2-1. 효과 종류

효과는 4종이며 모두 기존 원자·토큰을 재사용하거나 확장한다.

1. 프라이스 셀 팝(scale + glow).
   - 대상: SummaryBar 현재가 히어로, OrderbookPanel 현재가 경계(`mid`), MarketListPanel 현재가 셀.
   - 트리거: 셀 값 변동(가격 델타). 방향은 델타 부호로 판정한다(상승 Red·하락 Blue).
   - 표현: 값 변동 순간 셀 내부 텍스트를 중심 기준 scale로 미세 확대 후 복귀 + 방향색 글로우(box-shadow). 배경 플래시(`--color-up/down-flash`)를 병행한다.
   - 기존 자산: TickCell(web/components/TickCell.tsx)의 throttle·중첩취소·reduced-motion 훅 계약을 확장한다. 신규 원자를 만들지 않고 팝·글로우·강도 인지를 TickCell에 얹는다.

2. 체결 테이프 플래시.
   - 대상: TradesPanel 첫 행(신규 체결 도착).
   - 트리거: `trades[market]` 선두 갱신.
   - 표현: 신규 행 배경을 체결 방향색 틴트로 1회 점멸 후 소거. 방향은 `taker_side`(bid=매수 Red·ask=매도 Blue), TradesPanel.tsx의 `sideDir` 매핑을 그대로 쓴다(TradesPanel.tsx 체결가 셀은 이미 ▲▼ + 부호 병기).

3. 방향 표식.
   - 모든 효과 셀·행은 색과 무관하게 ▲(상승·매수)·▼(하락·매도)·부호를 텍스트로 병기한다. 보합(flat/EVEN)은 화살표 없이 무채색(`--color-flat`).
   - 팝·플래시가 강도 off이거나 reduced-motion이어도 표식은 상시 유지된다(색 단독 금지의 최종 방어선).

4. 대형 체결 강조.
   - 트리거: 체결량이 마켓별 최근 체결량 롤링 중앙값의 K배(K=8, 조정 가능) 이상.
   - 표현: 해당 팝을 한 단계 강한 스케일·글로우로 승격 + 테이프 행에 "대형" 마이크로 배지(`--font-micro`)와 체결 금액(방향 부호·화살표 병기)을 오버레이한다. 배지는 절대 배치 오버레이라 인접 행을 밀지 않는다(시프트 0).
   - 색: 방향색 유지. 크기·글로우 세기로만 위계를 만든다. 별도 강조색 없음.

방향색 매핑과 색 단독 금지 준수:

| 효과 | 방향 판정 | 색 토큰 | 병기 표식 |
|---|---|---|---|
| 셀 팝(히어로) | 가격 델타 부호 | 텍스트 `--color-up`/`--color-down`(히어로 500 허용), 글로우 `--effect-glow-*` | ▲▼ + 값 |
| 셀 팝(소형) | 가격 델타 부호 | 텍스트 `--color-up-text`/`--color-down-text`(600), 배경 `--color-up/down-flash` | ▲▼ + 값 |
| 테이프 플래시 | `taker_side` | 배경 `--color-up/down-flash`, 텍스트 `-text` | ▲▼ + 체결가 |
| 대형 체결 배지 | `taker_side` | `--color-up-strong`/`--color-down-strong` on `-bg`(틴트 위 700, §6 대비 계약) | ▲▼ + 금액 |

### 2-2. 강도 단계 시각 명세

강도는 `off | subtle | normal | strong` 4단계다. 기본값은 `normal`. 각 단계는 지속시간·스케일·글로우·빈도를 다르게 소비한다. 값은 기존 모션 토큰을 우선 재사용하고, 부족분만 신설 요청한다(§6).

| 항목 | off | subtle | normal(기본) | strong |
|---|---|---|---|---|
| 배경 플래시 | 없음 | `--color-up/down-flash` | `--color-up/down-flash` | `--color-up/down-flash` |
| 팝 스케일 | 없음 | 없음 | `--effect-pop-scale-normal`(1.06) | `--effect-pop-scale-strong`(1.10) |
| 글로우 | 없음 | 없음 | `--effect-glow-*`(soft) | `--effect-glow-*`(strong) |
| 지속시간 | 0 | `--dur-fast`(120ms) | `--dur-flash`(220ms) | `--dur-base`(200ms) 팝 + 글로우 페이드 |
| 셀 스로틀 | 무관 | 500ms | `--flash-throttle`(300ms) | 200ms |
| 테이프 플래시 | 없음 | 첫 행 1회 | 첫 행 1회 | 첫 행 1회 + 대형 승격 강화 |
| 대형 체결 | 배지(정적)만 | 배지 + 소형 팝 | 배지 + 팝 승격 | 배지 + 팝 승격 + 글로우 버스트 |
| 방향 표식 | 상시 유지 | 상시 유지 | 상시 유지 | 상시 유지 |

- off는 "표식만" 모드다. 모션·플래시·글로우 전부 끄되 색·부호·화살표·값 갱신은 유지한다. reduced-motion과 시각 결과가 유사하나, off는 운영자 선택이고 reduced-motion은 사용자 환경이다(둘 다 정적으로 수렴).
- subtle은 팝·글로우 없이 배경 플래시만. 밀도 높은 화면에서 소음을 줄이는 보수 모드.
- normal은 셀별 300ms throttle(`--flash-throttle` 계약)과 팝·글로우를 함께 쓴다.
- strong은 스케일·글로우를 키우고 throttle을 200ms로 낮춘다. 대형 체결에 글로우 버스트(1회 확장 링)를 더한다.

### 2-3. 자동 스로틀(체결률 기반 밀도 조절)

강도 단계 위에 자동 거버너를 얹는다. 거버너는 마켓별 체결 도착률 r(초당 건수, 클라이언트 EWMA 측정)로 밀도를 낮춘다. "알아서 대충 조절"의 실체다. 관리자 OPS 값에 의존하지 않고 클라이언트가 실측하므로 Sim·Http 양쪽에서 동일하게 동작한다.

| 체결률 r | 거버너 동작 |
|---|---|
| r < 5/s | 선택 단계 그대로. 팝·플래시·테이프 전량 표시 |
| 5 ~ 20/s | rAF 코얼레싱 윈도 120ms로 프레임당 1회 병합. 셀 스로틀 +100ms. 동시 팝 캡 8개 |
| 20 ~ 60/s | 강도 한 단계 강등(strong→normal, normal→subtle). 최신 셀만 팝, 나머지는 값만 갱신. 테이프 배치 append |
| r >= 60/s | 홍수 모드. 개별 팝 off. 패널 방향 히트 틴트를 지속 표시(마지막 우세 방향색 저알파 배경) + 테이프 배치 append. 셀은 값만 갱신 |

- 병합 규칙: rAF 프레임 내 같은 셀의 다중 델타는 최종값 1회로 합쳐 플래시·팝한다. 프레임 간 최소 간격은 셀 스로틀로 보장한다.
- 강등은 시각 결과에만 적용하고 데이터·값 갱신은 항상 실시간이다. 강등 중에도 방향 표식은 유지한다.
- 히트 틴트는 방향 히트(우세 방향)만 표현하며 개별 체결을 표현하지 않는다. 저알파(`--color-up/down-flash`)로 리플로우 없이 배경만 바꾼다.
- 히스테리시스: 상향·하향 임계를 20% 벌려(예: 20/s 강등, 16/s 복귀) 경계에서 깜빡임을 막는다.

구현 반영(v1.1): 거버너는 밴드별로 세 축만 소비한다. 셀 스로틀 가산(밴드1 이상 +100ms, TickCell 소비), 동시 팝 캡(밴드1·2는 8, 홍수 0), 홍수 히트 틴트. rAF 프레임 코얼레싱과 "최신 셀만 팝"은 별도 배치 레이어·셀 간 조정이 필요해 초판 범위에서 제외했다. 강등은 유효 강도 하향(effectiveLevel)으로, 소음 억제는 스로틀 가산·팝 캡·홍수 off로 달성한다. 값 갱신은 강등·홍수와 무관하게 항상 실시간이다.

### 2-4. reduced-motion 대체·접근성

- `prefers-reduced-motion: reduce`이면 팝(transform)·글로우 트랜지션·배경 플래시 트랜지션을 전부 건너뛴다. TickCell.tsx가 이미 matchMedia로 `data-tick` 토글 자체를 스킵하며, 팝·글로우 훅도 같은 게이트를 공유한다.
- 정적 대체: 모션 대신 방향색 텍스트 + ▲▼ + 부호로 정적 강조한다. 대형 체결은 정적 "대형" 배지만 남긴다. 값 갱신은 그대로 반영된다.
- 토큰 킬스위치: 프론트_디자인시스템.md §5의 reduced-motion 블록이 `--dur-*`를 0으로, `.price-cell[data-tick]` 배경을 transparent로 무력화한다. 신규 팝·글로우 CSS도 동일 미디어쿼리에서 transform·box-shadow를 none으로 강제하도록 요청한다(§6).
- 대비: 배지·텍스트는 §6 대비 계약을 따른다. 틴트(`-bg`) 위 소형 텍스트는 `-strong`(700), 흰/기본 surface 위는 `-text`(600). 글로우는 장식이며 정보 전달용 대비 계산 대상이 아니다(텍스트 대비는 글로우 없이도 4.5:1 확보).
- 접근성 라벨: 팝·플래시는 순수 시각이며 `aria-live`로 낭독하지 않는다(시세 tick 미낭독 계약, A-14). 셀·행의 기존 `aria-label`(방향·가격)은 유지한다.
- 색각: 색 + 부호 + 화살표 3중 표기로 적록·청적 색각 사용자도 방향을 구분한다.

### 2-5. 성능

- rAF 코얼레싱: 프레임당 1회 배치 적용. 셀별 마지막 플래시 시각을 기록해 스로틀 미만은 스킵(TickCell 계약 승계).
- 상한: 동시 팝 애니메이션을 캡(기본 8)한다. 초과분은 값만 갱신하고 팝을 생략한다. 시각 품질을 CPU·프레임 예산 아래로 유지한다.
- 리렌더 최소화: 셀 단위 `React.memo` + 안정 key. 효과 상태는 DOM 속성·CSS로 처리하고 React state 갱신을 유발하지 않는다(TickCell가 ref·setAttribute로 처리하는 방식 승계).
- 레이아웃 시프트 0: 팝은 transform scale(합성 단계, 리플로우 없음), 글로우는 box-shadow(레이아웃 무관). 셀은 `overflow: visible`로 확대를 허용하되 컨테이너 폭은 tabular-nums로 고정. 대형 배지는 절대 배치 오버레이.
- 정적 export 무해: 전부 클라이언트 CSS·훅. `window`·`matchMedia` 접근은 마운트 후로 가드(TickCell 패턴). SSR 산출물에 효과 상태를 굽지 않는다.
- 거버너 측정: 체결 도착 간격 EWMA만 유지(상수 메모리). 히스토리 버퍼는 대형 체결 중앙값용 링버퍼(최근 N=64)로 제한한다.

### 2-6. 컴포넌트·토큰

신규·확장 대상. 전부 `components/trade/`·`lib/`에 둔다. 인벤토리 중복을 피하려 기존 원자를 확장한다.

- `TickCell`(확장): 팝 스케일·글로우·강도 인지를 추가한다. props에 강도·대형 여부를 받는다. 신규 셀 원자를 만들지 않는다.
- `useEffectIntensity`(신규 훅, lib): 스토어의 효과 강도 config를 셀렉터로 구독한다. 셀은 이 훅으로 현재 단계를 읽는다.
- `useTradeRateGovernor`(신규 훅, components/trade): 마켓별 체결률 EWMA를 계산해 유효 밀도 단계를 반환한다. 지역 상태(전역 스토어 오염 금지).
- `useLargeTradeThreshold`(신규 훅, components/trade): 마켓별 체결량 롤링 중앙값과 K배 임계를 계산한다.
- `TradesPanel`(확장): 첫 행 플래시 + 대형 배지 오버레이를 추가한다.
- 재사용: PanelCard·PricePill·format.ts·derive.ts·globals.css의 `.price-cell`·`.dir-text` 규칙은 그대로 쓴다.

토큰 소비: 색·글로우·모션은 토큰만 쓴다. 기존 토큰으로 충분한 부분은 신설하지 않는다.

- 재사용: `--color-up/down-flash`(배경 플래시), `--color-up/down`·`-text`·`-strong`(방향 텍스트), `--dur-fast/flash/base`(지속), `--flash-throttle`(셀 스로틀), `--ease-standard/emphasized`(가감속), `--font-micro`(배지).
- 신설 요청(tokens.css 직접 수정 아님, §6에 분리 표기): 팝 스케일 3단계, 방향 글로우 색(라이트·다크), reduced-motion에서 팝·글로우 무력화 규칙.

## 3. 관리자 콘솔 제어 UI

### 3-1. 배치·라우트

- 위치: `/admin/bots`(봇 플릿) 페이지에 "시장 생동감" 섹션을 확장한다. 신규 라우트를 만들지 않는다. 봇 대수·방향 바이어스·자동 균형·효과 강도는 함께 튜닝하는 한 벌이라 한 페이지에 둔다.
- 대안(비채택): 별도 `/admin/liveliness` 라우트. 나눌 만큼 독립적이지 않아 채택하지 않는다.
- 셸 재사용: PanelCard·DataTable·admin ui(PageHeader·PermissionNote·StatTile·HealthPill)·RequestButton·Toast를 재사용한다. 거래 도메인 컴포넌트는 가져오지 않는다(관리자_설계.md §4-1 격리).
- 색 도메인: 봇·효과 제어는 시세 방향(양전 Red·음전 Blue)을 다루므로 시세 도메인 색을 쓴다. 시스템 헬스 색과 섞지 않는다.

### 3-2. 봇 타입별 대수(스케일)

- 컨트롤: 타입별(마켓메이커·테이커·추세·노이즈) 목표 대수 슬라이더 + 숫자 입력. 마켓 선택(전역 또는 마켓별).
- 동작: 목표 대수는 set-point다. 서버가 현재 대수와 목표의 차이를 생성·제거로 수렴한다. 현재 대수·활성 대수를 StatTile로 병기한다.
- 전송: `PUT /admin/v1/sim/scale`(신규, §6). 기존 `POST /admin/v1/sim/bots`(count 증가분)와 `DELETE /admin/v1/sim/bots/{id}`를 대체하지 않고 상위 set-point로 얹는다.
- 게이팅: BOT_OPS 이상. approval 불요(가역, start/stop과 동급). 미충족 시 PermissionNote + 컨트롤 disabled.
- 검증: 타입별 0 ~ 상한(예: 50), 정수. 합계 상한(예: 200)을 넘으면 인라인 에러 + 제출 차단.

### 3-3. 방향 바이어스(양전/음전)

- 컨트롤: 마켓별 목표 net bias 슬라이더. 범위 −1(음전·하락 Blue) ~ +1(양전·상승 Red), 중앙 0(중립).
- 색 규칙: 슬라이더 트랙을 Blue~중립~Red 스펙트럼으로 그리되, 색 단독 금지에 따라 현재값에 부호·화살표·수치를 병기한다(예: "양전 ▲ +0.35", "음전 ▼ −0.20", "중립 0.00"). 값 라벨은 §6 대비 계약(`-text`/`-strong`) 준수.
- 값 표기: net bias는 문자열(예: "0.35", "-0.20"). float 금지 규약(관리자_설계.md §5) 상속. 표시는 방향 부호로 양전·음전을 구분한다.
- 동작: 바이어스는 추세·테이커 봇의 매수·매도 확률을 목표 net으로 편향한다. 실측 net bias(current)를 목표(target)와 함께 표시해 수렴을 확인한다.
- 전송: `PUT /admin/v1/sim/bias`(신규, §6).
- 게이팅: BOT_OPS 이상. approval 불요(가역, 시나리오·rate와 동급). 전량 감사(admin_audit_log). 분류 근거: 완전 시뮬레이션 데모에서 봇이 곧 시장이며 바이어스는 가역·시장 단위 연출 파라미터다. 실행 중 개별 봇 파라미터 변경(`sim.bots.params`)만 2인 승인 유지(백엔드_API_설계.md §6-A·관리자_설계.md §2-1).

### 3-4. 자동 균형(토글 + 강도)

- 컨트롤: 마켓별 자동 균형 토글(on/off) + 강도 슬라이더(0 ~ 1, 문자열).
- 동작: on이면 실측 net이 목표에서 벗어날 때 봇 확률을 강도에 비례해 되돌린다. off이면 목표 bias를 그대로 유지한다.
- 전송: `PUT /admin/v1/sim/bias`의 `autoBalance`·`strength` 필드로 함께 보낸다(별도 엔드포인트 없음).
- 게이팅: BOT_OPS. approval 불요.

### 3-5. 효과 강도

- 컨트롤: `off | subtle | normal | strong` SegmentedTab + "자동(체결률 스로틀)" 토글. 자동 on이면 선택 단계를 상한으로 두고 §2-3 거버너가 하향 조절한다.
- 전송·저장: `PUT /admin/v1/sim/effects`(§6-A) → system_config UI 화이트리스트 키 `ui.trade_flash_intensity`(값 `off|subtle|normal|strong|auto`). 운영자 설정을 서버가 보관하고, 트레이딩 UI가 공개 조회로 읽는다(§4).
- 게이팅: BOT_OPS. approval 불요. 전량 감사. 근거: 표시 전용·가역·비금융 설정이며 봇 튜닝과 함께 조작한다. 정본이 더 엄격한 등급(SUPER)을 원하면 capability 상수 1개만 바꾼다(roles.ts ACTION/CAP 확장).
- 미리보기: 강도 변경 시 관리자 패널 내 축소 프리뷰(모의 셀 3개 팝)로 결과를 즉시 보인다. 실사용 트레이딩 UI 반영은 §4 흐름을 탄다.

### 3-6. 실시간 반영·낙관 UI·검증·에러·감사

- 실시간: 봇 상태는 기존 2초 폴링(bots/page.tsx 패턴) 또는 `WS /admin/v1/ws/sim/telemetry`(백엔드_API_설계.md §6-A)를 재사용한다. 신규 폴링 경로를 만들지 않는다.
- 낙관 UI: 슬라이더·토글은 조작 즉시 로컬 반영(낙관) 후 요청. 실패 시 직전 서버 값으로 롤백 + Toast error. 성공 시 다음 상태 폴에서 확정.
- 검증: 대수 정수·범위, 바이어스 −1~1, 강도 0~1. 위반은 인라인 에러 + 제출 차단(서버도 `invalid_parameter`로 재검증).
- 에러 상태: 세션 없음(`jwt_verification`)·권한 부족(`admin_forbidden`)·서버 오류를 Toast + 컨트롤 상태로 노출한다. 조회 실패는 Skeleton 유지 후 재시도.
- 역할 게이팅: BOT_OPS 미만은 조회만. 컨트롤 disabled + PermissionNote. useCan("BOT_OPS")로 판정(roles.ts: CHAOS_OPS·SUPER가 BOT_OPS 포함).
- 감사 안내: 모든 변경은 admin_audit_log 적재 대상임을 패널에 명시한다. 감사 항목은 `/admin/audit`에서 조회.

### 3-7. AdminApi·세션 소비

- AdminApi(lib/admin/api.ts) 확장 메서드(§6 타입): `setFleetScale(market, targets)`, `setDirectionBias(market, target, autoBalance, strength)`, `getEffectConfig()`, `setEffectConfig(trade_flash)`.
- SimAdminApi·HttpAdminApi 양쪽 구현. Sim은 인메모리 상태에 반영(런타임 외부 의존 0). Http는 `/admin/v1/sim/scale`·`/admin/v1/sim/bias`·`/admin/v1/sim/effects` 호출.
- 세션: 기존 mTLS 유래 단기 세션(AdminSession)을 Bearer로 소비(httpAdmin.ts). 신규 인증 경로 없음. 화면은 AdminApi 인터페이스만 소비하고 fetch·시뮬레이터를 직접 부르지 않는다.

## 4. 데이터 흐름

두 제어를 경로로 분리한다. 봇 파라미터는 관리 API로, 효과 강도는 system_config를 거쳐 트레이딩 UI 읽기로 흐른다.

### 4-1. 봇 파라미터(관리 API)

```
관리자 UI(/admin/bots 시장 생동감)
  → AdminApi.setFleetScale / setDirectionBias
  → [Http] PUT /admin/v1/sim/scale · /admin/v1/sim/bias   (BOT_OPS, 감사)
  → 봇 플릿 상태 변경 → 체결 흐름·방향에 반영
  → GET /admin/v1/sim/status(scale·bias 확장) 폴링/telemetry로 확인
```

- Sim 정합: SimAdminApi가 인메모리 봇 배열의 대수·방향 확률에 반영한다. 트레이딩 화면의 SimEngine(고객 평면)과는 프로세스 내 별개지만, 데모에서 동일 창발 모델을 공유하도록 SimStatus.scale·bias를 노출한다.
- Http 정합: 서버가 봇 플릿에 반영하고 체결이 REST·WS로 트레이딩 UI에 창발한다. UI는 별도 처리 없이 기존 체결 스트림을 받는다.

### 4-2. 효과 강도(system_config → 트레이딩 UI 읽기)

```
관리자 UI  → AdminApi.setEffectConfig(trade_flash)
           → [Http] PUT /admin/v1/sim/effects → system_config['ui.trade_flash_intensity']  (BOT_OPS, 감사)

트레이딩 UI → DataSource.getEffectConfig()                 (공개 조회 스냅샷)
            → useEffectConfigPolling(15초)                 (재조회로 갱신, WS push 없음)
            → store.effectConfig → useEffectIntensity 셀렉터 → TickCell 강도
```

- 쓰기 권위: 관리 평면(system_config). 읽기: 고객 평면 공개 경로. 값은 비민감(표시 강도)이라 공개 조회 허용.
- 읽기 엔드포인트: `GET /api/v1/exchange-config`(§4-A-6) → `{ schema_version, trade_flash }`, `trade_flash ∈ off|subtle|normal|strong|auto`. 실시간 push 채널은 두지 않는다. 갱신은 폴링(useEffectConfigPolling, 기본 15초) 재조회로 반영한다.
- 프론트 내부 표현: 어댑터가 `trade_flash`를 `EffectConfig{mode, level, schema_version}`로 좁힌다. `auto → {mode:auto, level:normal}`(거버너가 관측 강도로 하향), 그 외 열거값 → `{mode:manual, level:값}`. 이 좁힘은 lib/api 어댑터(httpDatasource.coerceEffectConfig)에만 있고 화면은 EffectConfig만 소비한다.
- DataSource 정합:
  - SimDataSource: 공유 저장소(localStorage 키 `exchange.effects`, 값 `{mode, level}`)를 읽기 소스로 둔다. 관리 Sim과 고객 Sim은 별개 싱글턴이라 데모 즉시 반영용이다. 미설정·손상 시 기본값(mode=auto, level=normal). 외부 의존 아님.
  - HttpStompDataSource: `GET /api/v1/exchange-config` REST 조회 + coerceEffectConfig 좁힘. WS 구독 없음.
- 기본값·폴백: config 미수신·조회 실패 시 `mode=auto, level=normal`로 동작한다. 화면은 config 없이도 정상 렌더한다(강도 결정은 항상 안전 기본값 존재).
- 저장 형식(system_config value): 키 `ui.trade_flash_intensity`에 열거 문자열 1개(`"normal"` 등). 문자열 열거값만(정밀도 문제 없음). V5__admin.sql의 system_config 스키마 그대로 사용, 신규 컬럼 불요.

### 4-3. 타입 미러(lib/types.ts·lib/admin/types.ts)

신규 타입(정본 개정 후 추가, §6):

- 고객 평면(lib/types.ts): `EffectLevel = "off"|"subtle"|"normal"|"strong"`, `EffectMode = "auto"|"manual"`, `EffectConfig = { mode, level, schema_version }`, `DEFAULT_EFFECT_CONFIG`. config는 WS 채널이 아니라 공개 조회·폴링이므로 WsMessage·dest 헬퍼는 추가하지 않는다(§4-A-6).
- 관리 평면(lib/admin/types.ts): `FleetScale = { market?: string; targets: Record<BotType, number> }`, `DirectionBias = { market: string; target: string; autoBalance: boolean; strength: string; current: string }`, SimStatus에 `scale: Record<BotType, number>`·`bias: DirectionBias[]` 추가.

## 5. 토큰·CSS 계약(요청 명세)

tokens.css는 본 문서에서 수정하지 않는다. 아래는 디자인시스템 소유자에게 요청하는 신설 항목이다. 승인 전까지 코드는 기존 토큰만 소비한다.

### 5-1. 신설 요청 토큰

```css
/* :root (라이트) 추가 요청 */
--effect-pop-scale-subtle: 1.03;
--effect-pop-scale-normal: 1.06;
--effect-pop-scale-strong: 1.10;
--effect-glow-up:   0 0 0 3px rgba(242,54,69,.28);    /* red-500 #F23645 파생, --color-up-flash와 알파 분리 */
--effect-glow-down: 0 0 0 3px rgba(28,130,232,.28);   /* azure-500 #1C82E8 파생 */
--dur-pop: 220ms;                                     /* 필요 시. 없으면 --dur-flash 재사용 */

/* [data-theme="dark"] 추가 요청 */
--effect-glow-up:   0 0 0 3px rgba(255,93,99,.32);    /* dark --color-up #FF5D63 파생 */
--effect-glow-down: 0 0 0 3px rgba(53,166,255,.32);   /* dark --color-down #35A6FF 파생 */
```

- 근거: 배경 플래시(`--color-up/down-flash`, 알파 0.10~0.16)는 면 틴트용이라 글로우 링으로 부적합하다. 글로우는 더 강한 알파의 box-shadow 값이 필요하다. 팝 스케일은 모션 계약이라 컴포넌트 상수보다 토큰이 일관적이다.
- hex 리터럴은 신설 요청 값이며 tokens.css의 primitive 파생 규칙(§1)을 따른다. 승인 시 tokens.css가 소유하고, 컴포넌트는 var()만 소비한다.

### 5-2. reduced-motion 규칙 확장 요청

프론트_디자인시스템.md §5 reduced-motion 블록에 추가 요청:

```css
@media (prefers-reduced-motion: reduce){
  .price-cell[data-pop]{ transform: none !important; box-shadow: none !important; }
}
```

- 기존 킬스위치는 `.price-cell[data-tick]` 배경만 무력화한다. 팝·글로우용 `data-pop` 속성도 함께 무력화해야 정적 대체가 완성된다.

### 5-3. globals.css 소비 예(구현 시)

```css
/* 팝 셀. 강도·방향은 data 속성, throttle·중첩취소는 TickCell 훅 */
.price-cell[data-pop]{ transition: transform var(--dur-pop) var(--ease-emphasized), box-shadow var(--dur-pop) var(--ease-standard); }
.price-cell[data-pop="up"]{ transform: scale(var(--effect-pop-scale-normal)); box-shadow: var(--effect-glow-up); }
.price-cell[data-pop="down"]{ transform: scale(var(--effect-pop-scale-normal)); box-shadow: var(--effect-glow-down); }
.price-cell[data-pop][data-strong="true"]{ transform: scale(var(--effect-pop-scale-strong)); }
```

## 7. 테스트·리스크

### 7-1. 테스트

- 모션 접근성: reduced-motion 강제 시 transform·box-shadow·transition 미적용 확인. off 단계와 시각 등가. 값 갱신·방향 표식 유지 확인.
- 색 규칙 회귀: 팝·플래시·배지에 green 부재. 방향은 항상 색 + 부호 + 화살표 3중. 틴트 위 소형 텍스트 `-strong`(700). 하드코딩 hex lint 통과(코인 브랜드색 예외만).
- 성능 상한: 고체결률(60/s 이상) 주입 시 동시 팝 캡·홍수 모드 진입 확인. 드롭 프레임·리렌더 수 측정. 레이아웃 시프트 0(CLS) 확인.
- 거버너: 임계 경계에서 히스테리시스로 깜빡임 없음. 강등 중 값·방향 표식 실시간 유지.
- 강도 config 흐름: 관리자 설정 → system_config → 트레이딩 UI 반영(Sim·Http 양쪽). config 미수신 시 normal 폴백. 권한·검증·감사 적재.
- 정적 export: `npm run build` 통과. SSR 산출물에 window·matchMedia 접근 부재. generateStaticParams 보존.
