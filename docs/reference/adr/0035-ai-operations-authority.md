# ADR 0035. AI 운영 조치는 수동·자동 두 모드와 허용 목록 안에서만 한다

- 상태: 채택(사용자 결정 2026-09-24). 규칙과 1단계 화면·시뮬레이터를 정한 결정이며 서버 정책 엔진과 AI 판단 서비스는 2단계에서 구현한다.
- 날짜: 2026-09-24
- 대체 범위: [ADR 0027](0027-msp-operations-and-autoscaling.md)에서 AI를 근거 정리와 보고에 한정한 원칙과, "AI에 확장 대수 변경·서버 재시작·DB 승격 권한을 주지 않는다" 가운데 확장 대수 변경 부분. 서버 재시작과 DB 승격을 AI에 맡기지 않는다는 부분은 아래 금지 목록으로 그대로 유지한다.
- 근거: 사용자가 관리 콘솔의 종합 관제를 MSP AI 관제센터로 바꾸기로 하면서 AI의 조치 권한을 수동 모드와 자동 모드 두 가지로, 규칙은 엄격하게 두도록 정했다. 아래 수치 가운데 사용자가 정하지 않은 값은 '초기값'으로 표시했고 운영 전에 다시 정한다.

## 배경

0027을 정할 때 AI는 일일·장애 보고의 근거를 정리하는 역할이었고, 확장은 AWS 지표 정책이, 운영 변경은 사람이 맡았다. 이후 관리 콘솔을 Grafana로 보는 것과 관제센터에서 판단·조치·기록하는 것으로 나누면서, 관제센터에서 AI가 상황을 판단하고 조치안을 내는 화면이 필요해졌다. 조치안을 운영자가 매번 승인하는 방식만 두면 야간처럼 사람이 바로 보지 못하는 시간에는 AWS 정책 이상의 대응을 할 수 없다. 반대로 AI가 제한 없이 실행하면 DB 승격이나 보안 설정처럼 되돌리기 어려운 조치까지 열린다.

사용자는 두 모드를 두고, 자동 모드에서도 AI가 할 수 있는 일을 짧은 허용 목록과 한도로 묶고, 어느 모드에서도 하지 않는 일을 금지 목록으로 따로 적도록 정했다.

## 결정

### 두 모드

수동 모드가 기본이다. AI는 상황 판단과 근거, 원인 가설, 허용 목록 안의 조치안까지만 만든다. 실행은 운영자가 조치 카드에서 승인할 때 일어난다. 임계값을 바꾸는 조치안은 [1인 승인](0019-single-operator-approval.md) 티켓(`ops.threshold.set`)을 거친다.

자동 모드에서는 허용 목록 조치를 AI가 한도 안에서 실행한다. 자동 모드를 켜려면 확인 대화상자에서 사유와 유효 시간을 적고 1인 승인 티켓(`ops.ai.auto`)을 거친다. 유효 시간은 최대 8시간이고 화면에 남은 시간을 보이며, 만료되면 수동 모드로 돌아간다. 끄기(`즉시 끄기`)는 승인 없이 누구나 언제든 할 수 있고 자동 모드인 동안 늘 보인다.

자동 모드인 동안 화면 위쪽에 오늘 자동 조치 수와 상한, 조치 종류별 쿨다운 남은 시간, 조치 뒤 관찰 창(5분)을 보인다. 자동으로 실행한 조치는 '자동 실행됨 · 되돌리기', 관찰 창에서 악화해 되돌린 조치는 '자동 되돌림 · 수동 모드로 전환'으로 적는다. 금지 목록의 조치는 어느 모드에서도 조치 카드로 나타나지 않는다.

### 허용 목록

| 조치 | 범위와 한도 |
|---|---|
| 조회 노드 증감 | 최소~최대(현재 2~3대) 안에서 1회 ±1. 쿨다운 10분 |
| 임계값 변경 | 항목별 허용 범위 안. 1회 변경폭 제한(항목별, 초기값). 쿨다운 30분. 항목당 하루 상한(초기값 2회) |
| 경보 보류 | 최대 30분. 장애 등급 경보는 불가. 같은 경보를 잇달아 보류하지 않음 |
| 시장 봇 부하 줄임 | 줄이는 방향만. 1회 최대 절반, 쿨다운 10분(초기값) |
| 백업 즉시 실행 | Databasus 백업 실행. 하루 1회, 저장 디스크 여유 30% 이상(초기값) |

### 금지 목록

어느 모드에서도 AI가 실행하지 않는다.

1. DB 승격, 페일오버, 복제 재구성
2. 매칭 리더 전환, 리스 조작, 파티션 재배정
3. 데이터·로그·백업 삭제, 스키마 변경
4. 보안 그룹, IAM, 네트워크, 인증서, 비밀 값 변경
5. 앱·DB 재시작과 중지
6. 회원·자산·주문·출금 조작
7. 비용이 드는 자원 생성(ASG 최대 대수를 넘는 증설 포함)
8. 자기 권한 변경(자동 모드 켜기, 한도 늘리기)

DB 자동 전환 도구를 도입하더라도 전환 판단은 그 도구의 규칙이 하며 AI가 하지 않는다.

### 자동 실행 전제 조건

자동 모드에서 한 조치를 실행하려면 아래를 모두 만족해야 한다. 하나라도 어긋나면 조치안을 카드로만 남기고 이유를 적는다.

1. 판단 근거가 된 지표가 60초 안에 수집된 것이다. 미수집이면 실행하지 않는다.
2. 확신도가 기준(초기값 80%) 이상이고 같은 판단이 두 번 연속 나왔다.
3. 한 번에 한 조치만 한다. 조치 뒤 5분 관찰 창이 끝나야 다음 조치를 한다.
4. 하루 자동 조치 상한(초기값 5회)을 넘지 않는다. 상한에 닿으면 수동 모드로 바꾸고 Teams로 알린다.
5. 관찰 창 안에서 지표가 악화하면 자동으로 되돌리고 수동 모드로 바꾸며 알린다.
6. AI가 응답하지 않거나 출력 형식이 맞지 않으면 조치하지 않는다. 기존 경보와 AWS 지표 정책은 그대로 동작한다.

### 두 층 실행

AI는 조치 요청만 만든다. 허용 목록, 한도, 쿨다운, 전제 조건은 AI가 아닌 서버 정책 엔진이 다시 검사한 뒤 실행한다. AI는 최소 권한의 전용 운영자 계정으로 요청하고, 모든 조치와 되돌림은 감사 기록에 남으며 Teams 알림에 되돌리기 링크를 싣는다. AWS에서 AI는 조정 정책의 목표값과 임계만 조정하고 희망 대수를 같은 조치에서 함께 바꾸지 않는다. 조회 계층의 기본 증감은 AWS 지표 정책이 계속 맡는다.

### 데이터

판단 모델은 로컬 모델(DGX Spark)을 우선한다. 프롬프트에 비밀 값과 개인정보를 넣지 않고, 출력은 JSON 스키마를 강제해 어긋나면 조치하지 않는다. 기존 일일·장애 보고 경로(0027)는 이 결정과 별개로 유지한다.

### 구현 단계

1단계는 관리 콘솔 관제센터 화면과 브라우저 시뮬레이터다. 규칙과 초기값은 [웹의 정책 정의](../../../web/lib/admin/aiPolicy.ts), 흉내 낸 판단과 자동 실행은 [시뮬레이터](../../../web/lib/admin/opsSim.ts)에 있다. 시뮬레이터는 모델을 부르지 않는 규칙 판단이고 서버 정책 엔진이 아니다. 실제 데이터 원천(http)에서는 AI 패널이 'AI 연결 전'만 보이고 자동 전환은 '서버 연결 전'으로 막혀 있다. 2단계에서 서버 정책 엔진, AI 판단 서비스, 임계값 레지스트리, 승인 원장의 두 액션, 감사와 Teams 되돌리기 링크를 구현한다. 계약 초안은 [관리자 설계 4-4](../product/관리자_설계.md)에 있다.

## 근거와 한계

모드를 둘로 나누면 평시에는 사람이 모든 실행을 승인하고, 사람이 자리를 비우는 시간에만 사유와 유효 시간을 남기고 자동 실행을 연다. 허용 목록은 되돌릴 수 있고 영향이 조회 계층·경보·봇 부하·백업에 그치는 조치로 한정했다. 금지 목록은 되돌리기 어렵거나 데이터·자산·보안에 닿는 조치이며 [ADR 0027](0027-msp-operations-and-autoscaling.md)의 서버 재시작·DB 승격 금지를 그대로 이어받는다.

AI가 실행 여부를 스스로 판정하지 않게 하려고 두 층으로 나눴다. 다만 지금은 두 층 중 어느 것도 서버에 없다. 1단계의 규칙 검사는 브라우저 시뮬레이터 안에 있어 우회를 막는 장치가 아니며, 이 화면과 시험은 규칙이 화면에서 어떻게 보이고 흐르는지만 확인한다. 초기값(확신도 기준, 하루 상한, 항목별 변경폭과 하루 횟수, 봇 부하 쿨다운, 백업 디스크 여유)은 측정 근거 없이 정한 값이다.

## 대안

AI를 보고 전용으로 두는 0027의 원칙은 사용자가 두 모드를 정하면서 대체했다. 그 원칙으로는 관제센터가 조치안을 내고 승인까지 잇는 흐름을 만들 수 없다. 아래 두 안은 이 문서를 쓰며 비교한 것이고 사용자가 따로 검토한 안은 아니다. 자동 모드만 두거나 허용 목록 없이 확신도만으로 실행하는 안은 되돌리기 어려운 조치를 막지 못한다. 조치 판단을 고정 규칙으로만 하는 안은 AWS 지표 정책이 이미 하는 일과 겹쳐 관제센터에서 더할 것이 없다.

## 영향

[0027](0027-msp-operations-and-autoscaling.md) 머리에 대체 범위를 적는다. [0099](0099-current-architecture.md)의 운영 보고 문단과 관리 콘솔 문단, ADR 표를 같은 변경에서 고친다. 화면 규칙은 [관리자 설계 4-4](../product/관리자_설계.md)와 [디자인 시스템 §12-9](../contracts/프론트_디자인시스템.md)가 같은 용어로 싣는다. 저장소 공통 규칙(AGENTS.md)의 "AI가 운영 조치를 직접 실행하지 않는다" 문장은 이 결정과 어긋나므로, 사용자가 확정한 문장으로 바꾸는 일을 통합 단계에서 한다. 이 변경은 저장소의 설계와 화면이며 학교 AWS의 운영 상태를 바꾸지 않는다.
