# ADR 0035. AI 운영 조치는 수동·자동 두 모드와 허용 목록 안에서만 한다

- 상태: 채택(사용자 결정 2026-09-24, 보강 2026-09-25). 규칙과 1단계 화면·시뮬레이터를 정한 결정이며 서버 정책 엔진과 AI 판단 서비스는 2단계에서 구현한다. 2026-09-25 사용자 결정으로 AI 즉시 정지, 자동 모드 1회 활성당 상한, 운영자의 한도 변경을 더하고 한도 수치를 확정했다.
- 날짜: 2026-09-24(보강 2026-09-25)
- 대체 범위: [ADR 0027](0027-msp-operations-and-autoscaling.md)에서 AI를 근거 정리와 보고에 한정한 원칙과, "AI에 확장 대수 변경·서버 재시작·DB 승격 권한을 주지 않는다" 가운데 확장 대수 변경 부분. 서버 재시작과 DB 승격을 AI에 맡기지 않는다는 부분은 아래 금지 목록으로 그대로 유지한다.
- 근거: 사용자가 관리 콘솔의 종합 관제를 MSP AI 관제센터로 바꾸기로 하면서 AI의 조치 권한을 수동 모드와 자동 모드 두 가지로, 규칙은 엄격하게 두도록 정했다. 한도 수치(확신도 기준, 자동 조치 상한, 임계값 항목당 횟수, 봇 부하 쿨다운, 백업 즉시 실행 디스크 여유, 임계값 아홉 항목의 초기값·허용 범위·AI 1회 변경폭, 자동 유효 시간 선택지)는 2026-09-25 사용자가 AI 권장값을 채택해 확정했다. 아래에서 '사용자 확정'은 이 결정을, 'AI 선택'과 'AI 해석'은 사용자 결정의 빈 곳을 이 문서가 채운 부분을 뜻한다.

## 배경

0027을 정할 때 AI는 일일·장애 보고의 근거를 정리하는 역할이었고, 확장은 AWS 지표 정책이, 운영 변경은 사람이 맡았다. 이후 관리 콘솔을 Grafana로 보는 것과 관제센터에서 판단·조치·기록하는 것으로 나누면서, 관제센터에서 AI가 상황을 판단하고 조치안을 내는 화면이 필요해졌다. 조치안을 운영자가 매번 승인하는 방식만 두면 야간처럼 사람이 바로 보지 못하는 시간에는 AWS 정책 이상의 대응을 할 수 없다. 반대로 AI가 제한 없이 실행하면 DB 승격이나 보안 설정처럼 되돌리기 어려운 조치까지 열린다.

사용자는 두 모드를 두고, 자동 모드에서도 AI가 할 수 있는 일을 짧은 허용 목록과 한도로 묶고, 어느 모드에서도 하지 않는 일을 금지 목록으로 따로 적도록 정했다.

## 결정

### 두 모드

수동 모드가 기본이다. AI는 상황 판단과 근거, 원인 가설, 허용 목록 안의 조치안까지만 만든다. 실행은 운영자가 조치 카드에서 승인할 때 일어난다. 임계값을 바꾸는 조치안은 [1인 승인](0019-single-operator-approval.md) 티켓(`ops.threshold.set`)을 거친다.

자동 모드에서는 허용 목록 조치를 AI가 한도 안에서 실행한다. 자동 모드를 켜려면 확인 대화상자에서 사유와 유효 시간을 적고 1인 승인 티켓(`ops.ai.auto`)을 거친다. 유효 시간은 1·2·4·8시간 가운데 고르고(사용자 확정) 최대 8시간이며, 화면에 남은 시간을 보이고 만료되면 수동 모드로 돌아간다. 자동에서 수동으로 돌아가는 것은 승인 없이 세션이 있는 운영자면 언제든 할 수 있다.

자동 모드인 동안 화면 위쪽에 이번 자동 모드의 조치 수와 상한, 조치 종류별 쿨다운 남은 시간, 조치 뒤 관찰 창(5분)을 보인다. 자동으로 실행한 조치는 '자동 실행됨 · 되돌리기'로 적는다. 관찰 창에서 악화해 되돌린 조치는 '자동 되돌림'과 함께 되돌리며 실제로 한 일(예: 조회 노드 −1을 무르는 조회 노드 +1)과 악화 이유를 적고, 자동 모드였으면 수동으로 바뀐다. 금지 목록의 조치는 어느 모드에서도 조치 카드로 나타나지 않는다.

### AI 즉시 정지

'AI 즉시 정지'는 자동 모드를 끄는 스위치에 그치지 않고 수동·자동 두 모드에서 AI를 멈추는 정지 장치다(사용자 결정 2026-09-25: 즉시 끄기는 수동 모드에서도 늘 보여야 한다. 두 모드에 쓰는 정지로 넓힌 것은 AI 해석이다). 버튼은 두 모드에서 늘 보이고 승인 없이 세션이 있는 운영자면 누구나 누른다.

정지하면 자동 모드가 곧바로 풀리고 AI는 새 판단과 조치안을 내지 않는다. 대기 중이던 조치안은 '정지로 만료'되어 승인할 수 없다. 정지 전에 자동으로 실행한 조치의 관찰 창은 끝까지 보고, 그 안에서 악화하면 자동으로 되돌린다. 되돌림은 조치를 무르는 안전 방향이라 정지 중에도 허용한다. 경보와 AWS 지표 정책은 AI와 무관하게 그대로 동작한다.

재개는 사유를 적어 수동 모드로만 한다. 승인 티켓은 없고, 자동 모드는 재개 뒤 다시 `ops.ai.auto` 승인을 거쳐 켠다. 재개할 수 있는 역할은 조치안 승인과 같은 총괄(SUPER)로 두었다(AI 선택). 정지와 재개는 누가 언제 했는지와 사유가 감사 로그와 사건 타임라인에 남는다. 정지 중에는 모드 줄이 주의 모양(▲, 주의 면)과 'AI 정지 중' 문구로 바뀌고 'AI 재개'가 선다.

### 허용 목록

| 조치 | 범위와 한도 |
|---|---|
| 조회 노드 증감 | 최소~최대(현재 2~3대) 안에서 1회 ±1. 쿨다운 10분 |
| 임계값 변경 | 항목별 허용 범위 안. 1회 변경폭 제한(항목별). 쿨다운 30분. 자동 모드 1회 활성당 항목별 2회(사용자 확정) |
| 경보 보류 | 최대 30분. 장애 등급 경보는 불가. 같은 경보를 잇달아 보류하지 않음 |
| 시장 봇 부하 줄임 | 줄이는 방향만. 1회 최대 절반, 쿨다운 10분(사용자 확정) |
| 백업 즉시 실행 | Databasus 백업 실행. 하루 1회, 저장 디스크 여유 30% 이상(사용자 확정) |

### 금지 목록

어느 모드에서도 AI가 실행하지 않는다.

1. DB 승격, 페일오버, 복제 재구성
2. 매칭 리더 전환, 리스 조작, 파티션 재배정
3. 데이터·로그·백업 삭제, 스키마 변경
4. 보안 그룹, IAM, 네트워크, 인증서, 비밀 값 변경
5. 앱·DB 재시작과 중지
6. 회원·자산·주문·출금 조작
7. 비용이 드는 자원 생성(ASG 최대 대수를 넘는 증설 포함)
8. 자기 권한 변경(자동 모드 켜기, 한도 늘리기)

DB 자동 전환 도구를 도입하더라도 전환 판단은 그 도구의 규칙이 하며 AI가 하지 않는다.

### 자동 실행 전제 조건

자동 모드에서 한 조치를 실행하려면 아래를 모두 만족해야 한다. 하나라도 어긋나면 조치안을 카드로만 남기고 이유를 적는다.

1. 판단 근거가 된 지표가 60초 안에 수집된 것이다. 미수집이면 실행하지 않는다.
2. 확신도가 기준(80%, 사용자 확정) 이상이고 같은 판단이 두 번 연속 나왔다.
3. 한 번에 한 조치만 한다. 조치 뒤 5분 관찰 창이 끝나야 다음 조치를 한다.
4. 자동 모드 1회 활성당 자동 조치 상한(5회, 사용자 확정)을 넘지 않는다. 상한에 닿으면 수동 모드로 바꾸고 Teams로 알린다.
5. 관찰 창 안에서 지표가 악화하면 자동으로 되돌리고 수동 모드로 바꾸며 알린다.
6. AI가 응답하지 않거나 출력 형식이 맞지 않으면 조치하지 않는다. 기존 경보와 AWS 지표 정책은 그대로 동작한다.

### 횟수 초기화와 한도 변경

자동 조치 상한과 임계값 항목당 횟수는 하루가 아니라 자동 모드 1회 활성(최대 8시간)마다 센다. 수동에서 자동으로 다시 켜면 두 횟수는 0부터 다시 센다(사용자 결정 2026-09-25). 끄고 다시 켜서 횟수를 비우려면 매번 `ops.ai.auto` 승인 티켓과 사유를 거치고 감사에 남으므로 우회가 통제된다. 조치 종류별 쿨다운(10분·30분)과 5분 관찰 창은 시스템을 안정시키려는 장치라 모드와 무관하게 남고 초기화하지 않는다. 백업 즉시 실행의 하루 1회는 운영자 실행과 함께 세는 날짜 기준 한도라 그대로 둔다.

운영자는 확신도 기준, 자동 조치 상한, 임계값 항목당 횟수, 봇 부하 쿨다운, 백업 즉시 실행의 디스크 여유 조건을 화면에서 바꿀 수 있다(사용자 결정 2026-09-25). 변경은 1인 승인 티켓(`ops.ai.limits`)을 거치고 사유가 필수이며, 감사와 사건 타임라인에 남고, 이력에서 같은 승인으로 되돌린다. 값은 코드에 고정한 하드 범위 안에서만 받고 범위 밖의 값은 입력 단계에서 막는다(AI 선택).

| 한도 | 확정값 | 하드 범위 | 좁히는 방향 |
|---|---|---|---|
| 확신도 기준 | 80% | 70~95% | 올림 |
| 자동 조치 상한(활성 1회당) | 5회 | 1~10회 | 내림 |
| 임계값 항목당 자동 변경(활성 1회당) | 2회 | 1~3회 | 내림 |
| 봇 부하 줄임 쿨다운 | 10분 | 5~60분 | 늘림 |
| 백업 즉시 실행 디스크 여유 | 30% | 20~50% | 올림 |

자동 모드가 켜져 있는 동안 AI 권한을 좁히는 변경은 곧바로 적용하고, 넓히는 변경은 지금 자동 모드가 끝난 뒤(다음 활성부터) 적용한다(AI 선택, 안전 방향). 사용자는 이를 '낮추는 변경은 즉시, 높이는 변경은 다음 활성부터'로 적었고, 확신도 기준·쿨다운·디스크 여유처럼 값을 올려야 좁아지는 항목에는 그 방향을 거꾸로 읽었다(AI 해석). 자동 모드가 꺼져 있으면 모든 변경을 곧바로 적용한다. 상한을 이번 자동 모드에서 이미 쓴 횟수 이하로 낮추면 곧바로 수동으로 바뀐다. AI는 한도를 바꿀 수 없다(금지 목록 8).

### 두 층 실행

AI는 조치 요청만 만든다. 허용 목록, 한도, 쿨다운, 전제 조건은 AI가 아닌 서버 정책 엔진이 다시 검사한 뒤 실행한다. AI는 최소 권한의 전용 운영자 계정으로 요청하고, 모든 조치와 되돌림은 감사 기록에 남으며 Teams 알림에 되돌리기 링크를 싣는다. AWS에서 AI는 조정 정책의 목표값과 임계만 조정하고 희망 대수를 같은 조치에서 함께 바꾸지 않는다. 조회 계층의 기본 증감은 AWS 지표 정책이 계속 맡는다.

### 데이터

판단 모델은 로컬 모델(DGX Spark)을 우선한다. 프롬프트에 비밀 값과 개인정보를 넣지 않고, 출력은 JSON 스키마를 강제해 어긋나면 조치하지 않는다. 기존 일일·장애 보고 경로(0027)는 이 결정과 별개로 유지한다.

### 구현 단계

1단계는 관리 콘솔 관제센터 화면과 브라우저 시뮬레이터다. 규칙과 확정 한도는 [웹의 정책 정의](../../../web/lib/admin/aiPolicy.ts), 흉내 낸 판단과 자동 실행, AI 즉시 정지와 한도 변경은 [시뮬레이터](../../../web/lib/admin/opsSim.ts)에 있다. 시뮬레이터는 모델을 부르지 않는 규칙 판단이고 서버 정책 엔진이 아니다. 실제 데이터 원천(http)에서는 AI 패널이 'AI 연결 전'만 보이고, 자동 전환은 막혀 있으며, 'AI 즉시 정지'는 보이되 '서버 정책 엔진 연결 전'으로 비활성이다. 2단계에서 서버 정책 엔진, AI 판단 서비스, 임계값 레지스트리, 승인 원장의 세 액션(`ops.threshold.set`, `ops.ai.auto`, `ops.ai.limits`), 정지·재개와 한도 API, 감사와 Teams 되돌리기 링크를 구현한다. 계약 초안은 [관리자 설계 4-4](../product/관리자_설계.md)에 있다.

## 근거와 한계

모드를 둘로 나누면 평시에는 사람이 모든 실행을 승인하고, 사람이 자리를 비우는 시간에만 사유와 유효 시간을 남기고 자동 실행을 연다. 허용 목록은 되돌릴 수 있고 영향이 조회 계층·경보·봇 부하·백업에 그치는 조치로 한정했다. 금지 목록은 되돌리기 어렵거나 데이터·자산·보안에 닿는 조치이며 [ADR 0027](0027-msp-operations-and-autoscaling.md)의 서버 재시작·DB 승격 금지를 그대로 이어받는다. 정지 장치를 두 모드에 두면 수동 모드에서 AI 판단이 틀리게 보일 때도 조치안이 쌓이는 것을 곧바로 멈출 수 있다.

AI가 실행 여부를 스스로 판정하지 않게 하려고 두 층으로 나눴다. 다만 지금은 두 층 중 어느 것도 서버에 없다. 1단계의 규칙 검사는 브라우저 시뮬레이터 안에 있어 우회를 막는 장치가 아니며, 이 화면과 시험은 규칙이 화면에서 어떻게 보이고 흐르는지만 확인한다. 한도 수치는 사용자가 AI 권장값을 채택해 확정했지만 측정으로 정한 값은 아니다. 하드 범위도 측정 근거 없이 AI가 고른 값이다.

## 대안

AI를 보고 전용으로 두는 0027의 원칙은 사용자가 두 모드를 정하면서 대체했다. 그 원칙으로는 관제센터가 조치안을 내고 승인까지 잇는 흐름을 만들 수 없다. 아래 두 안은 이 문서를 쓰며 비교한 것이고 사용자가 따로 검토한 안은 아니다. 자동 모드만 두거나 허용 목록 없이 확신도만으로 실행하는 안은 되돌리기 어려운 조치를 막지 못한다. 조치 판단을 고정 규칙으로만 하는 안은 AWS 지표 정책이 이미 하는 일과 겹쳐 관제센터에서 더할 것이 없다.

## 영향

[0027](0027-msp-operations-and-autoscaling.md) 머리에 대체 범위를 적는다. [0099](0099-current-architecture.md)의 운영 보고 문단과 관리 콘솔 문단, ADR 표를 같은 변경에서 고친다. 화면 규칙은 [관리자 설계 4-4](../product/관리자_설계.md)와 [디자인 시스템 §12-9](../contracts/프론트_디자인시스템.md)가 같은 용어로 싣는다. 저장소 공통 규칙(AGENTS.md)의 AI 조치 문장은 2026-09-25 사용자가 확정한 문장("ASG 기본 제어는 AWS 지표 정책이 맡는다. AI 운영 조치는 이 결정의 수동·자동 모드와 허용 목록·한도 안에서만 하며, 금지 목록의 조치는 어느 모드에서도 AI가 실행하지 않는다")으로 바꿨다. 이 변경은 저장소의 설계와 화면이며 학교 AWS의 운영 상태를 바꾸지 않는다.
