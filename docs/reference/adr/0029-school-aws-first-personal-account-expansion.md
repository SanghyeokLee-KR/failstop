# ADR 0029. 학교 EC2에서 먼저 검증하고 개인 계정에서 보강한다

- 상태: 채택. 실행 순서와 환경 제약을 정한 결정이며 배포 완료를 뜻하지 않는다.
- 날짜: 2026-09-19
- 근거: 사용자가 전달한 학교 AWS 제한·EC2 생성 안내와 학교 계정 선행, 10월 초 개인 계정 보강 지시. 2026-09-19 [학교 안내 원문](https://rowan-cupboard-1fe.notion.site/AWS-Management-Console-Credentials-AIKOPO-Detailed-3dd2156ceb5f8096a9cbf02253b18f2a)을 직접 확인했다. 자격증명 표는 저장하지 않는다.
- 대체 범위: ADR 0028의 VM 선행 조건, ADR 0010의 학교 환경 규격·배포 방식, ADR 0020의 학교 환경 NAT 사용.

## 배경

학교 계정은 사용할 수 있는 네트워크와 인스턴스 규격이 제한돼 있다. 기존 보고본을 그대로 구축할 수 있다고 가정하지 않고, 허용된 범위에서 Linux 운영과 서비스 검증을 먼저 진행한다. 별도 VM을 준비하는 순서는 현재 필수 단계에서 제외한다. Linux를 직접 설치·설정하고 진단하는 목적은 유지한다.

## 결정

개발팀의 Docker 검증 결과와 실행 조건을 확인한 뒤 학교 EC2에서 인프라 실습을 시작한다. 앱, DB primary, DB standby, 관측은 처음부터 서로 다른 인스턴스에 배치한다. 먼저 생성한 한 대는 첫 앱 노드이며 이 노드에서 계정·권한·서비스·로그·디스크·네트워크를 확인한다. 전체 스택을 먼저 넣고 사용량을 보고 분리하는 순서는 채택하지 않는다. DB 복구 검증에는 서로 다른 호스트의 primary와 standby가 필요하다. 앱 한 대의 기동 성공을 고가용성 검증으로 기록하지 않는다.

2026-09-19 사용자 정정에 따라 '한 대에서 시작한 뒤 분리'라는 이전 문구를 바로잡았다. 학교 제약은 규격·네트워크·권한의 변경이며 기존 역할별 인스턴스 분리를 폐기하는 근거가 아니다. [0099의 역할별 배치](0099-current-architecture.md#역할별-인스턴스-배치)를 공통 기준으로 삼는다.

학교 환경에서 가능한 구축과 검증을 진행한 뒤, 2026년 10월 초 개인 AWS 계정에 재배포해 제한됐던 부분을 보강한다. 이는 실행 계획이며 완료일이나 비용을 보장하는 약속은 아니다. 학교에서 막힌 항목은 미검증으로 남기고 개인 계정에서 실제 검증한 뒤 완료를 판단한다.

앱·DB·관측 도구는 Linux에 직접 설치하고 OS 서비스로 운영한다. 첫 수행은 명령어와 결과를 하나씩 확인하고 이후 반복 절차를 자동화한다. Docker는 필요한 항목에만 이유와 범위를 기록한다. 기존 Compose는 버전·환경변수·포트·데이터·기동 조건을 확인할 자료로 보존한다. 직접 설치 절차와 서비스 정의는 별도로 검증해야 한다.

## 학교 계정에서 지킬 조건

아래는 사용자가 전달한 안내의 조건이다. 실제 계정 권한이나 서비스 할당량을 확인한 결과와 구분한다.

| 항목 | 적용 조건 |
|---|---|
| 네트워크 | 기존 Default VPC와 Public Subnet을 사용한다. Private Subnet·NAT Gateway·VPC Endpoint를 새로 구성하지 않는다. 기존 Internet Gateway와 라우팅을 임의로 삭제하거나 바꾸지 않는다. |
| EC2 | t3.small 이하, gp3 스토리지 50GiB 이하. 첫 앱 노드는 t3.small·gp3 20GiB다. 사용자가 2026-09-19에 DB primary와 standby를 각각 암호화 gp3 50GiB로 지정했다. 생성 완료 규격은 로드맵과 증거에서 확인한다. |
| CPU와 OS | t3는 x86_64다. Graviton ARM64 전용 산출물을 그대로 사용하지 않는다. 첫 서버 생성 후 기존 Rocky 계획과의 차이를 설명했고 사용자는 학교 실습에서 Amazon Linux 2023을 그대로 사용하기로 확정했다. 이는 학교의 Rocky 금지 조건이 아닌 사용자 선택이다. 이후 생성할 공식 AMI도 출처·유효성·버전·아키텍처를 확인한다. |
| 보안 그룹 | 별도 보안 그룹 화면에서 인바운드 없이 만든 뒤 자동 username 태그가 붙었는지 확인하고 필요한 규칙만 추가한다. EC2 생성 화면에서는 기존 보안 그룹을 선택한다. 안내상 기존 규칙 수정이 제한되므로 저장 전에 검토한다. DB·관리 포트를 전체 인터넷에 개방하지 않는다. |
| 역할과 접속 | EC2는 기존 SafeInstanceProfile-{username}, 기타 서비스는 SafeRole-{username}을 사용한다. 연결 권한과 SSM 조건은 실제 확인한다. Access Key 발급이나 IAM 사용자·역할 생성은 하지 않는다. |
| 도메인과 TLS | Route 53·ACM을 사용하지 않는다. CloudFront를 사용할 수 있으면 기본 도메인을 검토한다. 브라우저 구간 HTTPS와 원본 서버 구간 암호화는 구분한다. |
| 배포와 관리 | 학교 안내에 따라 수동 배포한다. AWS Budgets·Cost Explorer·CloudTrail의 계정 전체 설정은 운영자 영역이며 변경하지 않는다. CloudWatch 사용 가능 범위도 실제 확인한다. |
| 추가 서비스 | 안내의 기본 제공 목록은 EC2·RDS·S3·Bedrock이다. S3 버킷 이름은 본인 IAM username으로 시작해야 한다. 실제 동작별 권한은 확인해야 하며 ALB·ASG·시작 템플릿·CloudFront도 허용을 단정하지 않는다. RDS 허용 안내가 자체 운영 PostgreSQL 선택을 바꾸지는 않는다. |

50GiB는 디스크 용량 조건이다. 메모리 50GB나 EC2 50대라는 뜻이 아니며, 계정 전체 EBS 할당량·노드 수·추가 볼륨 허용 범위까지 확인한 것도 아니다. 첫 앱 노드는 20GiB로 시작한다. DB와 관측의 디스크·메모리는 각 전용 인스턴스에서 산정하고 측정한다. 비용이나 권한 때문에 배치 변경이 필요하면 사용자와 변경 범위를 정하며 앱 노드에 임의로 합치지 않는다.

## 개인 계정으로 옮길 때

계정을 합치거나 크레딧을 합산하지 않고 학교와 개인 환경을 독립적으로 운영한다. 운영 도중 학교 앱과 개인 DB를 나누어 배치하는 방식도 기본안으로 삼지 않는다. 개인 계정의 잔액·만료일·권한·규격과 견적을 확인한 뒤 제한됐던 사설 네트워크·NAT·도메인 등의 적용 범위를 정한다. 기존 도면의 모든 자원을 반드시 생성한다는 뜻은 아니다.

같은 코드 버전과 설정 항목, 패키지 버전, 검증 가능한 백업·복원 절차로 재배포한다. 계정별 역할·주소·비밀 설정은 새 환경에 맞춰 준비한다. 학교 계정의 데이터나 AMI를 외부로 반출할 때는 학교 정책과 소유권을 먼저 확인한다. 이전 성공은 새 계정의 접속·거래·관측·복원 시험으로 판단한다.

월 40만 원은 사용자 지정 운영 예산이며 전액 사용 조건도 사용자가 설명했다. 지급·정산 조건과 실제 사용액은 별도 확인한다. 개인 크레딧은 학교 예산과 별개이며 과거 달러 잔액을 현재 견적으로 쓰지 않는다.

## 증거와 도면

AWS 설정 확인·변경과 Linux 명령 실행마다 실제 화면을 [증거본](../../../증거본/README.md)에 순서대로 남긴다. 명령어와 출력은 텍스트로도 보존해 재배포할 때 참고한다. 비밀 입력 과정은 캡처하지 않으며 누락 구간은 표시한다. 실패와 접근 거부도 결과로 보관하고 화면을 합성해 성공 증거로 만들지 않는다.

기존 AWS·VM 도면과 PPTX는 원본을 보존한다. 학교 환경과 차이가 있는 보고본은 목표 설계 또는 과거 계획으로 설명한다. 개인 계정으로 옮긴다는 계획만으로 도면이 검증되는 것은 아니다. 네트워크·DB 복구·조회 자동 확장·관측의 실제 증거와 대조한 범위만 확인됐다고 말한다.

## 대안과 영향

VM을 먼저 구축하는 [ADR 0028](0028-vm-validation-before-aws.md)의 방법은 유효한 실습 대안이지만 현재 착수 조건으로 강제하지 않는다. 개인 계정에서 바로 전체 구성을 만드는 방법 대신 학교 자원을 먼저 사용해 허용 범위와 실행 절차를 확보한다.

[ADR 0027](0027-msp-operations-and-autoscaling.md)의 운영 목표, 단일 매칭 리더, 조회 계층만의 ASG, 비동기 DB 복제와 수동 승격, AI 보고의 실행 권한 제한은 유지한다. [배포 안내](../../../deploy/README.md), [로드맵](../../ROADMAP.md), [0099](0099-current-architecture.md)에 현재 적용 관계를 반영한다. 로컬·학교·개인 계정의 결과를 서로의 검증 증거로 대체하지 않는다.
