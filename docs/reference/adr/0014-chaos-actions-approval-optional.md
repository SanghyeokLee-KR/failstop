# ADR 0014. 카오스 파괴 액션 4종의 approval_token을 필수에서 선택으로 내린다

- 상태: 채택
- 날짜: 2026-09-01(정본 전파 2026-09-02)
- 결정자: backend-engineer(구현), 아키텍처 담당(정본 반영)

## 배경

관리 평면은 4중 방어를 둔다. 네트워크 격리와 mTLS, `scope=admin` 서명, 비가역 액션 이중 승인, 전 액션 감사다(`docs/reference/product/관리자_설계.md:24`). 셋째 겹인 `approval_token`은 발급 주체와 사용 주체가 서로 달라야 성립한다. 판정은 자가신고 `operator_id`가 아니라 인증 주체(mTLS 인증서 CN) 유래 값으로 하고(`docs/reference/contracts/백엔드_API_설계.md:459`), DB가 `chk_approval_two_person`으로 같은 운영자의 자가승인 행을 막는다(`server/app/src/main/resources/db/migration/V5__admin.sql:84`).

카오스 주입·해제 4종(`chaos.kill_node`, `chaos.network`, `chaos.app`, `chaos.network.clear`)이 그 필수 완결 열거에 있었다. 그런데 이 배포의 카오스 실행 주체는 1인이고, 데모 운영자 클라이언트 인증서도 1장이다(`docs/reference/product/관리자_설계.md:115`). 그 조건에서 필수 열거를 유지하면 선택지가 둘뿐이다. 카오스 실험을 관리 API로 아예 못 돌리거나, 운영자 계정을 하나 더 만들어 혼자 발급과 사용을 겸하는 것이다.

## 결정

카오스 4종에 한해 `approval_token`을 필수에서 선택으로 내린다(API v2.34, 커밋 89b1e40).

- 토큰이 없으면 승인 없이 진행하고 `approval_id`를 null로 적재한다. 응답에서도 키를 빼지 않고 null로 싣는다. 부재와 미승인은 다른 사실이다(`server/app/src/main/java/kr/exchange/admin/ChaosAdminController.java:234`).
- 토큰을 제시하면 종전 계약이 그대로 걸린다. action·대상 바인딩, TTL 5분, 단회 소각이 남는다. 2인 운영 배포는 코드 변경 없이 종전대로 쓴다.
  - 반결탁은 이 ADR 뒤에 없어졌다. ADR 0019 가 승인을 1인 승인으로 바꿔 발급자와 사용자가 같아도 되게 했다(`V34__single_operator_approval.sql`). 이 줄의 종전 판은 "반결탁 전부 남는다" 였으나 더 이상 사실이 아니다.
- 완화 대상은 이 4종뿐이다. 봇 파라미터 변경, 마켓 halt·resume·수수료, 운영자 생성·상태·역할, 회원 폐쇄는 필수 열거에 그대로 있고 2인 승인 체계 자체도 그대로다.
- 화면은 이 액션들을 계속 파괴 액션으로 표시하고 확인 다이얼로그 2단계를 유지한다. 토큰 입력란은 남기되 선택이다.

## 근거

- 2인 승인은 두 주체가 실재할 때만 통제다. 1인이 계정을 둘 쥐고 두 역을 하면 CHECK 제약과 CN 대조는 전부 통과하는데 검토자는 없다. 그 상태가 규정을 사실에 맞추는 것보다 나쁘다. 승인 원장과 감사 로그가 2인이 검토한 것처럼 보이는 행을 남기기 때문이다.
- 대안이 실험 중단으로 끝나지 않는다. 필수 열거를 유지하면 E1~E9가 관리 API 밖으로 나가는데, 호스트 직접 주입은 감사 로그·annotation·역할 게이트를 통째로 우회하는 뒷문이라 계약 위반이다(`docs/reference/contracts/하네스_CICD_IaC.md:335`).
- 빠지는 것이 한 겹으로 한정된다. 역할 게이트·대상 검증·감사 적재·명령 큐 적재는 승인 유무와 무관한 경로에 있다.
- 데모 인증서가 1장인 배포에서 카오스만 도는 상태를 제약의 우회가 아니라 이 완화의 귀결로 정리할 수 있게 된다(`docs/reference/product/관리자_설계.md:115`).

## 대안

- 필수 열거를 유지하고 운영자 계정을 하나 더 만든다. 기각. 근거 첫 항.
- 인원이 2인이 될 때까지 카오스를 관리 API 밖에서 돌린다. 기각. 호스트 직접 주입은 계약 위반이고, 카오스 주입의 유일한 입구를 관리 API로 못 박은 규정과 정면으로 어긋난다(`docs/reference/contracts/하네스_CICD_IaC.md:836`).
- 카오스 전용 1인 승인 절차를 새로 만든다. 기각. 같은 주체가 발급하고 쓰는 토큰은 통제가 아니라 절차이고, 승인 원장이 승인처럼 보이는 행으로 오염된다. 첫 항과 같은 결함이다.
- 승인 요구를 설정 스위치로 둔다. 기각. 스위치 자체가 통제 완화 경로가 되고, 어느 값으로 떠 있었는지를 감사 로그가 담지 않아 사후 판독이 갈린다. 2인 배포로 옮길 때 필수화가 코드 변경을 요구한다는 대가는 영향 절에 적는다.

## 영향

- 정본 개정이 넷이다.
  - `docs/reference/contracts/백엔드_API_설계.md`. §3-6 비가역 액션 이중 승인 불릿(`:457`)이 카오스 4종을 필수 완결 열거에서 불요 열거로 옮겼다. §6-B 표 네 행(`:1274`~`:1277`)의 승인 컬럼이 "불요(제시 시 검증·소각)"이고, 완화 근거·잔여 통제·파괴성 불변을 `:1283`~`:1287`에 적었다. kill-node 예시 주석(`:1292`~`:1293`)도 함께 갈렸다.
  - `docs/reference/product/관리자_설계.md` v1.3. §1-1(`:24`), §1-2 RBAC 표와 본문(`:39`·`:41`·`:43`), §1-3 흐름(`:59`·`:67`), §1-6(`:115`), §2-2 카오스 콘솔 표(`:140`~`:160`), §3-2 승인 매트릭스(`:234`·`:239`), §4-2(`:256`), §6 안전 규약(`:284`·`:287`), §7-4(`:298`). 완화 근거·범위·대가는 §2-2-a 신설(`:162`~`:176`)에 모았고 정합 기록은 §7-8(`:302`)이다.
  - `docs/reference/contracts/하네스_검증설계.md`. 실험 판정 프로토콜 ⓑ(`:60`), 카오스 공통 전제(`:335`), 데모 사전 준비(`:685`), 데모 타임라인 04:30 승인 절차 행(`:705`).
  - `docs/reference/contracts/하네스_CICD_IaC.md:836`.
- 승인 거부 시연은 대상 바인딩 불일치를 사용하도록 바꿨다. 토큰 없는 kill 호출은 이 결정 이후 정상 접수될 수 있으므로, 그 요청에서 403을 기대하면 실제 리더를 중단할 수 있다.
- 감사 판독에 규약이 하나 는다. `admin_audit_log.approval_id`와 `chaos_commands.approval_id`에 null 행과 값 있는 행이 섞인다. 카오스 4종의 null은 승인 우회가 아니라 계약이다.
- 남는 통제는 넷이다. `CHAOS_OPS` 역할 게이트, mTLS 인증 주체 유래 `operator_id`(바디 자가신고 불신), `requireSafeTarget` 대상 문자열 검증, 승인 유무와 무관한 전 액션 감사와 `chaos_commands` 적재다. 주입 입구도 관리 API 하나로 남는다(toxiproxy 8474 호스트 미공개).
- 그 넷이 보상하지 못하는 것을 적는다. 감사는 사후라 오조작을 막지 못하고, 역할 게이트는 같은 주체의 반복 실행을 막지 않는다. 확인 다이얼로그는 클라이언트 측이라 API 직호출에는 없다. 관리 키나 관리 세션 하나가 탈취되면 그 주체 단독으로 리더 kill과 네트워크 단절을 주입할 수 있다. 종전에는 둘째 운영자의 발급이 더 필요했다.
- 회귀를 테스트로 고정했다. 무토큰 4종이 200이고 `approval_id`가 null인 채 큐와 감사에 적재되는 것을 `server/app/src/test/java/kr/exchange/admin/AdminPlaneIntegrationTest.java:687`·`:720`이 본다. 호출 주체를 `CHAOS_OPS` 단독으로 잡아 역할 게이트 잔존을 함께 태운다.
- 코드 정합이 하나 남았다. 카탈로그 응답이 아직 `approval_required: true`를 내보내 콘솔 표시가 완화 이후 계약과 어긋난다(`ChaosAdminController.java:302`, 관리자 설계 §7-8).
- 되돌리려면 `consumeIfPresent`를 무조건 소각으로 되돌리고 위 정본 넷과 데모 대본을 함께 되돌린다. 되돌린 배포는 카오스 실행에 서로 다른 운영자 둘의 mTLS 인증서를 요구하므로, 인증서 발급 절차(관리자 설계 §1-6)가 선행 조건이다.
