# ADR 0031. 학교 봇 관리자는 HTTPS 비밀번호 로그인과 내부 mTLS로 연결한다

- 상태: 채택
- 날짜: 2026-09-20

## 배경

사용자는 PC에 인증서를 설치하지 않고 기존 봇 관리자 화면에 로그인해 종목과 속도를 바꾸도록 요청했다. 학교의 거래 사이트에는 Nginx와 Let's Encrypt HTTPS가 이미 적용돼 있다. 기존 관리 API는 클라이언트 인증서와 그 신원에 묶인 단기 세션을 검사한다.

## 결정

학교 실습에서는 `https://www.sang.it.kr/admin/bots`로 접속한다. 로그인 요청 하나만 Nginx에서 bcrypt 비밀번호 파일로 확인한다. 비밀번호는 봇 서버로 보내지 않는다. 이후 브라우저는 메모리에 보관한 단기 Bearer 세션을 사용한다. 비밀번호 로그인은 HTTPS에서만 허용한다.

Nginx가 운영자 한 명을 대표하는 클라이언트 인증서를 제시하고, 봇 서버는 기존 mTLS·세션·권한 검사를 유지한다. 전달 헤더를 신원으로 신뢰하는 설정은 켜지 않는다. 운영자는 `VIEWER`와 `BOT_OPS`만 가지며 거래 회원·Grafana 계정과 분리한다. 같은 인증서에 여러 사람의 비밀번호 계정을 연결하지 않는다. 다중 운영자가 필요하면 운영자별 신원을 보존하는 인증 설계를 먼저 바꾼다.

봇 노드의 8443은 앱 SG에서만 허용하고 인터넷에는 추가 포트를 열지 않는다. 봇 플릿과 관리 API는 같은 JVM에서 실행해 기존 시작·정지·플릿 조절 기능이 실제 봇을 제어하게 한다. 매칭 엔진과 거래 API는 별도 앱 노드에 유지한다. 관리 모드가 켜졌다는 이유로 카오스 권한이나 DB 초기화 권한을 부여하지 않는다.

## 근거와 한계

PC 인증서 설치 없이 접속하면서 기존 백엔드 검증을 재사용할 수 있다. 대신 앱 Nginx는 운영자 인증을 맡는 신뢰 경계에 포함된다. 앱 서버가 침해되면 게이트웨이 신원도 악용될 수 있으며, 비밀번호 파일·인증서·앱 서버 접근 권한을 함께 보호해야 한다. 이 구성은 기존의 운영자 PC별 인증서 격리와 같지 않다.

로그인 요청은 IP별 분당 5회와 짧은 버스트로 제한한다. 게이트웨이 인증서는 60일이며 자동 갱신은 아직 없다. 만료 전에 내부 서버·게이트웨이 인증서를 교체하고 양쪽 검증을 해야 한다. 공개 웹의 Let's Encrypt 갱신과 별개다. 로그아웃은 브라우저 메모리의 세션을 지우며, 탈취된 기존 토큰의 즉시 폐기를 뜻하지 않는다.

기존 직접 mTLS 접속을 기본으로 한 [관리자 설계](../product/관리자_설계.md)와 [API 계약](../contracts/백엔드_API_설계.md)의 학교 배포 예외다. 다른 환경의 인증 경계를 일괄 변경하지 않는다. 실제 배포·검증 상태와 남은 작업은 [로드맵](../../ROADMAP.md), 설치·복구 절차는 [AWS 작업 안내](../../reports/AWS_작업.md)에 둔다.

## 대안

운영자 PC별 인증서는 사용자가 설치 부담 때문에 선택하지 않았다. SSM 터널은 이미 실험했으며 일상적인 관제 접속은 HTTPS 로그인으로 바꾸기로 했다. 백엔드의 mTLS를 끄거나 운영자 이름 헤더만 신뢰하는 방식은 사용하지 않는다.
