# ADR 0030. NAT Gateway를 제외하고 조회 ASG를 2~3대로 제한한다

- 상태: 채택. 비용·배치 기준이며 AWS 자원 생성 완료를 뜻하지 않는다. 2026-09-25 사용자 정정으로 대수의 해석을 바꿨다(아래 절).
- 날짜: 2026-09-19
- 근거: 사용자가 한 달 상시 운영, 조회 ASG min 2 / max 3과 비용을 이유로 NAT Gateway 제외를 지정했다.
- 대체: [ADR 0020](0020-managed-nat-gateway.md)의 NAT Gateway 두 대 사용을 현재 학교·개인 실습 범위에서 대체한다. [ADR 0027](0027-msp-operations-and-autoscaling.md)의 조회 전용 확장 범위는 유지한다.

## 결정

학교와 개인 계정의 이번 실습에 NAT Gateway를 만들지 않는다. NAT instance로 대체하지도 않는다. 인터넷 통신에 필요한 기존 Internet Gateway는 유지한다. 과거 보고 도면은 이력으로 보존하며 현재 배포도와 구분한다.

개인 계정의 조회 ASG는 최소 2대, 최초 희망 2대, 최대 3대를 계획한다. 두 AZ에 배치하고 부하 감소 후 2대로 돌아오게 한다. 매칭 리더·DB·관측 노드는 이 ASG에 넣지 않는다. 최대 3대에 해당하는 DB 연결 풀·메모리·비용을 배포 전에 계산한다. 확장 지표·임계값·워밍업·축소 지연은 아직 정하지 않았고 실제 AWS 시험으로 확정한다.

개인 조회 노드는 퍼블릭 서브넷과 공인 IPv4로 패키지·AWS 서비스에 접근하는 실습안을 사용한다. 퍼블릭 IP가 있다는 이유로 앱·관리 포트를 인터넷 전체에 열지 않는다. 앱 서비스는 지정한 ALB에서만, 지표는 관측 노드에서만 접근하도록 제한한다. 관리 접속은 SSM을 우선하고 기존 운영자 인증을 유지한다. 학교 DB의 5432는 승인된 앱·복제 경로만 허용한다. 비밀 값과 사용자별 응답을 CDN에 캐시하지 않는다.

## 사용자 정정(2026-09-25): 2~3대는 앱 계층 전체 대수다

사용자가 조회 전용 노드 read-1·read-2는 없다고 정정했다. 조회 ASG의 최소 2·최대 3은 앱 계층 전체 대수로 읽는다. app-1·app-2는 마켓을 나눠 맡는 매칭 리더이면서 조회도 받는 고정 노드이고, 조회 전용 app-3 한 대만 부하에 따라 자동으로 켜고 끈다. 평시 앱 계층은 두 대이고 부하가 오르면 app-3이 켜져 조회가 세 노드로 나뉘며, 부하가 내려가면 다시 두 대가 된다.

Auto Scaling 그룹에는 app-3만 넣고 그룹 크기는 0~1대다. 매칭 리더는 AWS가 임의로 종료하거나 교체하지 않도록 그룹 밖에 둔다는 위 결정은 그대로다. 위 「결정」 절의 "조회 ASG 최소 2대, 최초 희망 2대, 최대 3대"와 「비용과 영향」 절의 조회 노드 2~3대 계산은 정정 전 기록으로 남긴다. 비용은 매칭 리더 두 대가 늘 켜져 있고 app-3 한 대가 켜진 시간만큼 더해지는 모양으로 다시 계산한다.

관리 콘솔의 sim(관제센터, 서버·노드, 용량·부하, 서비스 흐름, 지표 관제, AI 조치안)은 같은 날 이 모델로 맞췄다. 배포 코드는 아직 맞추지 않았다. `deploy/terraform`의 조회 ASG는 별도 reader 역할 노드를 `read_capacity.min >= 1` 검증으로 만들고 `example.tfvars`는 최소 1·최대 2다. 그룹을 app-3 한 대(최소 0·최대 1)로 줄이고 앱 계층 대수 계산과 비용을 이 정정에 맞출 것이다. 맞추기 전까지 Terraform 값을 이 정정의 구현으로 인용하지 않는다.

## 피어링은 별도 선행 조건이다

학교와 개인 기본 VPC는 모두 `172.31.0.0/16`이라 그대로 연결할 수 없다. 겹치지 않는 개인 VPC와 학교 운영자의 연결·왕복 경로 허용이 필요하다. 학교 사용자로 수행한 변경 없는 검사에서 `ec2:CreateVpcPeeringConnection`과 `ec2:CreateRoute`가 허용 정책 부재로 거부됐다. 수락 API는 실제 요청이 없어 확인하지 않았다. 기존 공유 기본 라우트 테이블을 임의로 변경하거나 다른 역할로 거부를 우회하지 않는다.

피어링이 허용되지 않으면 학교 검증을 유지하고 개인 계정에 독립 재배포하는 [ADR 0029](0029-school-aws-first-personal-account-expansion.md)의 경로를 따른다. NAT 제외와 ASG 대수 결정이 피어링 구현 완료나 모든 계정 변경 허가를 뜻하지 않는다.

## 비용과 영향

서울 t3.small·gp3 20GiB·공인 IPv4 한 개를 30일 유지하는 노드 비용은 $24.144다. 조회 노드 2대와 ALB(공인 IP 두 개·평균 1 LCU)의 계산값은 $77.448이며 3대가 한 달 내내 유지되면 $101.592다. 전송·추가 LCU·백업·CloudWatch·세금은 별도다. ASG max 3은 청구액의 절대 상한이 아니다. 계산 근거는 [AWS 작업 안내](../../reports/AWS_작업.md)에 둔다.

NAT Gateway 두 대의 시간·공인 IP 비용 약 $92.16/30일과 별도 데이터 처리 요금을 피한다. 대신 공인 주소·SG·서비스 바인딩을 직접 관리하며 공인 IP가 없는 노드의 외부 통신을 제공하는 구조는 아니다. 실제 자원 삭제는 이번 결정에 포함하지 않는다.

## 검증 조건

개인 VPC·서브넷·SG와 ASG를 만들기 전에 학교 연결 허용 또는 독립 재배포 범위를 확정한다. 이후 2대 정상 등록, 부하에 따른 3대 증설, 준비 전 유입 차단, 연결 종료를 기다린 축소, 다시 2대 유지와 관측 대상 갱신을 확인한다. 학교·개인 계정의 실행 증거와 비용을 구분한다.
