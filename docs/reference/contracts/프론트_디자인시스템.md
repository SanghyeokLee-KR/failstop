# 고가용성 가상 암호화폐 거래소 · 디자인 시스템 문서 (v1.17)

> 본 문서는 토큰 초안·화면 초안·비평(JSON, 73점)을 종합하고, 비평의 **critical 1건·high 3건·medium 4건·low 3건 전부**를 반영해 확정한 단일 소스다. 값·이름 충돌을 제거해 `tokens.css` 하나를 **계약(contract)** 으로 고정했다. 색은 항상 시맨틱 토큰으로 소비한다(primitive 직접 사용 금지).
>
> 스택: Next.js(App Router)+TypeScript / Spring REST·WebSocket(STOMP). 폰트: 오픈폰트 **Pretendard**. 산출물 언어: 한국어(토큰·기술명은 영어).

---

## 0. 디자인 원칙 (전 화면 불변 규약)

1. **한국 시장 관례 절대 준수. 상승/매수 = Red, 하락/매도 = Blue.** 전 화면·차트·호가·손익에 강제. 반전 금지.
2. **방향은 색 단독 표현 금지.** 반드시 `색 + 부호(+/−) + 화살표(▲▼)` 병기 → 적록색약·명도 저하 상황 보정.
3. **가격 방향에 green 금지.** green은 시스템 성공(체결완료 등) 전용.
4. **하락-Blue ≠ 브랜드-Blue.** 링크/버튼(브랜드)과 하락 숫자를 hue·명도로 분리. **다크에서도 동등한 gap 유지**(초안이 붕괴시킨 지점 → 본 문서에서 다크 down을 cyan-lean으로 재조정). 링크는 색 외 밑줄 등 비색 단서 병행.
5. **접근성 대비 실패 지점(초안의 critical) 해소**. 방향색을 **면/대형용(`--color-up`)** 과 **텍스트용(`--color-up-text`, 600단계)** 으로 분리. 소형 숫자·CTA 텍스트는 4.5:1 이상 확보.
6. **숫자는 `tabular-nums` + `Intl.NumberFormat('ko-KR')`** + 컨테이너 폭 고정 → 실시간 갱신 시 레이아웃 시프트 0.
7. **오리지널리티**. 토스의 상표/로고/브랜드명("토스" 등)·독점 자산 미사용. 토큰 값·카피 보이스는 본 문서의 오리지널 정의만 사용(§10·§10-1). Pretendard(오픈폰트) 사용.
8. **고정형 데스크톱 전용**(기준 폭 1280px, 콘텐츠 max 1920px 중앙). 넉넉한 여백·큰 볼드 숫자·라운드 16~20px·부드러운 모션. 카피는 §10-1 보이스 규정(개조식 명사 종결)을 따른다. 초안은 모바일 퍼스트(360~390px, safe-area)였고 그 시절 표기가 본문 여러 절에 남아 있다. 데스크톱_레이아웃설계 §4가 고정형 전용을 확정했으므로 이 항이 우선한다. 각 절의 "모바일:" 하위 항목은 폐기 표기이며 구현 근거로 삼지 않는다.

### 2-1. 표면별 대비 실측 (라이트)

```css
  /* 패널 사이 이음새 채널. bg-muted가 surface 사이로 비친다 */
  --surface-seam:var(--bg-muted);
  --seam-width:var(--space-3);
  /* 표면 라운드. 패널 12, 인풋·칩 8. 16 이상은 오버레이·시트 전용 */
  --panel-radius:var(--radius-md);
  --control-radius:var(--radius-sm);
  /* 계측 눈금 hairline. 무채, 색이 아니라 위치로 값을 더한다 */
  /* 계측 눈금(v1.7). border-subtle은 면 대비 1.21:1(다크 1.23:1)이라 눈금이 안 보였다.
     호가 잔량·관리 게이지·미터 레일이 전부 이 토큰을 쓰는데 계기 어휘가 화면에서 사라진 상태였다.
     반복 텍스처라 단일 그래픽 객체 기준(3:1)이 아니라 지각되되 데이터에 종속이 목표다.
     border-strong 실측: 라이트 1.92:1 / 다크 2.07:1 */
  --rule-tick:var(--border-strong);
  --rule-tick-gap:var(--space-4);
  /* 프라이스 마크 공용 프레임(v1.7). 호가 경계행과 차트 마지막가 태그가 같은 radius·padding을 쓴다.
     같은 슬롯 형태가 반복돼야 "가격 판독 자리"로 학습된다.
     초안의 "3지점"에서 요약 바 히어로는 뺀다. 프레임을 받은 둘은 축 위의 위치 표식이고
     히어로는 판독값이라 성격이 다르다. 요약 바는 이미 카드 테두리 안이라 프레임이 이중이 된다.
     차트는 캔버스라 chartTheme이 px 수로 넘긴다(useChartTheme의 pxVar) */
  --price-mark-radius:var(--radius-sm);
  --price-mark-pad-y:var(--space-1);
  --price-mark-pad-x:var(--space-2);

  /* 차트 지표선 계열 램프(차트_기술적분석_설계 §4.2·§7-1). 기간 차이를 브랜드 명도 차로 표현.
     라이트 on #FFF: 400 3.82 / 500 4.81 / 600 6.31 / 700 8.20 (그래픽 3:1 통과) */
  --chart-series-1:var(--brand-400);
  --chart-series-2:var(--brand-500);
  --chart-series-3:var(--brand-600);
  --chart-series-4:var(--brand-700);
}
/* 램프 다크 미러. 라이트 600·700은 다크 surface #171A21 위 2.76·2.12:1로 그래픽 최소
   3:1(WCAG 1.4.11) 미달. 실측: 200 9.77 / 300 6.73 / 400 4.55 / 500 3.62 */
[data-theme="dark"]{
  --chart-series-1:var(--brand-200);
  --chart-series-2:var(--brand-300);
  --chart-series-3:var(--brand-400);
  --chart-series-4:var(--brand-500);
}
```

소비 규칙.

- `--chrome-accent`는 텍스트·보더·인디케이터 전용. 면(fill) 배경 금지.
- 패널 이음새 폭은 `--seam-width` 단일 채널로만 소비한다. 리터럴 12px 금지.
- `--chart-series-*`는 지표선 그래픽 전용. primitive 브랜드 램프 직접 소비는 다크 대비 미달로 금지.
- `--text-on-brand-light/-dark`(§2)는 심볼칩 라벨 전용. 칩 배경만 데이터 색 예외이고 라벨은 토큰 소유다.

## 7. 컴포넌트 인벤토리 (16종 + 파생)

각 항목: 용도 / 변형 / 상태 / 사용 토큰. 모든 토큰명은 §1~5 계약 이름.

**A-1. AppBar**. 최상단 타이틀/뒤로가기/우측 액션. 변형 `default·back·large·transparent`. 상태 `rest·scrolled`(하단 `--border-subtle` 1px + 미세 `--shadow-1`). 토큰: 높이 56px, 좌우 `--layout-gutter`, 타이틀 `--font-title-3`, 배경 `--surface-default`.

**A-2. TabBar** (하단 글로벌 네비, 오리지널 정의). 5탭(홈/마켓/주문/자산/더보기). `active`(아이콘 fill + 라벨 `--brand-primary`, 600 수식은 라이트 한정, 다크는 전용값 #6B9DF7) / `inactive`(line + `--text-secondary`) / `badge`. 높이 56px + `env(safe-area-inset-bottom)`, 아이콘 24px, 라벨 `--font-micro`, 상단 `--border-subtle`. 히트영역 ≥48px, `aria-current="page"`.

**A-3. Button**. color `primary·buy·sell·secondary·danger·light`, fill `fill/weak`, display `inline/block/full`, size `sm/md/lg/xl`. 상태 `rest·pressed`(`--pressed-layer` 오버레이) `loading`(3점, **폭 불변**, `aria-busy`) `disabled`(`--surface-sunken` + `--text-disabled`. 단, 라벨이 비활성 사유를 싣는 버튼은 안내 텍스트라 `--text-default`로 승격한다. 주문 CTA가 그 경우다(v1.7)). 라운드 `--radius-lg`, xl 높이 56px, 라벨 `--font-body-lg` 600. **fill 배경은 라벨(`--text-inverse`/`--text-on-brand`) 대비 ≥4.5:1 확보값**(라이트: 방향=600단계·브랜드=brand-500 / 다크: 테마 전용값, §2·§3의 재검증 주석 참조), pressed는 한 단계 어두운 값. weak 버튼 텍스트는 `-text`(600) 계열.

**A-4. ListRow**. 3영역(에셋/텍스트/값·액션). 변형 `coin·asset·nav·control`. 상태 `rest·pressed`(`--pressed-layer`)·`flashing`·`skeleton`. 높이 64~72px, 좌우 `--layout-gutter`, 심볼칩 40px `--radius-md`, 제목 `--font-body` 600, 서브 `--font-caption` `--text-secondary`(정보 전달이므로 secondary 최소선), 우측 가격 `--font-body` 700 tabular.

**A-5. NumberDisplay**. 실시간 숫자 원자 단위. size `hero/lg/md/sm`, `withUnit`, `flashMode`. 상태 `up·down·flat·stale`(연결 끊김. 마지막 값을 제 잉크 그대로 두고 값 면에 `--stale-hatch` 사선 무늬 + 마지막 수집 시각을 단 "지연" 배지. 글자·버튼에 opacity를 쓰지 않는다. 차트·스파크라인 같은 그래픽만 흐리게 둘 수 있다(v1.8)). `tabular-nums`, 방향색은 셀 크기별로 `--color-*`(hero) vs `--color-*-text`(md 이하). 전환 `background-color var(--dur-flash)`.

**A-6. PriceChange**. 등락률/폭·손익률. 변형 `pill·inline·withAmount`. `up`(pill=`--color-up-strong` on `--color-up-bg` / inline=`--color-up-text`, ▲+) `down`(pill=`--color-down-strong` on `--color-down-bg` / inline=`--color-down-text`, ▼−) `flat`(`--color-flat`, 화살표 없음). 틴트 위 텍스트는 항상 `-strong`(§6). `aria-label="상승 3.24퍼센트"`.

**A-7. OrderBookRow**. 가격+잔량+depth bar. depth 틴트는 전용 토큰 `--depth-up-bg`/`--depth-down-bg`(칩·pill 공용 `-bg`보다 진함). 알파 상한은 막대 위 텍스트가 정하고(라이트 0.22·다크 0.32), 그 범위에서 막대는 면 대비 1.3~1.8:1에 그치므로 길이 판독은 방향색 1px 종단선(`border-right`)이 담당한다(면 대비 3.9~6.7:1). 변형 `ask`(파랑, 좌 채움) `bid`(빨강, 우 채움) `mid`(현재가 기준선). 상태 `rest·flashing·myOrder·pressed` + 패널 상태 `resyncing`(orderbook seq gap→재스냅샷 동안 호가 패널 전체에 반투명 오버레이(`--overlay-dim` 약화 알파) + 스피너 + "호가 동기화 중" 라벨, 행 인터랙션 잠금). **행 시각 높이 44px로 상향**(medium 반영, ::before 히트확장 시 인접 겹침 → 오탭 금전사고 방지). 겹침 불가피 구간은 상/하 절반만 각 행 귀속. 탭 → 주문가 **프리필(즉시 확정 아님)** + 확인 단계 유지.

**A-8. ChartPanel**. 캔들/라인/도넛. `candle`(양봉=`--color-up`/음봉=`--color-down`)·`line·area`·`donut`(구성비 전용, 브랜드/뉴트럴 팔레트, 방향색·시스템 헬스색 사용 금지), `timeframe`, `withVolume/withMA`. 상태 `rest·loading`(`Skeleton chart`)·`error`(요약 텍스트 유지 + 재시도 버튼)·`empty`. **라이브러리 기본값(up=green) 하드코딩 금지 → `getComputedStyle`로 토큰 주입, 테마 변경 시 `applyOptions` 재적용.** `dynamic(ssr:false)`. 접근성용 요약 텍스트 + 숨김 데이터테이블 병행.

**A-9. SegmentedTab**. `directional`(매수=Red/매도=Blue 인디케이터)·`neutral`(브랜드)·`underline`. `selected`(캡슐 슬라이드 `--dur-base --ease-standard`, `--surface-default`+`--shadow-1`. 다크는 캡슐 면이 트랙과 1.06:1이고 그림자도 보이지 않아 `--surface-elevated` 면 + `inset 0 0 0 1px var(--btn-secondary-border)`(트랙 대비 3.89:1)로 올린다. 명시 다크와 시스템 자동 다크 블록 양쪽에 둔다, v1.8)·`unselected`(`--text-default`, 트랙이 `--surface-sunken`이라 `--text-secondary`는 라이트 4.27:1 미달, §9 sunken 규칙)·`disabled`. 트랙 `--surface-sunken`, 라운드 `--radius-md`.

**A-10. AmountInput**. `qty·amount·price`(±스텝, 호가 연동) + `PercentChips`(10/25/50/최대) + slider(옵션). `rest·focus`(브랜드 보더 + 래퍼 포커스 링 `.focus-ring-owner`)·`error`(최소주문금액 미만 등, 보더 `--color-danger` + 인라인 안내)·`disabled`. 높이 52px, `--radius-md`, 숫자 `--font-title-3` 700 tabular 우측정렬, 칩 `--radius-full`(rest `--surface-sunken` + 라벨 `--text-default`(§9 sunken 규칙) / active `--brand-weak-bg` + `--text-brand`). 관례: 매수 시장가=금액, 매도 시장가=수량.

**A-11. BalanceCard**. `portfolioHero·available·coinHolding·kpi`(화면7 시스템 지표용, 라벨 `--font-caption` `--text-secondary` + 값 `--font-title-2` 700 tabular, 색 도메인=시스템 헬스). `rest·loading·hidden`(`••••••`)·`profit`(up)·`loss`(down). `--radius-xl`, 패딩 `--space-6`, `--shadow-1`, 총자산 `--font-display-lg` 700 tabular(히어로 → `--color-up/down` 500 허용), 라벨 `--font-caption` `--text-secondary`.

**A-12. PnLBadge**. 손익 특화(PriceChange 공유). `pct·amount·combined`. `profit`(`--color-up-text` ▲) `loss`(`--color-down-text` ▼) `even`(회색) `hidden`. 큰 변형은 `--font-body-lg` 700(단, body-lg는 large-text 아님 → text 계열 색 유지).

**A-13. BottomSheet**. 주문 확인·선택·필터. `default·withCTA·withDoubleCTA·select·expandable`. `entering`(슬라이드업 `--dur-slow --ease-emphasized`)·`open·exiting·dimClickClose`. 상단 `--radius-2xl`, `--shadow-3`, 딤 `--overlay-dim`, 헤더 `--font-title-3`, CTA-본문 간격 `--gap-cta-content`, 핸들바 + safe-area/키보드 대응.

**A-14. Toast**. 체결·액션 결과·에러. position `top/bottom`, `withIcon/withButton/higherThanCTA`. `success`(`--color-success`, 방향과 별개)·`error·info`·`entering/exiting`. `--radius-lg`, `--shadow-2`, `--toast-duration`(버튼 시 `--toast-duration-action`), `aria-live="polite"`(시세 tick은 미낭독).

**A-16. StatusPill**. `connection·market·order·health`. 색(점·아이콘): connected=`--color-success` 점 / connecting=`--color-warning` / **disconnected=`--color-warning`(orange) 또는 전용 alert, up-red 재사용 금지**(medium 반영, red 다중의미 혼동 차단) + 재연결 버튼 / `order` 방향: 매수=`--color-up-strong`(700) 라벨 on `--color-up-bg` 틴트 / 매도=`--color-down-strong`(700) 라벨 on `--color-down-bg` 틴트(§6 change-badge와 동일 경로, `--font-micro` 소형 텍스트이므로 500 원색·600 `-text` 금지, §9 틴트 규칙) + 아이콘·라벨 병기 / filled=`--color-success` / 유의=`--color-warning` / `health`: healthy=`--color-success`·degraded=`--color-warning`·장애=`--color-danger`(crimson, up-red 미사용, §1 도메인 확장). **라벨 텍스트는 `--color-success-text`/`--color-warning-text`/`--color-danger`**(600 원색 green/orange는 아이콘·점 전용, 소형 텍스트 대비 미달, §2). `--radius-full`, weak 틴트. size `sm`(기본, `--font-micro` 500, 아이콘 12px, 패딩 `--space-1` `--space-2`)·`lg`(화면7 종합 헬스 히어로 전용, `--font-title-3` 600, 아이콘 20px, 패딩 `--space-2` `--space-4`; 색 경로·라벨 토큰은 sm과 동일). **항상 아이콘+라벨 동반**(색 단독 금지).

- **구조:** 풀스크린 단일 컬럼. 히어로 → 여백 → CTA 스택. 뷰포트 세로 중앙 정렬(v1.7).

## 10. 오리지널리티 주의 (필수)

- 토스의 **상표·로고·브랜드명("토스" 등)·독점 자산·저작 일러스트·스쿼클 자산을 복제하지 않는다.** 여백·큰 볼드 숫자·라운드·부드러운 모션 같은 질감은 품질 참고에 그친다. 토큰 값과 카피 보이스(§10-1)는 본 문서의 오리지널 정의를 사용하며, 레퍼런스 말투를 가져오지 않는다.
- 브랜드 블루는 토스 시그니처(#3182F6)와 hue·명도를 분리한 독자값(#2E6BE6)이다.
- 폰트는 오픈폰트 **Pretendard**만 사용(라이선스 준수).
- 마이크로카피·일러스트는 자체 제작하며, 외부 브랜드 문구를 인용하지 않는다.

### 10-1. 보이스 · UI 카피 규정

고객 평면의 시각 노출 카피는 단일 보이스를 쓴다. 해요체·합쇼체 혼용은 리뷰 반려 사유다.

- **기본형은 개조식 명사 종결.** 완료 통지 "주문 취소 완료", 빈 상태 "기록 없음", 안내 "로그인 필요".
- **행동 지시는 명령형 축약.** "실계정 정보 입력 금지", "첫 코인을 담아 포트폴리오 시작".
- **해요체·합쇼체 금지.** "취소했어요"·"취소했습니다" 모두 불가. 에러 문구도 같은 보이스: "잔고 부족", "입력값 확인 필요". 재시도 안내는 "잠시 후 다시 시도 필요"로 통일.
- **예외 1: 낭독문.** sr-only·aria-label·aria-live 텍스트는 화면 카피가 아니라 보조기술 문장이므로 자연스러운 서술("~합니다" 포함)을 유지한다.
- **예외 2: 짧은 의문형 확인.** 파괴적 액션 직전 인라인 확인("삭제할까요?")과 전환 유도 질문("이미 회원이신가요?")은 의문형을 허용한다.
- **불변.** 도메인 용어·계약 문자열(에러 코드, API 필드, 서버가 본문으로 내려주는 문자열)은 보이스 치환 대상이 아니다.

**관리 콘솔 카피(v1.11, 사용자 결정 2026-09-25).** 관리 콘솔 문장 문구는 합니다체, 라벨은 명사형이다. 고객 평면의 규칙은 그대로다.

- **문장은 합니다체.** 화면 설명, 안내, 빈 상태 설명, 확인 대화상자 본문, AI 판단 문장, 시뮬레이터가 만드는 사건·판단 문장, 용어 설명처럼 주어와 서술어가 있는 문장은 '~합니다', '~입니다'로 끝낸다. 예: 'AI 정지 중입니다. 재개하면 다시 판단합니다'. 종전의 '여러 문장으로 이유를 적는 해설 문단은 한다체' 규칙은 관리 콘솔에서 이것으로 대체한다.
- **라벨은 명사형.** 버튼('승인하고 실행'), 칸 제목, 상태어('운영 중', '임계치 초과'), 배지('자동 실행 가능'), 표 머리, 짧은 결과 표지('실행됨', '정지로 만료')는 바꾸지 않는다.
- **반말 평서문 금지.** 화면 문구를 '~한다.', '~된다.', '~없다.'로 끝내지 않는다. 저장소 문서(`docs/`)와 코드 주석은 문서 규칙대로 평서문을 쓴다.

### 10-2. 탭 타깃 규정 · 플랫폼별 밀도

44x44px 히트 영역은 손가락 입력 기준이다. 이 제품은 고정형 데스크톱 전용(최소 1280px, 반응형 리플로우 없음)이라 전 컨트롤에 44px 시각 높이를 강제하면 고밀도 판독 존이 무너진다.

- **기본 규칙 유지.** 버튼·링크·폼 컨트롤 등 단발 조작 요소는 히트 영역 ≥44x44px. 시각 높이가 32~40px이면 투명 `::after`로 히트만 확장한다(인접 gap 안에서만, 겹침 금지). 조작 버튼의 시각 높이 하한은 32px이며 그 아래는 허용하지 않는다.
- **밀도 예외(데스크톱 한정).** 마우스 포인터 전제의 고밀도 판독 행은 시각 높이 32~36px을 허용한다. 대상: 호가 행(32px), 체결 테이프 행(28px), 감사 로그 행(36px). 근거는 정밀 포인터 입력과 행 밀도가 판독 성능의 주 채널이라는 점이며, 오조작 방지는 히트 확장이 아니라 **프리필 후 확인 단계**가 담당한다(호가 탭은 즉시 확정이 아니다).
- **높이 예산 압축(§2.3, `max-height: 820px` 한정).** 짧은 뷰포트에서 주문 패널은 입력 32px·CTA 40px로 눌린다. 이 구간에 한해 위 히트 규정의 예외다. 종전에는 예외 목록에 없어 §2.3과 이 절이 서로 어긋나 있었다. 근거는 같다. 정밀 포인터 입력이고, 주문은 즉시 확정이 아니라 확인 대화상자를 지난다. **범위는 이 미디어 쿼리 안, 주문 패널로 한정한다.** 뷰포트가 그보다 높으면 압축이 풀리고 44px 규정이 그대로 적용된다. 다른 화면·다른 구간으로 확장하지 않는다.
- **모바일 전개 시.** 모바일 화면을 만들면 위 예외는 무효다. 호가 행 44px 상향 등 §11 medium 항목의 원래 처방을 그대로 적용한다.

2. **§12-9 신설:** AI 패널, 근거 칩, 확신도, 조치 카드, 임계 눈금, 모드 스위치, 출처 칩과 환경 배지, 상태 요약, 세 가지 빈 모양의 규칙을 적었다.
3. **§12-2·§12-4·§12-5·§12-8 보강:** 관제센터 수치 단계, AI 판단 중 빛띠와 근거 강조 고리의 모션과 움직임 줄이기 대체, 조치 카드 승인의 approve 변형, 원천 연결 전 모양을 더했다.
4. **운영 관제 내비 개편(2026-09-24 사용자 요구로 개편):** 내비를 관제·인프라·조치·시연 네 묶음으로 나누고 메뉴 상태 배지와 바닥의 AI 모드 표시 규칙을 §12-9에 더했다. 새 화면(경보·사건, AI 판단, 서버·노드, 데이터베이스, 임계값 관리)은 관제센터와 같은 부품과 규칙을 쓴다. 상황별 대본을 지워 §12-2와 §12-6의 대본 예시를 다른 예로 바꿨다.

### v1.10 패치 노트 (AI 즉시 정지, AI 한도, 처리된 조치 카드, 2026-09-25)

2026-09-25 사용자가 '즉시 끄기'는 수동 모드에서도 늘 보여야 한다고 정했고, 자동 조치 상한을 자동 모드 1회 활성당으로 바꾸고 운영자가 AI 한도를 바꾸게 했다([ADR 0035](../adr/0035-ai-operations-authority.md)). 같은 날 캡처 검토에서 자동 되돌림 순간에 AI 패널, 조회 ASG, 권장 조치 카드, 사건 타임라인이 서로 다른 상태를 말하는 결함이 나와 카드 규칙을 함께 고쳤다. 정지 상태의 모양, 처리된 조치의 배치, AI 한도 칸의 모양은 이 개정이 정했고 사용자가 하나씩 확정한 값은 아니다. 확인은 sim 데이터 원천의 웹 검사와 1920x1080·1440x820, 라이트·다크 브라우저 캡처다.

1. **§12-9 모드 스위치 개정:** '즉시 끄기'를 두 모드에서 늘 보이는 'AI 즉시 정지'(danger, ■, 승인 불요)로 바꿨다. 정지 중에는 모드 줄이 주의 면으로 바뀌고 'AI 재개'(neutral)가 그 자리에 선다. 정지는 운영자가 AI를 멈춘 상태라 장애(■)가 아니고, 꺼짐(○)으로 두면 평시와 구분이 약해 재개를 잊을 수 있어 §12-3의 주의(▲)로 적는다. http 데이터 원천에서는 'AI 즉시 정지'를 보이되 비활성으로 둔다. '오늘 자동 조치'를 '이번 자동 모드'로 바꿨다.
2. **§12-9 조치 카드 개정:** 번호는 대기 중인 조치안에만 붙인다. 처리된 조치는 '처리된 조치' 묶음에 번호 없이 한 단 낮춘 제목과 '처리됨' 표식으로 두고, 예상 영향 대신 실제로 바꾼 것(결과)을 적는다. 정지로 만료된 카드는 승인 버튼을 §12-6의 비활성 모양으로 남긴다.
3. **§12-9 AI 한도 칸 신설과 내비 바닥 표시 보강:** AI 판단 화면의 한도 편집 칸 규칙과, 정지 중 내비 바닥의 '▲ AI 정지' 표시를 적었다.

### v1.11 패치 노트 (관제센터 2라운드, 관리 콘솔 합니다체, 시각 절제 규칙, 2026-09-25)

2026-09-25 사용자가 관제센터에 참고 시안의 정보 구조(상단 바의 검색·전체 상태·알림, 증감과 추세선이 있는 요약 칸, 역할 묶음 인프라, AI 판단 요약)를 적용하고, 관리 콘솔 화면 문구를 합니다체로 쓰며, 온프레미스 AI 서버를 두기로 정했다([ADR 0038](../adr/0038-on-prem-ai-inference-server.md)). 같은 날 '디자인은 AI 느낌이 없게' 해 달라는 요구가 가장 우선으로 더해졌다. 시안의 정보 구조와 밀도만 따르고 시안의 발광·그라디언트·보라 면은 따르지 않는다. 색 값, 크기, 막대 두께 같은 세부 값과 §12-10의 세부는 이 개정이 정했고 사용자가 하나씩 확정한 값은 아니다. 확인은 sim 데이터 원천의 웹 검사와 1920·1440·1280 폭, 라이트·다크 브라우저 캡처다.

1. **§9·§10-1 카피 규칙 개정(사용자 결정 2026-09-25):** 관리 콘솔 문장 문구는 합니다체, 라벨은 명사형이다. 고객 평면의 명사형 규칙은 그대로다. `scripts/check-tokens.mjs`의 카피 검사를 평면별로 나눠 관리 콘솔에서는 반말 평서문 종결을 잡게 했다(`scripts/copy-tone.mjs`, 시험 `scripts/tests/copy-tone.test.mjs`).
2. **AI 강조 토큰 채도 조정(§1·§2·§3):** violet 600·700·50과 다크 값의 채도를 낮췄다. 대비 계약은 그대로 넘는다.
3. **§12-9 개정:** AI 패널과 근거 칩을 무채로 바꾸고 AI 강조색을 작은 자리로 좁혔다. AI 판단 요약 네 칸, 조치 카드 배지와 ⋮ 메뉴, 상태 요약의 증감과 추세선(관제센터 추이 금지의 유일한 예외), 운영자 바, 인프라 역할 묶음, 사건 타임라인 레일을 더했다. 자동 모드 줄은 면을 칠하지 않는다.
4. **§12-2·§12-3·§12-4 보강:** 큰 한 줄 판단, 증감, 운영자 바 시각의 단계를 더하고, 재생 표시를 무채 점선으로 바꾸고, 서비스 흐름의 판단 요청 알갱이 모션을 더했다.
5. **§12-10 신설:** 시각 절제 규칙이다. 이후 관리 화면도 이 규칙을 따른다.

### v1.13 패치 노트 (관리 콘솔 보정 A: 줄바꿈, 증감, 시뮬레이션 표식, 용어, 숫자·시간, 정지 단추와 상담 패널 자리, 2026-09-25)

### v1.17 패치 노트 (3라운드 구현 묶음 A, 2026-09-25)

경보·사건, AI 판단, 서버·노드, 데이터베이스를 구현하며 §12-15의 단계 막대를 코드로 옮기고 새로 정한 규칙이다. 화면의 동작은 [관리자 설계 4-10-2·4-10-3](../product/관리자_설계.md)의 '구현' 항목이 정한다. 세부 값은 이 개정이 정했고 사용자가 하나씩 확정한 값은 아니다. 확인은 sim 프로덕션 빌드의 웹 검사, 브라우저 게이트, 1920·1440·1280 폭 라이트·다크 캡처다.

1. **§12-15 단계 막대 구현:** 부품은 `web/components/admin/StageBar.tsx`다. 선은 마지막으로 지난(또는 실패한) 칸까지 차고, 그 앞에서 건너뛴 칸은 함께 차며 끝에 남은 건너뛴 칸(확인으로 멈춘 호출)으로는 잇지 않는다. 건너뛴 칸의 둘째 줄은 '없음' 대신 이유('확인 없음 · 자동 조치', '조치 없이 해제', '확인으로 멈춤', '해제로 멈춤', '기록 없음')를 적는다. 진행 중인 사건의 지금 칸만 주의 색 고리와 주의 글자이고, 호출 막대의 지금 칸 둘째 줄은 다음 호출까지 남은 mm:ss다. 드로어 안에서는 원 안쪽 면이 층의 elevated 면을 따른다(`--stage-surface`). 막대 폭이 219px 이하면 이름 대신 번호를 두고 이름은 툴팁과 접근 이름이 싣는다.
2. **호출 칩:** 경보 행과 사건 목록의 호출 단계는 StateChip이다. 호출 중이면 주의 ▲와 '1차 호출', 확인·해제로 멈췄으면 무채 링과 '1차 호출 · 멈춤'이다. 보낸 호출이 없으면 칩을 두지 않는다.
3. **§12-14 부품 적용:** 사건 목록 행은 행 전체가 단추이고 고른 행만 왼쪽 2px 선과 sunken 면(`aria-current`)이다. 사건 판독은 StatStrip 넷(담당, 확인까지, 경과 또는 해제까지, 런북), 경보·사건 요약은 Tile 다섯이다. 사후 분석 양식의 입력은 44px이고, 재발 방지 조치 한 건은 할 일 한 줄과 담당·기한·완료·빼기 한 줄의 두 줄이다. 완료한 분석은 읽기 표(할 일, 담당, 기한, 완료)다.
4. **자산 표:** 여덟 칸 두 줄(윗줄 값, 아랫줄 짝 항목의 보조 글 `--text-secondary`), 행 52px이고 칸 폭은 표 폭의 몫(%)이다. 식별 글은 왼쪽, 수치와 시각은 오른쪽 tabular다(§12-7). 원천이 없는 칸은 그 칸만 ◌이고, 구축 전 `ai-1`은 짧은 '가정' 표식(원문은 툴팁)이다. 칸 안 구분점도 4.5:1 대비를 지킨다.
5. **아이콘 둘:** 'ack'(확인)과 'timer'(해제 시간)를 경보·사건 요약 칸에 더했다. 다른 관리 아이콘과 같은 16px 선 격자다.
6. **화면 뼈대:** 판을 기다리는 동안 화면마다의 판형(요약 칸 수, 두 칸 비율, 칸마다의 줄 수)으로 뼈대를 세우는 `PageSkeleton`이다. 띠는 기다리는 동안에만 지나가고 움직임 줄이기에서는 멈춘 뼈대다(§12-4).
7. **§12-12 줄바꿈 보강:** 하이픈이 든 이름(app-3, ai-1, db-primary)은 한 덩이로 둔다. 브라우저가 하이픈 뒤를 줄바꿈 자리로 보아 좁은 칸에서 'app-'과 '3'을 가르기 때문이다. 글 안의 이름은 `KeepNames` 조각이 감싸고 글자는 바꾸지 않는다. 승인 티켓 id처럼 표 칸에 드는 식별자는 한 줄 말줄임과 원문 툴팁이다.
8. **누름 영역:** 드로어 안의 입력·고르기·단추를 44px로, 글 단추(빼기, 조치 더하기, 판단 과정), 노드 상세의 이웃 이동 단추, 조치 카드의 더 보기(⋮)의 누름 영역을 44x44로 넓혔다.
9. **본문 스크롤 상자:** 관리 셸의 본문 스크롤 상자(`#admin-main`)를 절대 위치 자손의 기준 상자로 둔다. 기준이 문서면 아래쪽의 보조기술용 글이 문서 높이를 늘려, 초점 이동이나 scrollIntoView가 운영자 바까지 셸 전체를 위로 밀어 올렸다.

## 12. 관리 평면 규칙 (v1.8)

관리 콘솔(`web/app/admin`)에만 적용한다. 거래 화면의 고밀도 계기 규격(패널 명판 micro 11px, 전역 `.btn` 등)은 바꾸지 않는다. 관리 콘솔은 발표에서 강의실 뒷자리와 녹화 영상으로 보이는 화면이라, 조용한 계기 톤은 유지하되 판독 거리를 한 단 늘린다. 화면 판형은 [데스크톱 레이아웃 §7](데스크톱_레이아웃설계.md), 서비스 흐름 화면 고유의 요소는 [관리자 설계 7-10 (i)](../product/관리자_설계.md), 관제센터의 구성요소는 §12-9와 [관리자 설계 4-4](../product/관리자_설계.md)에 있다.

### 12-1. 기본 테마

관리 콘솔은 다크로 시작한다. 관제 화면을 어두운 면 위에 띄우는 B안의 방향이다. 운영자가 테마를 한 번이라도 고르면(`localStorage`의 `theme`) 그 값을 따른다. 저장된 값이 없을 때만 관리 라우트가 `data-theme="dark"`를 세우고, 관리 평면을 떠나면 자기가 세운 표시만 거둬 거래 화면의 기본(시스템 설정)을 건드리지 않는다. 테마 토글은 지금처럼 선택을 저장한다. 두 테마가 같은 대비 계약을 지키므로 라이트는 선택지로 남는다. 현장 프로젝터에서 다크의 틀 선이 흐려지면 리허설에서 라이트로 바꾸고, 그 선택이 저장되어 이후에도 유지된다.

### 12-2. 타이포 단계

**여섯 단계와 굵기 셋(v1.14).** 관리 평면의 글자 크기는 12, 13, 14, 18, 24, 28 여섯 단계이고 굵기는 400, 600, 700 셋이다. 12는 보조 라벨·단위·배지·표 머리·메타, 13은 촘촘한 판독 글과 게이지 값, 14는 본문·패널 제목·단추, 18은 큰 한 줄 판단·상세와 대화상자 제목·임계값 현재값, 24는 화면 제목, 28은 상태 요약 수치와 조치 확인의 변경 전후다. 400은 글과 라벨, 600은 강조·패널 제목·단추·판독값, 700은 화면 제목·큰 수치다. 크기와 굵기를 한 단씩만 늘려 한 칸 안의 강조가 하나로 읽히게 한다(§12-10). 평가 때 한 화면에 크기 10단계와 조합 23가지가 섞여 위계가 흐려졌기 때문이다.

거래 화면의 램프(§4)는 바꾸지 않는다. 관리 셸의 뿌리와 셸 밖에 뜨는 층(모달, 드로어, 확인 대화상자)에서만 토큰을 다시 잇는다. micro(11)는 dense(12)로, body(15)는 body-sm(14)으로, body-lg(17)와 title-2(20)는 title-3(18)로, display-lg(34)는 display-md(28)로 잇고, medium(500)은 regular(400)로 잇는다. 그래서 아래 표에서 micro 11이라 적은 자리는 관리 평면에서 12로, title-2 20은 18로 읽는다. 서비스 흐름 구성도 안의 글자는 무대 배율로 함께 커지는 그림 글자라 같은 여섯 단계를 쓰되 실제 화면 크기는 배율(데스크톱 레이아웃 §7)이 정한다.

### 12-3. 상태 색과 형태

같은 상태는 모든 관리 화면에서 같은 형태와 말로 적는다.

| 상태 | 형태 | 색 | 상태어 |
|---|---|---|---|
| 정상 | ● | 형태(점)만 `--color-success`, 글자는 잉크(`--text-strong`·`--text-default`) | 정상 |
| 주의 | ▲ | 글자 `--color-warning-text`, 형태·선 `--color-warning` | 주의 |
| 장애 | ■ | `--color-danger` | 장애 |
| 중지 | ○ | `--text-secondary` | 중지 |
| 미수집 | ◌ | `--text-secondary` | 미수집 |

- **형태 기호 부품(v1.14).** 형태 기호는 글꼴 글자가 아니라 SVG 부품 `StatusShape` 하나로 그린다. ●(정상·정보), ▲(주의), ■(장애), ○(중지), ◌(미수집·연결 전), ◇(사건 발생), ▶(재생)를 같은 격자(기본 10px, 제목 줄 12px)에 그리고, 한 줄 글에서는 줄의 가운데, 두 줄 행에서는 첫 줄의 가운데에 맞춘다. 글꼴마다 ●와 ▲의 크기와 기준선이 달라 같은 줄의 형태가 1~2px씩 들쭉날쭉하던 문제를 없앤다. 색은 이 표의 형태 색이고 보조기술에는 숨기며 뜻은 옆 글자가 싣는다. 사건 기록 문장이나 토스트처럼 문장 안에 섞인 기호는 글자로 둔다.
- 미수집은 값을 받지 못했다는 사실이고 판정이 아니라 무채로 둔다. 다만 기대한 검사가 수집되지 않아 종합 판정이 막히는 자리(종합 관제의 안전 검사)는 판정 불가를 주의로 올려 '▲ 미수집'으로 적는다.
- 상태어의 '위험'은 '장애'로 적는다. 화면 글자와 보조기술 낭독문 모두 같다. 서버가 응답 본문으로 내려주는 문구(용량 권고의 '안정' 등)는 §10-1의 불변 조항에 따라 화면이 바꾸지 않고, 형태와 색만 이 표를 따른다.
- 서비스 흐름 구성도는 사용자 결정(2026-09-23)에 따라 실행 카드 테두리와 실행 상태 글자를 초록(`--color-success`, 글자는 `--color-success-text`)으로 둔다. 이 예외는 그 화면 안에서만 쓴다.
- 주황(`--color-warning*`)은 실제 주의 상태에만 쓴다. 재생 중 표시, 역할 배지(총괄), 차트 기준선의 축 표지처럼 상태가 아닌 자리에는 쓰지 않는다. 역할 배지는 `--brand-weak-bg` 면에 `--text-brand` 글자(라이트 5.58:1, 다크 7.03:1)를 쓴다. 재생 표시는 v1.11부터 면을 칠하지 않고 1px 점선 `--border-strong` 윤곽에 `--text-default` 글자를 쓰며 형태는 ▶다(§12-10). 차트 기준선은 선만 주황 점선으로 두고, 축 표지는 현재 값이 기준을 넘었을 때만 주황 면으로 칠한다. 평소 표지는 무채 기준선(TTL 등)과 같은 면을 쓴다.

### 12-4. 모션

움직이는 것은 상태 전이뿐이다. 매초 바뀌는 값은 숫자만 바꾸고 움직이지 않는다(§0-6).

- **링 펄스.** 상태가 바뀐 노드 카드와 Auto Scaling 그룹 틀에 바깥 고리가 0에서 10px로 퍼지며 사라진다. 한 번이 `--dur-pulse`(900ms)이고 두 번 반복해 1.8초 동안 보인다. 이징은 `--ease-decelerate`. 고리 색은 새 상태의 형태 색(실행 `--color-success`, 전환 중 `--color-warning`, 장애 `--color-danger`, 중지 `--text-tertiary`)을 45%에서 0%로 투명에 섞는다. 화면이 처음 값을 받는 순간은 전이로 치지 않는다.
- **헬스 플래시.** 대수처럼 사건 때만 바뀌는 숫자는 바뀌는 순간 값 자리 배경을 `--color-health-flash-*`로 `--dur-flash`에 켜고 600ms 뒤 끈다. 기존 `useHealthTransition`과 같은 길이다.
- **표식 등장.** 끊김 표식처럼 새로 나타나는 표식은 `--dur-base`, `--ease-emphasized`로 0.6배에서 제 크기가 된다. 한 번만 돈다.
- **진행 막대.** 재생 경과 막대는 재생 틱 주기와 같은 1초 선형으로 늘어난다.
- **선택 고리 보존.** 링 펄스와 그 정적 대체는 카드의 제 그림자를 덮어쓰므로, 팝오버를 연 노드의 선택 고리는 펄스 동안에도 그 위에 그대로 그린다. 펄스 고리는 선택 고리 바깥으로 보인다.
- **AI 판단 중(v1.9).** 관제센터 AI 패널이 근거를 모아 판단하는 몇 초 동안만 머리 줄 아래 2px 막대에 `--ai-accent` 빛띠가 1.6초 선형으로 왼쪽에서 오른쪽으로 지나가고, 머리에 '판단 중' 글자가 선다. 판단이 끝나면 멈춘다. 늘 도는 장식 애니메이션은 두지 않는다.
- **판단 요청 알갱이(v1.11, v1.14 개정).** 서비스 흐름에서 관제 판의 AI 판단 요청이 걸리는 순간 알갱이 하나가 매칭 칸에서 온프레미스 `ai-1`로 900ms 동안 지나가고, 응답이 돌아오는 순간 알갱이 하나가 반대로 지난다. 알갱이는 12px 채운 원(`--ai-accent`)과 그 뒤를 따르는 투명도 .5와 .25의 작은 점 둘이다. 발광, 흐림, 빈 원은 쓰지 않는다(v1.14). 판단이 없으면 움직이지 않는다. 요청이 걸린 동안에는 점선이 `--ai-accent`로 바뀌고 이름표가 '판단 요청 처리 중'을 적으며, `ai-1` 카드 테두리가 `--ai-accent`가 되고 상태 낱말이 '처리 중'이다. 응답이 돌아오는 순간 카드의 추론 지연 값('0.9초')이 scale(.9→1)로 160ms 동안 제 크기가 된다. 흐름이 없는 선은 초록이 아니라 무채 `--border-strong`이다. 범례 글자는 12px이다. 움직임 줄이기에서는 알갱이 대신 선 가운데에 멈춘 점을 하나 더 두고 지연 값은 커지지 않는다.
- **근거 강조(v1.9).** AI 패널의 근거 칩을 누르면 그 근거가 가리키는 경보 행이나 호스트 카드에 `--ai-accent` 2px 고리가 2초 동안 서고 사라진다. 고리는 제자리 윤곽이라 배치가 움직이지 않는다.
- **움직이는 속성(v1.12).** 전이와 애니메이션은 transform과 opacity만 움직인다. 게이지 막대(`MeterRail`)와 확신도 막대의 채움은 폭이 아니라 가로 배율(scaleX)로, 편향 표지는 left가 아니라 전폭 자리 안의 translateX로 옮긴다. 폭과 위치를 전이하면 매 프레임 배치를 다시 계산해 넓은 판에서 비용이 커진다. 사이드바 폭은 전이 없이 한 번에 바꾼다.
- **상담 패널(v1.12).** 열릴 때 오른쪽에서 24px 들어오며 나타난다(`--dur-base`, `--ease-decelerate`). 생성 중 표시는 AI 판단 중 막대와 같은 2px 빛띠이고 답을 기다리는 동안에만 돈다. 답이 곧바로 와도 0.5초는 보여 깜빡임처럼 스치지 않게 한다.
- **숫자 전환(v1.14).** 사건 때만 바뀌는 수(앱 계층 대수, 활성 경보 수, 대기 조치안 수, 오늘 사건 수, 인프라 정상·주의·장애 집계)는 바뀌는 순간 값 자리에 헬스 플래시(위 헬스 플래시와 같은 600ms)를 켜고, 새 숫자가 opacity .4에서 1로 `--dur-fast`(120ms) 동안 들어온다. 플래시 색은 바뀐 뒤의 상태다(늘어난 경보는 주의, 0으로 내려간 경보는 정상). 매초 바뀌는 지표(CPU, p95, 가용성, 남은 시간, 'n초 전')는 움직이지 않는다. 모든 숫자를 세어 올리는 카운트업은 쓰지 않는다.
- **카드 상태 전이(v1.14).** 관제센터의 호스트 카드, DB 묶음, app-3 Auto Scaling 띠, 상태 요약 칸은 상태가 바뀌면 테두리 색이 `--dur-base`(200ms) 동안 옮겨 가고 위 링 펄스가 선다. 색과 길이는 서비스 흐름과 같다. 화면이 처음 판을 받는 순간은 전이가 아니다.
- **목록 행 등장(v1.14).** 새로 선 경보 행과 사건 기록의 새 행은 translateY(4px→0)와 opacity(0→1)로 `--dur-dialog`(160ms) 동안 들어온다. 사건 기록의 새 행은 들어온 뒤 600ms 동안 헬스 플래시 면을 켠다. 목록을 처음 그릴 때는 움직이지 않는다.
- **조치안 카드 자리 이동(v1.14).** 대기 조치안이 처리된 조치로 옮겨 가거나 앞 카드가 빠져 자리가 바뀌면 FLIP으로 옮긴다. 바뀐 자리에서 이전 자리만큼 되돌려 놓은 뒤 200ms(`--dur-base`) 동안 제자리로 온다. transform만 쓰고 1px 아래 움직임은 무시한다.
- **사건 단계 막대(v1.14).** 사건 단계 줄 뒤의 막대가 지나온 단계까지 가로 배율(scaleX)로 200ms 동안 늘어난다.
- **층 등장(v1.14).** 모달과 확인 대화상자는 opacity와 scale(.98→1)로 `--dur-dialog`(160ms), 드로어는 opacity와 translateX(24px→0)로 `--dur-base`(200ms), 배경 덮개는 opacity로 160ms 동안 들어온다. 닫을 때는 같은 속성을 거꾸로 120ms 동안 돌린다. 이징은 `--ease-decelerate`다.
- **뼈대 로딩(v1.14).** 관제 화면이 처음 판을 기다리는 동안 판의 구조(모드 줄, 상태 요약 다섯 칸, 세 기둥의 머리와 행)를 따르는 골격을 그린다. 골격 위를 `::after` 띠가 `--dur-skeleton`(1.2초)에 한 번 왼쪽에서 오른쪽으로 지난다(transform). 판이 오면 멈춘다. 늘 도는 장식이 아니라 기다리는 동안의 표시다.
- **판단 과정 점등(v1.14).** AI 판단 상세(§12-13)를 한 판단에 대해 처음 열 때 판단 과정 다섯 단계가 120ms 간격으로 차례로 켜진다(각 단계 opacity와 translateY 4px, 160ms). 같은 판단을 다시 열면 곧바로 모두 보인다.
- **되돌림·정지 순간(v1.14).** 자동 되돌림은 app-3 Auto Scaling 띠와 되돌린 조치의 주의 색 링 펄스, 모드 줄의 30초 알림 줄(§12-9), 사건 기록 새 줄의 플래시, 조치안 카드 자리 이동이 함께 알린다. AI 정지와 재개, 자동 상한 도달, 유효 시간 만료도 모드 줄 알림 줄을 쓴다.
- **움직이는 속성의 예외(v1.14).** 링 펄스(box-shadow)와 헬스 플래시(배경색)는 상태가 바뀔 때 한 번만 도는 표시라 위 transform·opacity 규칙의 예외다. 테두리 색 전이도 같다.
- **움직임 줄이기.** `prefers-reduced-motion`에서는 위 애니메이션과 전이를 모두 끈다. v1.14의 대체는 다음과 같다. 숫자 전환은 플래시와 교차 없이 값만 바뀌고, 카드 상태 전이의 링 펄스는 같은 1.8초 동안 3px 정적 고리, 목록 행과 층은 움직임 없이 나타나며, FLIP과 단계 막대는 곧바로 바뀐 자리에 서고, 뼈대는 멈춘 골격, 판단 과정은 한 번에 모두 보인다. 상담 패널은 등장 움직임 없이 나타나고 생성 중 빛띠는 멈춘 점선 막대로 대신한다. 링 펄스 자리는 같은 1.8초 동안 3px 정적 고리로 대신하고(선택 고리가 있는 노드는 그 바깥 3px, 움직임이 아니라 표시다), 플래시는 켜지 않으며(§5 킬스위치), 진행 막대는 틱마다 바로 바뀐다. AI 판단 중의 빛띠는 멈춘 점선 막대로 대신하고 '판단 중' 글자는 그대로 둔다. 근거 강조 고리는 움직임이 아니라 표시라 같은 2초 동안 그대로 선다. 상태는 늘 테두리 모양과 형태 기호가 함께 실으므로 움직임이 없어도 뜻은 남는다.

### 12-5. 버튼 규격

관리 평면의 조작 버튼은 한 규격이다. 시각 높이 36px, 좌우 여백 `--space-4`, 글자 `--font-body-sm` 14/600, 모서리 `--panel-radius`, 히트 영역 44px(투명 `::after`, §10-2). 변형은 넷이다.

- **approve.** `--brand-primary-fill` 면에 `--text-on-brand`. 화면당 긍정 확정 하나(출금 승인, 문의 답변 등록)에만 쓴다. 관제센터의 조치 카드 '승인하고 실행'은 운영자의 결정이라 AI 색이 아니라 이 변형을 쓴다(§12-9). 같은 화면의 승인 목록 '발급'은 조치 카드와 같은 승인 흐름의 한 단계라 예외로 함께 둔다.
- **neutral.** `--surface-control` 면에 `--text-strong`. 기본 조작이다.
- **danger.** 투명 면에 `--color-danger` 1px 테두리와 글자. 되돌릴 수 없는 거절·삭제·중단이다.
- **텍스트 링크.** 관측 딥링크(`boardLink`)처럼 다른 화면으로 가는 자리다.

**대화상자 단추 줄(v1.14).** 확인 대화상자와 모달의 단추는 오른쪽 끝에 모으고, '취소'가 왼쪽, 확정이 오른쪽 끝이다. '취소'는 neutral 변형이고 첫 포커스다. 확정은 긍정 확정(승인하고 실행, 승인하고 켜기, 재개)이면 approve, 되돌릴 수 없는 중단·삭제·거절이면 danger, 비파괴 주의 조작이면 주의 윤곽(`--color-warning-text` 1px 테두리와 글자)이다. 두 단추는 버튼 규격 그대로 36px에 누르는 자리 44px이다. 층의 면(`--surface-elevated`)은 다크에서 중립 단추 면(`--surface-control`)과 같은 색이라, 층 안의 neutral 단추는 1px `--border-default` 안쪽 테두리로 모양을 남긴다. **폼 줄(v1.14).** 입력칸, 고르기, 숫자 입력은 40px이고, 폼 줄에서 입력칸과 나란히 서는 단추는 입력칸 높이(40px)에 맞춰 윗선과 아랫선이 한 줄에 선다.

전역 `.btn`(A-3, 17px/44px, 수식어 없이는 면이 없다)은 관리 평면에서 쓰지 않는다. 한 줄에 파괴 버튼과 다른 버튼이 함께 서면 버튼을 한쪽 끝에 모으고 파괴 쪽을 맨 끝 묶음에 두며, 묶음 사이를 세로 헤어라인이나 12px 이상 간격으로 가른다.

### 12-6. 비활성 표현

글자와 버튼에 opacity를 쓰지 않는다. 겹친 투명도는 곱해져 토큰이 지킨 대비를 무너뜨리고(잠긴 단계 0.72 x 비활성 0.5 = 0.36), 버튼 모양도 사라진다.

- **비활성 버튼.** 면을 비우고(transparent) 1px 점선 `--text-tertiary` 테두리(흰 면 3.59:1, sunken 3.23:1), 라벨 `--text-secondary`, 커서 not-allowed. 막힌 이유는 지금처럼 옆에 문구로 둔다. 네 변형 모두 같다.
- **아직 오지 않은 단계와 판정하지 않는 줄**(사건 단계의 아직 오지 않은 단계, 원천 없는 줄). 글자만 `--text-secondary`로 한 단 낮추고 표식 원은 면을 비운 채 `--border-strong` 테두리로 두며, 상태어가 있으면 앞에 ○나 ◌를 둔다. 설명과 판독값은 제 잉크 그대로다. 이 규칙을 처음 쓴 상황별 대본은 2026-09-24 사용자 요구로 지웠다(관리자 설계 4-5).
- **연결 지연.** A-5를 따른다. 관리 화면의 지연 구역도 글자를 흐리지 않고 사선 무늬 면과 머리의 지연 배지로 알린다.

### 12-7. 표 정렬

열의 성격으로 정렬을 정한다. 식별 텍스트(이메일, 표시명, 마켓, 운영자, 액션 코드, 대상)는 왼쪽, 수치·금액·수수료·비율·시각은 오른쪽(tabular-nums), 상태 배지는 가운데, 조치 버튼 열은 오른쪽이다. 표 전체를 가운데로 두는 `defaultAlign="center"`는 쓰지 않는다. 예외는 모든 칸이 한두 자리 대수라 오른쪽 정렬로 얻는 자릿수 맞춤이 없는 행렬(봇 플릿의 마켓 x 유형 대수 표)이고, 그 표의 수치 열은 가운데에 둘 수 있다. 정렬만 바꾸며 금액의 표시 형식과 계산 경로는 건드리지 않는다.

### 12-8. 패널 제목과 오류 상태

- 관리 셸 안의 PanelCard 제목은 §12-2의 패널 제목 단계를 쓴다. 공용 PanelCard의 거래 화면 명판은 그대로 두고 관리 셸 범위에서만 덮는다.
- 최초 로드 실패는 빈 상태와 모양을 가른다. 1px `--color-danger` 테두리, `--color-danger-bg` 면, `--panel-radius`, 제목 앞 ■와 `--text-strong` 제목, 설명 `--text-default`. 세션 만료는 ▲와 `--color-warning-text` 테두리, `--color-warning-bg` 면이다. 빈 상태(값 없음)는 지금처럼 무채 계기 마크를 쓴다.
- 원천 연결 전(v1.9)은 셋째 모양이다. 값이 없는 것도, 불러오기에 실패한 것도 아니고 그 값을 낼 원천을 아직 붙이지 않았다는 사실이다. 1px 점선 `--border-strong` 테두리, 면 없음, 제목 앞 ◌와 `--text-default` 제목('원천 연결 전'), 설명은 붙일 원천의 이름(예: 'Prometheus 조회 API · 2단계')이다. 경보색을 쓰지 않는다.

### 12-9. MSP AI 관제센터 (v1.9)

관제센터(`/admin`)는 Grafana와 역할을 가른다. Grafana는 추이를 보고 탐색하는 곳이라 임계값을 고치거나 조치를 실행하지 않는다. 관제센터는 지금 값과 임계를 보고 판단하고, 조치를 승인하고, 누가 무엇을 왜 바꿨는지 남기는 곳이다. 그래서 이 화면은 추이 그래프를 그리지 않고 현재값, 임계 눈금, 상태, 조치, 기록을 둔다. 예외는 상태 요약 칸의 작은 추세선 하나씩이다(v1.11, 2026-09-25 사용자 요구). 범위만 1·6·24시간 가운데 고르고 확대·비교·탐색은 하지 않는다. 추이를 탐색할 자리마다 Grafana 딥링크를 둔다. 구성과 동작은 [관리자 설계 4-4](../product/관리자_설계.md), AI 권한 규칙은 [ADR 0035](../adr/0035-ai-operations-authority.md)가 정한다.

- **AI 강조색(v1.11 개정).** `--ai-accent`(그래픽), `--ai-accent-text`(글자), `--ai-accent-bg`(면)는 AI가 말하거나 한 일에만, 그것도 작은 자리에만 쓴다. AI 표지(칩 모양 아이콘), 확신도 막대, 대기 조치 카드의 안쪽 2px 선, '자동 실행 가능' 배지 윤곽, 사건 단계와 타임라인의 AI 점과 행위자, 판단 중 막대, 자동 모드 줄의 테두리, 임계값 표의 AI 제안값 표식, 서비스 흐름의 판단 요청 알갱이가 그 자리다. 면(`--ai-accent-bg`)은 판단 중 막대의 트랙과 임계값 표·이력의 AI 표지 같은 작은 태그에만 쓰고 패널이나 줄 전체를 칠하지 않는다. AI 패널의 틀과 머리, 근거 칩은 다른 기둥과 같은 무채다. 운영자의 결정(승인하고 실행)은 브랜드 approve 버튼이고, 상태는 §12-3의 헬스 색이다. 보라를 상태어·경고·링크에 쓰지 않는다.
- **AI 패널(v1.11 개정).** 세 기둥 가운데 기둥이다. 틀은 다른 두 기둥과 같은 1px `--border-subtle` 헤어라인이고 머리 줄은 면을 칠하지 않는다. AI라는 사실은 빛이나 틴트가 아니라 내용(큰 한 줄 판단, 근거, AI 판단 요약, 정책 검사 결과)과 판단 과정으로 드러낸다. 머리에는 AI 표지(`--ai-accent`)와 'AI 관제' 제목, 모드, 오른쪽에 판단 시각과 '판단 기록' 링크를 둔다. 시뮬레이션 표식은 화면 머리에 한 번만 두므로(§12-12) 패널 머리에는 달지 않는다. 본문 순서(v1.13)는 큰 한 줄 판단과 이어지는 설명(§12-2), 권장 조치 카드, 근거 칩과 원인 가설, 처리된 조치, 판단 기록이다. 운영자가 할 일(승인하고 실행)이 판단 바로 아래 첫 화면에 서게 하려는 순서다. 새 판단 기록이 생기면 기둥 안 스크롤을 맨 위로 되돌려 새 판단과 조치안이 먼저 보이게 한다. 바닥 줄에 모델, 판단 시각, 근거 수집 시각과 가드레일 문장('AI는 허용 목록 안의 조치만 제안하고 실행한다. 금지 목록은 어느 모드에서도 하지 않는다')을 둔다. http 데이터 원천에서 AI 원천이 없으면 'AI 연결 전' 빈 상태만 그리고 지어낸 문장을 보이지 않는다.
- **평상 한 줄(v1.14).** 대기 조치안이 없으면 '권장 조치 n건' 머리와 빈 상자를 두지 않고 한 줄로 적는다. '권장 조치 없음 · 5초마다 판단 · 지난 24시간 AI 조치 n회 · 되돌림 m회'(dense 12 `--text-secondary`, 값만 600 `--text-strong`). n은 지난 24시간에 승인·자동으로 실행한 AI 조치 수, m은 그중 되돌린 수이고 감사 기록에서 센다. 평상시 AI 패널이 빈 상자 두 개로 자리를 먹던 모양을 없앤다.
- **마지막 조치 결과(v1.14).** 대기 조치안이 없고 15분 안에 처리된 조치가 있으면 평상 한 줄 대신 그 자리에 '마지막 조치 결과'를 둔다. 결과의 형태 기호와 낱말(실행됨, 자동 실행됨, 자동 되돌림, 되돌림, 거절, AI 정지로 만료), 조치 제목, 결과('되돌림 · app-3 켜기 (앱 2 → 3대) · 앱 평균 CPU 62% ≥ 60%'), 시각과 행위자다. 자동 되돌림은 주의 색 형태다. 되돌림과 정지 직후 AI 패널이 빈 상자로 비어 보이지 않게 하고, 같은 조치를 아래 '처리된 조치'에 한 번 더 적지 않는다.
- **판단 기록 행(v1.14).** 첫 줄에 시각과 결과(600), 둘째 줄에 요약을 두 줄까지 적고 넘치면 말줄임과 원문 툴팁이다. 행을 누르면 AI 판단 상세(§12-13)가 열린다. 1280 창에서 요약 칸이 130px로 좁아 툴팁으로만 읽히던 한 줄 배치를 바꾼다.
- **근거 칩(v1.11 개정).** 무채 네모 칩이다(1px `--border-default`, 면 `--surface-default`, 모서리 `--radius-xs`, 글자 `--text-default`, 값만 600 `--text-strong`). 경보 근거는 그 경보의 심각도 형태(■▲●)를 앞에 두고, 지표 근거는 형태 없이 이름과 값을 적는다. 누르면 근거 강조(§12-4)가 선다. 호스트를 가리키는 근거는 DB 묶음 안에서도 그 노드의 칸만 켜고, 복제를 가리키는 근거만 묶음 전체를 켠다(v1.14). 칩 묶음 머리에는 '근거'와 함께 '판단 hh:mm:ss 기준'(dense 12, tabular)을 적는다(v1.13). 칩의 값은 판단한 순간의 값이라, 매초 바뀌는 경보 행·게이지·사건 기록의 값과 같은 판에 나란히 서도 어느 시점의 값인지 읽힌다.
- **AI 판단 요약(v1.13 개정).** 네 칸 상자를 거두고 그 내용을 대기 조치 카드 안의 요약 한 줄로 옮긴다. 줄은 확신도(값, 48px 막대와 자동 실행 기준 눈금), 위험도(형태와 낱말), 되돌리기('과거 같은 조치 n회 · 되돌림 m회')를 가운뎃점으로 잇는다(dense 12, 값만 600 `--text-strong`). 위험도는 상태가 아니라 조치의 성질이라 낮음은 무채 ●이고 중간만 `--color-warning-text` ▲다. 카드 폭이 좁으면 항목 단위로 다음 줄로 넘기고 항목 안에서는 끊지 않는다. 조치안이 없으면 요약도 없다. 네 칸에 '해당 없음'을 채우던 모양은 쓰지 않는다. '과거 같은 조치'는 감사 기록에서 센 값이고 근거 없는 성공률이나 '유사 패턴 n회 분석' 같은 수치는 쓰지 않는다.
- **확신도(v1.13 개정).** 요약 한 줄의 첫 항목이다. 값은 '88% · 높음'(tabular)이고 옆에 4px 막대를 둔다. 막대 채움은 `--ai-accent`, 트랙은 라이트 `--surface-sunken`, 다크 `--border-default`다. 다크 sunken이 패널 면과 1.06:1이라 트랙 끝이 보이지 않는 이유로 서비스 흐름의 자막 진행 막대와 같게 둔다. 눈금은 자동 실행 기준(ADR 0035, AI 한도의 확신도 기준)이다. 낱말은 그 기준에 맞춘다. 기준 이상이면 '높음', 60% 이상 기준 미만이면 '보통', 60% 미만이면 '낮음'이다. 기준을 넘는 값을 '보통'으로 적어 자동 실행 조건과 모순되게 하지 않는다.
- **조치 카드.** 대기 중인 조치안은 번호, 제목, 요약 한 줄(확신도, 위험도 ● 낮음·▲ 중간, 과거 같은 조치), 대상, 예상 영향, 되돌리기 방법, 버튼 세 개(승인하고 실행은 approve 변형, 거절과 나중에는 neutral 변형)를 한 카드에 담는다. 카드마다 `ai-proposal-n` 앵커를 두어 모드 줄의 조치안 링크가 첫 카드로 스크롤하고 포커스를 옮긴다(v1.13). 카드 틀은 무채 헤어라인이다. 대기 카드는 번호 칸(20px 네모)의 테두리와 번호 글자를 `--ai-accent`·`--ai-accent-text`로 두어 AI가 낸 대기 조치임을 알린다(v1.14). 안쪽 왼쪽 2px 선은 §12-14의 선택 표시에만 쓰므로 카드에 두지 않는다. 머리 오른쪽에 배지 하나('자동 실행 가능'은 `--ai-accent` 윤곽과 `--ai-accent-text` 글자, '승인 필요'는 무채 윤곽이고 자동 모드에서도 완화 방향의 임계값과 봇 용량 보호 기준 아래의 봇 부하 줄임은 '승인 필요'(ADR 0035), '정지로 만료'와 처리된 표지는 무채 흐린 글자)와 ⋮ 메뉴(근거 보기, 기록 보기)를 둔다. 배지는 네모 태그(`--radius-xs`)다. 번호는 대기 중인 조치안에만 붙이고 '권장 조치 n건'의 n과 같다(v1.10). 처리된 조치는 그 아래 '처리된 조치' 묶음에 번호 없이 두고, 제목을 body-sm으로 한 단 낮추며 '처리됨' 표식(무채 윤곽)을 단다. 처리된 카드는 예상 영향 대신 '결과'에 실제로 바꾼 것을 적고, 바닥에 결정을 적는다('승인 · 김수퍼 14:02 · 실행됨', '거절', '나중에'). 자동 실행된 카드는 '자동 실행됨 · 되돌리기 mm:ss'와 되돌리기 버튼, 자동 되돌린 카드는 ▲ '자동 되돌림'이고 결과에 되돌린 방향과 이유를 적는다('되돌림 · app-3 켜기 (앱 2 → 3대) · 앱 평균 CPU 62% ≥ 60%'). AI 정지로 만료된 조치는 카드가 아니라 한 줄 상태로 적는다('○ AI 정지로 만료 · app-3 켜기 (앱 2 → 3대) · 김수퍼 08:10:02', v1.14). 누를 수 없는 승인 버튼을 카드째 남기던 모양은 쓰지 않는다. '승인하고 실행'을 누르면 조치 확인(§12-13의 5)이 열린다. 자동 조건에 걸려 대기하는 카드는 이유를 한 줄로 적는다('한 번에 한 조치 · 관찰 창 뒤'). 금지 목록 조치는 카드로 나오지 않는다.
- **임계값 편집 칸(v1.14).** 행마다 슬라이더와 숫자 칸이 같은 값을 고치지만 건반 초점은 숫자 칸 하나에만 선다(슬라이더는 끌기 전용, `tabindex=-1`). 위·아래 화살표는 한 눈금, PageUp·PageDown은 열 눈금씩 허용 범위 안에서 움직이고, Esc는 고치던 값을 버린다. 표를 건너는 탭 수가 행마다 둘에서 하나로 준다.
- **임계 눈금.** 호스트 게이지·ASG 사용률·복제 지연 막대의 2px `--text-strong` 눈금(MeterRail 기준선)은 임계값 관리 표의 현재값과 같은 값이다. 값이 임계 이상이면 채움이 `--color-warning`, 장애 임계 이상이면 `--color-danger`이고 형태 기호를 함께 적는다. 디스크는 사용률로 그리고 눈금은 '100 - 여유 임계'에 둔다.
- **모드 스위치.** 머리 아래 AI 운영 모드 줄의 두 칸 분절 [수동 | 자동]이다. 수동이 기본이다. 자동을 누르면 확인 대화상자(사유 입력, 유효 시간 1·2·4·8시간, 허용·금지 목록, 1인 승인 티켓 발급·소각 고지)를 거쳐야 켜진다. 줄 끝에는 허용·금지 목록과 'AI 한도' 텍스트 링크를 둔다. 'AI 즉시 정지'와 'AI 재개'는 v1.13부터 이 줄이 아니라 운영자 바에 선다(아래 운영자 바). AI 상담 패널이 줄 오른쪽 끝을 덮어 정지 단추가 가려지던 배치를 없애고, 관제센터 밖의 화면에서도 같은 자리에서 멈출 수 있게 한다. 수동 모드 줄은 뜻과 함께 '조치안 n건'을 텍스트 링크로 적고, 누르면 AI 관제의 첫 대기 카드로 스크롤해 그 카드에 포커스를 옮긴다(v1.13). 자동인 동안 줄 테두리가 `--ai-accent`가 되고 면은 칠하지 않는다(v1.11). 자동 줄은 숫자를 먼저 싣는다. 남은 유효 시간('1시간 59분', §12-12), '이번 자동 모드 n/상한', 조치별 쿨다운(mm:ss), 관찰 창 진행과 대기 조치안 링크 순서이고, 사유는 줄에 적지 않고 정보 표지의 툴팁과 접근 이름으로 옮긴다(v1.13). 칸 폭이 모자라면 관찰 창 막대를 먼저 거두고 숫자는 남긴다. 숫자가 잘려 '09:'처럼 보이는 일이 없어야 한다. **알림 줄(v1.14).** 자동 되돌림, AI 정지와 재개, 자동 상한 도달, 유효 시간 만료 뒤 30초 동안 모드 줄의 뜻 글자 자리에 그 사건을 한 줄로 적는다('▲ 08:12:03 자동 되돌림 · app-3 켜기 (앱 2 → 3대) · 앱 평균 CPU 62% ≥ 60% · 수동으로 바뀌었습니다'). 형태와 글자 색은 사건의 성질이다. 되돌림과 정지는 주의, 재개·상한·만료는 무채다. 오른쪽 끝에 사건 기록을 여는 텍스트 링크를 둔다. 줄 높이는 그대로이고 30초가 지나면 평소 글로 돌아간다. 알림과 그 끝 시각은 관제 판의 AI 칸(`notice`)이 정하고 화면이 따로 세지 않는다. 되돌림 뒤 모드 줄이 평소 문구로 곧바로 돌아가 무슨 일이 있었는지 사라지던 문제를 없앤다. 정지 중에는 줄이 `--color-warning-bg` 면과 `--color-warning-text` 테두리로 바뀌고, 두 스위치 칸은 §12-6의 비활성 모양이 되며, 글에 ▲ 'AI 정지 중'(`--color-warning-text`)과 정지한 운영자·시각, 관찰 창이 남았으면 '관찰 창은 끝까지 봄'을 적는다. 정지는 장애가 아니라 운영자가 AI를 멈춘 주의 상태로 적는다(§12-3). 줄 높이는 세 상태 모두 같다. http 데이터 원천에서는 자동 칸이 보이되 비활성이고 줄 글에 '서버 정책 엔진 연결 전'을 적는다. 남은 시간과 쿨다운은 숫자만 바뀌고 낭독하지 않는다.
- **AI 한도 칸(v1.10).** AI 판단 화면에 둔다. 임계값 관리 표와 같은 표 문법(항목과 설명, 현재값 title-3, 허용 범위, 새 값 숫자 입력)이고, 넓히는 변경이 다음 활성을 기다리면 현재값 아래에 '→ 값 다음 활성부터'를 caption 13/600으로 적는다. 값을 바꾸면 변경 검토 상자에 변경 전후, 적용 시점, 사유 입력이 서고, 사유가 없거나 하드 범위 밖이면 [변경 요청]을 §12-6의 비활성 모양으로 두고 이유를 옆에 적는다(범위 밖은 ■와 `--color-danger` 글). 승인 대기와 변경 이력(적용: '곧바로', '다음 활성부터', 되돌리기)은 임계값 관리와 같은 부품이다. 한도는 AI가 말하거나 한 일이 아니라 운영자의 설정이라 AI 강조색을 쓰지 않는다.
- **출처 칩과 환경 배지(v1.13 개정).** 머리 제목 옆에 값의 출처를 한 번 적는다. sim이면 §12-12의 '시뮬레이션' 표식 하나만 둔다. 환경 배지 '시뮬레이터'와 출처 칩 '시뮬레이션 · 재생'을 나란히 두던 중복은 거둔다. 실측 원천이면 환경 배지(로컬 Docker, 학교 AWS, 개인 AWS, 환경 미확인. 무채 윤곽)와 출처 칩을 둔다. 출처 칩은 '● 실측 · N초 전', 마지막 수집이 폴링 두 주기를 넘으면 '▲ 실측 · N초 전 · 지연', 원천이 없으면 '◌ 원천 연결 전'이다. 모두 네모 칩(`--radius-xs`)이다.
- **상태 요약(v1.11 개정).** 다섯 칸이다(외부 가용성, 응답 p95, 5xx 비율, 활성 경보, 오늘 사건). 칸마다 왼쪽 32px 아이콘 칸(무채 헤어라인), 이름과 오른쪽 끝의 증감(§12-2), 큰 수치(display-md)와 흐린 단위(caption 13 `--text-secondary`), 오른쪽의 작은 추세선, 목표·보조 줄(dense 12)을 둔다. 증감(v1.13 개정)은 지금 값과 고른 범위의 6분의 1 앞 시점 값의 차이다(1시간 범위는 10분 전, 6시간은 1시간 전, 24시간은 4시간 전). 한 구간 평균끼리 견주면 방금 오른 507ms 옆에 '0%'가 서는 모순이 생겨서다. 값은 지표 단위로 적는다(p95는 ms, 가용성·5xx는 %p 소수 둘째 자리, 경보는 활성 수의 차, 사건은 그 사이에 연 수). 차이가 없으면 '±0'이다. 칸이 목표를 벗어난 동안에는 증감 대신 벗어난 시간을 칸의 상태색으로 적는다('목표 초과 12분째', 가용성은 '목표 미달', 경보 칸은 '첫 경보 3분째', 사건 칸은 '진행 5분째'). 증감의 색은 칸의 상태색을 넘지 않는다. 정상 칸에서 좋아진 증감은 `--color-success-text`, 나빠진 증감은 잉크 `--text-default`, 변화 없음은 `--text-secondary`이고, 주의·장애 색은 목표를 벗어난 칸에서만 쓴다. 목표를 벗어난 칸만 테두리·형태 기호·수치가 헬스 색을 받고 정상 칸은 잉크로 둔다. 활성 경보는 ■ 장애, ▲ 주의, ● 정보의 개수를 형태와 함께 적는다. 추세선은 1.5px `--text-tertiary` 선 하나이고 마지막 점(7px)만 `--chrome-accent`, 목표를 벗어난 칸이면 상태색이다. 세로 축은 최저·최고가 아니라 지표마다 정한 최소 폭(가용성·5xx 0.06%p, p95 60ms)을 덮어 작은 흔들림을 칸 높이 전체로 늘리지 않는다. 경보는 0부터 잰 선, 사건은 바닥선 위의 막대다. 가리키면 그 시점의 값이 뜨고, 같은 값은 보조기술용 요약(최저·최고·마지막)으로도 읽힌다. 칸 폭이 230px 아래면 아이콘 칸을 거둔다.
- **세 가지 빈 모양.** 값 없음(무채 계기 마크, 예: '활성 경보 없음'), 불러오기 실패(§12-8의 장애 면), 원천 연결 전(§12-8의 점선 윤곽)을 섞지 않는다.
- **운영자 바(v1.11).** 왼쪽은 관제 검색칸(1px `--border-default` 윤곽, 면 없음, 16px 돋보기와 'Ctrl K' 키 표지)이다. 결과는 떠 있는 층(`--surface-elevated`, `--shadow-2`)에 서버·경보·사건·조치 기록 묶음으로 나뉘어 묶음마다 4건까지 선다. 콤보박스 규칙(화살표로 고르고 Enter로 가고 Escape로 닫기)을 따른다. 오른쪽의 전체 상태는 형태·낱말·세부 수('경보 2 · 노드 1')를 한 네모 안에 적는다. 정상은 무채 윤곽과 초록 점, 주의는 `--color-warning-text` 윤곽과 글자, 장애는 `--color-danger` 윤곽·글자와 `--color-danger-bg` 면이다. 장애가 하나라도 있으면 '정상'이라 쓰지 않는다. 경보 종은 활성 경보 수를 작은 원 안에 적고(가장 무거운 등급의 색 윤곽), 누르면 경보·사건으로 간다. 오른쪽 묶음 맨 앞(검색칸 다음, 세로 헤어라인으로 상태 신호와 가름)에 'AI 즉시 정지'를 둔다(v1.13). 운영 관제 셸의 모든 화면에서 같은 자리이고 승인 없이 누구나 누른다. 수동 모드의 평상 톤은 neutral 버튼에 형태 ■만 `--color-danger`다. 조치를 실행하지 않는 수동 판에서 가장 채도 높은 조작이 정지 단추가 되지 않게 한다. 자동 모드 동안에는 AI가 실제로 조치를 실행하므로 danger 변형(투명 면, `--color-danger` 테두리와 글자)으로 올린다. 정지 중에는 그 자리에 ▲ 'AI 정지 중'(`--color-warning-text`)과 'AI 재개'(neutral, 사유 입력 대화상자, SUPER)가 선다. http 원천에서는 단추가 보이되 §12-6의 비활성 모양이고 이유('서버 정책 엔진 연결 전')를 툴팁과 접근 이름에 싣는다. 백오피스 셸은 관제 판을 읽지 않아 두지 않는다.
- **인프라 역할 묶음(v1.11).** 묶음 이름표(dense 12/600 `--text-default`와 흐린 설명)가 카드 위에 선다. 카드 상태 문구는 운영 중(● 초록 점), 임계치 초과(▲·■와 상태색 테두리), 수집 끊김(◌ 점선)이다. DB 묶음은 Primary와 Standby를 한 카드에 나란히 두고 사이 칸에 복제 화살표, 지연 초(caption 13/700)와 바이트를 적는다. 온프레미스 `ai-1` 카드는 구축 전이라 점선 테두리다. sim은 `ai-1`이 붙어 판단 요청에 답한다고 가정하므로 카드에 §12-12의 '시뮬레이션 가정' 표식과 '구축 전 · 연결 경로 결정 전'을 함께 적고, 이 가정을 쓰는 모든 화면(서버·노드, 서비스 흐름, 설정, 상담 답)이 같은 표식과 같은 말을 쓴다(v1.13). 머리 집계(정상·주의·장애)는 구축 전인 `ai-1`을 세지 않는다. 기둥 안쪽 폭이 340px 아래면 관측과 온프레미스 카드도 한 줄에 하나씩 쌓아 카드가 칸 밖으로 넘치지 않게 한다.
- **사건 타임라인(v1.11).** 기록은 세로 헤어라인 레일 위의 9px 점으로 늘어선다. 점은 누가 했는지(시스템 무채 빈 원, AI `--ai-accent`, 운영자 `--text-strong`)와 발생(주의 색 마름모), 되돌림(주의 색), 해제(초록)를 가른다. 머리의 거르기는 전체·경보·AI·운영자 네 칸 분절이다.
- **외부 도구 딥링크.** Grafana(추이)와 Databasus(백업 관리) 링크는 §12-5의 텍스트 링크 변형이고 ↗를 붙인다. 주소는 빌드 때 받고, 없으면 링크를 그리지 않는다. 닿지 않는 주소를 걸어 두지 않는다.
- **운영 관제 내비(2026-09-24 사용자 요구로 개편, v1.16 3라운드 개정).** 묶음은 관제(관제센터, 경보·사건, AI 판단), 인프라(서버·노드, 데이터베이스, 용량·부하, 네트워크·보안), 조치(임계값 관리, 변경·작업, 조치 기록, 런북, 봇 플릿), 보고(보고서, SLA 월간 보고, 비용), 시연(서비스 흐름, 지표 관제, 시나리오)이고 맨 아래 바닥 줄에 설정과 백오피스로 가는 링크가 있다. 처음에는 관제 묶음과 지금 화면이 든 묶음만 펴고, 운영자가 펴고 접은 선택을 묶음마다 기억한다(관리자 설계 4-10-1). 메뉴 배지는 셀 것이 있을 때만 단다. 3라운드의 새 배지는 네트워크·보안의 인증서 만료(30일 이내 ▲ 주의, 7일 이내 ■ 장애), 변경·작업의 진행 중인 계획 작업 창(무채 윤곽의 '진행', 상태가 아니라 사실), 비용의 소진 예상(계획 소진 예상일이 운영 종료일보다 이를 때 ▲)이고 모양은 아래 배지 규칙과 같다. 경보·사건은 가장 무거운 경보의 형태와 개수(■ 2, ▲ 1, ● 1), 서버·노드는 임계를 넘은 호스트와 조회 계층의 수, 데이터베이스는 복제 지연·끊김이나 백업 지연의 형태, AI 판단은 '제안 n', 임계값 관리는 AI 제안값 수 'AI n'이다. 배지는 네모 태그(`--radius-xs`) 한 모양이다(v1.11). 장애·주의 배지만 옅은 상태 면을 칠하고, 정보와 AI 배지는 무채 윤곽에 글자만 색(AI는 `--ai-accent-text`)을 받는다. 늘 글자나 형태와 함께 쓴다. 배지의 형태는 StatusShape 8px다. 내비를 접으면 글자 배지 대신 형태 하나(8px, 둘레 2px을 사이드바 면 색으로 파낸 12px 원 안)가 아이콘의 오른쪽 위 모서리에 선다(v1.14). 형태 색은 배지의 뜻(장애 `--color-danger`, 주의 `--color-warning`, 정보 `--text-secondary`, AI `--ai-accent`)이고 AI 배지는 원이다. 72px 기둥에서 '제안 2' 같은 글자 배지가 아이콘을 덮고 목록 상자에 잘리던 모양을 없앤다. 접힌 기둥의 건수는 화면 낭독 글이 싣는다. 내비 바닥에는 AI 모드를 적는다('AI 수동 · 실행은 승인', 자동이면 'AI 자동 · 1시간 59분 남음'(모드 줄과 같은 꼴, §12-12)이고 표지와 '자동'만 AI 강조색(v1.11, 테두리와 면은 무채), 정지면 '▲ AI 정지 · 판단 멈춤'과 주의 색 테두리·글자, 원천이 없으면 'AI 연결 전'). v1.12에서 관제 묶음에 보고서를 더하고, 설정은 백오피스 링크와 나란한 바닥 줄(44px 두 칸, 사이 세로 헤어라인)에 두었다. 묶음 머리(시각 32px, 누르는 자리 44px)를 누르면 묶음을 접고 편다. 접힌 머리는 항목 수와 항목들의 배지를 모아 적고 셰브런이 -90도 돈다. 지금 화면이 든 묶음은 접지 않는다. 명판 줄은 위 여백 8px에 높이 40px이라 가운데가 운영자 바(56px)의 가운데에 선다. 줄 오른쪽의 두 단추(AI 상담, 내비 접기)는 36px에 누르는 자리 44px이고, 상담이 열려 있으면 상담 단추가 크롬 악센트 글자와 sunken 면으로 눌린 상태를 적는다(aria-expanded 병기).
- **새 화면.** 경보·사건, AI 판단, 서버·노드, 데이터베이스, 임계값 관리는 관제센터의 부품(상태 요약 칸, 호스트 카드, 경보 행, 사건 단계, AI 패널, 임계값 표)을 그대로 쓰고 새 모양을 만들지 않는다. 도입 전인 구성(Patroni 자동 전환)은 원천 연결 전과 같은 점선 윤곽에 '◌ 구성 전'으로 적었고, 3라운드부터는 설계와 구현이 다른 작업 브랜치에서 진행 중이라 '◌ 구성 중'으로 적는다(v1.16). 3라운드의 새 화면이 더 쓰는 부품은 §12-15에 있다.

### 12-10. 시각 절제 규칙 (v1.11)

2026-09-25 사용자 요구('디자인은 AI 느낌이 없게')에서 나온 규칙이다. 관리 콘솔의 모든 화면이 따른다. 조용하지만 촘촘한 운영 도구의 판면이 목표다.

- **장식 효과를 쓰지 않는다.** 발광(글로), 그라디언트 면, 유리 효과(배경 흐림), 반짝이 기호, 이모지, 채도 높은 보라 면을 두지 않는다. 판독에 쓰는 무늬(지연 사선, 빈 계기 눈금)는 장식이 아니다.
- **그림자는 떠 있는 층에만.** 드롭다운, 검색 결과, 팝오버, 대화상자만 그림자를 받는다. 카드와 패널은 1px 헤어라인으로 가른다. 서비스 흐름 노드 카드의 얕은 그림자는 그 화면의 기존 규칙으로 남는다.
- **무채 바탕에 강조 하나.** 강조색은 크롬 악센트 하나다. 상태색은 상태에만, AI 강조색은 AI가 말하거나 한 일의 작은 자리(표지, 막대, 점, 윤곽)에만 쓴다(§12-9). 뜻 없는 색을 칠하지 않는다.
- **알약을 아낀다.** 완전히 둥근 모양은 개수 표지(경보 종)와 점, 슬라이더 손잡이에만 쓴다. 칩, 배지, 태그, 상태 알림은 `--radius-xs` 네모다(부품은 §12-14의 StateChip). 미터·슬라이더의 트랙과 채움, 확신도 막대, 관찰 창 막대는 모서리 1px의 곧은 막대다(v1.14). 끝이 둥근 막대는 계기가 아니라 장식으로 읽힌다.
- **위계는 크기와 굵기로.** 한 칸에 강조는 하나다. 수치는 tabular-nums와 오른쪽 정렬, 단위는 작고 흐리게 둔다. 가운데 정렬은 빈 상태와 서비스 흐름 카드에만 쓰고 목록·표·판독은 왼쪽에서 시작한다.
- **간격은 4px 배수, 주로 8px 격자.** 한 묶음 안의 간격은 같게 두고 묶음 사이를 한 단 넓힌다.
- **추세선은 요약 칸에만.** 선 하나(1.5px 무채)와 끝점 하나만 색이다. 칸마다 장식으로 곡선을 깔지 않는다.
- **움직임은 상태가 바뀔 때만**(§12-4). 늘 도는 애니메이션을 두지 않는다.
- **아이콘은 한 벌.** 16px 격자, 1.5px 선, 둥근 끝이다(`icons.tsx`, `FlowIcon.tsx`).
- **모든 칸에 빈·로딩·실패·연결 전 모양을 둔다**(§12-8). 포커스는 전역 이중 링이고 모든 조작이 키보드로 된다.
- **캡처로 스스로 검토한다.** 'AI가 만든 템플릿처럼 보이는가'를 묻고, 1px 어긋남, 간격 불일치, 위계 충돌, 같은 모양 카드의 반복을 찾아 고친다.

### 12-11. AI 상담, 보고서, 설정 (v1.12)

세 자리의 동작은 [관리자 설계 4-6~4-8](../product/관리자_설계.md)이 정한다. 여기에는 판면 규칙만 둔다.

- **AI 상담 패널.** 오른쪽 끝에 붙는 떠 있는 층이라 그림자(`--shadow-4`)를 받는다(§12-10). 층위는 대화상자 바로 아래여서 확인 대화상자가 뜨면 패널도 배경으로 가라앉는다. 모달이 아니다. 패널은 운영자 바(56px) 아래에서 시작해 운영자 바와 그 안의 'AI 즉시 정지'를 덮지 않는다(v1.13). 1600px 이상 창에서는 패널 폭만큼 본문을 밀어 판의 오른쪽 기둥을 가리지 않고, 그보다 좁은 창에서는 본문 위에 뜬다. 머리(56px)에 AI 표지, 'AI 상담' 제목(body 15/600), sim이면 '시뮬레이터 응답' 점선 칩, 오른쪽에 '대화 지우기' 텍스트 단추와 닫기 단추(32px, 누르는 자리 44px)를 둔다. 이 패널에서 AI 강조색을 쓰는 자리는 AI 표지와 생성 중 막대뿐이다. 머리 아래 한 줄 안내(dense 12 `--text-secondary`)가 조회 전용이라는 사실을 적는다.
- **상담 대화.** 운영자 말은 오른쪽 정렬의 sunken 말풍선(오른쪽 위 모서리만 `--radius-xs`)이다. AI 답은 면 없이 AI 표지와 시각, 답(body-sm 14/22 `--text-default`), 근거, 메타 줄, 링크 순서다. 근거는 종류(지표, 경보, 사건, 조치안, 임계값, 호스트)마다 한 줄이고, 종류 이름을 줄 머리에 한 번 적은 뒤 §12-9와 같은 무채 근거 칩을 늘어놓는다. 칩마다 종류를 되풀이하지 않는다. 경보 근거는 심각도 형태를 앞에 둔다. 메타 줄(micro 11)은 '근거 n건 · 수집 시각'과 모델 이름이고, 근거가 없는 안내 답은 관제 판의 수집 시각만 적는다. 링크는 §12-5의 텍스트 링크이고 실행 단추를 두지 않는다. 조치를 부탁한 질문의 답 머리에는 '○ 조회 전용 · 실행하지 않음' 무채 네모 표식을 단다.
- **상담 입력.** 1px `--border-default` 윤곽 안에 글칸과 보내기 아이콘 단추를 두고, 입력을 막으면 윤곽이 §12-6처럼 점선이 된다. 아래 줄에 키 안내와 개인정보 주의, 오른쪽에 'n/500'(tabular, 90%부터 `--color-warning-text`)을 둔다. 막힌 이유는 입력칸 위에 적는다. AI 정지면 ▲와 주의 글, http 원천이면 ◌와 점선 윤곽(§12-8의 원천 연결 전)이다. 폭 손잡이는 왼쪽 헤어라인 위 6px 띠이고, 가리키거나 포커스하면 32px 세로 막대가 보인다. 1100px보다 좁은 창에서는 패널이 판 전체를 덮고 손잡이를 거둔다.
- **보고서.** 머리 아래 요약 네 칸은 한 헤어라인 상자를 세로 헤어라인으로 가른다. 칸은 이름(dense 12), 값(title-3 18/600 tabular와 흐린 단위), 보조 줄(dense 12)이다. 목록 칸(340px)의 행은 형태 기호, 제목(body-sm 14/600), 우선순위(dense 12/600 tabular), 종류·시각·전송 결과 줄이고, 고른 행은 사이드바 활성 항목과 같이 왼쪽 2px `--chrome-accent` 선과 sunken 면이다(aria-current 병기). 목록 칸은 본문을 스크롤해도 위에 붙어 있다(v1.14, sticky). 상세를 읽어 내려가도 다른 보고로 건너갈 자리가 사라지지 않게 한다. 상세는 헤어라인 판 하나에 제목(title-2 20/700과 형태 기호), 개입 판정(형태 기호와 상태색 글자, 이어서 판정 이유), 사실 네 칸, 본문 절(영향, 담당자 조치 표, 후속 관측, 참고 분석)을 헤어라인으로 가른다. 담당자 조치 표는 §12-7을 따르고 역할과 착수를 한 칸에 두 줄로 적는다. 후속 관측은 같은 모양의 카드를 늘어놓지 않고 한 헤어라인 상자를 세로 헤어라인으로 가른 칸으로 적는다(v1.14, §12-14의 StatStrip). 참고 분석의 AI 표지와 모델 태그가 이 화면의 AI 강조색 자리다. 한국어 문장은 낱말 안에서 줄을 바꾸지 않고(keep-all), 기록 id 같은 긴 영문 토막만 어디서든 끊는다.
- **Teams로 보낸 카드.** 보고서 상세의 'Teams로 보낸 카드' 단추가 여는 모달(§12-13의 4) 안에 선다(v1.14). sunken 바탕 위의 카드다. Teams의 모양을 흉내 내지 않고 이 콘솔의 판면으로 그린다. 카드의 뜻(해제·관찰 유지는 초록, 조치·확인은 주의, 즉시 대응은 장애)은 제목 색과 형태 기호(●, ○, ▲, ■)가 싣는다. 안쪽 왼쪽 2px 색 선은 §12-14에 따라 쓰지 않는다(v1.14). 보고 서비스가 쓰는 그림 문자는 형태 기호로 옮긴다(§12-10의 이모지 금지). 전송 기록은 시도마다 한 줄(번호, 결과 형태와 낱말, 오류 코드, 시각)이다.
- **설정.** 연동 표는 §12-7을 따른다. 원천 이름(body-sm 14/600)과 역할(dense 12), 상태(형태 기호와 낱말. 연결됨은 초록 점과 잉크 글자, 연결 전은 ◌ 무채, 오류는 ■ 장애 색), 지금 값, 마지막 확인(오른쪽 정렬, tabular), 바로 가기 텍스트 링크 순서다. Teams 연결 시험 단추는 neutral 변형이고, 막히면 §12-6의 비활성 모양과 옆 문구로 이유를 적는다. 예시 명부와 sim의 '연결됨'은 화면 머리의 '시뮬레이션' 표식 하나가 알리고 패널마다 따로 칩을 달지 않는다(§12-12). `ai-1` 행만 '시뮬레이션 가정' 표식을 단다.

### 12-12. 글자·숫자·시간·용어 (v1.13)

관리 콘솔의 글자 형식이다. 같은 값은 모든 화면에서 같은 꼴로 적고, 한국어 문장은 낱말 안에서 끊지 않는다. 동작과 구성은 [관리자 설계 4-4](../product/관리자_설계.md)가 정한다.

- **줄바꿈.** 관리 셸의 뿌리와 셸 밖에 뜨는 층(확인 대화상자, 토스트, 로그인 화면)에 `word-break: keep-all`과 `overflow-wrap: anywhere`를 둔다. keep-all은 한국어를 공백에서만 끊고, anywhere는 공백 없이 칸보다 긴 토막(URL, 긴 영문 식별자)만 끊는다. 숫자와 단위('74%', '400ms', '2 → 3대', '1시간 59분')와 짧은 판독값은 한 덩이(nowrap)로 둔다. 하이픈이 든 노드 이름(app-3, ai-1, db-primary)도 한 덩이다. 브라우저가 하이픈 뒤를 줄바꿈 자리로 보기 때문이고, 글 안의 이름은 `KeepNames` 조각이 감싼다(v1.17). 가운뎃점으로 이은 글('앱 계층 · 평균 74%')은 가운뎃점 앞 공백을 줄바꿈하지 않는 공백(U+00A0)으로 적어 줄이 가운뎃점으로 시작하지 않게 한다. 사람이 읽는 낱말이 아닌 긴 토막(기록 id, 해시, 액션 코드, 인증서 CN)만 `word-break: break-all`로 어디서든 끊는다. 칸이 좁아 한 줄에 들지 않는 판독 줄은 글자를 자르지 않고 항목 단위로 다음 줄로 넘긴다. 줄임표로 자르는 것은 표의 긴 대상 칸과 판단 기록 요약처럼 원문을 툴팁으로 함께 싣는 자리뿐이다. 여러 줄 글은 `text-wrap: pretty`로 끝 줄에 낱말 하나만 남지 않게 줄을 고른다(v1.14). 줄 수와 칸 폭은 바뀌지 않는다.
- **숫자.** 한 자리에 오는 값은 소수 자리를 고정해 끝자리 0이 흔들리지 않게 한다. 비율(외부 가용성, 5xx)과 그 증감(%p)은 소수 둘째 자리('99.70%', '0.50%', '▲0.02%p'), 초 단위 지연은 소수 첫째 자리('0.3초', '2.4초'), 사용률(CPU·메모리·디스크·GPU), ms, 건수, 대수, OPS는 정수다. 단위는 숫자에 붙여 적고 수치는 tabular-nums다.
- **시각.** 관리 콘솔의 시각은 모두 KST(Asia/Seoul)로 적고 브라우저 시간대를 따르지 않는다. 운영자 바 시계만 'KST'를 붙여 기준을 한 번 밝히고 다른 자리는 붙이지 않는다. 보고서와 Teams 카드처럼 밖으로 나가는 문서의 시각은 지금처럼 'KST'를 붙인다. 시각은 24시간제 hh:mm:ss이고, 날짜가 필요하면 'M.D hh:mm'이다.
- **기간.** 1시간 이상 남은 시간은 시와 분으로 적는다('1시간 59분 남음', 분은 내림). 1시간 아래의 되돌리기·쿨다운·관찰 창은 mm:ss 카운트다운이다. 지난 기간(복구 시간)은 '5분 00초', 1시간이 넘으면 '1시간 12분'이다. 같은 값을 두 자리에서 다른 꼴로 적지 않는다. 사이드바 바닥과 모드 줄의 남은 시간이 그 예다.
- **용어.** 아래 왼쪽 말을 쓰고 오른쪽 말은 쓰지 않는다. 서버가 응답 본문으로 내려주는 문구(용량 권고 등)는 §10-1의 불변 조항에 따라 바꾸지 않는다.

  | 쓰는 말 | 쓰지 않는 말 | 뜻 |
  |---|---|---|
  | 판단 기록 | 판단 이력 | AI가 낸 판단의 목록 |
  | 사건 기록 | 사건 타임라인 | 경보 발생부터 해제까지의 기록 |
  | 노드 | 서버(조회 서버, 매칭 서버, 서버 한 대씩) | EC2 한 대와 온프레미스 `ai-1`. 서버는 소프트웨어(관리 서버, 보고 서비스)를 가리킬 때만 쓴다 |
  | 현재값 | 지금 값 | 임계값·한도·연동 판독의 지금 값 |
  | p95 | P95 | 응답 지연의 95번째 백분위 |
  | 중지 | 꺼짐 | 운영자나 정책이 내린 노드 상태(§12-3의 ○) |
  | 해제 | 복구(경보·사건이 끝남을 뜻할 때) | 경보와 사건의 끝. '평균 복구 시간'과 '앱 복구 판정'은 지표 이름이라 그대로 둔다 |
  | 되돌린 조치 | 무른 조치 | 되돌리기로 거둔 조치 |
  | 마지막 조회 | 최종 실측 | 수동 갱신 화면이 값을 읽은 시각 |
- **시뮬레이션 표식.** 값이 브라우저 시뮬레이터에서 오면 화면마다 한 번, 화면 머리의 제목 옆에 '시뮬레이션' 표식을 둔다. 한 부품(`SimMark`)이고 1px 점선 `--border-strong` 네모(`--radius-xs`)에 micro 11/500 `--text-default` 글자다. 보조기술에는 '값은 브라우저 시뮬레이터가 만든 것'을 함께 싣는다. 판 안의 패널(AI 관제, 보고서, 설정, 연락 체계)은 따로 표식을 달지 않는다. '시뮬레이션 · 재생', '시뮬레이터 응답', '시뮬레이션 · 예시', '예시 · 시뮬레이션', '값은 시뮬레이션', '연결됨은 시뮬레이터가 흉내 낸 값'처럼 자리마다 다르던 문구는 이 표식 하나로 모은다. 예외는 셋이다. 화면 위에 떠서 여러 화면을 오가는 AI 상담 패널은 머리에 같은 표식을 한 번 단다. 구축 전인 `ai-1`은 연결과 값이 시뮬레이터의 가정이라 그 카드와 행에 '시뮬레이션 가정' 표식(같은 부품, 같은 모양)을 단다. 서비스 흐름과 지표 관제가 로컬 측정 기록을 재생하는 동안에는 관제 판과 다른 세계라 '재생 · 관제 값과 별개' 표식을 화면 머리와 무대 머리에 크게 둔다(body-sm 14/600, 2px 실선 `--border-strong` 네모, ▶ 형태). 주의 상태가 아니라 값의 세계가 다르다는 사실이라 주황을 쓰지 않는다.
- **토스트.** 관리 콘솔의 토스트는 화면 오른쪽 아래(아래·오른쪽 24px)에 서고 층위는 확인 대화상자 바로 아래다. 대화상자가 떠 있을 때 토스트가 대화상자의 단추를 덮지 않는다. AI 상담 패널이 열린 동안에는 패널 왼쪽 24px에 서서 패널의 입력칸을 덮지 않는다. 거래 화면의 토스트 자리는 바꾸지 않는다.

### 12-13. 상세 모달·드로어 (v1.14)

관리 콘솔은 판에서 한 대상을 골라 깊이 보는 자리를 다섯 둔다. 노드 상세, 사건 드로어, AI 판단 상세, 보고서 카드 미리보기, 조치 확인이다. 판을 떠나지 않고 보고, 닫으면 누른 자리로 돌아온다. 동작과 데이터는 [관리자 설계 4-9](../product/관리자_설계.md), 자리와 크기는 [데스크톱 레이아웃 §7](데스크톱_레이아웃설계.md)이 정한다.

- **공통 층.** 다섯 모두 모달이다(`aria-modal`). 배경 덮개는 `--overlay-dim`이고 운영자 바를 포함한 뒤의 판은 inert가 되어 누를 수 없다. 층은 `--surface-elevated` 면, `--shadow-4`, 다크에서 가장자리가 보이도록 1px `--border-subtle`, 모서리 `--radius-lg`(드로어는 왼쪽 두 모서리만)다. 머리는 56px이고 제목(title-3 18/700), 보조 줄(dense 12 `--text-secondary`), 오른쪽 닫기 단추(32px, 누르는 자리 44px)를 두며 머리 아래를 1px `--border-subtle`로 가른다. 본문만 스크롤하고 머리와 단추 줄은 제자리다. §12-2의 관리 평면 글자 단계와 §12-12의 줄바꿈 규칙을 층에도 건다.
- **열고 닫기.** Esc, 닫기 단추, 덮개 누르기로 닫는다. 조치 확인만 덮개로 닫지 않는다. 결정 직전의 대화상자가 판을 잘못 누른 한 번으로 사라지지 않게 한다. 층이 겹치면 Esc는 맨 위 층만 닫는다. 닫으면 연 단추로 포커스가 돌아간다. 첫 포커스는 조치 확인이 '취소', 탭이 있는 상세는 고른 탭, 그 밖의 상세는 층 자체(제목을 읽는다)다. Tab은 층 안에서 돈다. 움직임은 §12-4의 층 등장이다.
- **실행 단추.** 노드 상세, 사건 드로어, AI 판단 상세, 보고서 카드는 읽는 자리라 실행 단추를 두지 않는다. 조치는 조치 카드와 승인 절차에서만 한다. 다른 화면으로 가는 텍스트 링크(Grafana ↗, 용량·부하, 보고서)만 둔다.
- **값의 출처.** 층이 화면 머리를 덮으므로 sim이면 층 머리의 보조 줄 끝에 §12-12의 '시뮬레이션' 표식을 층마다 한 번 단다. http 원천에서 값을 받지 못한 칸은 §12-8의 원천 연결 전 모양이다.

1. **노드 상세(모달 880x640).** 인프라 카드, app-3 Auto Scaling 띠의 노드 칸, 서버·노드 화면의 수집 대상 표, 관제 검색에서 연다. 머리는 형태 기호와 노드 이름, 역할 줄('Spring Boot · 매칭 리더 · p0'), 상태 칩(§12-14)이고, 오른쪽에 ←·→ 이웃 노드 단추와 'n / 전체'(tabular)가 선다. 이웃의 순서는 인프라 칸을 읽는 순서다(app-1, app-2, app-3, db-primary, db-standby, bot-1, ai-1). 탭은 §12-14의 분절 조작이고 개요, 자원, 서비스, 로그 요약, 조치 기록이다. ←·→ 키는 탭 목록 위에서는 탭을, 그 밖에서는 이웃 노드를 옮긴다. 개요는 정체(역할, 규격·AZ, 맡은 마켓, 수집 상태와 마지막 수집)와 지금 걸린 경보다. 자원은 CPU·메모리·디스크(와 크레딧)의 큰 판독값(title-3 18/600)과 임계 눈금 막대(§12-9)다. 서비스는 그 노드에서 도는 systemd 서비스 이름과 상태다. 로그 요약은 관제가 그 노드에 대해 남긴 시스템 기록(경보 발생·해제)과 journald 원문 요약 자리(원천 연결 전)다. 조치 기록은 운영자와 AI가 그 노드에 한 일이다. 바닥 줄에 Grafana 딥링크를 둔다. app-3은 '켜기·끄기는 용량·부하에서 합니다' 링크를 둔다.

4. **보고서 카드 미리보기(모달 520px).** 보고서 상세의 'Teams로 보낸 카드' 단추로 연다. 제목은 'Teams로 보낸 카드', 보조 줄은 전송 결과와 시각이고 본문은 §12-11의 카드다.

### 12-14. 부품 한 벌 (v1.14)

관리 콘솔의 모든 화면이 같은 부품을 쓴다. 용량·부하, 봇 플릿, 백오피스가 관제 화면과 다른 세대의 부품(44px 분절 탭, 둥근 상태 알약, 칸마다 다른 요약 타일)을 쓰던 것을 한 벌로 모은다.

- **화면 머리.** 제목(title-1)과 출처 표식, 설명 한 줄(caption 13 `--text-secondary`), 오른쪽의 판독과 조작이다. 운영 관제 화면은 3라운드(v1.16)부터 설명 줄을 두지 않는다(사용자 결정, 관리자 설계 4-10). 한 화면이 답하는 질문은 제목과 첫 판의 배치가 싣고, 설명 줄에 있던 사실은 그 사실이 걸리는 판의 안내 글로 옮긴다. 머리 높이 예약(레이아웃 §7의 57px)은 그대로라 첫 판의 시작점이 바뀌지 않는다. 관제 화면의 수집 상태('● 실시간 수집 중')와 수동 갱신 화면의 조회 시각('○ 마지막 조회 08:18:10')은 같은 글자 단계(caption 13)와 같은 형태 기호 자리로 같은 곳에 선다. 수동으로 읽은 값은 실시간이 아니라 조회 시각의 형태는 무채 빈 원(○)이고, 폴링이 실패해 값이 굳으면 ▲와 '갱신 지연 · 마지막 조회 08:18:10'(`--color-warning-text`), 아직 읽지 않았으면 점선 원과 '조회 전'이다. 새로고침은 머리의 다른 조작과 같은 neutral 단추(36px, 누르는 자리 44px)에 새로고침 아이콘과 낱말이다.
- **요약.** 상태를 싣는 칸(관제센터 상태 요약, 경보·사건 머리)은 칸마다 테두리를 둔 Tile이다. 상태가 아닌 판독 묶음(봇 플릿 요약, 용량의 노드 대수, 처리 대기, 보고서 전송 요약, AI 자동 조치 수, 보고서 후속 관측)은 한 헤어라인 상자를 세로 헤어라인으로 가른 StatStrip이다. 칸은 이름(caption 13 `--text-secondary`), 값(title-3 18/600 tabular와 흐린 단위, 화면의 대표 칸만 display-md 28/700), 보조 줄(dense 12)이다. 칸의 상태는 값 앞 형태 기호와 값 색으로 적고, 멱등 위반 같은 장애만 칸 면을 `--color-danger-bg`로 칠한다. 같은 모양의 카드를 여러 장 늘어놓지 않는다.
- **상태 칩.** StateChip 한 모양이다. `--radius-xs` 네모 안에 형태 기호(StatusShape)와 낱말(dense 12/600)이다. 정상은 초록 형태와 잉크 글자에 면과 테두리가 없고, 주의는 `--color-warning-text` 1px 테두리와 글자, 장애는 `--color-danger` 테두리·글자와 `--color-danger-bg` 면, 중지·미수집·중립은 1px `--border-default` 테두리와 `--text-default` 글자다. 관리 평면에서 둥근 HealthPill(`status-pill`)을 쓰지 않는다.
- **분절 조작.** Segmented 한 모양이다. `--surface-sunken` 트랙에 안쪽 1px `--border-default`, 칸 높이 32px(판독 거르기는 28px), 누르는 자리 44px, 고른 칸은 `--surface-elevated` 면과 안쪽 1px 경계다. 판을 가르는 필터와 상세의 탭은 탭 의미(tablist, 화살표 키로 옮김, 고른 칸만 Tab 정지)이고 값을 고르는 스위치는 눌림 의미(`aria-pressed`)다. 관리 평면에서 전역 SegmentedTab(44px)을 쓰지 않는다.
- **왼쪽 2px 선.** 한 뜻이다. '고른 것·지금 위치'(사이드바의 지금 화면, 보고서 목록의 고른 보고, 사건 목록의 고른 사건)만 `--chrome-accent` 2px 선을 받는다. 상태(경보 행, Teams 카드, 용량 권고, 운영자의 보유 역할)와 AI(대기 조치 카드)는 왼쪽 선을 쓰지 않고 형태 기호, 배지, 칩으로 적는다. 보유 역할은 역할 행의 '보유' 칩이다. 서비스 흐름 구성도의 매칭 리더 표식(카드 테두리 안쪽에 떨어뜨려 세운 3px 레일)은 범례가 '리더'로 뜻을 적는 도면 기호라 이 선과 다르다.
- **미터 채움.** 한 규칙이다. 채움은 무채 `--text-secondary`(다크의 관제 게이지는 `--border-default`)이고 임계 이상이면 `--color-warning`, 장애 임계 이상이면 `--color-danger`다. 초록과 브랜드 색으로 채우지 않는다. AI가 한 일인 확신도 막대만 `--ai-accent`다.
- **패널.** 관리 셸 안의 PanelCard는 관제 기둥과 같은 머리(§12-8의 패널 제목 단계, 오른쪽 메타와 링크)다.

### 12-15. 3라운드 부품과 판 (v1.16)

[관리자 설계 4-10](../product/관리자_설계.md)의 새 화면이 쓰는 부품이다. 모두 §12-2의 글자 여섯 단계, §12-3의 상태 형태, §12-4의 움직임과 줄임 모션 대체, §12-10의 시각 절제를 따른다. 상태가 아닌 것(계획의 단계, 변경 요청의 진행)에는 헬스 색을 쓰지 않고 형태 기호와 무채 윤곽으로 가른다. 자리와 크기는 [레이아웃 §7](데스크톱_레이아웃설계.md)이 정한다.

- **달력 보기(CalendarView).** 변경·작업의 계획 달력과 SLA 월간 보고의 일별 가용성이 같은 부품을 쓴다.
  - 격자. 월 보기는 월요일에 시작하는 7열과 5~6행이다. 머리 줄은 요일(dense 12 `--text-secondary`)이고, 칸은 1px `--border-subtle` 헤어라인 한 줄로 가르며 면을 칠하지 않는다. 칸 최소 높이는 88px이다. 날짜 숫자는 칸 왼쪽 위의 caption 13/600 tabular이고, 다른 달의 날은 `--text-secondary`로 적고 항목을 싣지 않는다. 오늘은 날짜 숫자를 1px `--chrome-accent` 윤곽 네모(20px, `--radius-xs`)와 `--chrome-accent` 글자로 적는다. 날짜의 경계는 KST다(§12-12).
  - 항목 칩. 높이 20px, `--radius-xs`, dense 12/600, 한 줄 말줄임과 원문 툴팁이다. 여러 날에 걸친 계획 작업 창은 칸 경계를 넘어 이어진 막대로 그리고, 주가 바뀌면 끊어 다음 줄에서 이어 그린다. 상태는 형태와 윤곽으로 적는다. 승인 대기는 ◌와 1px 점선 `--border-strong`, 예정(승인됨)은 ○와 1px `--border-default`, 진행 중은 ▶와 1px `--chrome-accent` 윤곽에 `--surface-sunken` 면, 완료는 ●와 윤곽 없는 `--text-secondary` 글자, 되돌림은 ▲와 `--color-warning-text` 윤곽(실제로 되돌린 사실이라 주의), 취소는 ○와 `--text-secondary` 글자의 가운데 줄이다. 칩 글자는 따로 적은 것 말고는 `--text-default`이고, sunken 면(진행 중) 위에는 `--text-secondary`를 쓰지 않는다(sunken 위 4.27:1, 토큰 게이트의 대비 계약). 한 칸에 셋을 넘으면 '+n'(dense 12 텍스트 단추)으로 그날 목록을 연다.
  - SLA 칸. 칸마다 그날 가용성(caption 13 tabular, '99.98%'), 형태(목표 이상은 무채 잉크 ●, 목표 미만은 ▲ 주의), 사건 수(dense 12)를 적는다. 칸 면을 색으로 칠하는 열지도는 쓰지 않는다. 예시 날과 관제 판에서 센 날의 구분은 툴팁이 싣는다.
  - 조작. 격자 의미(`role=grid`)이고 화살표 키로 날을 옮기며, PageUp·PageDown으로 달을, Home·End로 주의 처음과 끝을 옮긴다. Enter는 그날 목록을 연다. 머리에 '이전 달', '오늘', '다음 달' 단추(neutral 36px, 누르는 자리 44px)를 둔다.
  - 움직임. 달을 바꾸면 격자가 opacity 120ms로 교차한다. 줄임 모션에서는 곧바로 바뀐다.

- **타임라인 스크럽 바(ScrubBar).** 시나리오 재생의 가상 시계를 옮긴다.
  - 모양. 판 전폭이고 누르는 자리 높이는 44px, 트랙은 4px(모서리 1px)이다. 트랙은 라이트 `--surface-sunken`, 다크 `--border-default`이고 지나온 몫은 `--chrome-accent`다(서비스 흐름 재생 자막의 진행 막대와 같다, 관리자 설계 7-10 (i) 1). 단계 경계는 1px x 10px `--border-strong` 눈금과 그 위의 단계 번호(dense 12 tabular)다. 기록 표지는 8px로 사건 기록 레일의 문법을 따른다(시스템 무채 빈 원, AI `--ai-accent` 채운 원, 운영자 `--text-strong` 채운 원, 경보 발생 주의 색 마름모, 해제 초록 원). 재생 위치는 14px 원 손잡이(`--surface-elevated` 면과 2px `--chrome-accent` 테두리)이고 위에 'mm:ss'(dense 12 tabular)를 적는다. 슬라이더 손잡이라 둥글어도 된다(§12-10).
