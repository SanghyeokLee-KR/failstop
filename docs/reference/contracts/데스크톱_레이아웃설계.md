# 데스크톱 웹 레이아웃 설계서 (v1.14)

> 방향: 미감은 토스증권(카드·여백·정돈), 정보 구조는 업비트(거래 패널 동시 노출). 디자인 토큰은 `docs/reference/contracts/프론트_디자인시스템.md`의 tokens.css를 그대로 소비하고, `web/lib`의 DataSource·zustand 스토어·시뮬레이터를 레이아웃과 무관하게 재사용한다. 상승 Red·하락 Blue, 색 단독 표현 금지 규약 유지. 단, WS 연결 상태 노출을 위해 스토어·DataSource 인터페이스를 §5.1의 범위로 경미 확장한다.

## 1. IA 재편

### 1.1 글로벌 내비게이션

- 하단 TabBar 폐지. `components/TabBar.tsx`, `TabBar.module.css` 삭제.
- 상단 HeaderNav 1줄, 높이 56px, `position: sticky; top: 0`, 전 화면 공통. 토스증권 헤더(52px) 골격 차용.
- 좌 → 우 구성.
  - 로고(텍스트 로고, 클릭 시 `/exchange`)
  - 내비 링크 4개: 거래소 · 자산 · 거래내역 · 시스템 상태. 활성 링크는 `--text-strong` + 하단 2px 언더라인(`--brand-primary`), 비활성 `--text-secondary`.
  - 우측: WS 연결 상태 점(연결 green·단절 crimson, 라벨 텍스트 병기), ThemeToggle.
- WS 연결 상태의 데이터 소스는 스토어 `connected`. 현재 `lib/store.ts:76`의 `connected: true`는 갱신 주체가 없는 선언뿐인 필드이므로, DataSource에 `onConnectionChange` 콜백, 스토어에 `setConnected` 액션을 신설해 연결한다(§5.1 경미 수정 표에 계약 명시). 시뮬레이터 구현체는 항상 `true`를 통지하되 인터페이스는 동일하게 구현.
- 고정형 정책(§4)에 따라 축소 변형 없음. 내비는 전 해상도에서 동일 구성.

### 1.2 라우트 (권장안 확정)

`/market`(목록)과 `/coin/[market]`(상세), `/order/[market]`(주문)을 거래 화면 하나로 통합한다. 마켓 목록·주문 폼이 거래 화면의 상주 패널이 되므로 독립 페이지의 존재 이유가 없다. 업비트 `/exchange` 단일 화면 모델과 동형.

**제약**: `next.config.ts`가 `output: "export"`(정적 산출물, Nginx 서빙)이므로 `next.config` `redirects()`는 동작하지 않는다. 모든 이관은 페이지 파일을 유지한 채 본문을 클라이언트 리다이렉트로 교체하는 방식으로 구현한다. 동적 라우트의 `generateStaticParams`는 삭제하지 않고 유지한다(정적 export 산출 경로 보존).

| 라우트 | 처리 |
|---|---|
| `/exchange/[market]` | 신설. 거래 화면 본체(§2). `generateStaticParams`로 전 마켓 사전 생성 |
| `/exchange` | 클라이언트 컴포넌트에서 localStorage 최근 마켓(없으면 KRW-BTC)으로 `router.replace` |
| `/` | `app/page.tsx` 기존 클라이언트 리다이렉트 패턴 재사용, `/exchange`로 replace |
| `/market` | 페이지 유지, 본문을 `/exchange`로 replace하는 클라이언트 컴포넌트로 교체 |
| `/coin/[market]` | 페이지·`generateStaticParams` 유지, `/exchange/[market]`로 replace (딥링크 보존) |
| `/order/[market]` | 페이지·`generateStaticParams` 유지. `useSearchParams`로 `side`·`price`를 읽어 `/exchange/[market]?side=...&price=...`로 replace. 쿼리는 OrderPanel 프리필로 승계. 서버 redirect로는 쿼리 승계가 불가하므로 반드시 클라이언트 처리 |
| `/assets` `/history` `/system` | 유지, 와이드 레이아웃으로 개편(§3) |
| `/welcome` | 유지. 최초 진입 후 `/exchange` 이동 |

- 고정형 정책(§4): 모바일 리플로우 없음. `.app-frame`(max-width 420px)은 전역에서 제거하고 관련 클래스도 삭제한다.

## 2. 거래 화면 그리드 (`/exchange/[market]`, 1280px 이상)

### 2.1 원칙

- 업비트식 동시 노출: 차트·호가·체결·주문·마켓 목록을 스크롤 없이 한 화면에. 단 무스크롤 원칙은 뷰포트 높이 659px 이상에서만 유지하고, 그 미만은 페이지 스크롤을 허용한다(§2.3).
- 토스증권식 구획: 1px 실선 보더 대신 `--bg-muted` 페이지 배경 위 `--surface-default` 카드, radius 16px(`--radius-lg`), 카드 간 gap 12px. 카드 내부 패딩 16px, 테이블성 패널(호가·체결·마켓 목록)은 12px.
- 콘텐츠 최대 폭 1920px 중앙 정렬, 좌우 패딩 16px.

### 2.2 그리드 정의

```css
.tradeGrid {
  display: grid;
  grid-template-columns: minmax(0, 1fr) 300px 320px;
  grid-template-rows: 64px minmax(380px, 1fr) 260px;
  grid-template-areas:
    "summary summary side"
    "chart   book    side"
    "trades  book    side";
  gap: 12px;
  padding: 16px;
  height: calc(100dvh - 56px);
  max-width: 1920px;
  margin: 0 auto;
}
```

- side 영역은 내부 grid `auto minmax(160px, 1fr)` 세로 2분할. OrderPanel(위, 높이 auto·내용 기준 약 440~460px) + MarketListPanel(아래, min-height 160px, 내부 스크롤). OrderPanel 고정 px를 두지 않아 압축 구간에서 자연 수축.
- 1280px 뷰포트 가로 실측: 좌우 패딩 32 + gap 24 + book 300 + side 320 → 1열(차트·체결) 폭 604px. 1920px 기준 1244px.

### 2.3 세로 예산과 높이 브레이크포인트

기본 스펙 최소 소요 = 헤더 56 + 상하 패딩 32 + 요약 64 + 차트 min 380 + 체결 260 + gap 24 = **816px**. 1366x768 노트북의 실제 뷰포트(브라우저 크롬 제외 약 620~660px)를 초과하므로 높이 미디어 쿼리를 둔다.

| 뷰포트 높이 | 규칙 |
|---|---|
| 821px 이상 | 기본 스펙. 무스크롤 |
| 641~820px (`@media (max-height: 820px)`) | 압축 스펙: 요약 64→48, 차트 min 380→300, 체결 260→180, 카드 내부 패딩 16→12. 최소 소요 640px, 무스크롤 유지. OrderPanel도 패딩·행 간격 축소로 약 400px, MarketListPanel 최소 160px 확보 |
| 640px 이하 (`@media (max-height: 640px)`) | 무스크롤 원칙 해제. `height: auto; min-height: calc(100dvh - 56px)`, 각 트랙 min값 유지, 페이지 세로 스크롤 허용 |

- 참고 실측: 1080px 뷰포트에서 차트 높이 약 644px, 768px급 노트북(압축 스펙)에서 약 300~340px.

## 4. 화면 정책 (고정형, 데스크톱 전용)

업비트와 동일한 고정형 데스크톱 웹이다. 반응형 리플로우를 두지 않고, 모바일은 지원하지 않는다.

- 최소 지원 폭 1280px. 뷰포트가 더 좁으면 레이아웃을 접지 않고 가로 스크롤을 낸다(body에 min-width 1280px).
- 1280px 이상 모든 모니터에서 §2 풀 그리드가 항상 유지된다. 콘텐츠 최대 폭 1920px 중앙 정렬, 초광폭 모니터는 좌우 여백만 확장.
- 가로 미디어 쿼리는 두지 않는다. 세로만 §2.3 높이 브레이크포인트(820·640)를 적용한다.
- 1279px 이하 뷰포트(모바일·태블릿 포함)는 별도 레이아웃 없이 가로 스크롤로 열람만 가능하다. 접속 차단이나 안내 배너는 두지 않는다(업비트 동형).
- 기존 모바일 전용 컴포넌트와 화면(TabBar, AppBar, BottomSheet 주문 경로, CoinDetailClient·OrderClient 모바일 레이아웃, `.app-frame`)은 데스크톱 전환 완료 시점에 제거한다. 죽은 코드로 남기지 않는다.

3. **PR-3 호가·체결 패널**: OrderbookPanel(10+10호가·잔량 막대·ticker 역산 등락률·가격만 프리필) + TradesPanel 데스크톱 밀도 구현, 임시 조각 대체.
4. **PR-4 주문·마켓 목록 패널**: OrderPanel(인라인 폼 + 인라인 2단계 확인) + MarketListPanel(검색·탭·정렬). `/order` 리다이렉트 쿼리 프리필 연결.
5. **PR-5 서브 화면 와이드화**: DataTable 신설, 자산·거래내역·시스템을 §3 스펙으로 개편.

각 PR은 독립 배포 가능. PR-2 이후 어느 시점에도 거래 기능이 끊기지 않도록 기존 모바일 조각을 임시 탑재 후 단계 대체하는 전략.

## 7. 관리 콘솔 판형 (v1.2~v1.8)

관리 콘솔은 거래 화면의 HeaderNav 대신 자기 셸을 쓴다([관리자 설계 4-1](../product/관리자_설계.md)). 왼쪽에 고정 사이드바(232px)가 서고, 그 오른쪽 본문 스크롤 상자(`#admin-main`) 안에 운영자 바와 화면이 놓인다. 고정형 정책(§4)과 최소 폭 1280px은 같다. 이 절은 화면을 옮겨 다닐 때 제목과 본문이 같은 자리에 서도록 판형을 하나로 정한다. 시연에서 서비스 흐름과 지표 관제를 오가면 제목이 1920px 창에서 약 200px 옆으로, 위아래로 4px 움직이던 문제가 근거다.

- **운영자 바(v1.4).** 본문 스크롤 상자 맨 위의 56px 줄이고 좌우 여백은 본문과 같은 24px이다. 그래서 왼쪽 검색칸(높이 36px, 최대 440px)의 왼쪽 끝이 화면 제목과 한 줄에 선다. 오른쪽은 'AI 즉시 정지'(v1.6), 세로 헤어라인, 전체 상태, 경보 종, 현재 시각, 테마 전환, 사용자 메뉴 순서다. 검색, 정지 단추와 상태 신호는 관제 데이터를 읽으므로 운영 관제 셸에만 서고 백오피스 셸의 바는 시각, 테마 전환, 사용자 메뉴만 싣는다. 1440px보다 좁은 창에서는 시계의 날짜를 거두고 시각과 'KST'만 남겨 검색칸이 280px 아래로 줄지 않게 한다. 사이드바 바닥에는 설정과 평면 전환 링크를 나란히 둔 바닥 줄(44px) 아래에 사용자 카드(52px)를 헤어라인으로 붙이고, 사이드바를 접으면 이름표 표지만 남긴다(v1.5).
- **사이드바 세로 예산(v1.5).** 명판 줄은 위 여백 8px에 높이 40px이라 가운데가 운영자 바의 가운데(28px)에 선다. 메뉴 목록은 묶음 머리 32px와 항목 40px(누르는 자리는 둘 다 44px)로 쌓고, 접힌 묶음은 머리 아래 간격을 두지 않는다. 그래서 시연 묶음이 접힌 기본 모양에서 1280x800 창의 메뉴 목록(570px)이 목록 자리(574px) 안에 들어 스크롤이 생기지 않는다(2026-09-25 헤드리스 Chromium 실측). 더 낮은 창에서는 메뉴 목록만 스크롤하고 명판 줄, AI 모드 표시, 바닥 줄, 사용자 카드는 제자리에 남는다.
- **사이드바 3라운드 예산(v1.10).** 묶음이 다섯, 항목이 열여덟이라 모든 묶음을 펴면 목록이 약 1,010px로 574px 자리를 넘는다. 누르는 자리 44px를 지키면 항목 간격을 줄일 수 없으므로 기본 모양을 줄인다. 처음에는 관제 묶음과 지금 화면이 든 묶음만 펴고 나머지는 머리만 둔다(관리자 설계 4-10-1). 가장 긴 기본 모양은 조치 묶음이 펴진 때이고 관제 166px, 조치 266px(묶음 사이 12px 포함), 접힌 머리 셋 132px로 564px이다. 종전 실측이 계산보다 4px 컸으므로 약 568px이고 574px 자리에 든다. 계산값이며 구현 뒤 1280x800 헤드리스 실측으로 확인한다. 운영자가 여러 묶음을 펴면 목록만 스크롤한다. 아이콘만 남긴 72px 기둥은 모든 묶음을 펴므로 묶음 사이 간격을 위아래 12px에서 8px로 줄여 목록을 약 872px에서 840px로 줄인다. 1920x1080 창에서 좁은 기둥의 목록이 스크롤 없이 드는지는 구현 뒤 실측으로 확인하고, 800px 높이 창의 좁은 기둥은 목록만 스크롤한다.
- **AI 상담 패널(v1.5, v1.6 개정).** 화면 오른쪽 끝에 붙는 층이고 운영자 바(56px) 아래에서 시작해 바닥까지 선다. 운영자 바는 패널이 열려도 전폭 그대로라 'AI 즉시 정지'가 가려지지 않는다. 기본 폭 440px, 손잡이로 360~720px이다. 1600px 이상 창에서는 패널 폭만큼 본문 스크롤 상자(`#admin-main`)의 오른쪽을 비워 본문을 민다. 이때 본문 판형은 좁아진 폭에서 제 규칙대로 다시 선다. 1600px보다 좁은 창에서는 본문을 밀지 않고 그 위에 뜨며, 1100px보다 좁은 창에서는 운영자 바 아래 전폭을 덮는다.
- **토스트(v1.6).** 관리 콘솔의 토스트는 화면 오른쪽 아래 24px에 서고, 층위는 확인 대화상자 바로 아래다. 대화상자의 단추 위에 겹치지 않는다. AI 상담 패널이 열린 동안에는 패널 폭만큼 왼쪽으로 옮겨 패널 왼쪽 24px에 선다.
- **실패·로딩 판(v1.6).** 수동 갱신 화면(용량·부하 등)이 처음 불러오는 동안과 불러오기에 실패했을 때도 공통 페이지 틀과 화면 머리(제목, 설명 예약 높이)를 그대로 두고 그 아래에 골격이나 오류 판을 그린다. 틀 밖에 판 하나만 그려 제목이 사라지거나 본문 시작점이 달라지지 않게 한다.
- **본문 시작점.** 모든 관리 화면의 본문은 사이드바 오른쪽 같은 x에서 시작한다. 공통 페이지 틀은 가운데 정렬을 쓰지 않고 왼쪽에 붙이며, 여백은 위 24px, 좌우 24px, 아래 48px(`--space-6`, `--space-9`)이다. 최대 폭은 1680px이다. 1440px 창에서는 본문 폭이 이 상한보다 좁아 달라지는 것이 없고, 1920px 창에서 1280px 상자가 가운데에 떠 좌우와 아래가 비던 모양이 없어진다.
- **서비스 흐름.** 구성도를 남은 자리에 맞춰 확대하므로 최대 폭 없이 전폭을 쓴다. 여백은 공통 틀과 같은 위·좌우 24px이다. 그래서 서비스 흐름과 지표 관제의 제목 x·y가 같다.
- **화면 머리.** 제목은 `--font-title-1`로 본문 왼쪽 위에 서고, 오른쪽은 조작 자리다. 머리 높이는 설명 줄이 없어도 57px을 예약해 첫 패널이 같은 높이에서 시작한다. 서비스 흐름 머리에는 설명 줄을 두지 않는다(2026-09-23 사용자 결정). 높이는 예약 높이로만 맞춘다. 3라운드부터는 운영 관제 화면 모두 설명 줄을 두지 않고 같은 예약 높이를 쓴다(v1.10, 관리자 설계 4-10).
- **서비스 흐름 구성도(v1.4, v1.8 개정).** 구성도 높이는 폭과 무관한 615px이다(v1.3의 589px에서 매칭 칸과 온프레미스 틀을 더하며 659px로 늘었다가, v1.8에서 Auto Scaling 상자가 app-3 한 자리만 감싸며 줄었다). Auto Scaling 상자 안의 app-3은 다른 노드와 같은 높이의 카드이고 그 가운데가 주축이다. 페이지는 이 높이와 남은 자리의 비율로 설계 폭을 고른 뒤 통째로 확대하므로, 1920x1080과 1440x900에서 구성도가 무대를 가로세로로 채운다. 배치의 세부(열과 틀, 선 경로)는 [관리자 설계 7-10 (i)](../product/관리자_설계.md)와 `FlowTopology.tsx` 머리 주석이 정한다.
- **서비스 흐름 무대 머리 줄.** 구성도 카드 안 첫 줄은 높이 44px을 늘 잡는다. 왼쪽부터 출처 칩, 재생 중에만 나타나는 상황 자막, 오른쪽 끝 '크게 보기'다. 자막이 나타나고 사라져도 줄 높이가 같아 구성도 배율이 흔들리지 않는다. 각 요소의 내용은 [관리자 설계 7-10 (i)](../product/관리자_설계.md)가 정한다.
- **보고서(`/admin/reports`, v1.5, v1.7 개정).** 공통 페이지 틀을 쓴다. 머리 아래 요약 네 칸이 한 줄이고, 그 아래 목록 칸(340px)과 상세가 16px 간격으로 선다. 목록 칸은 본문 스크롤에서 위 16px에 붙어(sticky) 상세를 읽어 내려가도 제자리에 남고, 목록이 창보다 길면 목록 안에서 스크롤한다(v1.7). 'Teams로 보낸 카드'는 상세 머리의 단추가 여는 모달(520px)로 옮겼다(v1.7). 상세 틀은 폭을 재는 컨테이너이고, 1080px 이상이면(1920px 창) 전송 기록이 상세 오른쪽 380px 칸에 서고 그보다 좁으면 상세 아래로 내려간다. 상세는 본문 스크롤을 따른다.

AI 관제 기둥은 판단 한 줄 바로 아래에 대기 조치 카드를 둔다(디자인 시스템 §12-9). 상태 요약 칸은 칸 폭이 230px 아래로 좁아지면(1440px 이하 창) 아이콘 칸을 거두고 수치와 추세선 자리를 지킨다. 칸 폭에 맞춘 조정이라 화면 재배치가 아니다. 인프라 기둥은 역할 묶음을 위에서부터 앱 계층(app-1·app-2 한 줄과 그 아래 전폭의 app-3 Auto Scaling 띠, v1.8), 데이터베이스, 관측과 온프레미스(한 줄)로 쌓고, 고정 높이를 쓰는 창에서는 넘치면 기둥 안에서 스크롤한다. 기둥 안쪽 폭이 340px 아래면(1440·1280px 창) 카드를 한 줄에 하나씩 쌓아 게이지 막대가 줄지 않고 온프레미스 카드가 칸 밖으로 넘치지 않게 한다(v1.6, 종전 300px). 조치와 기록 기둥은 안쪽 폭이 340px 아래면(1440px 이하 창) 사건 기록의 글을 시각·행위자 줄 아래에 두고 경보의 확인·보류 단추를 설명 아래 줄로 내린다. 모두 칸 폭을 재는 컨테이너 쿼리라 화면 재배치가 아니다. 서버·노드 화면은 같은 묶음을 네 칸 두 줄(앱 계층 세 칸·온프레미스 / 데이터베이스 두 칸·관측, 온프레미스는 두 줄에 걸침)로 편다. 앱 계층 칸은 app-1·app-2·app-3 띠를 한 줄에 둔다(v1.8). app-3 띠는 안쪽 폭이 280px 아래면(서버·노드 1280·1440 창, 관제센터 1280 창) '앱 평균 CPU' 글 아래로 막대를 내려 막대가 204·244·244px를 받는다. 그보다 넓은 띠는 글 옆에 막대를 두고 막대가 서버·노드 1920 창 261px, 관제센터 1440·1920 창 193·350px다. 글 옆에 두던 서버·노드 1280 창의 막대는 약 100px였다(v1.14, 컨테이너 쿼리). 판단 기록, 사건 기록, 경보 목록처럼 늘어나는 목록은 기둥 안에서 높이를 묶고 안쪽에서 스크롤한다. 최소 지원인 1440x820에서는 세 기둥의 윗부분까지 보이고 나머지는 본문 스크롤이다. 열 구조는 가로 미디어 쿼리 없이 비율 열로 1280px까지 같다. 1600px 경계(v1.6)는 기둥의 높이와 상담 패널의 밀기만 가르고 열의 순서와 비율은 바꾸지 않는다. 자동 모드를 켜고 끌 때 모드 줄 높이가 같아 아래 판이 움직이지 않는다.
