# 상세 자료 안내

구현하거나 검토할 때 필요한 조건을 찾는 곳이다. 전체 흐름은 [프로젝트 이해하기](../reports/프로젝트_이해하기.md), 실제 소스 위치는 [코드 지도](architecture/프로젝트_코드지도.md)에서 먼저 확인할 수 있다.

지금 적용하는 구조를 판단할 때는 [0099 현재 구조](adr/0099-current-architecture.md)를 먼저 읽는다. 현재 채택한 결정과 대체 관계, 배포와 검증의 한계를 한곳에서 설명한다. 세부 조건은 아래 계약에서, 작업 진행 상태는 [로드맵](../ROADMAP.md)에서 확인한다.

교수님께 보고한 구성도·네트워크 실습 파일·기존 화면은 [아키텍쳐 자료](../../아키텍쳐/README.md)에 보존한다. 보고본과 현재 구현의 차이도 그 안내에 적었다. 실제 실행 결과는 촬영 환경과 검증 증거를 함께 확인한다.

## 구현 계약

| 확인할 내용 | 문서 |
|---|---|
| 테이블, 금액 계산, 거래 기록과 복구 | [DB 설계](contracts/백엔드_DB_설계.md) |
| 요청·응답, 오류, 인증, 주문 재시도, WebSocket | [API 설계](contracts/백엔드_API_설계.md) |
| 색상, 글꼴, 간격, 상태 표현 | [디자인 시스템](contracts/프론트_디자인시스템.md) |
| 고정형 거래 화면의 영역과 배치 | [데스크톱 레이아웃](contracts/데스크톱_레이아웃설계.md) |
| 장애 실험과 판정 조건 | [하네스 검증 설계](contracts/하네스_검증설계.md) |
| CI·CD, 관측성, 인프라 검사 | [CI·CD·인프라 설계](contracts/하네스_CICD_IaC.md) |

이 문서들이 해당 범위의 구현 기준이다. 코드가 계약과 다르다면 실제 동작과 요구를 구분해 확인한다. 보고서의 쉬운 설명으로 세부 조건을 대체하지 않는다.

## 결정과 원본

학교·개인 실습의 NAT Gateway 제외와 조회 ASG 최소 2대·최대 3대 기준은 [0030](adr/0030-nat-free-lab-and-bounded-read-asg.md)을 따른다. 피어링은 학교 운영자의 연결·라우팅 허용이 필요하며 실제 구축 완료와 구분한다.

[ADR 폴더](adr/)에는 설계를 선택하거나 바꾼 이유가 있다. [0001](adr/0001-record-architecture-decisions.md)은 작성 규칙이다. 0099는 현재 구조를 계속 갱신하는 예약 번호이며 일반 결정 순번에서 제외한다. 최신 MSP 운영·자동 확장·Teams 보고 방향은 [0027](adr/0027-msp-operations-and-autoscaling.md)에 있다. 학교 EC2에서 먼저 검증하고 10월 초 개인 계정에서 보강하는 순서는 [0029](adr/0029-school-aws-first-personal-account-expansion.md)를 따른다. [0028](adr/0028-vm-validation-before-aws.md)의 VM 선행 조건은 보류했다. 개별 결정이 대체됐다면 0099의 적용 관계와 후속 ADR을 확인한다.

[웹 화면 명세 HTML](contracts/웹_화면명세서.html)은 같은 폴더 PDF의 원본이다. [화면설계서 HTML](product/화면설계서.html)은 별도의 화면 설계 원본이다. 측정 결과는 [측정 폴더](../measurements/README.md), 배포 설정은 [deploy 안내](../../deploy/README.md)에서 확인한다.
