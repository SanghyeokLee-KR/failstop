# 코드 지도

기능을 수정할 때 어디서 시작하고 어떤 테스트를 볼지 정리한 문서다. 전체 동작은 [프로젝트 이해하기](../../reports/프로젝트_이해하기.md), 남은 작업은 [로드맵](../../ROADMAP.md)에서 읽을 수 있다.

기존 거래 경로는 2026-09-17에 조사했고, 09-18에는 정본 `codex/docs-linux-operations`의 Linux 운영·역할별 배포·관측·보고 경로를 추가했다. 09-23에는 주문 접수의 V47 판정, 정산 일시 오류 재시도와 학교 백업·경보·워치독 템플릿 경로를 더했다. 참고 문서이며, 실행 검증의 조건과 한계는 [09-18 기록](../../measurements/20260918.md)에 있다.

## 저장소와 실행 진입점

기본 관제는 기존 Grafana의 여섯 MSP 화면이다. [생성기](../../../deploy/observability/tests/build-msp-dashboards.py), [PromQL](../../../deploy/observability/tests/msp_queries.py), [Canvas](../../../deploy/observability/tests/msp_canvas.py)가 서비스·Spring·AWS/서버·DB 요약·SQL/세션·복제/복구를 구성한다. 화면 JSON은 `harness/grafana/dashboards/10-msp-overview.json`부터 `15-msp-db-replication.json`까지의 생성 결과다.

운영자용 별도 화면은 [관제 콘솔](../../../deploy/console/README.md)이다. `deploy/console/static/`이 사이드바·관제·운영·관리 화면, [서버](../../../deploy/console/server.py)가 Grafana 인증과 제한 API, [지표 어댑터](../../../deploy/console/metrics.py)가 고객 범위 Prometheus 조회를 담당한다. [보고 목록](../../../deploy/reporting/console_api.py)은 기존 보고 SQLite와 저장 PDF·HTML을 읽으며 거래소 Next.js 경로와 분리된다.

서버는 [settings.gradle.kts](../../../server/settings.gradle.kts)에 등록된 `engine`, `app` 두 모듈이다. `engine`은 매칭 계산을, `app`은 API와 저장·복구를 담당한다. 웹은 별도의 Next.js 프로젝트다.

분석에서는 추적 파일 전체의 목록을 확인하고 핵심 실행 경로를 따라 읽었다. 실험 원자료를 포함한 모든 파일의 본문을 읽은 것은 아니다. 확인 범위는 마지막 절에 적었다.

| 화면 갱신 | [MarketDataPublisher](../../../server/app/src/main/java/kr/exchange/api/ws/MarketDataPublisher.java), [store.ts](../../../web/lib/store.ts) | 커밋 후 발행, 순번·세대 검사와 재동기화 |

저널 커밋이 끝난 뒤에만 엔진에 명령을 전달한다. HTTP 응답은 주문 조회 결과에 반영되기를 기다리므로, 커밋과 응답 완료는 같은 시점이 아니다. 이 차이는 `OrderGateway`와 `EngineBridge`를 함께 읽어야 보인다.

정산을 바꾸려면 Java 코드뿐 아니라 DB 게시 함수와 제약조건도 봐야 한다. [Flyway 마이그레이션](../../../server/app/src/main/resources/db/migration/)은 V0부터 V47까지 48개이며, [DB 설계](../contracts/백엔드_DB_설계.md)가 테이블과 금액 계산 규칙을 설명한다.

## 저장과 복구

복구를 읽는 순서는 [PromotionCoordinator](../../../server/app/src/main/java/kr/exchange/engine/PromotionCoordinator.java), [EngineRecovery](../../../server/app/src/main/java/kr/exchange/engine/EngineRecovery.java), [ReplayService](../../../server/app/src/main/java/kr/exchange/journal/ReplayService.java)다. 승격 중에는 접수를 막고, 마켓별 스냅샷과 저널을 대조·재생한 뒤 접수를 연다. 평소 대기 서버의 추적은 [FollowerCatchUp](../../../server/app/src/main/java/kr/exchange/engine/FollowerCatchUp.java)이 맡는다.

DB에서 먼저 볼 테이블은 다음과 같다.

- `command_journal`, `event_journal`, `snapshots`: 명령, 처리 결과, 복구 시작 상태.
- `ledger_transactions`, `ledger_entries`, `balances`: 회계 기록과 조회용 잔고.
- `orders`, `trades`, `idempotency_keys`: 주문·체결과 중복 요청 처리.
- `leader_lease`: 리더 자격과 세대 번호. [LeaderLeaseService](../../../server/app/src/main/java/kr/exchange/engine/LeaderLeaseService.java)와 [리스 구현](../../../server/app/src/main/java/kr/exchange/engine/lease/)을 함께 본다.

순번을 다룰 때는 명령 순번, 마켓 이벤트 순번, WebSocket 채널 순번을 구분한다. 명령 채번은 DB의 `command_seq` 전환 기록에 따라 전역 모드와 마켓 대역 모드가 갈린다. 이 기록은 [V44](../../../server/app/src/main/resources/db/migration/V44__command_band_cutover_latch.sql), 이벤트 대역 확대는 [V46](../../../server/app/src/main/resources/db/migration/V46__event_seq_band_widen.sql)에 있다. 이번 분석에서는 실행 중인 DB의 적용 상태를 조회하지 않았다.

복구 기준도 마켓별이다. 다른 마켓의 최대 순번을 가져와 적용 완료 기준으로 삼으면 안 된다. 근거는 [ADR 0022](../adr/0022-market-partitioned-command-journal.md)와 [ADR 0023](../adr/0023-replay-bound-and-cursor-axis.md)에 있다. 리더 검증의 잠금과 인덱스를 수정할 때는 [V41](../../../server/app/src/main/resources/db/migration/V41__lease_key_share_lock.sql)과 [ADR 0026](../adr/0026-leader-lease-key-share-lock.md)을 함께 확인한다.

앱 리더 전환과 DB 승격은 별도다. DB의 비동기 복제와 수동 승격은 [ADR 0024](../adr/0024-async-two-node-replication.md), [운영 절차](../operations/DB_수동_페일오버.md), [DB 노드 설정](../../../deploy/compose.node-data.yml)을 따른다.

웹의 실제 API 연결 여부는 [datasource.ts](../../../web/lib/api/datasource.ts)가 고른다. `NEXT_PUBLIC_DATASOURCE=http`이면 HTTP/STOMP, 그 외에는 브라우저 시뮬레이터다. 관리자 모드는 `NEXT_PUBLIC_ADMIN_DATASOURCE`로 별도 지정할 수 있다. API·WS 주소를 포함한 `NEXT_PUBLIC_*` 값은 빌드할 때 정해진다.

공통 상태는 [store.ts](../../../web/lib/store.ts), 응답 타입은 [types.ts](../../../web/lib/types.ts), 주문 규칙은 [orderContract.ts](../../../web/lib/orderContract.ts)에 있다. 금액은 문자열로 전달하고 [decimal.ts](../../../web/lib/decimal.ts)의 BigInt 기반 함수로 계산한다. 화면 스타일은 [tokens.css](../../../web/styles/tokens.css)와 [globals.css](../../../web/app/globals.css)에서 시작한다.

브라우저의 [SimEngine](../../../web/lib/sim/engine.ts)과 서버의 [BotFleet](../../../server/app/src/main/java/kr/exchange/sim/BotFleet.java)은 다른 기능이다. 서버 봇은 [BotApiClient](../../../server/app/src/main/java/kr/exchange/sim/BotApiClient.java)로 실제 주문 API를 호출한다. [seed-data/](../../../seed-data/)의 수집 결과를 앱에 자동 적재하는 연결은 확인되지 않았고, 해당 폴더의 README에도 미연결 상태로 적혀 있다.

관리 API는 인증서 확인, 승인, 감사 기록을 거친다. 현재 승인 방식은 [ADR 0019](../adr/0019-single-operator-approval.md)의 1인 승인이다. 공개 웹 빌드에서 관리 화면을 분리하는 코드는 [prune-admin-bundle.mjs](../../../scripts/prune-admin-bundle.mjs)에 있다.

## 의존성과 실행 설정

서버는 Java 21, Gradle Wrapper 8.14, Spring Boot 3.5.16, PostgreSQL 17 계열이다. [app/build.gradle.kts](../../../server/app/build.gradle.kts)에서 Spring MVC·JDBC·WebSocket, Flyway, Micrometer, Resilience4j, DynamoDB SDK 등을 확인했다. [engine/build.gradle.kts](../../../server/engine/build.gradle.kts)에는 운영용 외부 라이브러리 의존성이 없다.

웹의 [잠금 파일](../../../web/package-lock.json) 기준으로 Next.js 15.5.20, React 19.2.7, Zustand 5.0.14, STOMP.js 7.3.0, TypeScript 5.9.3을 사용한다. 메인 차트는 klinecharts, 미니 차트는 lightweight-charts다. [next.config.ts](../../../web/next.config.ts)의 정적 export로 `web/out/`을 만든다.

DB 연결과 서버 프로파일은 [application.yml](../../../server/app/src/main/resources/application.yml), PostgreSQL/DynamoDB 리스 선택은 [LeaseStoreConfig](../../../server/app/src/main/java/kr/exchange/config/LeaseStoreConfig.java)에 있다. 비밀 환경 변수의 값은 이번 분석에서 읽지 않았다. 실제 기동 명령과 사전 준비는 [실행 가이드](../../../실행_가이드.md)를 따른다.

## 확인 범위와 남은 문제

주문 접수부터 매칭·정산·화면 갱신까지의 핵심 코드, 복구·리스 연결, 주요 DDL, 빌드·CI·로컬 실행 설정은 본문 또는 관련 구간을 읽었다. 회원·게시판·관리자·봇과 테스트는 구조와 대표 사례를 확인했으며, 모든 예외 처리를 검토한 것은 아니다.

과거 발표 자료, 과거 실험 원자료 전체, 모든 화면의 JSX/CSS, 시드 JSON 전체, 모든 마이그레이션 함수와 긴 설계 문서의 전 절은 읽지 않았다. 금액 계산 전체에 대한 정밀도 감사도 하지 않았다. 09-18의 서비스·DB·마이그레이션 검증은 날짜별 기록에 한정하며 실제 AWS 배포는 미검증이다.

후속 작업에서 주의할 문서 차이는 다음과 같다.

- 배포 계약 원본은 현재 저장소에 없다. 이전 엣지 설정과 실제 배포 계획의 차이도 남아 있다. 사용할 노드별 설정과 확인할 조건은 [배포 안내](../../../deploy/README.md)를 본다.
- [09-15 측정](../../measurements/20260915.md)에서 commit_delay 실험은 조건이 충족되지 않아 `NOT RUN`이다. 다른 단계의 통과 기록과 합쳐 전부 검증됐다고 해석하지 않는다.
- Terraform과 로컬 DB 승격·복원 러너를 추가했지만 AWS plan/apply·다중 호스트 장애·실제 ASG 증감은 아직 검증하지 않았다. 과거 E10 전수 재실행을 현재 완료 조건으로 삼지 않으며 [로드맵](../../ROADMAP.md)의 운영 시나리오를 따른다.

다음 수정에서는 해당 기능의 설계와 테스트를 다시 읽는다. 주문·원장·순번을 바꾸면 서버 코드, SQL, 실험 판정기를 함께 확인하고, API·WebSocket을 바꾸면 웹 통신과 상태 처리도 함께 확인한다.
