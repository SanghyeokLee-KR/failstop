# 디자인 방향 · 정숙 계기 (Quiet Instrument)

> 목적: 데스크톱 고정형 거래 화면(1280px, 실시간)에 자체 아이덴티티를 확정한다.
> 성격: 방향 정본이다. tokens.css와 기존 코드는 손대지 않는다. 여기서 확정하는 것은 토큰의 소비 규칙과 신규 시맨틱 별칭 후보이며, 실제 반영은 구현 PR이 별도로 집행한다.
> 원천: `docs/contracts/프론트_디자인시스템.md`(토큰 계약), `docs/contracts/데스크톱_레이아웃설계.md`(그리드 정본), `docs/contracts/웹_화면명세서.pdf`(라우트·상태), 현 `web/styles/tokens.css`.

## 0. 확정 방향과 합성 근거

방향 이름은 정숙 계기(Quiet Instrument)다. 세 후보와 판정단 심사를 종합한 단일 방향이다.

- 축: 고요한 프리미엄의 채도 예산. 화면의 크롬은 무채로 누르고, 유채색은 시세 방향에서만 발화한다. 판정단 다수가 실시간 정보 위계·밀도 목적성·계약 정합에서 이 축을 최상으로 봤다.
- 정체성 실체: GAUGE의 계기 언어를 이식한다. 채도를 빼는 절제만으로는 소유성(ownability)이 낮다는 지적을 계측 눈금과 계기 명판으로 보강한다. 단 판정 조건대로 등록마크·전역 크로스헤어 같은 장식 밀도는 억제해 자기 원칙(시각 소음 최소)과의 긴장을 제거한다.
- 실시간 소음 제어: EDGE의 엣지 펄스를 흡수한다. 전면 틴트 홍수 대신 셀 가장자리 점등·감쇠로 갱신을 알린다. 단 엣지가 방향을 단독으로 표현하지 않도록, 방향을 싣는 곳에는 부호·화살표를 병기하고 엣지 채널 자체는 위치(활성·선택) 신호로 쓴다.

한 문장 명제: 화면은 무채색 계기면이고, 색은 데이터에서만 발화하는 사건이다.

이 방향은 업비트(도처의 색·전면 고밀도)도, 제네릭 AI 산출물(보라 그라디언트·둥근 카드 남발·과장 카피)도 아니다. 업비트·토스는 품질 레퍼런스일 뿐 브랜드 색·형상·말투를 가져오지 않는다. 아이덴티티는 tokens.css 자체 토큰과 계기 어휘로 선다.

## 1. 디자인 원칙 (5)

1. 화면은 계기면이다. 카드를 그림자로 띄워 분리하지 않는다. 헤어라인과 이음새 채널이 구획하고, 패널이 공통 그리드에 정렬돼 한 장의 계기판으로 읽힌다.
2. 색은 데이터의 특권이다. 배경·보더·프레임·내비·버튼은 무채. 유채는 시세 방향(상승 Red·하락 Blue)과 시스템 상태에서만. 정지 스크린샷은 거의 무채로 보이고, 색이 뜨는 순간이 곧 시장이 뛰는 순간이다.
3. 정지가 기본값이다. 실시간 갱신은 계측기 바늘처럼 최소·정밀하게 움직인다. 시선을 끄는 장식 모션은 두지 않는다.
4. 위치로도 말한다. 눈금·엣지·부호·화살표가 색과 별개 채널로 값을 전달한다. 색 단독 표현 금지 규약을 우회 없이 보강한다.
5. 목적형 이중 밀도. 판독 영역은 여백을 두고, 주사 영역은 조인다. 균일 밀도는 프로 툴도 프리미엄도 아니다.

## 2. 색 철학과 토큰 방향

### 2.1 채도 예산 (Saturation Budget)

핵심 명제: 이 거래소에서 채도는 곧 정보다. 유채 픽셀은 원칙적으로 시세 방향(Red/Blue)과 시스템 상태에만 허용한다.

- 방향색 독점. Red(상승·매수)·Azure(하락·매도)는 시세·호가·손익·체결·주문 CTA에만. 규약대로 색 단독 금지, 부호(+/-)와 화살표(▲▼) 병기. 가격 방향에 green 금지, green은 시스템 성공 전용.
- 브랜드는 실선이 아닌 실오라기. Royal Blue(`--brand-*`)를 큰 면(fill)으로 쓰지 않는다. 허용처는 활성 내비 언더라인, 포커스 링, 링크(밑줄 병행), 활성·선택 인디케이터 hairline뿐. 최상위 확정 액션 한 곳에만 fill을 남긴다. 비방향 버튼은 `--surface-sunken` + 잉크 텍스트(중립 fill)로 처리해 하락 파랑(Azure)과 브랜드 파랑의 혼동을 원천 차단한다.
- 크롬은 잉크 온 페이퍼. 표면 위계를 그림자가 아니라 뉴트럴 4단(base·muted·default·sunken)으로 만든다. 색이 아닌 명도 차로 층을 나눈다.
- 경계는 색이 아니라 헤어라인. 구획은 `--border-subtle` 1px 또는 이음새 채널로. 유채 보더 금지(포커스 링 예외).

### 2.2 토큰 소비 방향

신규 색 primitive는 만들지 않는다. 하드코딩 hex 금지(코인 브랜드색 데이터만 예외). 아래는 소비 규칙의 이름표이며 값은 전부 기존 primitive·시맨틱 재사용이다. tokens.css 반영은 별도 PR이 집행한다.

| 별칭 후보 | 매핑 | 용도 |
|---|---|---|
| `--chrome-accent` | `var(--brand-primary)` | 내비·포커스·링크·활성 인디케이터 한정. fill 금지 표식 |
| `--surface-seam` | `var(--bg-muted)` | 패널 사이 이음새 채널의 의미 이름 |
| `--panel-radius` | `var(--radius-md)` | 거래 패널 표준 라운드(12) |
| `--control-radius` | `var(--radius-sm)` | 인풋·칩(8) |
| `--rule-tick` | `var(--border-subtle)` 파생 | 계측 눈금 hairline. 무채, 위치로 값 전달 |
| `--last-price-frame` | 색·라운드·패딩 묶음 | 프라이스 마크 3지점 공용 규격(§6.5) |

- 표면·경계·상태색은 기존 시맨틱 토큰을 그대로 소비한다. 시스템 상태는 `--color-success/warning/danger`, 시세 방향은 `--color-up/down` 계열, 소형 텍스트는 반드시 `-text`(틴트 위 `-strong`)를 쓴다. 방향색 틴트(`-bg`)는 호가 depth의 유일한 색면이고 나머지 면은 전부 무채.
- 다크가 본령이다. `--surface-default` `#171A21`·`--surface-sunken` `#12141A`의 차가운 뉴트럴 위에서 보더를 구조의 주역으로 승격하고, 그림자는 정적 패널에서 0으로 수렴한다.

## 3. 타이포 위계

Pretendard 단일 패밀리. 라벨·한글명은 sans, 숫자는 `tabular-nums lining-nums` 판독체. 위계는 크기 점프가 아니라 명도(strong·default·secondary·tertiary)와 굵기(700·600·500·400)로 만든다.

### 3.1 화면당 히어로 하나

- 거래 화면 히어로는 SummaryBar 현재가 단 하나. `--font-title-1`(24/700), 방향색 대형 규격(`--color-up/down`). 34px(`--font-display-lg`)·28px(`--font-display-md`)는 거래 화면 금지, `/assets` 총평가금액 등 비거래 히어로에만.
- 나머지는 급강하: 섹션 타이틀 `--font-title-3`(18/600, 밀도 필요 시 `--font-body-sm` 14/600) → 값 `--font-body`(15) → 라벨 `--font-caption`(13) → 틱·명판 `--font-micro`(11/500).

### 3.2 숫자 정체성

- 금액·수량은 예외 없이 `tabular-nums`. `.num/.price/.pnl`·`.price-hero` 계약을 전 패널에서 경유하게 강제한다. 우측 정렬 고정폭으로 소수점 수직 정렬, 통화·단위 접미는 `--font-micro` `--text-tertiary`로 낮춘다.
- 금액은 문자열로 다룬다(NUMERIC(40,18) 정밀도 보존). parseFloat 금지, 표시 포맷은 `Intl.NumberFormat('ko-KR')`.
- 20px 이상 큰 숫자에 `letter-spacing: -0.01em` 소비 규칙. 밀착감이 계기 판독감을 만든다.
- 중량 절제. 700은 히어로·섹션 타이틀에만, 본문 400, 라벨 500. 600 남발 금지.

## 4. 간격·밀도 스케일

4px 베이스 그리드. space 스케일(`--space-1`~`--space-10`) 밖 임의 값 금지. 페이지 배경 `--bg-muted`, 콘텐츠 max 1920px 중앙, 최소 지원 폭 1280px, 그보다 좁으면 가로 스크롤(리플로우·모바일 지원 없음).

### 4.1 두 밀도 존

- 판독 존(air). SummaryBar, OrderPanel, `/assets` 카드. 내부 패딩 `--space-5`(20)~`--space-6`(24), 행 간격 여유, 큰 숫자에 여백. 여백은 장식이 아니라 위계 신호다.
- 주사 존(scan). OrderbookPanel, TradesPanel, MarketListPanel. 패딩 `--space-2/3`, 폰트 13px, 라인하이트 압축. 행 구분은 여백이 아니라 `--border-subtle` 1px가 만든다.

### 4.2 정본 행 높이 (데스크톱 레이아웃설계 계승)

| 대상 | 값 |
|---|---|
| 페이지 기본 폰트 | 14px |
| 호가 행 | 32px, 13px |
| 체결 테이블 | 13px |
| 마켓 목록 행 | 40px, 13px |
| 카드 gap | 12px |
| 카드 내부 패딩 | 16px(테이블성 패널·압축 12px) |

업비트 12px보다 한 단계 낮되, 소비자 앱보다 조인 중간 밀도다.

### 4.3 라운드·깊이

- 라운드: 패널 `--radius-md`(12), 인풋·칩 `--radius-sm`(8). 16~24(`--radius-lg`~`--radius-2xl`)는 오버레이·시트 전용으로 격리. 데스크톱 프로 표면에서 16은 물러 보인다.
- 깊이: 정적 패널은 헤어라인(`--border-subtle`) + 이음새 채널. 라이트에서 그림자 제거 또는 최대 `--shadow-1` 속삭임 1회. 떠 있는 레이어(드롭다운·툴팁) `--shadow-2`, 오버레이·시트·다이얼로그 `--shadow-3/4` + 딤. 다크는 보더 병행.

## 5. 모션과 실시간 원칙

원칙: 거래 표면에서 움직이는 것은 원칙적으로 시세 방향뿐이다. 나머지는 정지해 있다.

### 5.1 이징·지속

- 거래 화면은 `--ease-standard`(감속)만. `--ease-emphasized`(스프링 오버슈트)는 거래 표면 금지, 사용자 개시 인터랙션(시트·세그먼트 슬라이드·확인 전환)에만. 튀는 숫자는 계기 정서를 깬다.
- 지속은 `--dur-fast`(120)·`--dur-base`(200). `--dur-slow`(320) 이상은 큰 레이어에만, `--dur-slower`(480) 거래 표면 금지.

### 5.2 실시간 = 배경만, 기본은 은은하게

- 틱 플래시는 배경색 전이만(`.price-cell` 계약). 셀별 throttle 300ms, rAF 코얼레싱, 셀 memo, 레이아웃 시프트 0.
- 강도 escalation. 평상 틱은 subtle(배경 플래시만, 팝·스케일 없음)을 기본으로. 팝 스케일(`--effect-pop-*`)·방향 글로우(`--effect-glow-*`)는 대형 체결(`data-strong`)에만. 화면이 매 틱마다 소리치지 않게 한다.
- 엣지 펄스(EDGE 이식). 홍수 상황에서 전면 틴트 대신 셀 가장자리 점등·감쇠를 쓸 수 있다. 방향을 싣는 셀은 부호·화살표를 병기하고, 엣지 채널 단독으로 방향을 표현하지 않는다. 순수 위치(활성·선택) 신호일 때만 엣지를 무채 `--chrome-accent` hairline으로 쓴다.
- 연결 상태·헬스 전이는 계기 상태등처럼 색 전이만. 깜빡임·바운스 금지. 스테일(연결 끊김)은 opacity .5 + 지연 배지, 값은 마지막 값 유지. 스켈레톤은 sweep 대신 pulse.

### 5.3 reduced-motion

- `prefers-reduced-motion` 완전 존중. 플래시 배경 무력화, 팝·글로우 정적 대체, 값·부호·화살표 표식은 유지(tokens.css §5 킬스위치 계약 그대로).

## 6. 시그니처 컴포넌트

여섯 장치가 함께 아이덴티티를 만든다. 6.1이 중심, 나머지가 보강이다.

### 6.1 채도 예산 (주 시그니처)

- 정의: 화면 전체가 준무채색 잉크·페이퍼이고, 유일한 유채색은 시세 방향과 시스템 상태다.
- 식별성: 정지 스크린샷만으로 색 없는 거래소로 특정된다. 색이 뜨는 순간이 시장 이벤트.
- 집행: §2 규칙(브랜드 fill 금지·크롬 뉴트럴·방향색 독점)을 컴포넌트 리뷰 체크로 강제.

### 6.2 계측 눈금 rail (GAUGE 이식, 소유성 장치)

- 정의: 호가 depth 막대, 주문 슬라이더, 퍼센트 칩 트랙, 차트 가격축에 일정 간격 hairline 눈금(`--rule-tick`)을 새긴다. 잔량·수량 비율이 캘리퍼로 읽는 값처럼 보인다.
- 규약 정합: 눈금은 무채색이고 색이 아니라 위치로 값을 더한다. 색 단독 표현 금지와 무관하게 정보를 보강한다. 이 장치가 소비자 거래소가 쓰지 않는 제도(製圖)·계측 어휘를 만든다.
- 억제: 눈금은 판독을 돕는 최소 간격으로만. 밀도가 소음이 되지 않게 관리한다.

### 6.3 계기 명판 (GAUGE 이식)

- 정의: 각 패널 헤더에 `--font-micro`(11/500) 라벨을 자간 확장해 계측기 명판처럼 붙인다(예: 호가 · KRW-BTC).
- 조건: 한글은 대문자화하지 않는다. 자간 확장으로만 명판 성격을 낸다. `--text-secondary` 잉크.

### 6.4 정숙한 이음새 표면 (Quiet Seam)

- 정의: 드롭섀도 카드 대신, 패널 사이로 `--surface-seam`이 12px 폭 채널로 비치는 이음새가 구조를 만든다. 그림자 없이 종이가 층으로 놓인 느낌.
- 집행: PanelCard를 헤어라인 우선으로, 라운드 12로 통일. 다크에서 특히 또렷하다.

### 6.5 프라이스 마크 일관 (Price Mark)

- 정의: 현재가가 나타나는 세 곳(SummaryBar 히어로, Orderbook 현재가 경계 행, 차트 last-price 마크)에 동일 시각 처리(`--last-price-frame`: 같은 방향색 규격·라운드·tabular 정렬)를 부여한다.
- 식별성: 세 지점이 하나의 가격 언어로 묶여 시선에 축을 준다. 산만한 거래 화면에서 가격만은 늘 같은 옷을 입는다.

### 6.6 방향 엣지 펄스 (EDGE 이식, 색 단독 가드)

- 정의: 실시간 갱신·활성 행 표시를 전면 배경 채움이 아니라 셀 가장자리 점등으로 처리한다. 시각 소음을 구조적으로 줄인다.
- 가드: 방향을 싣는 엣지는 부호·▲▼ 병기 필수. 방향 없는 위치 신호(활성·선택)일 때만 무채 `--chrome-accent` hairline 엣지 단독 사용. inset 처리로 레이아웃 시프트 0 유지.

로고는 브랜드 잉크 단색 워드마크. 그라디언트·다색 금지. 채도 예산과 일관되게 로고조차 조용하게.

의도적으로 배제한 장치: PanelCard 네 모서리 등록마크와 화면 전역 크로스헤어는 채택하지 않는다. 시각 소음 최소 원칙과 충돌하고, 1280px 고밀도 3열 표면에서 지속 밀도를 더한다. 크로스헤어는 차트 내부로만 한정한다.

## 7. 화면별 적용 지침

### 7.1 거래 (`/exchange/[market]`)

- 그리드는 데스크톱 레이아웃설계 정본을 그대로 소비한다. 1280px 이상 3열, 세로 높이 브레이크포인트(820·640) 유지. `generateStaticParams`로 전 마켓 사전 생성, 동적 라우트 추가 시 함께 정의.
- 판독 존(SummaryBar·OrderPanel)과 주사 존(호가·체결·마켓 목록)을 나란히 둔 이중 밀도가 이 화면의 리듬이다.
- 호가는 매도 위(`--color-down-bg`)·현재가 경계·매수 아래(`--color-up-bg`), 잔량 막대에 계측 눈금. 클릭 프리필은 가격만 주입하고 side 유지(상주 OrderPanel 컨텍스트 보호).
- 데스크톱 히어로는 SummaryBar 현재가 하나. 프라이스 마크 3지점 수렴 적용.
- 데이터 접근은 DataSource 인터페이스만. 화면 코드가 시뮬레이터·fetch를 직접 부르지 않는다. 상태는 zustand 스토어 셀렉터로 소비하고 화면 로컬 상태와 전역 상태를 구분한다.

### 7.2 대시보드

- 지표·차트 카드를 이음새 격자로 배치. KPI 값은 판독 존 밀도, 방향 지표는 부호·화살표 병기. 색은 방향·상태에만.
- 실시간 지표도 정지 기본값·escalation 원칙 적용. 매 갱신마다 팝 금지.

### 7.3 자산 (`/assets`)

- 총평가금액은 비거래 히어로로 `--font-display-md`(28) 허용. 손익은 방향색 + 부호·화살표.
- 보유 목록은 주사 존 밀도, 평가손익 셀만 `-text`. 나머지는 잉크.

### 7.4 회원

- 폼 중심 판독 존. 인풋 `--control-radius`(8), 중립 fill 버튼. 브랜드 fill은 최종 확정 액션 한 곳(가입·로그인 제출)에만.
- 상태(로딩·빈·에러) 설계 필수. 에러·빈 안내에만 해요체 온기, 나머지는 평서형 라벨.

### 7.5 게시판

- 텍스트 위계는 본문 `--font-body`(15) 중심. 거래 화면 밀도를 강요하지 않는다. 목록은 중밀도, 헤어라인 구획.
- 색은 시스템 상태(공지·경고)에만. 방향색은 게시판에서 쓰지 않는다.

### 7.6 관리자

- 고밀도 판(주사 존) 우선. 헬스·상태는 계기 상태등 어휘(색 전이, 명판 라벨). 시스템 헬스 플래시는 `--color-health-flash-*` 전용, 시세 플래시와 도메인 분리(차용 금지).
- 위험 액션(삭제·정지)은 `--color-danger`, 부호·라벨 병기. 확인 단계 필수. danger는 확정 지점(확인 다이얼로그의 확정 버튼, 승인 후 실행 버튼)과 실제 이상 상태 표시에 배급한다. 목록형 반복 트리거는 무채 버튼으로 두고, 파괴 의미는 동사 라벨과 확인 단계가 전달한다.
- 목록형 트리거의 등급 예외. 한 목록의 행이 서로 다른 파급을 가지면 최상위 등급에 한해 danger를 허용한다. 아래 4가지를 모두 만족할 때만 성립한다. 하나라도 어긋나면 목록 전체를 무채로 되돌린다.
  1. 등급이 데이터 필드다. 카탈로그 정의에 등급을 싣고 화면에서 즉석 판단하지 않는다(`ChaosExperimentDef.severity`).
  2. 등급 어휘가 같은 행에 글자로 보인다. 색 단독 표현 금지는 예외가 없다. 어휘는 감정어(위험·주의)가 아니라 멈추는 범위를 지시한다(체결 중단·계층 차단·지연 주입).
  3. 최상위 1단계까지만 배급한다. 중간 등급은 무채다. 3단계 척도라면 danger는 1단계에만 붙는다.
  4. 한 목록에서 danger 트리거가 과반이면 배급 실패로 본다. 목적은 눈에 띄는 것이 아니라 나머지와 구분되는 것이고, 과반이 원색이면 구분이 사라진다.
- 등급이 균일한 목록(같은 액션의 반복, 대상만 다른 경우)은 예외 대상이 아니다. 봇 12기의 중지, 사용자 목록의 정지처럼 모든 행의 파급이 같으면 전부 무채로 둔다.

## 8. 접근성 규약

- 대비 4.5:1 이상. 소형 텍스트는 `-text`(틴트 위 `-strong`), 시스템색 원색(600)은 아이콘·면·보더 전용. tokens.css 대비 검증값 준수.
- 탭 타깃 44px. 시각 높이는 계기답게 조밀하되 히트 영역은 `::after` 투명 확장으로 44px 확보(시각 밀도와 히트 영역 분리).
- 방향은 색 단독 금지. 부호(+/-)·화살표(▲▼) 병기. 눈금·엣지는 색 외 보조 채널.
- 포커스는 이중 링(`--focus-ring`, 안쪽 surface 오프셋 + 바깥 브랜드), 비색 단서 병행. 인터랙티브 요소에 접근성 라벨.
- `prefers-reduced-motion` 완전 대응(§5.3).
- 실시간 갱신 레이아웃 시프트 0. 컨테이너 폭 고정 + tabular + memo + rAF 코얼레싱.
