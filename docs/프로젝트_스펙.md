# 프로젝트 스펙 문서 (검증본)

작성 2026-08-25. 대상 고가용성 가상 암호화폐 거래소. 원격 SanghyeokLee-KR/failstop(private). 학교 제출 계획서의 근거 문서.

이 문서의 모든 수치는 2026-08-25 HEAD(2a71234) 기준으로 코드·git·빌드 산출물에서 직접 계측했다. 계측으로 재현되지 않은 값은 "미확인"으로 표기했고 추정으로 채우지 않았다. 기존 docs/프로젝트_현황보고서.md의 오류 정정 내역은 11절에 있다.

## 1. 정의와 증명 명제

정의. 봇 플릿이 실시간으로 매매하는 완전 시뮬레이션 암호화폐 거래소. 실거래·실자산·런타임 외부 API 의존이 없다. 메인 산출물은 고정형 데스크톱 웹(Next.js 정적 export, 최소 폭 1280px)이고 백엔드는 Spring Boot 멀티모듈이다.

이 프로젝트가 증명하려는 것은 기능 목록이 아니라 반증 가능한 두 명제다.

- 증명 ① 체결 무결. 트래픽 폭주와 인프라 장애 아래에서도 자산별 원장 합이 0이고, 주문 중복 접수·중복 체결·주문 유실이 0이다.
- 증명 ② 자동 복구. 리더 노드를 죽여도 사람 개입 없이 승격·복구가 일어나고 체결이 재개된다. 목표 RTO 30초 이내.

판정 방식. 사람 눈이 아니라 SQL 위반 행 수 0, 메트릭 임계, 스크립트 exit code로만 판정한다. 불변식 검증기는 REPEATABLE READ READ ONLY 트랜잭션에서 26개 체크를 돌리고 결과를 invariant_checks 테이블에 적재한다. 페일오버 판정은 별도 엔드포인트가 harness.failover_runs에 적재한다.

## 4. 아키텍처

### 모듈 구성

- `server/engine` (main 10파일 1,099줄, test 4파일). 순수 Java. main 소스의 import가 전부 `java.*` 표준 라이브러리이고 서드파티 import가 0건이다. 빌드 파일도 `java-library` 단독에 테스트 전용 의존성만 갖는다. OrderBook·MatchingEngineImpl·SingleWriterLoop·SnapshotCodec 계열.
- `server/app` (main 176파일 18,768줄, test 55파일). 패키지 분포는 api 69, admin 22, engine 19, sim 16, journal 16, config 9, harness 8, ledger 5, dev 4, chaos 4, snapshot 3, 루트 1.
- `web` (150파일 23,749줄). Next.js 정적 export.
- `harness` (compose·스크립트 12개·k6 자산·SQL 카탈로그·Prometheus 룰·Grafana 대시보드).

### 3계층 SoT

| 계층 | 테이블 | 성질 |
|---|---|---|
| ① 복구 원천 | command_journal, event_journal, snapshots | append-only. UPDATE·DELETE를 forbid_mutation 트리거가 ROW·STATEMENT 두 겹으로 물리 차단. 재생 가능 |
| ② 회계 원천 | ledger_transactions, ledger_entries | 복식부기. 자산별 합 0. 봉인 가드 3종(assert_txn_sealed_balanced·guard_sealed_txn·guard_txn_transition) |
| ③ 파생 프로젝션 | balances, orders, trades, position_cost | 언제든 재계산 가능. position_cost는 rebuild_position_cost로 재구축 |

balance_ledger_check 뷰가 잔고 대 원장 합의 불일치를 mismatch 열로 노출한다. 증명 ②는 ①의 명령 재생으로, 증명 ①은 ②의 자산 보존 불변식으로 각각 판정한다.

### 고가용성 기제

- 단일 라이터를 DB `leader_lease` 행으로 보장한다(resource='matching-engine' 단일 행, 부트스트랩 시드 INSERT).
- 함수 3종이 V1__init.sql에 있다. `try_acquire_leader`는 `lease_until < clock_timestamp()` 조건부 UPDATE로 epoch를 +1해 반환한다. `renew_leader_lease`는 holder·epoch 일치와 미만료를 조건으로 갱신한다. `assert_current_leader`는 holder 불일치·epoch 불일치·리스 만료를 각각 EXCEPTION으로 던진다.
- 자산 변경 트랜잭션은 커밋 전에 `assert_current_leader`를 호출한다. 호출 지점은 CommandJournalAppender, EventJournalAppender, SettlementService 3곳. stale 리더의 쓰기는 롤백된다.
- split-brain을 데이터로 감사한다. command_journal은 fencing_token, event_journal·trades·snapshots는 fencing_epoch에 승격 epoch를 저장한다.
- 수용 제한. 쓰기·조회 2버킷 + 재조회 전용 소형 버킷. 초과는 거절이 아니라 판정 보류(409 requery_deferred + Retry-After)로 내보낸다. 인증 앞단 전용 필터로 배치돼 인증 비용 자체를 상한 안에 둔다.
- 좀비 리더 자발적 강등. 쓰기 수요 대비 쓰기 커밋 완료율이 임계 미만으로 지속되면 리스 갱신을 포기하고 강등한다. 판정 규칙은 LeaderStallDetectorTest가 단위 고정한다(희박 완료로 회복 불가, 무주문 유휴는 비판정, 일시 하락은 비강등).

### 배포 단위 분리

- A 거래 평면. 다중 인스턴스 전제. 카오스 토폴로지에서 chaos-api-1·chaos-api-2.
- B 봇 플릿. 외부 클라이언트 규약(서명·자체 HTTP)만 사용하고 내부 직호출이 없다. 카오스 스택에서는 엔진을 끈 별도 노드로 분리해 승격 주체 오염을 막는다.
- C 관리 평면. 분리 포트·네트워크·mTLS. `exchange.admin.enabled=true` 조건부 등록.
- 코어 exchange-core. Spring·락·I/O·벽시계·난수 금지.

### 봇 플릿

12개 마켓에 마켓메이커 14 + 테이커 12. 봇마다 가상 스레드 1개(`Thread.ofVirtual()`). 전역 OPS 버킷이 처리량 상한을 쥔다. 방향 bias 하드캡 ±0.7, 기준가 대비 ±40% 이탈 시 0으로 강제. 모든 난수는 시드 SplittableRandom을 고정 순서로 소비한다. bias·레짐 배수는 확률·틱 오프셋 스칼라 전용이라 가격·수량 NUMERIC 산술에 유입되지 않는다.

### E4 리더 kill

판정 프로토콜. 사전 권위 run(불변식 green) -> docker kill 주입 -> 무개입 관찰 -> 사후 권위 run.

RTO 정의는 페일오버 후 최초 신규 TRADE의 engine_ts(T5)에서 kill 시각(T0)을 뺀 값이다. T5 술어는 명령 축 fencing 기준(command_journal.fencing_token > 구 epoch)으로 확정됐다. 이벤트 축 술어와 승격 워터마크 술어는 승격 재생 산출물을 재개로 오인해 RTO를 과소 보고하므로 폐기됐다(E6 동일 조건 실측 0.086초 대 10.698초).

E4 RTO 수치는 미확인이다. 구 보고서의 "약 11.4초"는 2026-07-22 베이스라인 커밋부터 한 글자도 바뀌지 않은 값이고, 그 사이 2026-08-18에 T5 술어가 이벤트 축에서 명령 축으로 교체됐다. 재측정 커밋이 없다. 현 술어로 잰 값이 아닐 가능성이 높으므로 제출 계획서에 옮기기 전에 e4-leader-kill.ps1 재실행이 필요하다.

## 10. 한계와 리스크

이름을 붙여 적는다. 안 한 것을 안 한 것으로 적는 편이 제출 근거로서 방어 가능하다.

### 물리·인프라

- 물리 장비 없음. 전 구성이 단일 개발 머신의 Docker 컨테이너다. 노드 간 네트워크 분단은 Toxiproxy로 모사한 것이고 실제 네트워크 파티션이 아니다.
- 다중 리전·다중 가용영역 없음.
- 시계 스큐 내성 미증명. Docker VM 시계의 비단조성이 과거 E5·E7 판정을 흔든 적이 있다. 시계 스큐 자체에 대한 내성은 검증 범위 밖이다.

### RPO 성립 범위

RPO=0은 단일 PostgreSQL 인스턴스 범위에서만 성립한다. 카오스 토폴로지의 PostgreSQL 인스턴스는 1개이고 standby·repmgr·patroni 서비스가 없다. failover를 포함한 무손실은 동기 standby, synchronous_commit, 클러스터 STONITH 운영 요건을 전제하며 그 전제는 충족돼 있지 않다.

### 다중 노드 선행 조건 (미충족)

- NonceStore가 ConcurrentHashMap 기반 단일 노드 인메모리다. 정본 계약은 Redis SET이다. 클래스 주석이 단일 노드 전제와 교체 필요를 명시한다.
- WS가 단일 노드 SimpleBroker다. StompBrokerRelay 등 크로스노드 팬아웃이 없다.
- 잔고 사전 가드의 in-flight 예약 누계가 게이트웨이 프로세스 인메모리다(InflightReserves). 다중 노드에서 성립하지 않는다.

즉 현재 다중 인스턴스는 리더·팔로워 페일오버 구조로는 성립하지만, 전 노드가 동등하게 쓰기를 받는 수평 확장은 위 3건이 닫히기 전까지 성립하지 않는다.

### 개발 환경

- 한글 경로 문제는 해소되지 않았다. 현재 저장소 물리 경로 `C:\Users\DEV-PC\Desktop\프로젝트`에서 `gradlew test`가 ClassNotFoundException으로 실패한다. Docker를 쓰지 않는 순수 단위 테스트에서도 재현된다(kr.exchange.api.common.AdmissionLimitsTest, BUILD FAILED).

### 문서 산출물의 실재성

- `.codex/agents/*.toml` 4개는 디스크에만 있고 git 미추적이다. 원격 저장소를 받아 평가하면 확인 불가다(.gitignore 항목은 아니고 단순 미커밋).
- `docs/15분_라이브데모_대본.md`도 미추적이다.
- docs/백엔드_DB_설계.md는 "DDL 정본"으로 불리지만 §3 전체 DDL에 담긴 CREATE TABLE이 30개이고 그중 4개(audit_log·candles·transfer_requests·shedlock)는 문서 스스로 미구현 로드맵으로 명시한 엔티티다. 즉 구현 테이블 DDL 수록은 26개로 실제 46개의 절반 남짓이다. ### 검증 증거의 휘발성

카오스 실험 판정 산출물이 저장소에 남지 않는다. Write-Verdict는 콘솔 JSON만 출력하고 파일을 남기지 않으며, 페일오버 판정은 chaos-pg 컨테이너 안의 harness.failover_runs에 적재되고 `down -v`로 파기된다. 결과적으로 실행 이력이 실제보다 적게 보일 수 있고, 반대로 코드로 반증할 수도 없다. 제출 전에 실험 산출물을 파일로 남기는 배선을 추가하는 편이 낫다.
