# 로드맵

2026년 6월 착수. 저장소 개설 2026-07-22. 계획서 제출 2026-09-01. 최종 발표 2026-10-16.

최상위 목표는 하나다. 봇 플릿이 대량 주문을 쏟아붓는 동안 서버가 버티고, 장애를 주입해도 체결이 어긋나지 않으며 자동 복구되는 것을 데이터로 증명한다.
회원, 게시판, 관리자, 추가 화면은 이 증명 위에 얹는 기능이다. 순서를 뒤집지 않는다.

마일스톤은 분기가 아니라 실측 규모로 적는다. 종전 판은 Q1~Q4로 나눈 1년 계획이었는데
실제 수행은 7월 하순에 시작해 10월 중순에 끝난다. 분모가 없는 분기 표기는 진척률 착시를 만든다.

M1~M3 에 시작일과 종료일을 적지 않는다. 커밋 이력을 그룹별로 갈라 보면 네 마일스톤이 전부
2026-07-22 부터 08-30 까지 같은 구간에 흩어져 있다. 1인 수행이라 도메인을 순차로 닫지 않고
서버와 화면과 하네스를 오가며 진행했다. 순차 구간을 적으면 없는 순서를 있는 것처럼 만든다.
대신 커밋 수와 작업일(커밋이 실제로 찍힌 날 수)을 적는다. 산출 규모는 그것으로 드러난다.

## 상시 게이트 (모든 마일스톤 공통)

마일스톤 종료 조건에 항상 포함한다. 실패하면 기능이 몇 개든 미완료다.

- 봇 부하(기저 부하와 스파이크 10배)에서 불변식 전 항목 통과: 자산별 원장 합 0, 주문 중복·유실 0
- 리더 kill 주입 시 사람 개입 없이 복구, RTO 30초 이내
- CI green: 빌드, V3 통합테스트, 스타일 게이트

## M1. 코어 거래와 HA 증명 1차 (완료. 커밋 258 · 작업일 14)

범위.
- server: 저널 계층(command append, fsync ACK), 리더 리스·fencing(v2.6 계약), 매칭엔진 실구현과 재생 결정론, 원장 게시 함수 경유 정산, REST·WS(핵심 경로)
- 봇 플릿: 마켓메이커·테이커 기본형, 전역 OPS 제어
- 하네스: 불변식 검증기 상시 실행, 카오스 E1~E3(리더 kill, DB 단절, 폭주 복합), RTO 측정 체인
- web: 데스크톱 거래 화면을 실제 백엔드에 연결(HttpStompDataSource)

완료 기준. 15분 데모 시나리오(정상 → 폭주 → 리더 kill → 자동 복구 → 불변식 통과)가 재현 가능하다.

달성. 카오스 라이브 PASS 6건(E1·E2·E5·E6·E7·E9). E4는 RTO 측정 술어를 명령 축으로 교체한
2026-08-18 이후 재측정 기록이 없어 미확정이다. 이것이 M4의 1순위 잔여 항목이다.

## M2. 회원 (완료. 커밋 11 · 작업일 7)

범위.
- 가입·로그인(데모 인증. 실제 금융 자격증명·실명 정보는 받지 않는다), 세션·API 키 발급, 회원별 계정·자산 분리
- web: 회원 가입·로그인·마이페이지 화면, 회원별 자산·거래내역
- 봇 계정과 회원 계정의 권한 분리

완료 기준. 회원 다수가 봇 부하와 동시에 거래해도 상시 게이트 통과.

## M3. 커뮤니티와 관리자 (완료. 커밋 29 · 작업일 7)

범위.
- 종목 토론 게시판: 코인별 게시판, 글·댓글, 목록·페이징. 매칭 핫패스와 격리된 모듈로 구현하고 장애가 거래에 전파되지 않게 한다
- 관리자 페이지(별도 화면·별도 인증): 봇 플릿 제어, 카오스 실험 콘솔, 노드·지표 모니터링, 회원·게시판 운영
- 화면 확장: 공지, 코인 정보, 설정 등 부속 페이지

완료 기준. 게시판·관리자에 부하나 장애가 있어도 거래 상시 게이트에 영향이 없다.

## M4. 클라우드 배포와 최종 증명 (진행 중. 2026-08-31 ~ 10-16, 종전 커밋 15)

이 구간이 남은 전부다. 새 애플리케이션 기능은 붙이지 않는다. 인프라·배포·운영·보안에 쓴다.

범위.
- 클라우드 배포: Terraform IaC, ALB 2 가용영역, 앱 2대 상시, 도메인·TLS, 외부 상시 접속 성립
- 관측 하단: 계층 프로브 3종(ICMP·TCP·HTTP), 로그 중앙화, 알람 실발화
- 커널 계층 장애 주입: E10 tc netem. 종전 E1~E9는 전부 프록시 모사라 커널 큐 거동을 재현하지 않는다
- E4 리더 kill RTO 재측정. 증명 ②의 대표 수치인데 현행 술어 기준 실측이 없다
- 백업과 복구 실증, 배포 자동화, 보안 하드닝 증빙
- 최종 데모 대본(클라우드 판)과 발표 자료

완료 기준. 외부에서 도메인으로 접속되는 상태에서 8실험 verdict 파일이 산출되고, 자산합 위반 0행,
E4 RTO 30초 이내가 실측으로 확정된다.

잘라낼 순서를 미리 정한다. 밀리면 E8 앱 assault, E1 프록시 지연 재실행, E9 재실행 순으로 뺀다.
셋 다 애플리케이션 계층이라 시스템 엔지니어 관점의 증거 기여가 낮다. E4와 E10은 자르지 않는다.
