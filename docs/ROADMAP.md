# 로드맵

2026년 6월 착수. 저장소 개설 2026-07-22. 계획서 제출 2026-09-01. 최종 발표 2026-10-16.

최상위 목표는 하나다. 봇 플릿이 대량 주문을 쏟아붓는 동안 서버가 버티고, 장애를 주입해도 체결이 어긋나지 않으며 자동 복구되는 것을 데이터로 증명한다.
회원, 게시판, 관리자, 추가 화면은 이 증명 위에 얹는 기능이다. 순서를 뒤집지 않는다.

마일스톤은 분기가 아니라 실측 규모로 적는다. 종전 판은 Q1~Q4로 나눈 1년 계획이었는데
실제 수행은 7월 하순에 시작해 10월 중순에 끝난다. 분모가 없는 분기 표기는 진척률 착시를 만든다.

M1~M3 에 시작일과 종료일을 적지 않는다. 커밋 이력을 그룹별로 갈라 보면 네 마일스톤이 전부
2026-07-22 부터 08-30 까지 같은 구간에 흩어져 있다. 1인 수행이라 도메인을 순차로 닫지 않고
서버와 화면과 하네스를 오가며 진행했다. 순차 구간을 적으면 없는 순서를 있는 것처럼 만든다.
대신 커밋 수와 작업일(커밋이 실제로 찍힌 날 수)을 적는다. 산출 규모는 그것으로 드러난다.

## 상시 게이트 (모든 마일스톤 공통)

마일스톤 종료 조건에 항상 포함한다. 실패하면 기능이 몇 개든 미완료다.

- 봇 부하(기저 부하와 스파이크 10배)에서 불변식 전 항목 통과: 자산별 원장 합 0, 주문 중복·유실 0
- 리더 kill 주입 시 사람 개입 없이 복구, RTO 30초 이내
- CI green: 빌드, V3 통합테스트, 스타일 게이트

## M1. 코어 거래와 HA 증명 1차 (완료. 커밋 258 · 작업일 14)

범위.
- server: 저널 계층(command append, fsync ACK), 리더 리스·fencing(v2.6 계약), 매칭엔진 실구현과 재생 결정론, 원장 게시 함수 경유 정산, REST·WS(핵심 경로)
- 봇 플릿: 마켓메이커·테이커 기본형, 전역 OPS 제어
- 하네스: 불변식 검증기 상시 실행, 카오스 주입 실험, RTO 측정 체인. 실험 번호와 주입 대상은
  `제출_20260901/기획안_원본.md` 10.3이 정본이다. 값을 여기에 복사하지 않는다
- web: 데스크톱 거래 화면을 실제 백엔드에 연결(HttpStompDataSource)

완료 기준. 15분 데모 시나리오(정상 → 폭주 → 리더 kill → 자동 복구 → 불변식 통과)가 재현 가능하다.

달성. V41(커밋 `2a818b6`) 위 2026-09-13 주행에서 카오스 라이브 PASS는 6건(E1·E2·E4·E5·E6·E7)이다.
여덟 회차 전부 미커밋 경로 0에서 돌았다. RTO 실측 범위는 5.116초에서 10.226초다. E2 5.116 ·
E4 6.518 · E5 10.041 · E6 7.275 · E7 10.226. 다섯 회차 모두 `rpo_records` 0, epoch 1 -> 2 이고
E5·E7 스테일 쓰기 0이다. E9는 판정기 교정 이전 결과라 세지 않는다. 전부 로컬 카오스 스택이고 클라우드
스택 실측은 0건이다.

**E1은 V41 이전 코드에서 세 번 연속 FAIL했고 V41 위에서 세 번 연속 PASS했다.** FAIL은 리더 자신의
정산 트랜잭션이 리스 행을 FOR SHARE로 쥐어 갱신 UPDATE가 TTL 안에 잠금을 얻지 못한 페일오버였다
(`harness/evidence/e1-lease-starvation-20260913/`). ADR 0026이 쓰기 경로를 FOR KEY SHARE로 낮췄다.
V41 위 세 회차는 epoch 1 유지, 리스 갱신 잠금 대기 표본 0(회차당 표본 324~330), 마지막 갱신 경과
최대 2.378~2.549초, 쓰기 잠금 동시 보유 최대 4, 주입 창 갱신 성공 69~70회, 주입 p99 1,621.8~1,729.1ms
(기저 8.9~9.1ms)다. 2026-08-07 PASS는 마켓별 라이터 배선(`cd2e026`) 이전 코드의 결과라 세지 않는다.

증거는 회차마다 저장소에 남는다. 판정 파일이 `harness/evidence/chaos-runs/<runId>.json`으로
떨어진다(커밋 `36e22ac`). V41 위 여덟 회차는 E1-20260913-150606·151025·151447, E2-20260913-151907,
E4-20260913-152059, E5-20260913-152225, E6-20260913-152439, E7-20260913-152638 이다. 같은 디렉터리의
나머지 2026-09-13 회차는 V41 이전 기준선이다.

## M3. 커뮤니티와 관리자 (완료. 커밋 29 · 작업일 7)

범위.
- 종목 토론 게시판: 코인별 게시판, 글·댓글, 목록·페이징. 매칭 핫패스와 격리된 모듈로 구현하고 장애가 거래에 전파되지 않게 한다
- 관리자 페이지(별도 화면·별도 인증): 봇 플릿 제어, 카오스 실험 콘솔, 노드·지표 모니터링, 회원·게시판 운영

완료 기준. 게시판·관리자에 부하나 장애가 있어도 거래 상시 게이트에 영향이 없다.

## M4. 클라우드 배포와 최종 증명 (진행 중. 2026-08-31 ~ 10-16, 종전 커밋 15)

이 구간이 남은 전부다. 새 애플리케이션 기능은 붙이지 않는다. 인프라·배포·운영·보안에 쓴다.

예외가 하나 있다. ADR 0022(명령 저널 마켓별 분할)의 되돌릴 수 있는 0~5단계를 배포 전에 한다.
2026-09-13 결정이다. 클라우드 배포가 지원금 확정 대기로 밀린 구간을 쓰고, 기능 추가가 아니라
접수 처리량 상한을 치는 구조 변경이다. 되돌릴 수 없는 6단계는 배포 뒤 클라우드에서 fsync 와
동시 커밋 확장성을 다시 재고 따로 정한다. 2026-09-14 사용자 결정으로 6단계 구현과 래치 실측은
도커 카오스 스택에서 먼저 하고, 클라우드 DB 의 래치는 배포 때 정한다.

범위. 토폴로지 사실은 여기에 복사하지 않는다.  6절이 정본이다.
- 클라우드 배포: Terraform IaC, 도메인·TLS, 외부 상시 접속 성립
- 관측 하단: 계층 프로브 3종, 상시면 관측 배선, 알람 실발화
- 커널 계층 장애 주입: E10 tc netem. 종전 E1~E9는 전부 프록시와 컨테이너 조작이라 커널 큐 거동을 재현하지 않는다
- 병목 이동 실측: DB를 키운 뒤 앱이 병목이 되는 구간을 잡는다. 2026-09-08 회차는 수요를 천장 아래로 고정해 이 이동이 드러나지 않았다
- DB 페일오버 리허설: 수동 승격 절차를 다중 호스트에서 한 번 끝까지 돌린다. 앱 엔드포인트 전환이 사람 손이고 그 구간이 미실측이다
- 백업과 복구 실증, 배포 자동화, 보안 하드닝 증빙
- 최종 데모 대본(클라우드 판)과 발표 자료

완료 기준. 외부에서 도메인으로 접속되는 상태에서 verdict 파일이 산출되고, 자산합 위반 0행,
E4 RTO 30초 이내, 그리고 병목 계층을 관측으로 특정해 조작 효과를 실측한 것이 확정된다.
마지막 항목이 새 정본의 증명 축 3이다.

잘라낼 순서를 미리 정한다. 밀리면 E8 앱 assault, E1 프록시 지연 재실행, E9 재실행 순으로 뺀다.
셋 다 애플리케이션 계층이라 시스템 엔지니어 관점의 증거 기여가 낮다. E10 은 자르지 않는다.

E4 는 로컬 스택 1회차 실측이라 클라우드에서 한 번 더 돌린다. 자르는 대상은 아니고 재현 대상이다.

## 원칙

- 게시판·관리자 등 부가 기능이 코어 경로(매칭, 정산, 저널)에 의존성을 추가하는 설계 금지.
- 새 화면·기능은 역할 하네스(backend-engineer, frontend-engineer)로 구현하고 reviewer 판정 후 병합한다.
- 이 문서는 마일스톤이 닫힐 때 갱신한다. 범위 변경은 커밋으로 남긴다.
