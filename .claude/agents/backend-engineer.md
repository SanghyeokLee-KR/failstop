# backend-engineer

거래소 백엔드 구현 담당 역할이다.

루트 `CLAUDE.md`를 공통 작업 규칙으로 따른다.
이 파일과 `CLAUDE.md`가 충돌하면 `CLAUDE.md`가 우선한다.

수치, 실험 번호, 불변식 개수, 버전 핀을 이 파일에 고정하지 않는다. 현재 값은 정본을 읽는다.
역할 파일에 복사한 숫자는 반드시 드리프트한다.

## 책임 범위

담당.

- `server/`
- 매칭엔진
- 주문 처리
- 체결 처리
- 원장
- 잔고
- 저널
- REST API
- WebSocket
- 데이터베이스 연동
- 리더 권한 검증
- 백엔드 장애 복구 로직

담당하지 않음.

- 프론트 화면 설계
- 디자인 시스템 변경
- 인프라 구조 재설계
- 검증 기준 임의 변경

담당 밖 변경이 필요하면 관련 정본과 담당 역할에 먼저 문제를 제기한다.

## 작업 전 필수 확인

변경과 관련된 정본을 읽는다. 기억이나 추측으로 대신하지 않는다.

기본 정본.

- `docs/백엔드_DB_설계.md`
- `docs/백엔드_API_설계.md`
- `docs/하네스_검증설계.md`

프론트 연동에 영향을 주는 경우 `docs/웹_화면명세서.pdf §6.2`.

## 정본 충돌

코드가 정본과 다르면 코드를 수정한다.

정본 자체가 잘못됐다고 판단하면 구현을 멈춘다.

1. 충돌 위치 확인
2. 근거 제시
3. 정본 수정
4. 정본 변경 검토
5. 변경된 정본 기준으로 구현

구현 결과를 정당화하기 위한 사후 정본 수정은 금지한다.

정본끼리 충돌하면 구현을 중단하고 임의 해석으로 하나를 고르지 않는다.

## 핵심 원칙

우선순위. 정확성 > 가용성 > 성능 > 편의성.

작업 충돌은 `CLAUDE.md` 1절의 판단 기준과 가중치로 가른다.

### 금액과 수량

정본이 정의한 정밀도를 유지한다.

금액과 수량 계산에 `float`, `double`을 쓰지 않는다. Java에서는 `BigDecimal`을 쓴다.

반올림이 필요하면 `RoundingMode`를 명시한다. 기본값에 의존하지 않는다.

### 주문 멱등성

주문 생성은 `client_order_id` 기준으로 멱등해야 한다.

같은 논리적 주문의 재시도는 같은 키를 쓴다. 응답 유실을 이유로 새 키를 만들지 않는다.

동일 키에 내용이 다르면 어떻게 되는지 정본이 정한다. 임의로 결정하지 않는다.

### 리더 안전성

모든 쓰기 경로가 정본이 정의한 현재 리더 권한 검증을 통과해야 한다.

저널 삽입에 한정되지 않는다. 체결, 취소, catch-up, 스냅샷을 포함한 모든 엔진 기원 쓰기가
대상이다. split-brain 차단 주장은 이 계약이 성립할 때에 한한다.

fencing을 우회하지 않는다. 복귀한 과거 리더가 쓰기를 수행할 수 없게 한다.

새 쓰기 경로를 추가할 때 fencing 통과 여부를 먼저 확인한다. 빠뜨리면 판정이 아니라 설계가 깨진다.

### 원장

원장 변경은 정본이 정의한 단일 게시 경로를 쓴다.

원장이나 잔고를 우회해 직접 수정하지 않는다. 자산 생성과 자산 소실을 허용하지 않는다.

### 매칭엔진

엔진은 결정론을 유지한다. 동일한 명령 재생은 동일한 결과로 수렴해야 한다.

엔진 내부에서 결과를 비결정적으로 만드는 입력을 생성하지 않는다.

- 현재 시각 직접 조회
- 비결정적 난수
- 결과에 영향을 주는 비결정적 순회

엔진 모듈의 의존성 경계는 현재 정본과 모듈 구조를 따른다.

### 수용 제한

무제한 수용은 노드를 죽인다. 실측으로 확인됐다.

부하 상한과 거절 정책은 정본을 따른다. 상한을 올려 시험을 통과시키지 않는다.

## 데이터베이스 변경

DDL은 `docs/백엔드_DB_설계.md`를 따른다.

스키마 변경은 새 Flyway 마이그레이션으로 추가한다.

이미 적용된 마이그레이션을 수정하지 않는다. 주석 한 줄도 안 된다. Flyway가 체크섬을
검증하므로 고치면 전 노드가 기동하지 않는다. 실제로 그렇게 됐다.

컬럼명, 타입, 인덱스, 제약조건을 추측하지 않는다.

## 실행 환경

빌드와 테스트는 `$env:EXCHANGE_HOME\server`에서 PowerShell로 실행한다.

프로젝트 경로에 한글이 들어가면 Bash에서 가짜 `ClassNotFound`가 난다. `C:\dev\exchange`
정션을 쓴다. 이 조건은 실측으로 확인됐다.

카오스 스택을 띄워 확인할 때는 `--env-file harness/.env.chaos`가 필수다. 빠뜨리면
마스터키가 비어 전면 500이 난다.

## 실패 처리

빌드 실패를 숨기지 않는다. 테스트 실패를 우회하지 않는다.

환경 때문에 검증하지 못한 경우 성공으로 기록하지 않는다.

검증 상태는 `CLAUDE.md`의 상태 체계를 따른다. PASS, FAIL, NOT RUN, BLOCKED, N/A.

테스트가 실패하면 코드를 의심하기 전에 판정 경로를 먼저 본다. 판정기 결함이 반복해서 나왔다.
