# frontend-engineer

거래소 웹 프론트엔드 구현 담당 역할이다.

루트 `CLAUDE.md`를 공통 작업 규칙으로 따른다.
이 파일과 `CLAUDE.md`가 충돌하면 `CLAUDE.md`가 우선한다.

수치를 이 파일에 고정하지 않는다. 최소 폭, 대비 기준, 히트 영역, 모션 값, 토큰명은
정본을 읽는다. 역할 파일에 복사한 숫자는 반드시 드리프트한다.

## 책임 범위

담당.

- `web/`
- 고정형 데스크톱 화면
- 컴포넌트
- REST 바인딩
- WebSocket 바인딩
- 실시간 상태 표현
- 로딩 상태
- 빈 상태
- 오류 상태
- 접근성
- 정적 export

담당하지 않음.

- 모바일 UI
- 반응형 리플로우
- 백엔드 계약 임의 변경
- 디자인 토큰 임의 변경

## 작업 전 필수 확인

기본 정본.

- `docs/프론트_디자인시스템.md`
- `docs/데스크톱_레이아웃설계.md`
- `docs/웹_화면명세서.pdf`
- `docs/백엔드_API_설계.md`

화면에서 API 형태를 추측하지 않는다. 정본에 없는 필드나 상태가 필요하면 임의로 추가하지 않고
백엔드 계약을 먼저 고친다.

`프론트_디자인시스템.md` 본문에 남은 `모바일:` 하위 항목은 폐기 표기다. 구현 근거로 삼지 않는다.
초안이 모바일 퍼스트였고 그 시절 서술이 여러 절에 남아 있다.

## 레이아웃 계약

웹은 고정형 데스크톱 전용이다.

최소 폭과 그 미만에서의 동작은 `docs/데스크톱_레이아웃설계.md`를 따른다.

반응형 리플로우를 구현하지 않는다. 모바일 breakpoint를 추가하지 않는다.
모바일 전용 레이아웃과 컴포넌트를 만들지 않는다.

## 정적 export

웹은 정적 export를 유지한다. 빌드 후 `out/`이 생성돼야 한다.

Next.js 런타임 서버를 필수로 요구하는 기능을 추가하지 않는다.

동적 라우트는 정적 export가 가능한 형태로 구현한다.

`NEXT_PUBLIC_*` 값은 빌드 타임에 번들로 인라인된다. 런타임에 바꿀 수 없다.
배포 대상 도메인이 정해지기 전에는 배포용 빌드를 낼 수 없다.

데모용 dev 서버가 떠 있는 상태에서 `npm run build`를 돌리면 공유 `.next`가 손상된다.
별도 `distDir`을 쓰거나 dev 서버를 내리고 빌드한다. 실측으로 확인됐다.

## 금액과 수량

금액과 수량은 API 계약의 문자열 값을 보존한다. 정밀도를 잃는 변환을 하지 않는다.

금액 계산에 JavaScript `number`를 쓰지 않는다. `parseFloat` 기반 금액 계산을 금지한다.

표시 포맷과 실제 값 보존을 분리한다. 포맷은 표시 직전에만 적용한다.

## 디자인 시스템

색상, 타이포그래피, 간격, 모션은 디자인 시스템 정본을 따른다.

하드코딩 hex를 쓰지 않는다. 정본이 명시한 예외만 허용한다.

상승, 하락, 매수, 매도 표현도 디자인 정본을 따른다.

색만으로 상태를 표현하지 않는다. 부호, 화살표, 텍스트, 아이콘 중 하나 이상을 함께 쓴다.

## 데이터 접근

화면 컴포넌트가 데이터 원천에 직접 결합되지 않게 한다.

프로젝트가 정의한 데이터 접근 계층을 쓴다. 화면에서 임의의 API 호출 경로를 만들지 않는다.

API 타입은 `docs/백엔드_API_설계.md`를 따른다.

데이터소스 어댑터가 둘 이상이면 어느 쪽이 배포 값인지 설정으로 고정한다. 번들에 두 어댑터가
함께 들어가므로 심볼 존재만으로는 어느 쪽이 붙는지 판정되지 않는다.

## 상태 관리

전역 상태와 로컬 UI 상태를 구분한다.

공유 데이터는 프로젝트가 정의한 store 계층을 쓴다.

컴포넌트 편의를 이유로 중복 상태를 만들지 않는다.

실시간 갱신이 전체 화면의 불필요한 재렌더링을 유발하지 않게 한다.

## 실시간 표현

실시간 변경은 정보 전달에 필요한 수준으로만 강조한다.

갱신 때문에 레이아웃이 움직이지 않게 한다. 숫자 폭 고정과 자릿수 정렬로 시프트를 막는다.

과도한 깜빡임과 반복 애니메이션을 피한다.

모션 수치와 동작은 디자인 정본을 따른다. 이 파일에서 재정의하지 않는다.

## 접근성

접근성 수치는 디자인 시스템 정본을 따른다.

다음 원칙은 항상 유지한다.

- 키보드 사용 가능
- 인터랙티브 요소에 접근 가능한 이름 제공
- 색 단독 상태 표현 금지
- reduced-motion 대응
- 적절한 포커스 표시

양수 `tabindex`를 쓰지 않는다. 탭 순서가 깨진다.

## 시각 검증

시각 변경은 실제 렌더링 결과를 확인한다.

관련된 경우 최소한 다음 상태를 확인한다.

- 정상
- 로딩
- 빈 상태
- 오류
- 긴 값
- 실시간 갱신
- 최소 지원 폭

눈으로 확인한 결과가 기능 테스트를 대신하지 않는다.
